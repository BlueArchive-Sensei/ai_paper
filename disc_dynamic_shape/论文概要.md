# DISC 论文概要

## 基本信息

- 题目：*DISC: A Dynamic Shape Compiler for Machine Learning Workloads*
- 作者：Kai Zhu、Wenyi Zhao、Zhen Zheng 等
- 会议：EuroMLSys 2021
- 原文：[arXiv:2103.05288](https://arxiv.org/abs/2103.05288)
- 本地文件：[paper.pdf](paper.pdf)｜[paper.txt](paper.txt)

## 一句话结论

DISC 用动态 HLO 方言、编译生成的 host runtime flow 和 shape constraint 驱动的融合，在不为每个新 shape 重编译整张图的前提下优化动态 shape workload。

## 核心方法

- 以 DHLO 扩展 HLO，把 slice/pad/broadcast 等原本要求常量的 attribute 改成 runtime tensor argument。
- 编译生成 shape inference、buffer management、kernel launch 和 library call 的 host 代码。
- 收集 dimension equality 与 tensor element-count equality 等 shape constraints。
- 用 shape propagation 和 constraints 判断动态 shape operator 是否可融合。
- 对 launch size、vectorization 和 broadcast 生成多版本 kernel，并在运行时选择。
- 静态 shape 子图仍回退到 static compiler。

## 关键结果

- 在 T4、CUDA 10 环境的 ASR、Seq2seq、TTS、BERT、广告排序和 Transformer 上评估。
- 相对原始 TensorFlow/PyTorch 平均 2.27×，最高约 3.35×。
- Transformer memory-bound 部分从 66.06 ms 降至 21.52 ms，kernel calls 从 42884 降至 6186。
- 与 static optimization 相比，dynamic compiler 平均达到约 85% 性能，显示动态通用性仍有代价。

## 与 Nimble 的区别

Nimble 用 VM 解释动态 runtime flow；DISC 尝试把 host flow 本身也编译出来，降低解释开销并扩大 host-device 联合优化机会。

## 主要局限

- 只支持 static rank、dynamic dimensions。
- 对 compute-heavy GEMM/Conv 仍依赖 library 或 shape-specific kernel。
- 论文篇幅短，部分对比使用重新实现的 Nimble 配置，复现口径需谨慎。
- 结果来自 2021 年的软件与硬件栈。

## 阅读价值

它解释了 symbolic shape 不只是 IR 里把整数换成变量：shape inference、buffer、fusion、launch configuration 和 host control 都必须一起改变。
