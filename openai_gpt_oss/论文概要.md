# 资料概要：《gpt-oss-120b & gpt-oss-20b Model Card》

## 一、基本信息

- 发布方：OpenAI
- 公开时间：2025-08
- 类型：开放权重模型卡，含较完整架构、训练、评测与安全测试
- 许可证：权重 Apache 2.0，并附 gpt-oss usage policy
- 本地材料：[官方 PDF](paper.pdf) · [提取文本](paper.txt) · [中文精读](论文中文解读.md)

## 二、一句话结论

gpt-oss 是 OpenAI 发布的两个开放权重（Apache 2.0）推理模型：都是 top-4 MoE，MoE 权重（占总参数 90% 以上）以 MXFP4 量化，交替使用带宽 128 token 的 banded attention 与 full attention，并公开 Harmony 多 channel 格式和可调 reasoning effort；它的架构开放度远高于 GPT-4/o1，但预训练数据与 RL recipe 仍只做高层披露。模型卡的安全部分以“对抗微调的最坏情况评估”为重点：对 120b 做生物与网络方向的对抗微调后，仍未达到 Preparedness Framework 的 High 阈值。

## 三、架构速览

| 模型 | 层数 | 总参数 | 每 token 激活 | experts | 上下文 |
|---|---:|---:|---:|---:|---:|
| gpt-oss-120b | 36 | 116.8B | 5.1B | 128，top-4 | 128K |
| gpt-oss-20b | 24 | 20.9B | 3.6B | 32，top-4 | 128K |

两者 residual width 均为 2880；64 个 query heads、8 个 KV heads；RoPE + YaRN；MoE 使用 SwiGLU；绝大多数 MoE 权重以 MXFP4 保存。

## 四、后训练

- 与 OpenAI o3 类似的 CoT 强化学习技术，训练 reasoning 与工具调用（具体算法、数据与规模未披露；只有指令层级一项明确说用了监督数据）。
- Harmony 格式用 analysis（CoT）、commentary（函数工具调用）、final（用户可见答案）三个 channel，并规定 System > Developer > User > Assistant > Tool 的指令层级。
- 同一模型支持 low/medium/high reasoning effort。
- 模型卡还评估 instruction hierarchy、幻觉 chain-of-thought 与最坏情况恶意微调风险。

## 五、局限

- “开放权重”不是完整 open source training：数据、训练代码与 RL 环境未全部公开。
- MXFP4 checkpoint 的实际速度依赖硬件/推理引擎支持。
- 公开 CoT 没有被施加优化压力，可能含幻觉内容和不符合安全政策的语言，不能直接展示给用户，也不能当可验证解释。
- benchmark 与安全结论是发布时快照，微调后风险会变化。
