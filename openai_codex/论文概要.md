# 论文概要：《Evaluating Large Language Models Trained on Code》

## 一、基本信息

- 作者：Mark Chen 等，OpenAI
- 公开时间：2021-07，arXiv:2107.03374
- 模型：Codex，GPT 系列在公开代码上继续训练，最大 12B
- 核心贡献：HumanEval、pass@k 与代码模型风险分析
- 开放边界：论文与 HumanEval 公开；原始 Codex 权重未开放
- 本地材料：[论文 PDF](paper.pdf) · [提取文本](paper.txt) · [中文精读](论文中文解读.md)

## 二、一句话结论

Codex 论文把代码生成从文本相似度改成“程序能否通过隐藏单元测试”，并表明多次采样会显著提高至少一个正确解的概率；但最佳样本选择、prompt 中的错误模式、依赖安全与许可证/数据治理仍是部署难点。

## 三、关键设置

- 从 GPT 模型出发，在来自 5400 万公共 GitHub 仓库的代码语料上训练，重点清洗 Python 文件。
- 建立 164 道手写 Python 函数题的 HumanEval，每题含 docstring、函数签名与隐藏测试。
- 用无偏估计器报告 pass@k，避免只按生成代码的 BLEU 排名。
- 研究采样 temperature、样本排序、docstring generation 与微调数据质量。

## 四、代表结果

Codex-12B 在 HumanEval 上报告约 28.8% pass@1，生成 100 个候选时 pass@100 约 72.3%。这说明采样预算是能力的一部分，但部署系统还必须从候选中选出正确程序；没有测试时，模型自身 log-probability 并非可靠排序器。

## 五、局限

- HumanEval 规模小、函数短，远不等于真实仓库修改。
- hidden tests 有限，pass 不代表安全、复杂度或完整语义正确。
- 公共代码训练存在近重复、许可证和脆弱模式继承问题。
- prompt 中有细微 bug 时，模型可能延续 bug，且规模增大不一定自动修复。
