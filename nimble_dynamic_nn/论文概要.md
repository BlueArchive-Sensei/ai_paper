# Nimble 论文概要

## 基本信息

- 题目：*Nimble: Efficiently Compiling Dynamic Neural Networks for Model Inference*
- 作者：Haichen Shen、Jared Roesch、Zhi Chen 等
- 会议：MLSys 2021
- 原文：[MLSys Proceedings](https://proceedings.mlsys.org/paper/2021/hash/5b47430e24a5a1f9fe21f0e8eb814131-Abstract.html)
- 本地文件：[paper.pdf](paper.pdf)｜[paper.txt](paper.txt)

## 一句话结论

Nimble 通过带 Any dimension 的渐进类型、runtime shape function、动态内存规划和轻量 VM，把控制流、数据结构和 tensor shape 的动态性编译成可跨 CPU/GPU 平台部署的执行程序。

## 核心方法

- 用 Any 表示编译期未知维度，并以 sub-shaping 尽量保留已知信息。
- 对每个 operator 附加 shape function，在运行时计算输出 shape 并检查无法静态证明的约束。
- 将隐式分配改写为显式 alloc/invoke/kill，支持动态 buffer reuse。
- 分析 shape computation 与 tensor computation，做 CPU/GPU heterogeneous placement。
- 为可能的 shape 生成多个 symbolic kernels，在运行时 dispatch。
- 用 VM bytecode 表达只能到运行时才确定的路径和内存行为。

## 关键结果

- 论文覆盖 LSTM、Tree-LSTM 和 BERT，在 Intel CPU、NVIDIA GPU、ARM CPU 上评估。
- 摘要报告相对既有方案最高 20×；具体收益随模型和平台差异很大。
- BERT 相对最佳替代方案约为 Intel CPU 1.5×、NVIDIA GPU 1.3×、ARM CPU 1.05×。
- 动态内存规划减少 47% buffer allocation，并在 Intel CPU 上降低 75% allocation latency。

## 主要局限

- 目标是已训练模型的 inference，不是任意 Python 训练程序捕获。
- VM 带来 instruction dispatch 和 shape function 开销。
- symbolic kernel 通常不及精确 static shape kernel；多版本 dispatch 用空间换性能。
- 实验基于 TVM 0.6 与当时硬件。

## 阅读价值

Nimble 把“动态”拆成控制流、数据结构、shape、内存和设备放置五类问题，是理解动态图编译器后半段 runtime 责任的好材料。
