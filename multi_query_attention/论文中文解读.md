## 一、一句话结论

Transformer 训练时可以沿序列长度并行，但**自回归生成（增量解码）**每次只能产生一个位置，每一步都要把此前所有位置的 key、value 张量重新从内存读一遍。现代加速器的算力比内存带宽高两个数量级，所以增量解码被“反复读取巨大的 K、V”这件事卡住。作者提出 **multi-query attention（MQA）**：保留多个 query 头，但所有头**共享同一组 key 和 value**（去掉 K、V 的“头”维度），K、V 缓存缩小为原来的 $1/h$。在 WMT 2014 英德翻译上，每个解码词的摊销耗时从 46 微秒降到 3.8 微秒（约 12 倍），翻译质量只轻微下降；在 Billion-Word 语言模型上，困惑度从 29.9 变为 30.2。

## 二、背景：多头注意力与增量解码的代价

### 2.1 einsum 记号与单个 query 的点积注意力

论文的代码用 `einsum`（TensorFlow、numpy 都有的广义张量收缩）：方程里给每个张量的各维度起一个字母；运算等价于把每个输入广播到所有字母的并集，逐元素相乘，再对**不出现在输出里**的字母求和。

单个 query $q\in\mathbb{R}^{k}$ 对 $m$ 对 (key, value)：$K\in\mathbb{R}^{m\times k}$，$V\in\mathbb{R}^{m\times v}$：

```python
def DotProductAttention(q, K, V):
    # q: [k]；K: [m, k]；V: [m, v]；返回 y: [v]
    logits = tf.einsum("k,mk->m", q, K)      # 点积分数，每个 key 一个
    weights = tf.softmax(logits)             # 归一化成注意力权重
    return tf.einsum("m,mv->v", weights, V)  # 对 value 加权求和
```

用公式写就是 $y=\sum_{j=1}^{m}\mathrm{softmax}(qK^\top)_j\,V_j$。论文还说明：原始 Transformer 在 logits 上有一个常数缩放因子，代码里略去，因为它可以并进投影矩阵 $P_q$ 或 $P_k$。

### 2.2 多头注意力（一个 query 的版本）

Transformer 并行用 $h$ 个注意力层（头）：query 来自 $h$ 个不同的可学习线性投影 $P_q$，key、value 来自对 $m$ 个输入向量构成的矩阵 $M$ 的 $h$ 组投影 $P_k,P_v$；$h$ 个头的输出再各自经过投影 $P_o$ 并求和。为简单起见输入输出维度都取 $d$：

```python
def MultiheadAttention(x, M, P_q, P_k, P_v, P_o):
    # x: [d]；M: [m, d]；P_q, P_k: [h, d, k]；P_v, P_o: [h, d, v]；返回 y: [d]
    q = tf.einsum("d,hdk->hk", x, P_q)          # 每个头一个 query
    K = tf.einsum("md,hdk->hmk", M, P_k)        # 每个头一份 key
    V = tf.einsum("md,hdv->hmv", M, P_v)        # 每个头一份 value
    logits = tf.einsum("hk,hmk->hm", q, K)
    weights = tf.softmax(logits)
    o = tf.einsum("hm,hmv->hv", weights, V)     # 每个头的输出
    y = tf.einsum("hv,hdv->d", o, P_o)          # 各头经 P_o 投影后求和
    return y
```

### 2.3 批量多头注意力与它的性能分析

实际中会把很多 query 打包：一是对序列中 $n$ 个不同位置同时生成 query（它们共享同样的 K、V）；二是同时处理 $b$ 条互不相干的序列。自回归模型靠给 logits 加一个值为 $-\infty$ 的 mask 来阻断“向后的信息流”。

```python
def MultiheadAttentionBatched(X, M, mask, P_q, P_k, P_v, P_o):
    # X: [b, n, d]；M: [b, m, d]；mask: [b, h, n, m]；P_q, P_k: [h, d, k]；P_v, P_o: [h, d, v]
    Q = tf.einsum("bnd,hdk->bhnk", X, P_q)
    K = tf.einsum("bmd,hdk->bhmk", M, P_k)
    V = tf.einsum("bmd,hdv->bhmv", M, P_v)
    logits = tf.einsum("bhnk,bhmk->bhnm", Q, K)
    weights = tf.softmax(logits + mask)
    O = tf.einsum("bhnm,bhmv->bhnv", weights, V)
    Y = tf.einsum("bhnv,hdv->bnd", O, P_o)
    return Y                                    # [b, n, d]
```

**性能分析**（原文 2.3.1 节）。为简化，论文设三个条件：$m=n$；$k=v=d/h$（Vaswani 等的设置）；$n\le d$。

- 算术运算总量：每个 `einsum` 的代价都是 $O(bnd^2)$，所以总计 $\Theta(bnd^2)$；
- 需要访问的内存总量，等于所有相关张量的大小之和：$O(bnd+bhn^2+d^2)$。第一项来自 $X,M,Q,K,V,O,Y$，第二项来自 logits 与 weights，第三项来自投影矩阵 $P_q,P_k,P_v,P_o$；
- 两者之比（内存访问 / 算术运算）为 $O\!\left(\tfrac1k+\tfrac1{bn}\right)$。

这个比值小是在现代 GPU/TPU 上获得高效率的必要条件，因为这类硬件的计算能力可以比内存带宽高两个数量级：每搬一个数字要做很多次运算，算力才用得满。批量多头注意力满足这一点。

### 2.4 增量（自回归）多头自注意力及它的瓶颈

有些场景数据依赖使得无法并行处理多个位置。典型例子是自回归语言模型里的自注意力层：位置 $t$ 的 query 要看到位置 $1$ 到 $t$ 的 key、value。训练时目标序列已知，可以像 2.3 那样并行；但**生成**时，某位置自注意力层的输出会决定下一个位置产生什么 token，而这个 token 又是该层下一位置的输入，所以不能并行。一步一步地算，代码如下（`prev_K`、`prev_V` 是此前所有位置缓存的 K、V，每一步把新位置的 K、V 拼接上去）：

```python
def MultiheadSelfAttentionIncremental(x, prev_K, prev_V, P_q, P_k, P_v, P_o):
    # x: [b, d]；prev_K: [b, h, m, k]；prev_V: [b, h, m, v]
    # 返回 y: [b, d]；new_K: [b, h, m+1, k]；new_V: [b, h, m+1, v]
    q = tf.einsum("bd,hdk->bhk", x, P_q)
    new_K = tf.concat([prev_K, tf.expand_dims(tf.einsum("bd,hdk->bhk", x, P_k), axis=2)], axis=2)
    new_V = tf.concat([prev_V, tf.expand_dims(tf.einsum("bd,hdv->bhv", x, P_v), axis=2)], axis=2)
    logits = tf.einsum("bhk,bhmk->bhm", q, new_K)
    weights = tf.softmax(logits)
    o = tf.einsum("bhm,bhmv->bhv", weights, new_V)
    y = tf.einsum("bhv,hdv->bd", o, P_o)
    return y, new_K, new_V
```

（更正：论文这段伪代码在计算新 key、新 value 时写成了 `M`，应为当前输入 `x`；最后一行把变量 `o` 写成了 `O`。）

**性能分析**（原文 2.4.1 节，条件同前）。在 $n$ 次调用中：

- 算术运算总量仍是 $\Theta(bnd^2)$；
- 内存访问总量是 $\Theta(bn^2d+nd^2)$：第一项来自反复读取 $K$ 和 $V$，第二项来自反复读取四个投影矩阵；
- 两者之比为 $\Theta\!\left(\tfrac nd+\tfrac1b\right)$。

当 $n\approx d$ 或 $b\approx1$ 时，这个比值接近 1，内存带宽成为主要的性能瓶颈。要让增量生成高效，两项都必须远小于 1。$\tfrac1b$ 这一项容易解决：用更大的 batch（受内存大小限制）。**$\tfrac nd$ 这一项难**：它对应每一步重新加载记忆张量 $K,V$ 的开销。已有的缓解办法是限制序列长度 $n$，或减少被关注的位置数（局部邻域注意力，或压缩记忆位置，如 Liu 等 2018、Zhang 等 2018、Povey 等 2018）。这篇论文提出一个**与之正交**的办法：去掉 K、V 的“头”维度，同时保留 query 的“头”维度。

（笔者核对：论文写 K、V 大小为 $bhmk=bn^2$，按 $hk=d$、$m=n$ 算，每一步 K、V 的大小应为 $bnd$，$n$ 步合计才是 $\Theta(bn^2d)$；这是论文中的一处小笔误，不影响结论。）

## 三、方法：Multi-Query Attention（第 3 节）

### 3.1 定义

多头注意力有多个并行的注意力层（头），它们对 query、key、value 和输出各有自己不同的线性变换。**多查询注意力与它完全相同，只是所有头共享同一组 key 和 value**。实现上，把多头版本 `einsum` 方程里表示 K、V、$P_k$、$P_v$ 的“头”维度的字母 `h` 删掉即可。

| 张量 | 多头（MHA）形状 | 多查询（MQA）形状 |
|---|---|---|
| Q（query） | $[b,h,n,k]$ | $[b,h,n,k]$ |
| K（key） | $[b,h,m,k]$ | $[b,m,k]$ |
| V（value） | $[b,h,m,v]$ | $[b,m,v]$ |
| 投影 $P_q$ | $[h,d,k]$ | $[h,d,k]$ |
| 投影 $P_k$ | $[h,d,k]$ | $[d,k]$ |
| 投影 $P_v$ | $[h,d,v]$ | $[d,v]$ |
| 投影 $P_o$ | $[h,d,v]$ | $[h,d,v]$ |
| logits / weights | $[b,h,n,m]$ | $[b,h,n,m]$ |

这张表是笔者根据论文代码中各张量的形状注释整理的。对第 $i$ 个头，注意力为 $O_i=\mathrm{softmax}\big(Q_iK^\top+\text{mask}\big)V$（所有头用同一个 $K,V$），最后 $Y=\sum_iO_iP_{o,i}$。论文标题里的“write-head”可以理解为：写入记忆（缓存）的是 K、V，这样的头只需要一个，而读取用的 query 头仍然可以有很多个（这是笔者对标题的理解）。

批量版本的代码（训练或 prefill 用）：

```python
def MultiqueryAttentionBatched(X, M, mask, P_q, P_k, P_v, P_o):
    # X: [b, n, d]；M: [b, m, d]；mask: [b, h, n, m]；P_q: [h, d, k]；P_k: [d, k]；P_v: [d, v]；P_o: [h, d, v]
    Q = tf.einsum("bnd,hdk->bhnk", X, P_q)
    K = tf.einsum("bmd,dk->bmk", M, P_k)        # 没有 h 维
    V = tf.einsum("bmd,dv->bmv", M, P_v)        # 没有 h 维
    logits = tf.einsum("bhnk,bmk->bhnm", Q, K)  # K 被广播给所有头
    weights = tf.softmax(logits + mask)
    O = tf.einsum("bhnm,bmv->bhnv", weights, V)
    Y = tf.einsum("bhnv,hdv->bnd", O, P_o)
    return Y
```

增量解码版本（缓存只有一份 K、V，没有头维度）：

```python
def MultiquerySelfAttentionIncremental(x, prev_K, prev_V, P_q, P_k, P_v, P_o):
    # x: [b, d]；prev_K: [b, m, k]；prev_V: [b, m, v]
    # 返回 y: [b, d]；K: [b, m+1, k]；V: [b, m+1, v]
    q = tf.einsum("bd,hdk->bhk", x, P_q)
    K = tf.concat([prev_K, tf.expand_dims(tf.einsum("bd,dk->bk", x, P_k), axis=1)], axis=1)
    V = tf.concat([prev_V, tf.expand_dims(tf.einsum("bd,dv->bv", x, P_v), axis=1)], axis=1)
    logits = tf.einsum("bhk,bmk->bhm", q, K)
    weights = tf.softmax(logits)
    o = tf.einsum("bhm,bmv->bhv", weights, V)
    y = tf.einsum("bhv,hdv->bd", o, P_o)
    return y, K, V
```

（更正：论文这段伪代码同样把新 key、新 value 的输入写成了未定义的 `M`（应为 `x`），把输出投影的输入写成了 `O`（应为 `o`）；`tf.expand_dims(..., axis=2)` 也应为 `axis=1`，因为 `prev_K` 的形状是 `[b, m, k]`，新增的位置在第 1 维。另外原文批量版函数的参数说明里 `P_v` 的形状少了左方括号。）

### 3.2 性能分析（原文 3.1 节）

条件与 2.3.1 节相同。在 $n$ 次调用中：

- 算术运算总量仍是 $\Theta(bnd^2)$，**没有变化**；
- 内存访问总量是 $\Theta(bnd+bn^2k+nd^2)$：第一项来自 $x,q,o,y$，第二项来自 $K$ 和 $V$，第三项来自 $P_q,P_k,P_v,P_o$；
- 两者之比为

$$
\Theta\!\left(\frac1d+\frac{n}{dh}+\frac1b\right).
$$

与多头增量解码的 $\Theta(\tfrac nd+\tfrac1b)$ 相比，$\tfrac nd$ 这一项被降低了 $h$ 倍。理论上，当 batch $b$ 足够大时，增量生成的性能应当显著改善。

**换成缓存大小来看**（笔者）：每个位置、每一层需要缓存的 K、V 元素数，在多头里是 $h\cdot k+h\cdot v=2d$（取 $k=v=d/h$），在多查询里是 $k+v=2d/h$，正好少 $h$ 倍。按论文翻译实验的设置（$d_{\text{model}}=1024$，$h=8$，$k=v=128$），每个位置每层的缓存是 2048 个数对 256 个数。同时 MQA 没有减少 query 头的数量，所以注意力的算术运算量不变；收益只在“读缓存”这一部分。

## 四、实验

### 4.1 实验设置

**机器翻译**（沿用 Vaswani 等的设置）：WMT 2014 英德翻译。基线是 6 层的 encoder-decoder Transformer：$d_{\text{model}}=1024$，$d_{ff}=4096$，$h=8$，$d_k=d_v=128$，可学习位置嵌入，词嵌入与输出层权重共享；基线和所有变体都是 **211M 参数**；训练 100,000 步（约 20 个 epoch）；每个训练 batch 有 128 个样本，每个样本是 256 个 token 的输入序列加 256 个 token 的目标序列（把多个训练句子拼接到这个长度）；在 32 核的 TPUv3 集群上训练，每个模型约 2 小时；实现来自 tensor2tensor 与 mesh-tensorflow。具体配置（学习率、dropout、label smoothing 等）原文写的是“[to be added before publication]”，没有给出。

**多查询模型**：把模型中**所有**注意力层换成多查询注意力，包括 encoder 的自注意力、decoder 的自注意力和 encoder-decoder 注意力三类；为使总参数量与基线相同，把前馈层的隐层从 4096 加宽到 5440。

**局部注意力对照**（local）：为证明局部注意力与多查询注意力正交，另训练了基线与多查询模型的 local 版本，其中只有 decoder 的自注意力层限制在“当前位置和前 31 个位置”内，其他注意力层不限制。

**更简单的缩小 K、V 的办法**：减少头数 $h$，和/或减小 key、value 的维度 $k,v$；也训练了几个这样的模型，同样加宽前馈层使总参数相同（$d_{ff}=6784$）。

**语言模型**：同样的一组实验在 “transformer-decoder” 语言模型和 Billion-Word 语言建模基准（Chelba 等 2013）上进行。基线：6 层，$d_{\text{model}}=1024$，$d_{ff}=8192$，$h=8$，$d_k=d_v=128$；基线和所有变体都是 192M 参数；训练 136K 步（10 个 epoch），batch 为 64K 个 token；32 核 TPUv3 上每个模型约 3 小时。

**参数量核对**（笔者计算，论文未给）：多头注意力层有四个投影，参数量为 $4hdk$。变成 MQA 后 $P_k,P_v$ 各少 $(h-1)dk$，每层少 $2(h-1)dk=2\times7\times1024\times128=1{,}835{,}008$。翻译模型有 $6+6+6=18$ 个注意力层（encoder 自注意力、decoder 自注意力、encoder-decoder 注意力各 6 个），共少 $33{,}030{,}144$；前馈层从 4096 加宽到 5440，12 个前馈层各多 $2\times1024\times1344=2{,}752{,}512$，合计 $33{,}030{,}144$，正好抵消。语言模型同理（6 个注意力层少 $11{,}010{,}048$；6 个前馈层从 8192 加宽到 9088 正好多 $11{,}010{,}048$）。减少头数的几种对照模型中 $h\cdot k=128$ 都不变，因此 K、V 的缓存大小与 MQA 一样，每个位置每层 256 个数，且 $d_{ff}=6784$（翻译）、9984（语言模型）也正好补回参数。所以表 1、表 3 的对照是“相同参数量、相同 K/V 缓存大小”下的比较。

**读法**：

- 基线多头与多查询的差距很小：开发集 ln(PPL) 为 1.424 对 1.439（笔者换算成困惑度约相差 1.5%），开发集 BLEU 为 26.7 对 26.5。论文的结论是：多查询模型比基线略差，但比任何减少 $h$、$d_k$、$d_v$ 的方案都接近得多（后者 ln(PPL) 在 1.480 到 1.518 之间，BLEU 为 25.8 到 26.2）。

|---|---:|---:|---:|---:|
| multi-head | 8 | 128 | 8192 | **29.9** |
| multi-query | 8 | 128 | 9088 | 30.2 |
| multi-head | 1 | 128 | 9984 | 31.2 |
| multi-head | 2 | 64 | 9984 | 31.1 |
| multi-head | 4 | 32 | 9984 | 31.0 |
| multi-head | 8 | 16 | 9984 | 30.9 |

（原文表 3，第 8 页。）读法：多查询（30.2）比基线（29.9）略差，但明显好于所有减小 $h$ 或 $d_k$ 的对照（30.9 到 31.2）。与翻译一致：在相同的 K/V 缓存大小下，“保留多个 query 头、共享 K/V”比“缩小头数或维度”损失更小。

### 4.3 速度

速度在一块 TPUv2（8 个核）上测量。

- **训练**：一个训练步包含 32,768 个输入 token 和 32,768 个目标 token，基线用 433 ms，多查询模型用 425 ms；除以 32,768 得每个（输入加目标）token 13.2 微秒（笔者核算：$433/32768\approx13.2$，$425/32768\approx13.0$）；
- **推理**：对 1024 条序列（每个核 128 条）做增量贪心解码，源序列 128 个 token，目标序列 128 个 token（注：由于系统要求形状固定，decoder 自注意力用了 padding 加 mask，记忆张量被 padding 到最大长度 128，local 版本为窗口大小 32，所以每一步解码耗时相同；如果改成逐步增长的张量，可以节省序列开头附近的时间）。基线的 encoder 部分用 222 ms，decoder 每个增量步 47 ms，除以相应的 token 数得到摊销耗时：encoder 每词 1.7 微秒，decoder 每词 46 微秒。多查询模型的 encoder 为 195 ms，decoder 每步 3.9 ms，对应每词 1.5 微秒和 3.8 微秒。

WMT14 英德翻译的摊销训练与推理成本（序列长度 128，单位：TPUv2 微秒 / 每个输出 token；“enc. + dec.”是 encoder 与 decoder 两部分之和；粗体为原文标出的最优值）：

| 注意力类型 | 训练 | 推理（enc. + dec.） | Beam-4 搜索（enc. + dec.） |
|---|---:|---|---|
| multi-head | 13.2 | 1.7 + 46 | 2.0 + 203 |
| multi-query | **13.0** | 1.5 + 3.8 | 1.6 + 32 |
| multi-head local | 13.2 | 1.7 + 23 | 1.9 + 47 |
| multi-query local | **13.0** | **1.5 + 3.3** | **1.6 + 16** |

（原文表 2，第 8 页。）

**读法**：

- **decoder 增量解码的变化最大**：多查询把每词 decoder 耗时从 46 降到 3.8 微秒（约 12 倍）；beam-4 搜索从 203 降到 32（约 6.3 倍）。这一加速（12 倍）超过了头数 $h=8$，论文没有解释；理论分析只说访存项 $\tfrac nd$ 降低了 $h$ 倍，实测还受 padding、实现与硬件的影响（笔者推测，论文未给出分析）。
- **训练和 encoder 几乎不变**：训练 13.2 对 13.0 微秒，encoder 1.7 对 1.5 微秒。这符合理论——并行处理时 K/V 的读取本来就不是瓶颈（算术强度已经够高）。
- **与局部注意力叠加**：local 版本把基线 decoder 从 46 降到 23，多查询 local 是 3.3，是表中最快的组合，与“局部注意力和多查询正交”的说法一致；即使窗口缩到 32，多头版（23）仍比多查询版（3.3）慢约 7 倍。
- 本表是一块 TPUv2、batch 1024、长度 128 下的结果。

## 五、局限与证据边界

- **质量有代价**：多查询模型在两类任务上都比基线略差（ln(PPL) 高 0.015，语言模型困惑度高 0.3），论文用“轻微”描述，但没有给出多次运行的方差，也没有 BLEU 的置信区间；
- **规模很小**：211M（翻译）与 192M（语言模型）参数，6 层，训练 2 到 3 小时；没有检验更大模型或更长序列；
- **只在 TPU 上测速**：论文的速度来自 TPUv2，且用了固定形状加 padding 的实现，不能直接外推到 GPU 上的实现；
- **只测了一组长度与 batch**：摊销耗时只在源、目标各 128 个 token、batch 为 1024 条序列这一个点上测量，没有给出随序列长度或 batch 变化的曲线；
- **对照模型的选择**：“减小 $h$ 或 $d_k,d_v$”的几个对照都是为了让 K/V 缓存与 MQA 同样大（$h\cdot k=128$），但它们同时也缩小了 query 和输出投影；论文没有测试“保持 query 头数不变、只把 K/V 头数减为 2 或 4”这类中间方案——后来的分组查询注意力正是这个方向（见下一节）；
- **超参数缺失**：学习率、dropout、label smoothing 等配置没有给出，难以严格复现；
- **笔误**：除前文提到的代码和 $bhmk=bn^2$ 外，表 2 的标题写 “sequence length 128”，但训练行对应的 batch 里序列是 256 个 token，两者的序列长度并不相同。

## 六、复现检查清单

- K、V 的投影是**一个独立的、可学习的投影** $P_k\in\mathbb{R}^{d\times k}$、$P_v\in\mathbb{R}^{d\times v}$，不是把多头的 K、V 平均得到；
- 所有头的 query 投影 $P_q$ 与输出投影 $P_o$ 保持 $h$ 份；
- 与基线比较时保持**总参数量相同**（论文通过加宽前馈层做到），否则质量比较不公平；
- 报告速度时分开 encoder / decoder（或 prefill / decode）、单步解码与 beam search、batch 与序列长度，并说明是否对缓存做 padding；
- 实现上避免把共享的 K、V 在内存里物理复制成 $h$ 份（`einsum` 里让 K、V 缺少 `h` 维并广播），否则带宽收益会被抵消；
- 注意缓存的形状：MHA 是 `[b, h, m, k]`，MQA 是 `[b, m, k]`，增量解码时拼接的维度不同。

## 七、与相关论文的关系

- [GQA（分组查询注意力）](../grouped_query_attention/论文中文解读.md)：在 MHA（$h$ 组 K/V）与 MQA（1 组 K/V）之间取折中，用 $g$ 组 K/V，质量更接近 MHA、速度接近 MQA；
- [FlashAttention](../flash_attention/论文中文解读.md)：优化的是 attention 中间量 $N\times N$ 矩阵的 HBM 读写；MQA 优化的是 K/V 缓存的读取量，两者针对不同的访存瓶颈；
- [DeepSeek-V2](../deepseek_v2/论文中文解读.md)：进一步用低秩潜在向量压缩 K/V 缓存（MLA）；
- [Bahdanau 注意力](../bahdanau_attention/论文中文解读.md)与 [Transformer](../transformer/论文中文解读.md)：本文第二节回顾的注意力与多头注意力的来源。
