# 论文概要：《DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model》

## 一、基本信息

- 作者：DeepSeek-AI
- 公开时间：2024-05，arXiv:2405.04434
- 规模：236B 总参数，21B 每 token 激活，128K context
- 核心贡献：Multi-head Latent Attention（MLA）+ DeepSeekMoE
- 本地材料：[论文 PDF](paper.pdf) · [提取文本](paper.txt) · [中文精读](论文中文解读.md)

## 二、一句话结论

DeepSeek-V2 把“模型容量”和“推理成本”分别从两个方向拆开：DeepSeekMoE 降低每 token 激活 FFN 计算，MLA 用低秩 latent 压缩需要缓存的 key/value；论文报告相对 DeepSeek 67B 将 KV cache 降低 93.3%、最大生成吞吐提升 5.76×，但这些收益依赖专门实现，不能只由公式自动获得。

## 三、MLA 的关键

- 对 key/value 做联合低秩压缩，每 token 主要缓存 latent vector。
- query 也可低秩投影，减少 activation memory。
- 将承载 RoPE 的维度与内容 key 分离，避免旋转位置编码破坏低秩吸收。
- 推理时把部分 projection 吸收到后续矩阵，避免还原完整 K/V cache。

## 四、MoE 的关键

- 采用细粒度 routed experts 与 shared experts。
- 增加 device-limited routing，限制一个 token 跨越的设备数，以约束通信。
- 用 expert/ device balance loss 与 token dropping 管理负载。

## 五、局限

- KV cache 字节下降不等于 latency 同比例下降；decode 还受权重读取、projection、kernel shape 和 batch 影响。
- 端到端吞吐对推理引擎实现敏感，普通 Transformers 路径无法自动兑现论文数字。
- 多项 benchmark 使用生成式/模型裁判，存在提示与 judge 偏差。
- 论文主要比较当时模型快照，今天更重要的是 MLA/MoE 结构本身。
