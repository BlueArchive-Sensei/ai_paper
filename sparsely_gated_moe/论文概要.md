# Sparsely-Gated MoE 论文概要

## 基本信息

- 题目：*Outrageously Large Neural Networks: The Sparsely-Gated Mixture-of-Experts Layer*
- 作者：Noam Shazeer 等
- 会议：ICLR 2017
- 原文：https://arxiv.org/abs/1701.06538
- 主题：条件计算、稀疏路由、专家并行、负载均衡

## 一句话结论

论文把一个可训练的 noisy top-$k$ router 插入普通网络，使每个样本只激活少量 FFN experts，从而让参数容量增长几个数量级而单样本计算近似不随专家总数增长；真正困难的是让稀疏路由在分布式硬件上保持大 batch 和负载均衡。

## 核心方法

$$
y=\sum_{i=1}^{n}G_i(x)E_i(x),
$$

其中只有 top-$k$ 个 $G_i(x)$ 非零。router logits 加输入相关噪声后取 top-$k$ 再 softmax，噪声既支持探索，也使 expected load 可微。

系统层面采用 data parallel 与 expert/model parallel 组合：各设备的 token 通过 all-to-all 汇总到拥有对应 expert 的设备，从而缓解“专家越多、每个 expert batch 越小”的问题。

训练加入：

- importance loss：均衡 gate probability 总量；
- load loss：均衡预计送达各 expert 的样本数。

## 主要结果

- 在近似相同的每 token 计算下，4→4096 experts 的语言模型 test perplexity 降低约 24%。
- 训练了数十亿到约 1370 亿参数的稀疏模型，论文强调相对既有系统超过 1000× 的容量提升，而非每个 token 执行全部参数。
- 在十亿词语言模型、机器翻译和多语言翻译上展示容量扩展与 expert specialization。

## 局限

- 架构基于 LSTM 时代，训练硬件和网络拓扑与现代 Transformer MoE 不同。
- top-$k$ 路由、all-to-all 和负载损失引入额外超参数与系统复杂度。
- “参数多但 FLOPs 不同比增长”不代表显存、通信或训练成本不增长。
- expert specialization 的例子是观察性证据，不等于可解释或稳定分工。

## 阅读价值

这是现代稀疏 MoE 的基础论文。后来的 Switch Transformer 简化 top-$k$ 和负载损失，MegaBlocks 则直接解决这里暴露的动态、负载不均 expert batch 如何映射到 GPU kernel。
