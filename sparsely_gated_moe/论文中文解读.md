## 1. 条件计算的核心承诺

Dense 网络每个输入都经过同一批参数。MoE 试图解耦两个量：

- capacity：模型可存储的参数/模式数量；
- computation：单个 token 实际执行的 FLOPs。

若有 $n$ 个 experts，但每个 token 只选 $k \ll n$ 个，那么总参数可随 $n$ 增长，而 token 计算主要随 $k$ 增长。

这不是“免费扩展”。未激活的参数仍需存储和更新；路由会产生通信、负载不均和小 GEMM。

## 2. MoE 层

$$
y=\sum_{i=1}^{n}G_i(x)E_i(x).
$$

$E_i$ 通常是同形状的 FFN，$G(x)$ 是 sparse gate。只有 $G_i(x)>0$ 的 expert 才执行。

普通 softmax 是 dense 的。论文定义 noisy top-$k$：

$$
H_i(x)=(xW_g)_i+
\mathcal{N}(0,1)\cdot \operatorname{Softplus}((xW_{\mathrm{noise}})_i),
$$

$$
G(x)=\operatorname{Softmax}(\operatorname{KeepTopK}(H(x),k)).
$$

KeepTopK 将非 top-$k$ 项设为 $-\infty$。噪声提供路由探索，并使“进入 top-$k$ 的概率”可估计，从而训练 load loss。

## 3. 为什么 GPU 上最难的不是公式

### 3.1 Shrinking batch

一个 batch 有 $b$ 个 token、$n$ 个 experts、每 token 选 $k$ 个时，平均每 expert 只收到约 $bk/n$ 个 token。$n$ 越大，expert GEMM 越小，GPU 利用率越差。

论文把 experts 分片到多个设备，并在设备间汇集 token，使每个 expert 看到来自所有 data-parallel shards 的联合 batch。代价是 all-to-all 通信。

### 3.2 计算/通信比

token hidden state 必须被发送到对应 expert，再把输出送回。要让通信值得，expert FFN 需足够大，使计算字节比高于设备的 compute/network 比。

### 3.3 路由塌缩

少量 experts 一旦先被选中，就获得更多训练、变得更强、继而更常被选中，形成正反馈；其余 experts 饿死。

## 4. 两个负载均衡损失

对 batch $X$，expert importance 是 gate mass：

$$
Importance_i(X)=\sum_{x\in X}G_i(x).
$$

论文用变异系数平方：

$$
L_{importance}=w_{importance}\,CV(Importance(X))^2.
$$

但 importance 均衡不代表 token 数均衡：一个 expert 可能收到少量高权重 token，另一个收到大量低权重 token。因此还有基于 noisy top-$k$ 进入概率的 expected load loss $L_{\mathrm{load}}$。

二者目的不同：

- importance 控制输出权重总量；
- load 控制实际 expert batch 和设备资源。

## 5. 固定计算、增加容量的实验

在 One Billion Word Benchmark 上，模型约保持 8M ops/timestep，experts 从 4 增加到 4096，最大的模型 test perplexity 相对 4-expert 版本降低约 24%。这支持“容量本身在大数据下有价值”，但只在论文的 LSTM/数据/训练预算下成立。

## 6. 专家是否真的“专业化”

论文列出某些 experts 常接收的上下文，能观察到语法/语义模式。但这只是路由样本的质性分析：

- expert 身份可在随机种子间置换；
- specialization 未必稳定；
- 某个 expert 的高频模式不代表它只负责该模式；
- 负载均衡损失会主动限制自然分工。

所以 MoE 的主要论据是质量/算力扩展，不是解释性。

## 7. 大参数数字怎样读

附录中的最大模型达到约 1370 亿参数，但每 token 只激活一小部分。应分开报告：

- total parameters；
- active parameters/FLOPs per token；
- expert storage per device；
- all-to-all bytes；
- tokens/expert；
- training hardware 与 wall-clock。

只说“137B 模型”会掩盖稀疏执行语义。

## 8. 常见误读

### “MoE 让计算成本不变”

只是在理想 FLOP 模型中近似不随总 expert 数增长。router、permutation、all-to-all、padding、小 GEMM 和 optimizer state 都会增长。

### “Noisy top-k 只是加随机探索”

它还让 expert 被选中的概率可用于 expected-load 估计，是 load loss 的技术基础。

### “负载均衡越强越好”

过强会压过主任务目标，阻止有用 specialization。它是质量与系统效率的权衡。

## 9. 复现检查点

- 同时画 token count、gate mass 和 expert utilization 分布。
- 报告 all-to-all 时间与 expert GEMM 时间。
- 区分总参数和 active parameters。
- 检查不同随机种子的 expert collapse。
- 记录 $k$、expert 数、noise、两个 auxiliary loss 系数。
- 测试 batch/sequence/world-size 改变后的 tokens per expert。

## 11. 最终判断

这篇论文奠定了现代稀疏 MoE 的算法—系统共同设计：稀疏 gate 只是起点，能否形成足够大的 expert batch、控制 all-to-all、避免路由塌缩，才决定“巨量参数、近似固定 token FLOPs”能否成为真实加速。
