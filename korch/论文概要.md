# Korch 论文概要

## 基本信息

- 题目：*Optimal Kernel Orchestration for Tensor Programs with Korch*
- 作者：Muyan Hu 等
- 版本：arXiv:2406.09465，2024
- 原文：https://arxiv.org/abs/2406.09465
- 主题：operator fission、primitive graph、kernel orchestration、整数规划

## 一句话结论

Korch 认为“先按完整 operator 做 fusion”粒度仍太粗：应先把 Softmax、Normalization 等算子裂解成细粒度 tensor primitives，再枚举候选 kernels，用二元线性规划全局选择覆盖整个图的最低延迟方案。

## 核心方法

1. 把 ONNX operator 通过规则 fission 成 primitive graph。
2. 在 primitive graph 上做代数变换，例如把 reduction 与相邻 MatMul 重组。
3. DFS 枚举合法 primitive 子图及输入输出，生成候选 kernel。
4. 用 TVM/Ansor 或 cuDNN/cuBLAS/TensorRT 生成并 profile 候选。
5. 将每个 candidate 的覆盖关系和实测 latency 写成 binary linear program，求全局 orchestration。

## 为什么重要

Softmax 内部的 exp、reduce、broadcast 并行度不同。把 Softmax 当原子，要么整颗融合、要么不融合；fission 后，不同部分可分别与前后算子融合，甚至一个逻辑 operator 的计算可分散到多个 kernels。

## 主要结果

- 5 个视觉模型、batch 1：V100 最高 1.7×、平均 1.39×；A100 最高 1.6×、平均 1.30×。
- 仅把 fission 后的 primitive graph 交给 TensorRT，在 SegFormer/V100 上也有 1.24×。
- EfficientViT attention 案例用 7 个 kernel 替代 TensorRT 的 12 个，子图加速 3.29×。
- 一个 SegFormer 子图中，“全部融合”为 batch 16 的次优方案，拆成多个 kernel 反而快 2.24×。

## 局限

- 候选 profiling 与 ILP 求解昂贵；最大案例含 3,078 个候选，求解可接近 1,000 秒。
- 只建模顺序 kernel 执行，未纳入 multi-stream/跨 kernel overlap。
- operator-fission rules 仍需要人工定义和保证数值语义。
- 实验仅 5 个视觉模型，动态 shape、训练和大语言模型未覆盖。

## 阅读价值

Korch 给出一个反直觉但关键的结论：最优 orchestration 可能既不是“每 operator 一个 kernel”，也不是“尽可能全融合”，而是先打破 operator 边界，再让代价模型决定哪些 primitive 重组、复制或分开执行。
