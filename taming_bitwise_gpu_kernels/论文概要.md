# 论文概要：《Taming Bitwise Behavior in GPU Kernels with Tensor Core》

## 基本信息

- 时间：2026
- 作者：Ziteng Yang、Nicholas J. Riasanovsky、Warren Deng、Vivek Sarkar
- 原文：[arXiv:2609.11356](https://arxiv.org/abs/2609.11356)
- 本地：[PDF](paper.pdf) · [可检索文本](paper.txt) · [中文精读](论文中文解读.md)

## 一句话结论

论文把 GPU kernel 的逐位行为建模为浮点归约依赖树，并给出一条完整工程路线：黑盒重建 cuBLAS 的归约纪律、在 Triton 编译器中强制固定顺序、再从 PTX/AMD GCN 静态验证两个已编译 kernel 是否逐位等价。

## 问题定义

数学上相同、各自运行也确定的两个 GPU kernel，仍可能因 tile、线程布局、split-K 或 Tensor Core 累加方式不同而产生不同结果。根因是浮点加法可交换但不可结合；调优配置一旦改变归约树，就可能改变最终比特。训练复现、batch-invariant serving 和强化学习中 rollout/训练引擎的 log-prob 对齐都会受到影响。

## 核心方法

1. **依赖树与 GEMMDesc**：把每个输出的浮点加法顺序表示为依赖树；用 instruction_k、split-K 位置、累加精度等真正影响比特的字段描述 GEMM，而不记录纯性能旋钮。
2. **cuBLAS 黑盒重建**：结合 profiling 与特制数值探针，从闭源库反推出“硬件/shape → 归约描述符”，再用 Triton 生成与对应 cuBLAS 路径逐位一致的 kernel。
3. **编译器强制**：为 Triton 后端加入平衡树归约模式和布局优化，使不同高性能配置仍遵守指定的归约顺序。
4. **静态等价检查**：从 PTX 或 AMD GCN 汇编恢复浮点依赖签名；检查器判定等价时保证 sound，并可作为 Triton autotuner 的 pruning predicate，只搜索同一逐位等价类。

## 主要证据

- 在 GB300、GB200、H100 上，对由 cuBLAS 自身完成全部求和且未触发已识别库缺陷的测试 shape，重建 kernel 报告 100% 逐位匹配。
- 编译器强制顺序的 27 个 kernel 中，19 个进入自由顺序实现性能的 10% 以内；部分 H100 kernel 还超过自由顺序基线。
- 静态检查器能在 GEMM 与 Inductor 融合 kernel 上恢复精确等价类；对 reduction/normalization 的划分可能比真实划分粗 1.0–2.5 倍。
- 黑盒探测还发现 cuBLAS split-K 尾部处理的逻辑错误，说明逐位分析也可成为库测试工具。

## 历史位置

这项工作把“确定性”从运行时开关推进为可描述、可编译、可静态验证的算术契约，也把 autotuning 的目标从单纯最快扩展为“在指定逐位等价类内最快”。它连接了可复现机器学习、Tensor Core kernel、编译器 lowering 与二进制级验证。

## 局限与版本提示

- 当前材料对应 arXiv v1（2026-09-10）；公开 LaTeX 仍含未完成的 TODO/附录，不能按成熟 artifact evaluation 解读全部推广性主张。
