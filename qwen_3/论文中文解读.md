>
> **本文的读法**：图为从原文 PDF 中按图裁出的原图；表为逐格核对后的中文转录（模型名、基准名、数字保持原样，表头与行名译成中文），个别很大的表只摘关键行并附原表截图。表中粗体是本文按“该行最高分”标出的，与原文用粗体标最高分、下划线标次高分的做法一致，本文不再标下划线。图中读出的数字都标了“约”，原文正文给出的数字优先。凡是“本文核算”“背景说明”的内容，是笔者由原文数字算出或补充的，不是原文的话。

## 一、一句话结论

Qwen3 是一个开放权重的大模型系列：6 个 dense 模型（0.6B、1.7B、4B、8B、14B、32B）和 2 个 MoE 模型（30B-A3B、235B-A22B），预训练语料约 36T token、覆盖 119 种语言和方言。它的核心做法有三点：（1）把**思考模式**（thinking，先写很长的推理再回答）和**非思考模式**（non-thinking，直接回答）融合进同一个模型，用 `/think`、`/no_think` 标记切换，并提供**思考预算**（thinking budget）让用户按延迟与难度分配推理 token；（2）旗舰模型走“长思维链冷启动 → 推理强化学习 → 思考模式融合 → 通用强化学习”四阶段后训练；（3）小模型不再各走一遍四阶段，而是用**强到弱蒸馏**（先 off-policy 再 on-policy 的 logits 蒸馏）从旗舰模型获得能力，论文报告它比直接做强化学习的效果更好，GPU 小时只有约 1/10。结果上，旗舰 Qwen3-235B-A22B（总参数 235B、激活 22B）在报告的 23 项后训练基准里，思考模式有 17 项超过 DeepSeek-R1（671B 总参数、37B 激活），非思考模式有 18 项超过 GPT-4o-2024-11-20；AIME'24 85.7、AIME'25 81.5、LiveCodeBench v5 70.7、CodeForces 评级 2056、BFCL v3 70.8。

## 二、背景与动机

### 2.1 要解决的问题

引言交代的背景是：GPT-4o、Claude 3.7、Gemini 2.5、DeepSeek-V3、Llama-4、Qwen2.5 等大模型在万亿 token 级数据上训练；o3、DeepSeek-R1 等推理模型又说明，用强化学习优化的模型可以通过**推理时扩展**（inference-time scaling，推理时多花 token 思考）提高水平。开放权重模型与闭源模型的差距在迅速缩小。

在 Qwen3 之前，Qwen 的产品是分开的：面向对话的 Qwen2.5 和专门做推理的 QwQ。用户要在“快而浅”和“慢而深”之间选，就得换模型。Qwen3 想解决的是：

1. **一个模型两种工作方式**：同一个权重既能快速回答，也能做复杂的多步推理，用聊天模板里的标记切换；
2. **让用户控制推理量**：用思考预算在延迟和效果之间连续取舍；
3. **小模型的构建成本**：不对每个小模型重复整套后训练，而是借助旗舰模型；
4. **多语言**：支持的语言从 Qwen2.5 的 29 种扩到 119 种语言和方言（本文核算：约 4.1 倍）。

### 2.2 报告的要点速览

|---|---:|---|---|---:|

读法：

- 命名规则：`235B-A22B` 表示总参数 235B、每个 token 激活 22B；`30B-A3B` 表示总参数 30B、激活 3B。激活参数约占总参数的 9%–10%（本文核算：22/235 ≈ 9.4%，3/30 = 10%）。
- 表里只给了层数、头数、专家数和上下文长度。**隐藏维度、专家中间维度等没有在报告里给出**，所以无法像对 PaLM 那样由表自行核算总参数与激活参数；本文不引用报告之外的配置数字。
- Q 头与 KV 头之比就是 GQA 对 KV cache 的压缩倍数（本文核算）：32B 是 64/8 = 8 倍，14B 是 40/8 = 5 倍，4B、8B 是 32/8 = 4 倍，0.6B、1.7B 是 16/8 = 2 倍；MoE 的 30B-A3B 是 32/4 = 8 倍，235B-A22B 是 64/4 = 16 倍。
- 128K 上下文并非从头训练出来的：预训练的长上下文阶段只到 32,768，推理时靠 YARN 与 DCA 外推 4 倍（见 4.2）；0.6B、1.7B 只标 32K。

### 3.2 dense 模型的结构（原文第 2 节）

Qwen3 dense 模型的结构与 Qwen2.5 相近，使用：

- **GQA**（Grouped Query Attention，Ainslie et al., 2023）：多个 Q 头共享一组 K/V 头，减小推理时的 KV cache，见 [GQA 笔记](../grouped_query_attention/论文中文解读.md)；
- **SwiGLU** 激活的前馈层（Dauphin et al., 2017），见 [PaLM 笔记](../palm/论文中文解读.md) 中对 SwiGLU 的说明；
- **RoPE** 旋转位置编码（Su et al., 2024），见 [RoPE 笔记](../rope/论文中文解读.md)；
- **RMSNorm** 且为预归一化（pre-normalization，归一化放在子层之前）。

相对 Qwen2.5 的两处改动：

1. **去掉 QKV 偏置**：Qwen2 里 Q、K、V 的线性投影带偏置，Qwen3 去掉了；
2. **加入 QK-Norm**（Dehghani et al., 2023）：在注意力里对 query 和 key 做归一化，论文给出的理由是“保证训练稳定”。（背景说明：QK-Norm 是在计算注意力打分前对每个头的 query、key 向量各做一次归一化，防止注意力 logits 随训练变得过大；报告没有展开实现细节。）

### 3.3 MoE 模型的结构

Qwen3 的 MoE 模型与 dense 模型的基本结构相同，把前馈层换成专家层。报告给出的选择：

- **128 个专家，每个 token 激活 8 个**；
- 沿用 Qwen2.5-MoE 的**细粒度专家切分**（fine-grained expert segmentation，Dai et al., 2024，即 DeepSeekMoE 的思路，见 [DeepSeekMoE 笔记](../deepseek_moe/论文中文解读.md)）：专家切得小、数量多，每次激活的数量也多，使组合更灵活；
- **不使用共享专家**（shared experts）：与 Qwen2.5-MoE 不同，Qwen3-MoE 的设计里去掉了共享专家；
- 采用**全局 batch 负载均衡损失**（global-batch load balancing loss，Qiu et al., 2025），论文的说法是“鼓励专家专业化”。

背景说明（报告没有展开）：MoE 用路由器对每个 token 给所有专家打分，选 top-$k$ 个专家，把它们的输出加权求和：

$$
y=\sum_{i\in\operatorname{TopK}(g(x),\,8)} w_i(x)\,E_i(x),
$$

其中 $g(x)$ 是对 128 个专家的路由打分，$E_i$ 是第 $i$ 个专家，$w_i(x)$ 是路由权重（权重怎样归一化，报告没有写）。常见的负载均衡损失形如 $N\sum_{i=1}^{N} f_i\,p_i$，$f_i$ 是被分给专家 $i$ 的 token 比例，$p_i$ 是路由器分给专家 $i$ 的平均概率，用来防止少数专家被挤爆。所引文献 Qiu et al. (2025) 的要点是：如果在每个 micro-batch 内部单独算这个损失，会强迫“每个小批内部”都均匀使用专家，抑制专家按领域分化；改成在整个全局 batch 上统计，就允许不同 micro-batch 偏向不同专家，利于专家专业化。以上是对所引文献的概述，不是本报告自己的推导。

### 3.4 分词器

使用 Qwen 的分词器（Bai et al., 2023）：字节级 BPE（byte-level byte-pair encoding），词表大小 151,669。字节级 BPE 能把任何 Unicode 文本拆成字节而不会出现未登录字符，对 119 种语言的覆盖有利。

### 3.5 总参数与激活参数怎么读

MoE 的收益体现在“总容量大、每 token 计算少”。报告用这样几组数字说明（本文已逐项核对）：

- 235B-A22B 的总参数约为 DeepSeek-V3/R1（671B）的 35%（235/671），激活参数约为其 60%（22/37 ≈ 59.5%）；
- 235B-A22B 的激活参数不到 Qwen2.5-72B（dense）的 1/3（22/72 ≈ 30.6%）；
- 30B-A3B 的激活参数约为 Qwen3-14B 的 1/5（3/14 ≈ 21%），约为 Qwen2.5-32B 的 1/10（3/32 ≈ 9.4%）。

注意这是**每 token 计算量**的度量；MoE 的权重要全部放进内存（总参数 235B），专家之间的路由与通信也有开销，所以“激活参数少”并不等于“部署成本等比例降低”。

## 四、预训练

### 4.1 预训练数据（原文 3.1 节）

和 Qwen2.5 相比，Qwen3 的数据在规模和多样性上都大幅扩展：所有 Qwen3 模型都在由 119 种语言和方言组成、共 **36 万亿 token** 的数据上训练（原文写作 twice as many tokens、three times more languages；语言从 29 种增加到 119 种，本文核算约 4.1 倍）。数据包含代码、STEM（科学、技术、工程、数学）、推理类任务、书籍、多语言文本和合成数据等高质量内容。

为了进一步扩充语料，报告用了三类办法：

1. **从 PDF 类文档里提取文本**：先用 Qwen2.5-VL 对大量 PDF 类文档做文字识别，再用 Qwen2.5 对识别出的文本做精修以提高质量，这两步合起来得到了数万亿 token 的额外高质量文本；
2. **用领域模型合成数据**：用 Qwen2.5、Qwen2.5-Math、Qwen2.5-Coder 合成数万亿 token，格式包括教科书、问答、指令和代码片段，覆盖几十个领域；
3. **增加多语言数据和新语言**：这也是支持语言从 29 种扩到 119 种的来源。

**数据标注与混合**：团队开发了一套多语言数据标注系统，用于提高训练数据的质量与多样性，已对超过 30T token 的预训练数据按多个维度做了标注，如**教育价值、领域、主题、安全性**。这些标注让数据过滤与组合更有效。与此前在**数据来源或领域**层面优化混合比例的工作（Xie et al. 2023 的 DoReMi、Fan et al. 2023 的 DoGE、Liu et al. 2024b 的 RegMix）不同，Qwen3 借助细粒度标签，在小型代理模型上做大量消融实验，在**单个样本（instance）级别**优化数据混合。报告没有给出具体的混合比例和消融结果。

### 4.2 三阶段预训练（原文 3.2 节）

| 阶段 | 数据与目标 | token 规模 | 序列长度 | 其他设置 |
|---|---|---|---:|---|
| S1 通用阶段（General） | 打好语言能力和通用世界知识的基础，覆盖 119 种语言和方言 | 超过 30T | 4,096 | – |
| S2 推理阶段（Reasoning） | 提高 STEM、代码、推理和合成数据的占比，使用更高质量的数据 | 约 5T | 4,096 | 加快学习率衰减 |
| S3 长上下文阶段（Long Context） | 高质量长上下文语料：75% 的文本长度在 16,384 到 32,768 之间，25% 在 4,096 到 16,384 之间 | 数千亿（hundreds of billions） | 32,768 | RoPE 基频从 10,000 提到 1,000,000（ABF）；引入 YARN 与 Dual Chunk Attention（DCA）使推理时序列长度容量提高 4 倍 |

（原文第 3.2 节；本文整理成表。本文核对：S1 的“超过 30T”加 S2 的约 5T 再加 S3 的数千亿，与总量约 36T 一致。）

三个阶段里“长上下文”是怎么做的，值得多说一点（背景说明，报告没有展开技术细节）：

- **ABF**（adjusted base frequency，Xiong et al. 2023）：RoPE 的旋转角度由一个“基频” $b$ 决定，$\theta_i=b^{-2i/d}$。把 $b$ 从 10,000 提高到 1,000,000，低频维度转得更慢，使较长位置之间的相对角度仍可区分，是扩展上下文窗口的常见做法；Qwen2.5 已经这样做；
- **YARN**（Peng et al. 2023）与 **DCA**（An et al. 2024）：两者都是在**推理时**使用的长度外推技术，把序列长度能力再放大 4 倍：训练最长 32,768，推理可到 128K（表 1）。附录的 RULER 评测里写明 YARN 的缩放因子为 4（见 6.6）。

**超参数的缩放律**：与 Qwen2.5 类似，报告基于上面三个阶段建立了“最优超参数缩放律”，来预测学习率调度和 batch size 等；做了大量实验系统研究模型结构、训练数据、训练阶段与最优超参数之间的关系，最终为每个 dense 或 MoE 模型设定预测出的最优学习率与 batch size 策略。报告没有给出具体的学习率、batch size 数值；它也没有描述训练基础设施（硬件规模、并行方式、算力利用率）、优化器和训练时长，所以无法像 [PaLM](../palm/论文中文解读.md) 那样讨论 MFU 与系统效率。

### 4.3 基础模型评测（原文 3.3 节）

**评测设置**：基础模型评测聚焦通用知识、推理、数学、科学知识、代码和多语言能力，共 15 个基准：

| 类别 | 基准（设置） |
|---|---|
| 通用任务 | MMLU（5-shot）、MMLU-Pro（5-shot，CoT）、MMLU-redux（5-shot）、BBH（3-shot，CoT）、SuperGPQA（5-shot，CoT） |
| 数学与 STEM | GPQA（5-shot，CoT）、GSM8K（4-shot，CoT）、MATH（4-shot，CoT） |
| 代码 | EvalPlus（0-shot；HumanEval、MBPP、HumanEval+、MBPP+ 的平均）、MultiPL-E（0-shot；Python、C++、Java、PHP、TypeScript、C#、Bash、JavaScript）、MBPP（3-shot）、CRUXEval 的 CRUX-O（1-shot） |
| 多语言 | MGSM（8-shot，CoT）、MMMLU（5-shot）、INCLUDE（5-shot） |

基线包括 Qwen2.5 基础模型和其他领先的开源基础模型：DeepSeek-V3 Base、Gemma-3、Llama-3、Llama-4 系列，**按参数规模**对应比较，并且“所有模型使用同一套评测流程和常用评测设置”。

**报告总结的三条结论**：

1. Qwen3-235B-A22B-Base 在大多数任务上超过此前开源的 SOTA dense 与 MoE 基础模型（DeepSeek-V3 Base、Llama-4-Maverick Base、Qwen2.5-72B-Base），而总参数或激活参数明显更少；
2. 对 Qwen3 的 MoE 基础模型：（a）在相同预训练数据上，MoE 基础模型只用 1/5 的激活参数就能达到与 Qwen3 dense 基础模型相近的性能；（b）由于 MoE 结构改进、训练 token 增加和更先进的训练策略，Qwen3 MoE 基础模型能以不到一半的激活参数和更少的总参数超过 Qwen2.5 MoE 基础模型；（c）仅用 Qwen2.5 dense 基础模型 1/10 的激活参数，Qwen3 MoE 基础模型就能取得相当的性能，在推理和训练成本上优势显著；
3. Qwen3 dense 基础模型的整体表现与参数量更大的 Qwen2.5 基础模型相当，例如 Qwen3-1.7B/4B/8B/14B/32B-Base 分别与 Qwen2.5-3B/7B/14B/32B/72B-Base 相当；在 STEM、代码和推理基准上甚至超过更大规模的 Qwen2.5 基础模型。

## 五、后训练（原文第 4 节）

### 5.1 总览与流水线（图 1）

后训练流水线围绕两个目标设计：

1. **思考控制**（Thinking Control）：把“非思考”和“思考”两种模式整合进一个模型，让用户选择模型是否要推理，并且可以用 token 预算控制思考的深度；
2. **强到弱蒸馏**（Strong-to-Weak Distillation）：简化并优化轻量模型的后训练，借助大模型的知识大幅降低小模型的计算成本和开发工作量。

先说这张图要说明什么：旗舰模型和轻量模型走的是两条不同的路，而且轻量模型的“教师”就是旗舰模型。

![图 1：Qwen3 系列模型的后训练流程](rendered_figures/fig1-post-training-pipeline.png)

*图 1（原文 Figure 1，第 9 页）：Qwen3 系列模型的后训练流水线。*

**图中文字翻译与读法**：

- **上半，Flagship Models（旗舰模型，橙色区）**：Base Models（基础模型）→ Stage 1 Long-CoT Cold Start（长思维链冷启动）→ Stage 2 Reasoning RL（推理强化学习）→（折回左侧）Stage 3 Thinking Mode Fusion（思考模式融合）→ Stage 4 General RL（通用强化学习）→ 红框输出：Qwen3-235B-A22B、Qwen3-32B；
- **下半，Lightweight Models（轻量模型，蓝色区）**：Base Models → Strong-to-Weak Distillation（强到弱蒸馏）→ 红框输出：Qwen3-30B-A3B 与 14B/8B/4B/1.7B/0.6B。从旗舰模型红框到蒸馏框有一条向下的箭头，表示旗舰模型充当教师；
- **读图结论**：旗舰（235B-A22B、32B）经历完整的四阶段，前两个阶段（冷启动、推理 RL）培养“思考”能力，后两个阶段（思考模式融合、通用 RL）把强大的“非思考”功能整合进来；其余 6 个轻量模型（含 MoE 的 30B-A3B）**不再各自跑四阶段**，而是通过蒸馏获得能力。

报告的初步实验结论是：直接把教师模型的输出 logits 蒸馏给轻量学生模型，可以有效提升性能，同时保持对其推理过程的细粒度控制；这样不必对每个小模型都跑一遍完整的四阶段训练。它的收益体现在：当下的表现更好（更高的 Pass@1），探索能力也更强（更高的 Pass@64），而且训练效率高得多，只需四阶段方法约 **1/10 的 GPU 小时**。具体证据见 7.2 节的表 21。

### 5.2 第 1 阶段：长思维链冷启动（Long-CoT Cold Start）

**数据**：先精心整理一个覆盖面广的数据集，类别包括数学、代码、逻辑推理和一般 STEM 问题；每个问题都配有经过验证的参考答案或基于代码的测试用例。这个数据集是长思维链训练“冷启动”阶段的基础。

数据构建分两步严格过滤：

1. **查询过滤（query filtering）**：用 Qwen2.5-72B-Instruct 识别并去掉不易验证的查询，包括含多个子问题的查询、要求做一般文本生成的查询；还要排除“Qwen2.5-72B-Instruct 不用 CoT 就能答对”的查询，避免模型靠表层猜测，确保留下的是确实需要更深推理的难题；另外用 Qwen2.5-72B-Instruct 标注每个查询的领域，以保持数据集的领域均衡；
2. **回答过滤（response filtering）**：留出一部分验证用查询后，用 **QwQ-32B** 为每个剩余查询生成 $N$ 个候选回答。如果 QwQ-32B 一直答不对，就由人工标注者评估回答的准确性。对 Pass@$N$ 为正（即 $N$ 个里至少有一个对）的查询，再用更严格的标准去掉这样的回答：（1）最终答案错误；（2）有大量重复；（3）明显是猜的、没有足够推理；（4）思考内容与总结内容不一致；（5）不恰当的语言混用或风格突变；（6）与潜在的验证集样本过于相似。

之后，从精炼后的数据里**精心挑出一个子集**用于推理模式的初始冷启动训练。这一阶段的目标是**给模型植入基础的推理模式，而不过分强调当下的推理成绩**，从而不限制模型的潜力，给后续强化学习阶段留出灵活提升的空间。要做到这一点，最好把这个准备阶段的训练样本数和训练步数都压到尽量少。

### 5.3 第 2 阶段：推理强化学习（Reasoning RL）

用于这个阶段的“查询—验证器”对（query-verifier pairs）必须满足四条：（1）冷启动阶段没用过；（2）对冷启动后的模型是“可学习的”；（3）尽可能有挑战；（4）覆盖广泛的子领域。最终共收集了 **3,995 对**，用 **GRPO**（Shao et al., 2024）更新模型参数。

训练中的经验：

- 用**大 batch size** 和**每个查询较多的 rollout 数**，再配合 off-policy 训练来提高样本效率，对训练有益；
- 通过控制模型的**熵**，使其稳步上升或保持稳定，来平衡探索与利用，这对维持训练稳定很关键；
- 因而在**单次 RL 运行**中，训练奖励和验证表现都持续提升，不需要对超参数做任何人工干预。例如 Qwen3-235B-A22B 的 AIME'24 分数在共 170 个 RL 训练步中从 70.1 升到 85.1。

背景说明（报告没有给出公式）：GRPO 的要点是不训练价值网络，而是对同一个问题采样一组输出，用组内奖励的相对高低作为优势，$A_i=\dfrac{r_i-\mathrm{mean}(\{r_j\}_{j=1}^{G})}{\mathrm{std}(\{r_j\}_{j=1}^{G})}$；完整目标函数见 [DeepSeek-R1 笔记](../deepseek_r1/论文中文解读.md)。这里的“验证器”就是规则判断（数学答案对不对、代码能不能通过测试），奖励因此可靠、不易被钻空子。

### 5.4 第 3 阶段：思考模式融合（Thinking Mode Fusion）

目标是把“非思考”能力整合进已经具备“思考”能力的模型：对推理 RL 之后的模型做**持续的监督微调（SFT）**，并设计聊天模板来融合两种模式。这样开发者可以管理和控制推理行为，也省去分别部署思考模型和非思考模型的成本与复杂度。作者还发现，能熟练处理两种模式的模型，在不同的思考预算下表现一致地好。

**SFT 数据的构成**：由“思考”数据和“非思考”数据混合而成。

- 为保证第 2 阶段模型的性能不被额外的 SFT 损伤，“思考”数据是用**第 2 阶段模型自己**对第 1 阶段的查询做拒绝采样（rejection sampling）生成的；
- “非思考”数据则精心整理，覆盖多样的任务：代码、数学、指令遵循、多语言任务、创意写作、问答和角色扮演；并用自动生成的**检查清单**（checklists）评估非思考数据的回答质量；
- 为提升低资源语言任务的表现，特意增加了翻译类任务的比例。

**聊天模板设计**：为了融合两种模式并允许用户动态切换，设计了如下模板（原文表 9）：

```text
思考模式：
<|im_start|>user
{query} /think<|im_end|>
<|im_start|>assistant
<think>
{thinking_content}
</think>

{response}<|im_end|>

非思考模式：
<|im_start|>user
{query} /no_think<|im_end|>
<|im_start|>assistant
<think>

</think>

{response}<|im_end|>
```

（原文表 9，第 11 页：“SFT 数据中思考与非思考模式的示例”。表注：思考模式下 `/think` 标记可以省略，因为那是默认行为；这一特性已经实现在 Hugging Face tokenizer 支持的聊天模板里，用额外参数 `enable_thinking=False` 就能关闭思考模式。）

设计要点：

- 样本里用 `/think` 和 `/no_think` 标记（放在用户查询或系统消息里）标明要不要思考，让模型按用户输入选择模式；
- **非思考样本保留一个空的思考块**（`<think>` 与 `</think>` 之间为空）。这使模型内部格式保持一致，并允许开发者在聊天模板里拼接一个空思考块来**阻止模型思考**；
- **默认是思考模式**，所以也加入了一些用户查询里**不带** `/think` 标记的思考样本；
- 对复杂的多轮对话，在用户的各轮查询里**随机插入多个** `/think` 和 `/no_think` 标记，模型的回答遵循**最后出现的那个标记**。

### 5.5 思考预算（Thinking Budget）

思考模式融合还有一个额外好处：模型一旦学会了非思考与思考两种模式，就自然获得了处理“中间情形”的能力——基于**不完整的思考**生成回答。这为实现思考过程的预算控制打下了基础。具体做法：

```text
当模型的思考长度达到用户设定的阈值时：
  1. 人工中止思考过程；
  2. 插入停止思考的指令：
     "Considering the limited time by the user, I have to give the solution based on the thinking directly now.\n</think>.\n\n"
  3. 之后模型基于到目前为止累积的推理继续生成最终回答。
```

原文特别强调：**这项能力不是显式训练出来的，而是应用思考模式融合后自然涌现的**。也就是说，训练数据里并没有“思考到一半被截断再作答”的样本（报告没有提到这类样本），预算控制是推理时的外部干预加上模型对不完整思考的泛化。预算的效果见 7.1 节的图 2。

### 5.6 第 4 阶段：通用强化学习（General RL）

目标是在各种场景下全面提升模型的能力和稳定性。为此建立了一套覆盖 **20 多个不同任务**的奖励系统，每个任务有定制的评分标准，针对下面这些核心能力：

| 能力 | 含义 |
|---|---|
| 指令遵循（Instruction Following） | 准确理解并遵循用户指令，包括内容、格式、长度、结构化输出等要求 |
| 格式遵循（Format Following） | 除显式指令外，遵守特定的格式约定：例如对 `/think`、`/no_think` 标记做出正确的模式切换，并始终用指定的符号（如 `<think>` 与 `</think>`）分隔思考和回答 |
| 偏好对齐（Preference Alignment） | 对开放式问题，改善有用性、参与度和风格，使体验更自然、更满意 |
| 智能体能力（Agent Ability） | 训练模型通过指定接口正确调用工具；在 RL rollout 中允许模型与**真实环境的执行反馈**进行完整的多轮交互，提升长程决策任务中的表现和稳定性 |
| 特殊场景能力 | 为特定场景设计专门任务；例如检索增强生成（RAG）任务里引入奖励信号，引导模型给出准确且符合上下文的回答，减少幻觉 |

为这些任务提供反馈用了三类奖励：

1. **基于规则的奖励（rule-based reward）**：在推理 RL 阶段已被广泛使用，对指令遵循、格式遵守等通用任务也有用；设计良好的规则奖励可以高精度地评估输出正确性，防止奖励投机（reward hacking）；
2. **有参考答案的基于模型的奖励**：给每个查询提供参考答案，让 Qwen2.5-72B-Instruct 对照参考答案给模型回答打分；比纯规则奖励更灵活，不要求严格格式，避免纯规则奖励的误判（false negative）；
3. **无参考答案的基于模型的奖励**：利用人类偏好数据训练一个奖励模型，给模型回答打标量分数；不依赖参考答案，能处理更广泛的查询，并有效提升模型的参与度和有用性。

### 5.7 强到弱蒸馏（Strong-to-Weak Distillation）

这条流水线专为优化轻量模型设计，涵盖 5 个 dense 模型（Qwen3-0.6B、1.7B、4B、8B、14B）和 1 个 MoE 模型（Qwen3-30B-A3B）。它在提升性能的同时，把稳健的模式切换能力也传给了这些小模型。分两个阶段：

1. **Off-policy 蒸馏**：把教师模型在 `/think` 与 `/no_think` 两种模式下生成的输出结合起来，做回答蒸馏（对教师输出做监督学习）。这帮助轻量学生模型建立基本的推理能力和在不同思考模式间切换的能力，为下一阶段打下基础；
2. **On-policy 蒸馏**：让**学生模型自己生成**序列（on-policy）来微调。具体地：采样提示词，学生模型在 `/think` 或 `/no_think` 模式下生成回答；然后让学生的 logits 与教师模型（Qwen3-32B 或 Qwen3-235B-A22B）的 logits 对齐，最小化 **KL 散度**。

背景说明（报告没有给出公式）：on-policy 蒸馏的损失大致是在学生自己采样的序列上，逐位置让学生的下一 token 分布逼近教师的：

$$
\mathcal{L}=\mathbb{E}_{x\sim\mathcal{D},\ y\sim\pi_{S}(\cdot\mid x)}\ \sum_{t}\mathrm{KL}\big(\pi_{T}(\cdot\mid x,y_{<t})\ \big\Vert\ \pi_{S}(\cdot\mid x,y_{<t})\big),
$$

其中 $\pi_S$ 是学生、$\pi_T$ 是教师。KL 的方向和是否逐位置计算，原文只说“对齐 logits、最小化 KL 散度”，没有写明；上式只是一种常见写法。与 off-policy 蒸馏的区别是：序列由**学生**采样而不是教师，所以学生训练时看到的前缀分布，与它推理时自己生成的前缀分布一致，避免了“训练时只见过教师的前缀、推理时却要接着自己的前缀”的分布偏移。教师信号是整个 token 分布，而不是一个采样出的答案；论文把“蒸馏能提升 pass@64、而 RL 不能”归因于借助教师 logits 扩大了学生的探索空间（见 7.2）。相关概念见 [知识蒸馏笔记](../knowledge_distillation/论文中文解读.md)。

## 七、讨论与消融（原文 4.7 节）

### 7.3 思考模式融合与通用 RL 的效果（表 22）

为评估后训练里**思考模式融合**（第 3 阶段）和**通用强化学习**（第 4 阶段）的作用，作者在 Qwen3-32B 的各个阶段做了评测。除了前面提到的基准，还引入了几个内部基准来监控其他能力：

- **CounterFactQA**（内部）：含反事实问题，模型需要识别出问题不符合事实，并避免生成幻觉式的回答；
- **LengthCtrl**（内部）：带长度要求的创意写作任务，最终得分取决于生成内容长度与目标长度的差距；
- **ThinkFollow**（内部）：多轮对话中随机插入 `/think` 和 `/no_think` 标记，测试模型能否按用户的要求正确切换思考模式；
- **ToolUse**（内部）：评估模型在单轮、多轮、多步工具调用过程中的稳定性，得分包含工具调用中意图识别的准确率、格式准确率和参数准确率。

读法（原文三条结论）：

1. 第 3 阶段把非思考模式整合进已有思考能力的模型。ThinkFollow 得分 88.7，说明模型已初步具备在两种模式间切换的能力，但仍偶尔出错。第 3 阶段还增强了思考模式下的通用与指令遵循能力：CounterFactQA +10.9，LengthCtrl +8.0；
2. 第 4 阶段进一步强化了两种模式下的通用、指令遵循和智能体能力；ThinkFollow 提高到 98.9，保证了准确的模式切换；
3. 对知识、STEM、数学和代码任务，思考模式融合和通用 RL **没有带来显著提升**；相反，对 AIME'24 和 LiveCodeBench 这类有挑战的任务，经过这两个阶段后**思考模式的成绩反而下降**（AIME'24 从阶段 2 的 83.8 降到阶段 4 的 81.4，LiveCodeBench v5 从 68.4 降到 65.7；本文核算分别为 -2.4、-2.7）。作者推测，这是因为模型在更广泛的通用任务上训练，可能损害了它处理复杂问题的专项能力；**在 Qwen3 的开发中，他们选择接受这个性能权衡，以换取模型整体的通用性**。

补充观察（本文）：阶段 4 的 Qwen3-32B 数字（思考 AIME'24 81.4、LiveBench 74.9、Arena-Hard 93.8；非思考 AIME'24 31.0）与表 13、表 14 中 Qwen3-32B 的成绩一致，说明这就是最终发布的模型。

## 八、局限、证据边界与常见误读

**报告自己写明的局限与计划**（第 5 节结论）：继续用质量更高、内容更多样的数据扩大预训练；改进模型结构和训练方法，以实现有效压缩、扩展到极长上下文等；增加强化学习的计算投入，尤其是从环境反馈中学习的**智能体 RL 系统**，以构建能处理需要推理时扩展的复杂任务的智能体。第 7.3 节还承认了专项能力的下降，附录 A.1.1 承认了思考模式下长上下文检索的下降。

**证据边界**（本文的归纳）：

- **消融很少**：报告没有给出预训练数据配方（各来源的比例、实例级混合优化的消融）、架构选择（QK-Norm、去掉共享专家、全局 batch 负载均衡损失）、三阶段预训练各自贡献的消融；基础模型表只是“成品对成品”。表 21、22 是仅有的后训练消融；
- **对基线的评测来源混杂**：基础模型表称同一流程评测，但后训练表里部分基线来自榜单（如 BFCL 取 FC 与 Prompt 中较高者）、部分自测，闭源模型的版本、提示和采样设置不能完全统一；
- **分数依赖评测预算**：思考模式的成绩依赖最大输出长度（32,768，AIME 为 38,912）、采样次数（AIME 每题 64 次平均，GPQA-Diamond 每题 10 次）和采样参数；跨论文比较前要对齐这些；
- **内部基准不可复核**：CounterFactQA、LengthCtrl、ThinkFollow、ToolUse 是内部数据集，表 22 中这些行无法由外部复现；
- **没有污染分析**：本文检索全文，没有看到对评测基准的数据污染分析（只在引用 LiveBench、LiveCodeBench 的标题里出现“contamination-free”）；预训练数据和比例也未公开；
- **多语言平均不可横比**：见 6.5，各语言纳入的基准不同，MT-AIME 每语言仅 30 题；
- **开放权重不等于可复现**：权重以 Apache 2.0 开放，但预训练数据、混合比例、学习率与 batch 等关键超参、训练基础设施与优化器、后训练数据、奖励模型都没有公开。

**常见误读**：

- **“思考预算是单独训练出来的控制能力”**：不是。报告明确说这项能力“不是显式训练的，而是思考模式融合后自然涌现的”；预算执行靠推理时强行截断思考并追加固定语句，模型对“不完整的思考”泛化出可用的回答；
- **“MoE 的激活参数就是部署成本”**：激活参数决定每 token 的计算量，但全部 235B 权重都要驻留内存，路由与专家间通信也有开销；
- **“思考模式总是更好”**：思考模式在推理类基准上大幅领先（AIME'24 85.7 对 40.1），但延迟和 token 消耗更高；RULER 这类检索任务上思考模式反而更低；融合与通用 RL 之后，思考模式的 AIME 与 LiveCodeBench 成绩还略有下降；
- **“Qwen3-235B-A22B 全面超过闭源模型”**：思考模式下，23 项里 Gemini2.5-Pro 最高的有 13 项、Qwen3 只有 7 项（6.2 节）；报告的说法是“很有竞争力、缩小了差距”；
- **“Qwen3-32B 超过 o3-mini”**：16/23 更好，但在 GPQA-Diamond、AIME'25、LiveCodeBench v5、CodeForces 等推理基准上 o3-mini 仍领先；
- **“蒸馏取代了强化学习”**：不是。教师（Qwen3-32B、Qwen3-235B-A22B）本身要靠完整的四阶段（含 RL）训练出来，蒸馏是把它的能力转给小模型，所以收益依赖旗舰模型；
- **“thinking token 是忠实的内部推理”**：报告没有检验思考内容是否忠实反映模型内部计算；它只展示了增加思考预算能提高成绩。

## 九、复现检查清单

- **模板与模式**：固定聊天模板与模式开关（`/think`、`/no_think`、`enable_thinking`）；非思考模式要保留空的思考块；多轮对话遵循最后一个标记；
- **思考预算**：说明预算计的是思考部分还是总输出；到阈值时追加的固定语句要原样复现；
- **采样与长度**：思考模式 temperature 0.6、top-p 0.95、top-k 20；非思考模式 temperature 0.7、top-p 0.8、top-k 20、presence penalty 1.5（Creative Writing v3、WritingBench 在思考模式也用 1.5）；最大输出 32,768（AIME 为 38,912）；AIME 每题 64 次采样平均、GPQA-Diamond 每题 10 次；
- **基准细节**：BFCL 的 FC 与 Prompt 格式、64k YARN 部署；LiveCodeBench 思考模式的 prompt 模板；CodeForces 每题 8 次独立尝试；INCLUDE 与 MMMLU 的 10% 抽样、MMMLU 排除约鲁巴语；
- **MoE**：128 个专家、每 token 激活 8 个、无共享专家、全局 batch 负载均衡损失；
- **训练数据与阶段**：推理 RL 的 3,995 个查询—验证器对必须满足四条标准；冷启动样本数与训练步数要尽量少；
- **蒸馏对照**：对比 RL 与 on-policy 蒸馏时，要从同一个 off-policy 蒸馏检查点出发，并用同口径的 GPU 小时；
- **长上下文**：YARN 缩放因子 4、思考预算 8192（RULER）；
- **随机性**：思考模式的数学与代码基准方差大，应报告多次采样的平均。

## 十、与相关论文的关系

- [DeepSeek-R1](../deepseek_r1/论文中文解读.md)：推理后训练的参照。R1 以“可验证奖励的纯 RL”为核心，再用约 80 万条数据蒸馏小模型；Qwen3 则是“冷启动 → 推理 RL → 思考模式融合 → 通用 RL”四阶段，并把非思考能力融合进同一个模型；小模型用 off-policy 加 on-policy 的 logits 蒸馏，表 21 说明后者在同一起点上比直接做 RL 更好也更省；
- [DeepSeek-V3](../deepseek_v3/论文中文解读.md)：Qwen3-235B-A22B 的基础模型与非思考模式的主要对比对象（671B 总参数、37B 激活）；
- [DeepSeekMoE](../deepseek_moe/论文中文解读.md)：Qwen3 的“细粒度专家切分”来自这一思路，不同之处是 Qwen3 去掉共享专家；
- [Kimi K2](../kimi_k2/论文中文解读.md)：另一条开放权重 MoE/agentic 路线；K2 主要以非思考模式评测，强调 agent/tool 使用，Qwen3 则把思考与非思考合在一个模型里；
- [gpt-oss](../openai_gpt_oss/论文中文解读.md)：可调的推理强度（low/medium/high）与 Qwen3 的思考预算都是“让用户控制推理量”的接口，前者是离散档位，后者是 token 级预算，且预算是由推理时截断实现的；
- [GQA](../grouped_query_attention/论文中文解读.md)、[RoPE](../rope/论文中文解读.md)、[PaLM](../palm/论文中文解读.md)：Qwen3 沿用的结构组件（GQA、RoPE、SwiGLU 等）；
- [知识蒸馏](../knowledge_distillation/论文中文解读.md)：强到弱蒸馏的基本概念。
