# 中文精读的制作与检查规范

本目录是给“逐篇核对中文解读、补齐原文图表、修复 GitHub Markdown 渲染问题”准备的工具和规范。

## 目标

每篇论文的 `论文中文解读.md` 必须做到：**只读中文就能学会这篇论文**，不需要再翻英文原文。具体含义：

1. 论文的问题、背景、方法、公式、算法步骤、训练/数据细节、实验设置、主结果、消融、局限，全部有中文讲解，且与原文一致。
2. 凡是对理解方法或结论重要的**图**，放入从原文 PDF 裁下的原图，并配中文图题、图中文字翻译和读图结论。
3. 凡是支撑结论的**表**，逐格转录为 Markdown 表（表头与行名译成中文，专有名词、模型名、数据集名、数字保持原样），并注明原文表号和页码。
4. 数字、公式、结论逐项和 `paper.pdf` / `paper.txt` 对照过；原来中文里的错误要改正。

## 工具

```bash
# 1. 列出 Figure/Table 标题所在页和纵向位置（页面比例 0-1，原点在左上）
python3 tools/fig.py captions <paper>/paper.pdf

# 2. 渲染某页并叠加带刻度的 10% 网格，用 Read 工具看这张 PNG 来定位图的边界
python3 tools/fig.py preview <paper>/paper.pdf <page> $SCRATCH/pN.png

# 3. 按页面比例裁剪（x0 y0 x1 y1），自动去白边、限制体积；.jpg 结尾则输出 JPEG（照片类图）
python3 tools/fig.py crop <paper>/paper.pdf <page> 0.14 0.09 0.87 0.285 <paper>/rendered_figures/fig1-xxx.png 170

# 4. Markdown 检查（GitHub 渲染问题；也检查相对链接、图片路径和 #锚点是否真实存在）
tools/mdlint.py <paper>/

# 5. 全仓库逐篇统计（字符数、图片引用、表格、公式块、格式错误、未引用的图片文件）
tools/audit.py > stats.md
```

`$SCRATCH` 用会话的 scratchpad 目录，预览图不要放进仓库。`mdlint.py` 和 `audit.py` 的 shebang 指向装有 `markdown-it-py`、`mdit-py-plugins` 的 Python 3.12，直接执行即可（用默认 `python3` 会缺模块）。裁完的每一张图都必须再用 Read 工具看一遍，确认：

- 是正确的那一张图，整幅图都在（多子图的所有子图、图例、坐标轴标题都不能被切掉）；
- 没有混入相邻的正文、别的图或原文图题（图题由中文图题代替；子图标号 (a)(b) 可以保留）；
- 清晰可读。字太小就提高 dpi（但单张保持在约 450 KB 以内；照片类用 `.jpg`）。

## 文件与命名

- 图片放在 `<paper>/rendered_figures/`，文件名 `fig<编号>-<英文短词>.png`（或 `.jpg`）。附录图 `figA<编号>-...`；原文没有编号的写成 `figure-<序号>-...`。
- 表格不放截图，转录成 Markdown。只有当表过大（大约超过 20 行或 10 列）无法合理转录时，才裁表的原图（命名 `table<编号>-...png`），同时在正文用 Markdown 小表摘出关键行并给出中文列名翻译。
- 不要整页截图，不要放原文大段文字页。
- 不要修改 `paper.pdf`、`paper.txt`；`论文概要.md` 只在发现事实错误时改，保持结构。

## 中文解读的结构

参照 [flash_attention/论文中文解读.md](../flash_attention/论文中文解读.md)。标题固定为 `# 论文中文解读：《原文标题》`，随后一个 blockquote 写基本信息（作者/机构、年份、arXiv/官方链接）和阅读说明。正文章节按论文内容组织，一般包含：

1. 一句话结论（问题、做法、结论）；
2. 背景与动机（读者需要的前置知识要讲到位）；
3. 方法（每个组件、公式的符号含义、算法逐步解释、架构图）；
4. 训练/数据/实现细节（超参数、数据规模、硬件等，数字要准）；
5. 实验（设置、基线、每张主表和主图；结论要写成“在什么条件下什么结果”）；
6. 消融与分析；
7. 局限、证据边界、常见误读；
8. 复现检查或与相关论文的关系；
9. 末尾 `## 原文证据导航`，链接 `paper.pdf`、`paper.txt`、`论文概要.md`。

篇幅跟随论文：短论文 1–2 万字符，大型技术报告可 3–5 万字符。不凑字数；也不能只写口号式概述。

### 图的写法

```markdown
![图 1：简短中文图题](rendered_figures/fig1-xxx.png)

*图 1（原文 Figure 1，第 2 页）：一句话中文图题。*

**图中文字翻译与读法**：

- **左图 …（英文标题）**：坐标轴、图例、各色线条含义的中文翻译；
- **读图结论**：这张图证明了什么，在什么条件下成立。
```

图中读出的近似数值要写“约”，并说明是从图上读出的；原文正文给出的数字优先用原文数字。

### 表的写法

表前写一行中文表题和设置（数据集、指标含义、越大越好还是越小越好、硬件等），表后写“原文表 N，第 P 页”和读法。数字必须逐格与原文核对（先用 `pdftotext -layout` 或 `paper.txt` 取数，再对照图像确认，不要凭记忆）。原文中的粗体最佳结果可以用 `**…**` 保留（注意下面的 CJK 粗体规则）。

## 逐篇流程

对每一篇论文，按顺序做完再做下一篇：

1. **通读原文**：完整读 `paper.txt`（正文、附录中有重要图表的部分），再读现有的 `论文中文解读.md` 和 `论文概要.md`。公式、表格、图在文本里提取不可靠时，用 `fig.py preview/crop` 生成图像后用 Read 工具看原页。
2. **核对旧稿**：逐条检查旧中文解读里的数字、公式、命名、结论是否与原文一致，列出发现的错误（最终报告里要列出）。旧稿里正确且有价值的内容保留，不要为了重写而丢弃。
3. **选图选表**：列出所有 Figure/Table（`fig.py captions`）。选入：架构/方法图、算法流程图、主要结果图、关键消融图、训练曲线；主结果表、消融表、关键超参数/配置表、数据集构成表。大型技术报告：正文表格为主，附录只取关键项，其余用文字概括；纯展示用的样例图库可以不选，但若是论文的核心证据（例如生成质量对比）要选。常见数量：图 3–12 张，表 3–10 张。
4. **裁图**：按上面的工具裁图并逐张验图。
5. **写稿**：重写 `论文中文解读.md`，图表就近放在讲到它的段落里；先讲清楚为什么要看这张图/表，再放图/表，再给读法与结论。
6. **自检**：`tools/mdlint.py <paper>/` 输出 `0 errors`；所有数字再抽查一遍；图片路径存在。

约束：

- 只改动自己负责的论文目录（`rendered_figures/`、`论文中文解读.md`，发现事实错误时才改 `论文概要.md`）。不要改 `tools/`、根目录文件、其他论文目录；不要执行会改变 git 状态的命令（add/commit/checkout/stash 等）。
- 临时文件放会话的 scratchpad 目录，不进入仓库。
- 不确定的数字不要编造：核对不了就不写，或明确标注“从图上读出的近似值”。
- 论文里若有网页快照（`source.html`、`source/`、`source_readme.md` 等），可以从中取图（复制到 `rendered_figures/`），但仍要核对内容。

## GitHub 渲染规则（`tools/mdlint.py` 会检查）

1. **CJK 粗体**：`**` 的收尾符号紧跟中文字符、且前面是标点时，GitHub 不会解析成粗体（会原样显示星号）。例如 `**注意：**文字` 是错的。正确：`**注意**：文字`（标点放到粗体外），或在 `**` 后加空格，或不用粗体。
2. **行内数学** `$...$`：开头 `$` 后、结尾 `$` 前不能有空格；结尾 `$` 后面不能直接跟数字；金额等普通美元符号写成 `\$`。
3. **表格里的数学**：单元格内不要出现裸 `|`（会切列）。条件概率写 `p(x\mid y)`，范数写 `\lVert x\rVert`，绝对值写 `\lvert x\rvert`。
4. **行块数学** `$$ ... $$`：放在顶层，前后各空一行，`$$` 独占一行；不要放在列表项里（列表里用行内 `$...$`）。
5. **GitHub 的 MathJax 不支持**：`\bm`、`\mathbbm`、`\mathds`、`\argmax`/`\argmin`（写 `\operatorname*{arg\,max}`）、`\newcommand`、`\DeclareMathOperator`、`\textsc`、`\label`/`\eqref`；括号 `{}`、`\left`/`\right`、`\begin`/`\end` 必须配平。
6. **尖括号**：`<think>`、`<X>`、`<s>` 这类写在正文里会被当成 HTML 标签吞掉；必须放进反引号 `` `<think>` `` 或写成 `&lt;think&gt;`。
7. **表格**：表头行前必须有空行；每行单元格数与表头一致；单元格里的竖线写成 `\|`。
8. 标题：全文只有一个 H1；层级不跳级；标题、列表、表格、代码块、图片前后各空一行。
9. 项目符号统一用 `-`；有序列表用 `1.`；代码块必须带语言标识（无语言写 `text`）；文件末尾恰好一个换行，无行尾空格、无 Tab、无连续空行。
10. 图片必须有非空 alt；所有相对链接和图片路径必须存在。
11. 路径和文件名里的中文无需转义；链接到本仓库其他论文用相对路径，例如 `../flash_attention_2/论文中文解读.md`。

交付前运行：

```bash
tools/mdlint.py <paper>/
```

必须输出 `0 errors`。
