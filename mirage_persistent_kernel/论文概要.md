# Mirage Persistent Kernel（MPK）论文概要

## 基本信息

- 题目：*MPK: A Compiler and Runtime for Mega-Kernelizing Tensor Programs*
- 项目名：Mirage Persistent Kernel
- 作者：Xinhao Cheng 等
- 版本：arXiv:2512.22219，2025 预印本
- 原文：https://arxiv.org/abs/2512.22219
- 主题：MegaKernel、persistent kernel、SM-level task graph、LLM inference

## 一句话结论

MPK 把完整 tensor program 降为按 SM 切分的 task graph，并在一个 persistent mega-kernel 内用事件驱动、分散式 scheduler 执行，使跨 operator pipeline、通信重叠和动态请求管理不再受 host kernel 边界限制。

## 核心方法

- tGraph：节点是分配给 SM 的细粒度 tasks，event 表示依赖完成。
- compiler：把 operator 分解为 tasks，正规化/fuse events，并生成 task implementations。
- runtime：少量 SM 运行 scheduler，其余作为 workers。
- hybrid launch：规则任务 AOT 分派，执行时间不稳定的任务 JIT/queue 分派。
- paged shared-memory pool：不同 tasks 复用 SMEM，而不是让整个 mega-kernel 静态占用峰值总和。
- runtime dynamism：设备侧 continuous batching、paged attention、KV metadata 更新。

## 主要结果

- 对 5 个 dense/MoE 模型、A100/H100/B200、batch 1–16，相对 vLLM/SGLang 最佳基线约 1.0×–1.7×。
- Qwen3-8B/A100 的 token latency 从约 14.5 ms 降到 12.5 ms；论文估计权重带宽下界约 10 ms。
- MoE hybrid balancer 相对 SGLang-MoE 在所测 batch 下约 1.07×–1.18×。
- 多 GPU Qwen3-1.7B 相对高优化 serving system 报告 1.1×–1.4×。

## 局限

- 是 2025 预印本，系统与基线快速演进。
- 端到端评测采用 offline batched inference，不等价于有到达过程和 SLO 的在线服务。
- 为 batch powers-of-two 生成多个 tGraphs，动态性仍通过 specialization 管理。
- scheduler 保留部分 SM，收益在大模型/大 batch 时缩小。
- CUDA codegen、设备侧 runtime 和调试复杂度很高。

## 阅读价值

MPK 是理解现代 MegaKernel 的主干论文：MegaKernel 不只是“超大 fusion kernel”，而是把过去由 CPU/runtime 完成的调度、依赖、KV 管理和通信协调部分迁入 persistent kernel。
