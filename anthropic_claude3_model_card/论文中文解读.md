# 中文精读：《The Claude 3 Model Family: Opus, Sonnet, Haiku》

## 一、这份资料能回答什么，不能回答什么

它能回答 Claude 3 的能力范围、训练原则、安全评估和发布决策；不能回答模型有多少层、多少参数、是否 MoE、视觉模块如何连接。Claude 的底层结构仍是闭源 Transformer，外界不应把猜测写成官方架构。

官方模型卡发布于 2024-03，本地 PDF 还包含部分后续 Claude 3.x addenda。材料包括 [PDF](paper.pdf)、[文本](paper.txt) 与 [概要](论文概要.md)。

## 二、一个模型族，而不是单一“Claude 3”

Opus、Sonnet、Haiku 分别面向最高能力、平衡和低延迟。模型族设计让产品在质量、成本和速度间选择，而不是所有请求都调用最大模型。

报告只说使用 Transformer、无监督预训练、RLHF 与 Constitutional AI 等高层技术；没有足够信息复现任一 checkpoint。

## 三、能力表格怎样读

Claude 3 在 MMLU、GPQA、GSM8K、HumanEval、阅读理解等任务上与 GPT-4/Gemini 等比较。表格中的 0-shot、5-shot、CoT、majority vote 设置不同；同一分数不能脱离脚注解释。

HumanEval 仍是单函数生成，不代表 Claude Code 的仓库级工程能力。agent 产品还取决于搜索、编辑、测试、工具权限和上下文压缩。

## 四、多模态、错误拒绝与事实性

视觉评测覆盖图表、文档、视觉问答等。Claude 3 相对前代降低 harmless prompt 的错误拒绝，并在困难事实问题上更多承认不确定性。

“少拒答”本身不是越低越好：有害请求应拒，合法边界请求应回答。模型卡同时测 toxic prompts 的安全拒答和 benign prompts 的 over-refusal，才构成完整 trade-off。

## 五、长上下文：recall 不等于 reasoning

论文测试到很长 context，并用 Needle-in-a-Haystack 和 QuALITY 衡量召回/理解。NIAH 主要问能否在长序列找回一个插入事实；它不测多文档冲突消解、跨数十处证据聚合或长对话状态一致性。

实践中应把长上下文拆成：有效 recall、推理准确率、位置偏差、延迟、TTFT、成本和引用可追溯性，而不是只看“支持多少 token”。

## 六、Responsible Scaling Policy 与发布门槛

Anthropic 对 autonomous replication/adaptation、生物与网络能力做评估，并按 Responsible Scaling Policy 决定 ASL 等级及安全措施。Claude 3 被按 ASL-2 部署。

这类系统卡的价值是把发布决策和风险证据放在一起；局限是许多评测内部、样本有限，模型能力与攻击方法还会快速变化。

## 七、Trust & Safety 与多模态红队

图像可绕过纯文本 classifier，例如把有害指令嵌入图片。模型卡因此做 multimodal policy red teaming，并评估歧视、BBQ bias 与选举相关使用。

安全评测报告通过率不能证明不存在未知 jailbreak；它是已知 threat model 下的覆盖情况。

## 八、Claude 的算法公开主线在哪里

Claude 本身没有完整架构论文。Anthropic 公开得最清楚的是三类方法：

1. [Constitutional AI](../constitutional_ai/论文中文解读.md)：RLAIF 与 constitution；
2. [Scaling Monosemanticity](../anthropic_scaling_monosemanticity/论文中文解读.md)：用 SAE 分解 Claude 3 Sonnet 激活；
3. 系统卡：能力、安全与部署边界。

这些能解释“如何训练行为、如何分析模型、如何发布”，却不能拼出完整 Claude 网络。

## 九、Claude Code 的正确定位

Claude Code 是 coding agent/harness，不是一家独立模型公司，也没有公开一篇描述其完整内部 orchestration 的学术架构论文。评估 Claude Code 应区分：

```text
Claude 基础模型
× system prompt / context management
× repository search / edit / terminal tools
× permissions / sandbox
× token and time budget
× test harness
```

用 Claude 3 model card 的 HumanEval 分数直接推导 Claude Code 工程能力，会把模型层与产品层混在一起。
