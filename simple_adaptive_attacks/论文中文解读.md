# 论文中文解读：《Jailbreaking Leading Safety-Aligned LLMs with Simple Adaptive Attacks》

## 一、核心论点

论文的中心不是“随机字符串很神奇”，而是：**安全评测必须允许攻击者针对目标模型和防御进行适配**。如果只拿固定攻击测试所有系统，很容易把“这项攻击不适合该接口”误判成“模型稳健”。

作者结合模型特定提示模板、对输出首 token 概率的随机搜索、同模型迁移、跨模型迁移和 assistant prefilling，在 50 条 AdvBench 请求上对多款当时模型报告很高、常为 100% 的 GPT-4-judge 攻击成功率。

## 二、第 1—2 节：研究背景

已有攻击包括人工提示、梯度优化后缀、遗传算法和 LLM 辅助搜索。论文认为这些方法经常被当作固定基线，而没有根据目标系统的接口、模板和已知防御做合理适配。

所谓 adaptive attack 与经典对抗鲁棒性中的白盒评估一致：攻击者知道防御思想，并利用可用信息选择最合适的优化目标和输入结构。它不是一定拥有模型权重；API 暴露的 logprobs、可预填 assistant 消息等也构成攻击面。

## 三、第 3 节：方法

### 3.1 评测设置

- 数据：50 条 AdvBench 有害行为请求。
- 成功判据：GPT-4 语义评审给出最高越狱分数。
- 访问级别：开源权重、API logprobs 或仅 token/消息接口。

### 3.2 模板加随机搜索

研究者先人工设计适合目标模型的提示框架，再附加一段可优化 token。随机搜索每次替换部分 token，以“模型更可能从肯定式回答开始”等概率目标作为代理损失。优化目标便宜、无需梯度，且能利用 API 返回的有限 logprobs。

代理目标并不直接衡量有害性，只推动模型进入顺从生成模式；最终仍需语义评审检查是否真正回答原请求。

### 3.3 自迁移、跨模型迁移与预填

- **Self-transfer**：在部分请求上找到的后缀迁移给同一模型的其他请求。
- **Cross-model transfer**：在可取得概率的模型上优化，再转给不开放概率的模型。
- **Prefilling**：接口允许预置 assistant 回答开头时，让模型从顺从上下文继续生成。

这些方法体现“接口就是威胁模型的一部分”。


![Figure 1 原论文第 4 页：主提示模板的完整结构](rendered_figures/page-4-04.jpg)

图中可见模板不是一句“忽略规则”，而是把目标行为、输出起始字符串、若干必须满足的规则以及可搜索 suffix 组合起来。固定框架负责制造“必须完成格式”的竞争目标，可搜索部分再提高肯定式起始 token 的概率；两者共同构成攻击算法。

## 六、逐实验评估

### 开源模型随机搜索

- **优势**：目标概率可精确计算，攻击预算透明。
- **结果**：多种模型达到报告口径下的满成功率。
- **限制**：攻击者访问权重或 logits，比普通聊天用户更强。

### API logprob 攻击

- **优势**：展示少量概率反馈足以支持黑盒优化。
- **限制**：API 字段和限流会变化，结果具有时间敏感性。

### R2D2 防御适配

- **优势**：真正按照防御特点修改攻击，符合鲁棒性评估原则。
- **含义**：对某个算法的对抗训练不等于对攻击目标的稳健。

### Claude 迁移与预填

- **优势**：在无 logprobs 情况下仍能自适应。
- **限制**：prefilling 是特定 API 能力，若产品禁用或加过滤，威胁模型会改变。

### 木马触发器搜索

- **意义**：方法可用于更广泛离散安全测试。
- **限制**：中毒竞赛与自然越狱的生成机制不同，不能直接合并成功率。

## 七、主要局限

1. 50 条请求规模较小，类别覆盖有限。
2. 以 GPT-4 judge 的 10/10 作为成功标准存在明显假阳性。
3. 论文使用的产品版本、系统提示和 API 已可能更新。
4. 报告的是找到攻击后的成功率，未充分表达总查询成本和攻击者前置调试成本。
5. 有害回答是否正确、可执行和增量提升现实能力，未被同等严格衡量。

## 八、防御启示

- 评测必须是防御感知、接口感知的自适应红队。
- 不应把隐藏 logprobs 当作唯一防线；消息预填、模板和工具接口也要纳入边界。
- 对抗训练要覆盖攻击目标和策略族，而非只覆盖某个字符串生成器。
- 自动 judge 必须做人工校准并报告假阳性/假阴性。
- 应同时报告攻击成功率、查询预算、迁移范围和输出实际危害质量。

## 九、与《Jailbroken》的关系

《Jailbroken》提供“竞争目标/泛化不匹配”的概念分类；本文把评测推进到更严格的自适应威胁模型。随机搜索利用模型概率反馈强化竞争目标，prefilling 利用消息结构改变生成起点，而模型特定模板则直接针对安全泛化缺口。

## 十、一句话结论

本文最可靠的结论不是所有当前模型永远可被 100% 越狱，而是：若攻击者能针对具体模型、模板、概率反馈和接口能力调整策略，静态攻击基准会严重高估安全鲁棒性；任何“已防住越狱”的声明都必须经受自适应评估。
## 十一、按统一标准补充：自适应攻击为何改变结论

### 11.1 静态 benchmark 与自适应对手

静态评测固定一批攻击字符串，防御可以针对它们过拟合。本文让攻击者看到目标模型或防御反馈，用模板、随机后缀搜索、跨模型迁移和 assistant prefilling 调整输入。评测对象因此从“能否挡住已知提示”变成“在给定查询预算下能否挡住会学习的对手”。

### 11.2 成功率的组成

攻击成功率同时受任务集合、搜索预算、重启次数、目标模型采样和 judge 影响。最佳一次成功与平均单次成功不是同一指标；API logprob 可见性、prefill 能力也属于攻击权限，必须写入威胁模型。

### 11.3 R2D2 结果说明什么

针对通用攻击训练出的防御在简单适配后仍可被突破，说明“对某攻击族鲁棒”不能外推为“对攻击者鲁棒”。这不是证明所有防御无效，而是要求评测把防御细节暴露给红队，并预留独立调参预算。

### 11.4 Judge 与真实伤害

自动 judge 可能把拒绝前缀后的有害续写判错，也可能把看似服从但内容无效的输出算成功。高风险类别需要人工复核，并区分政策违规、信息正确、可操作性和现实影响。

### 11.5 复现最低信息

固定系统提示、聊天模板、后缀长度、搜索迭代、候选数、迁移源、prefill 文本、温度、重复次数与 judge 版本。没有这些信息，跨论文成功率比较几乎没有意义。

## 十二、按原文逐节补读：算法与威胁模型

### 12.1 第 3.1 节：数据、模型和 judge

主评测用 AdvBench 的 50 条有害行为。攻击成功定义为 GPT-4 semantic judge 给出最高分，不等于人工确认内容正确可执行。模型访问分三类：本地权重可读 logits、API 返回有限 logprobs、仅有消息接口但允许 assistant prefilling。

因此 Table 1 的模型间比较不是统一白盒强度；它比较的是每个接口下作者能构造的最强适配攻击。

### 12.2 第 3.2 节：随机搜索做了什么

作者先写模型特定 prompt，把有害请求放进上下文，再追加固定长度 token suffix。每轮随机替换若干 token，保留能提高目标首 token（通常是 “Sure”）logprob 的候选，并用多次 restart 降低局部搜索风险。

目标 token 概率是便宜代理：它只表示模型进入肯定式续写模式，不保证回答有害、完整或正确。攻击到达阈值后还要用 semantic judge 复核。

### 12.3 Self-transfer 的统计含义

Request-specific search 对少量请求分别优化后，把成功 suffix 迁移到其余 50 条请求。最终 ASR 同时包含“单题优化能力”和“从先导题提取通用 suffix”的收益。报告时必须写清搜索了多少 seed 请求、每个请求预算和 restart 数。

### 12.4 Figure 3：API logprob 本身有噪声

同一 GPT 请求重复调用时，首 token logprob 有分布而非定值。随机搜索观察到的是带噪目标；作者用重复、阈值和迁移应对。API 实现、模型快照和服务器采样变化都会改变复现结果。

## 十三、Table 1–5 与 Figure 1–3 的正确读法

### 13.1 开源模型与 R2D2

Llama-2 Chat 的 plain prompt 为 0%，加入 random search 与 self-transfer 后报告到 100%；Llama-3 8B、Gemma 7B 也达到 GPT-4 judge 下 100%。R2D2 对 plain prompt 约 8%，对 in-context prompt 已达 90%，再加搜索到 100%。

R2D2 专门针对 GCG 训练，因此该结果证明“防住 GCG 分布”不能外推为“防住针对防御重写目标和模板的攻击”。

### 13.2 GPT 系列

GPT-3.5 的人工 prompt 已能达到报告口径下满成功；GPT-4 Turbo 从 prompt 的 28% 经 logprob 搜索与 self-transfer 升到 96%；GPT-4o 需要自定义消息模板，72% 再升至 100%。模型更新和消息层级改变了攻击面。

### 13.3 Claude 系列

Claude 没有目标 logprobs。作者将 GPT-4 上优化的提示迁移，或直接预填 assistant 的顺从开头。Claude 2.1 的 transfer 为 0%，prefilling 的 GPT-4 judge 为 100%，但 rule judge 约 80%，且论文发现明显假阳性。Claude 3 Opus 同样显示 transfer 近零、prefill 高成功，说明两类攻击权限不可互换。

### 13.4 Table 5：木马触发器搜索

SaTML 任务要求恢复中毒模型触发串。作者依据 token 先验限制搜索空间，再用随机搜索优化目标分数，获得竞赛第一。它验证算法可搜索离散触发器，但中毒模型和自然越狱的威胁模型不同。

### 14.3 Table 15：跨模型迁移

GPT-4 上搜索出的提示能迁移到部分 Claude 版本，但对 Claude 2.1、Claude 3 Opus 等可失败。迁移支持模型共享某些肯定式生成特征，却也证明目标模板和安全训练差异重要。

### 14.4 Table 16–17：Prefilling 消融

去除系统提示、改变预填内容、仅保留普通文本提示都会明显改变 ASR。高 Claude 结果依赖 API 允许把 assistant 消息开头作为已发生上下文；产品若禁用该接口，威胁模型随之变化。

其中 **Table 17**把请求结构拆成 `system+user+assistant`、`user+assistant` 等组合，并同时用 GPT-4 judge 与规则 judge 计分；它表明 assistant-prefill 是主要增益来源，系统提示是否保留也会改变结果。两种 judge 的差异再次说明高 ASR 部分来自判定口径，而不是纯粹的模型输出变化。

### 14.5 Figure 5–6 与 Table 18：样例证据

样例检查生成是否真的围绕请求，而不只是出现 “Sure”。作者只展示代表性成功输出，全量可靠性仍由 judge 和人工假阳性检查决定。本文保留原图页，不转录可直接复用的危险提示或操作内容。

### 14.6 Table 19：假阳性不是脚注

Claude 2.1 会输出带步骤框架但把关键内容留成占位符，GPT-4 与规则 judge 仍可能判最高越狱分。约 20% 的该模型结果受到假阳性影响，其他模型通常低于 5%。所以“100% ASR”必须同时注明 judge 校准。

### 14.7 Table 20：四种 judge

在代表模型上，GPT-4 与 Llama-3-70B judge 都给 100%；规则 judge 为 90–98%；Llama Guard 2 为 86–98%。攻击排序总体强，但绝对值变化足以影响“满成功”叙述。多 judge 一致也不能替代对输出正确性与可执行性的人工核验。

### 14.8 Table 21：JailbreakBench 直接对比

## 十五、证据强度、局限与复现

论文最强证据是：攻击只需理解目标模板、接口和防御，即可把多项静态基线下的低成功率提升到很高；R2D2 案例直接证明针对固定攻击训练会产生评测过拟合。

它不证明所有当前模型永久可 100% 越狱，也不测输出的事实正确性、现实可执行性和增量危害。50 条 AdvBench、有限版本 API 与自动 judge 都限制外推。

复现必须记录模型日期、系统/聊天模板、数据集、target token、suffix 长度、替换数、迭代与 restart、seed 请求、self-transfer 规则、API logprob 字段、prefill 权限、采样温度、停止条件、每种 judge 及人工假阳/假阴复核。
