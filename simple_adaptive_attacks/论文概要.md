# 论文概要：《Jailbreaking Leading Safety-Aligned LLMs with Simple Adaptive Attacks》

## 一、核心论点

论文的中心不是“随机字符串很神奇”，而是：**安全评测必须允许攻击者针对目标模型和防御进行适配**。如果只拿固定攻击测试所有系统，很容易把“这项攻击不适合该接口”误判成“模型稳健”。

作者结合模型特定提示模板、对输出首 token 概率的随机搜索、同模型迁移、跨模型迁移和 assistant prefilling，在 50 条 AdvBench 请求上对多款当时模型报告很高、常为 100% 的 GPT-4-judge 攻击成功率。

## 二、第 1—2 节：研究背景

已有攻击包括人工提示、梯度优化后缀、遗传算法和 LLM 辅助搜索。论文认为这些方法经常被当作固定基线，而没有根据目标系统的接口、模板和已知防御做合理适配。

所谓 adaptive attack，沿用经典对抗鲁棒性文献（Tramèr 等，2020）的定义：针对给定防御专门设计的攻击，攻击者利用可用信息选择最合适的优化目标和输入结构。它不是一定拥有模型权重；API 暴露的 logprobs、可预填 assistant 消息等也构成攻击面。

## 三、第 3 节：方法

### 3.1 评测设置

- 数据：50 条 AdvBench 有害行为请求。
- 成功判据：GPT-4 语义评审给出最高越狱分数。
- 访问级别：开源权重、API logprobs 或仅 token/消息接口。

### 3.2 模板加随机搜索

研究者先人工设计适合目标模型的提示框架，再附加一段可优化 token。随机搜索每次替换部分 token，以“模型更可能从肯定式回答开始”等概率目标作为代理损失。优化目标便宜、无需梯度，且能利用 API 返回的有限 logprobs。

代理目标并不直接衡量有害性，只推动模型进入顺从生成模式；最终仍需语义评审检查是否真正回答原请求。

### 3.3 自迁移、跨模型迁移与预填

- **Self-transfer**：把在较简单请求（目标 token 的 logprob 更大）上找到的后缀，作为同一模型上较难请求随机搜索的初始化；每条请求的后缀仍是单独搜索出来的，没有训练请求与测试请求之分。
- **Cross-model transfer**：在可取得概率的模型上优化，再转给不开放概率的模型。
- **Prefilling**：接口允许预置 assistant 回答开头时，让模型从顺从上下文继续生成。

这些方法体现“接口就是威胁模型的一部分”。

## 四、主结果逐项阅读

### 表 1：结果总览

表 1 对 Llama-2/3、Gemma、R2D2、GPT-3.5、GPT-4o 和 Claude 系列列出访问条件、适配攻击和先前/本文成功率。作者在所用数据与 GPT-4 judge 下报告大量 100%。

但表下注明：只有 Claude 2.1 存在约 20% 的评审假阳性，其他模型通常低于 5%。因此“100%”首先是自动评审口径，不是人工确认的 100% 有效危害输出。

### 图 1：主提示模板

图 1 将原始请求嵌入人工构造模板，并保留可搜索后缀。关键是模板对模型家族做了调整；作者拒绝把单一通用字符串当作鲁棒性上限。

### 图 2：搜索收敛曲线

横轴是迭代次数（0 到 10000），左图纵轴是目标 token “Sure” 的平均 logprob，右图纵轴是攻击成功率；对 Llama-3-Instruct-8B、Llama-2-Chat-7B、Gemma-7B 三个模型，比较“提示 + 随机搜索”与再加自迁移两种设置。核心结论是：从自迁移得到的好初始化出发，搜索几乎一开始就接近 100% 成功率，而无自迁移的曲线要慢得多（Llama-2-7B 到 10000 次迭代也只有约 38%）；自迁移是查询效率与高成功率的关键。提高 “Sure” 的概率只是代理目标，最终仍由评审器判定成功。

### R2D2 实验

R2D2 专门对 GCG 类攻击做过对抗训练，固定 GCG 效果下降。作者改用 in-context 模板加随机搜索后重新突破，说明针对单一攻击分布训练可能造成“基准过拟合”，而不是一般鲁棒性。

### GPT 实验

GPT-3.5 的模板本身已很强；GPT-4o 则利用系统提示结构、可得 logprobs 和自迁移。结果强调商业 API 的返回字段会影响可攻击性。

### Claude 实验

Claude 不提供所需 logprobs，作者使用从其他模型迁移的提示或 assistant prefilling。高成功率部分来自接口能力，而不是相同优化算法直接作用于 Claude。

## 五、附录图表精读

### 图 4：后缀长度

在 Gemma-7B 上用 1000 次迭代比较 5、15、25、40、60 个 token 的后缀。目标 logprob 与攻击成功率都随后缀长度呈 U 形，25 个 token 最优（成功率约 62%）。更长后缀的问题有两点：优化变难（平均目标值反而更差），以及很长的后缀（如 60 个 token）会让模型转去回答无关请求，所以 60 个 token 的成功率最低（约 40%），但其平均目标 logprob 并非最低。

### 图 5、图 6：Claude 成功实例

图 5 展示迁移攻击，图 6 展示 prefilling。它们是定性证明，不代表所有输出质量。为避免滥用，本概要不复制完整危险提示或回答。

### 表 5：木马竞赛

作者把同样的受限随机搜索用于寻找中毒模型触发字符串，并在 SaTML 竞赛中取得第一。共同原理是：先利用先验限制 token 集（五个中毒模型由同一基座微调而来，触发 token 的嵌入向量会显著偏离，取各模型两两嵌入距离最大 token 的交集作为候选池），再用奖励模型分数做随机搜索来优化离散触发器；总分 −30.22，优于第 2 名的 −29.21。

## 六、逐实验评估

### 开源模型随机搜索

- **优势**：目标概率可精确计算，攻击预算透明。
- **结果**：多种模型达到报告口径下的满成功率。
- **限制**：攻击者访问权重或 logits，比普通聊天用户更强。

### API logprob 攻击

- **优势**：展示少量概率反馈足以支持黑盒优化。
- **限制**：API 字段和限流会变化，结果具有时间敏感性。

### R2D2 防御适配

- **优势**：真正按照防御特点修改攻击，符合鲁棒性评估原则。
- **含义**：对某个算法的对抗训练不等于对攻击目标的稳健。

### Claude 迁移与预填

- **优势**：在无 logprobs 情况下仍能自适应。
- **限制**：prefilling 是特定 API 能力，若产品禁用或加过滤，威胁模型会改变。

### 木马触发器搜索

- **意义**：方法可用于更广泛离散安全测试。
- **限制**：中毒竞赛与自然越狱的生成机制不同，不能直接合并成功率。

## 七、主要局限

1. 50 条请求规模较小，类别覆盖有限。
2. 以 GPT-4 judge 的 10/10 作为成功标准，在 Claude 2.1 上有约 20% 的假阳性（其他模型作者称低于 5%），且攻击把同一个 GPT-4 judge 作为停止判据，数字偏乐观。
3. 论文使用的产品版本、系统提示和 API 已可能更新。
4. 报告的是找到攻击后的成功率；运行时间在附录 C.2 有说明（Llama-3-8B 上 4000 次迭代约 20.9 分钟），但手工设计与调试模板的人力成本没有量化。
5. 有害回答是否正确、可执行和增量提升现实能力，未被同等严格衡量。

## 八、防御启示

- 评测必须是防御感知、接口感知的自适应红队。
- 不应把隐藏 logprobs 当作唯一防线；消息预填、模板和工具接口也要纳入边界。
- 对抗训练要覆盖攻击目标和策略族，而非只覆盖某个字符串生成器。
- 自动 judge 必须做人工校准并报告假阳性/假阴性。
- 应同时报告攻击成功率、查询预算、迁移范围和输出实际危害质量。

## 九、与《Jailbroken》的关系

《Jailbroken》提供“竞争目标/泛化不匹配”的概念分类；本文把评测推进到更严格的自适应威胁模型。随机搜索利用模型概率反馈强化竞争目标，prefilling 利用消息结构改变生成起点，而模型特定模板则直接针对安全泛化缺口。

## 十、一句话结论

本文最可靠的结论不是所有当前模型永远可被 100% 越狱，而是：若攻击者能针对具体模型、模板、概率反馈和接口能力调整策略，静态攻击基准会严重高估安全鲁棒性；任何“已防住越狱”的声明都必须经受自适应评估。
