## 一、核心观点：长 context 既是输入容量，也是搜索预算

k1.5 把 long CoT 视为在 token 空间执行的搜索：模型可以试错、回退、验证和修改。增加 RL context length，相当于允许更多搜索步。团队报告把 RL 从 32K 扩到 128K 后能力继续提升。

论文首次公开于 2025-01，arXiv:2501.12599。本地保存 [PDF](paper.pdf)、[文本](paper.txt) 和 [概要](论文概要.md)。

## 二、总体方法

k1.5 是多模态模型，同时在文本与视觉问题上做 reasoning RL。核心没有使用 MCTS、独立 value function 或 process reward model，而是依赖最终答案正确性：只要完整轨迹最终恢复到正确答案，途中错误探索也可获得正 reward。

这比逐步标注 reasoning process 便宜，但无法保证写出的 CoT 每一步都真实、必要或忠实。

## 三、online policy mirror descent

第 `i` 轮把当前 policy `π_i` 作为 reference，最大化期望 reward，同时用 KL 限制新 policy 偏离 `π_i`。闭式最优分布与 `π_i exp(r/τ)` 成比例，实际用采样近似 normalization，再拟合 log-ratio。

它与 GRPO 的共同点是同题多样本、用组内 reward baseline、没有 value model；差异在优化推导和 off-policy surrogate。每轮 reference 都更新，因此是在线 mirror descent 序列。

作者认为 value function 的逐步 credit assignment 可能过早惩罚“先走错、后纠正”的路径。这个观点合理，但 outcome reward 也会把偶然猜对与严密推理同奖，需要多样题目和 verifier 控制。

## 四、长度惩罚与采样

长回答提高成功率也会 overthink。k1.5 在同一问题的多个回答内，对正确答案偏好更短轨迹，对错误且更长的轨迹加惩罚，并逐步 warm up length penalty。

curriculum sampling 先给适中难度，避免早期在几乎不可能答对的题上浪费 rollout；prioritized sampling 根据历史成功率聚焦仍可学习的问题。二者都是提高 verifier signal density。

## 五、partial rollout：系统贡献

一条 128K 轨迹会让同步 iteration 被最慢样本拖住。partial rollout 给每次生成固定 token budget：未完成轨迹把前缀存入 replay buffer，下一轮从该状态继续；旧片段不必重新生成，训练 loss 也可只覆盖指定片段。

优点是减少重复计算、缓解 straggler、支持超长输出。代价是前缀来自旧 policy，新尾部来自新 policy，整条轨迹非严格 on-policy；系统还要保存 KV/文本状态、检测重复并处理权重更新。

## 六、long2short：不是所有用户都想看 100K CoT

k1.5 研究 model merging、shortest rejection sampling、DPO 等，把长 CoT 的解题能力迁移到短输出。shortest rejection sampling 从正确候选中偏向短轨迹；DPO 用长/短偏好对优化。

这揭示两个目标：最大正确率和单位 token 效率。reasoning 产品应允许预算控制，而不是固定输出最长思考。

## 七、评测结果与口径

报告给出 AIME 77.5、MATH-500 96.2、Codeforces 94th percentile、MathVista 74.9 等，并与 o1 比较。小数据集、多次采样和 consensus 会显著抬高结果；正确解读必须看 pass@1/cons@k、temperature、max tokens 和图像输入设置。

## 八、与 R1/M1 的区别

- R1：GRPO + cold-start/multi-stage pipeline，开放权重。
- k1.5：mirror descent + partial rollout + multimodal long2short，主要公开报告。
- M1：CISPO + hybrid linear attention，开放权重，强调 1M/80K 效率。

它们共同说明 reasoning scaling 不只看 policy loss，还要看 rollout architecture 与 token budget。

## 九、开放性边界

官方 GitHub 提供报告和图，但没有像 Kimi K2 那样发布完整 base/instruct checkpoints。应写“技术报告公开”，不写“k1.5 权重开源”。
