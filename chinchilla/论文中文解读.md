## 一、一句话结论

作者问的是：给定固定的训练计算预算（FLOPs），模型参数量 $N$ 和训练 token 数 $D$ 应该怎样分配？他们训练了 400 多个、参数从不到 7000 万到 160 多亿的语言模型，用三种不同的拟合方法估计最优分配，结论是**参数量和训练 token 数应当等比例增长**：训练计算每放大 $k$ 倍，$N$ 和 $D$ 各放大约 $\sqrt{k}$ 倍（指数 $a,b$ 都在 0.46 到 0.54 之间），而此前 Kaplan 等（2020）的结论是 0.73 与 0.27。按这一结论，当时的大模型（GPT-3、Gopher、MT-NLG 等）都严重“训练不足”：它们大多只训练了约 3000 亿 token。为了检验，作者用与 Gopher（280B 参数，3000 亿 token）相同的计算预算训练了 70B 参数、1.4T token 的 Chinchilla。它在 MMLU（5-shot 平均 67.6%，比 Gopher 高 7.6 个百分点）、BIG-bench、阅读理解、闭卷问答等绝大多数评测上超过 Gopher，并且因为模型小 4 倍，推理和微调的成本也更低。

## 二、背景与动机

### 2.1 要回答的问题

训练一个大语言模型通常只能做一次，所以在开跑之前，要根据手头的算力预算选好模型大小和训练时长。设预训练损失为 $L(N,D)$，训练计算 $C$ 是 $N$ 与 $D$ 的确定函数 $\mathrm{FLOPs}(N,D)$，则问题就是在计算约束下最小化损失：

$$
N_{opt}(C),\ D_{opt}(C)=\operatorname*{arg\,min}_{N,D\ \text{s.t.}\ \mathrm{FLOPs}(N,D)=C}L(N,D)\tag{1}
$$

函数 $N_{opt}(C)$ 与 $D_{opt}(C)$ 描述计算预算 $C$ 的最优分配。作者用 400 多个模型的损失来经验地估计它们（模型从不到 70M 到 16B 以上参数，训练 5B 到 400B 以上 token；每种配置都训练了若干种不同的训练长度）。为简单起见，分析用的是平滑后的训练损失：因为在“无限数据”区间（训练 token 数少于整个语料的 token 数），它是测试损失的无偏估计。

### 2.2 此前的做法

Kaplan 等（2020，见 [scaling_laws](../scaling_laws/论文中文解读.md)）发现语言模型的损失与参数量呈幂律，于是业界越训越大，期望性能随之提升。Kaplan 等的一个重要结论是：要做到计算最优，大模型不应训练到各自能达到的最低损失。本文**同意这一点**，但估计出大模型应当训练的 token 数比 Kaplan 等推荐的多得多。具体来说，算力增加 10 倍时，Kaplan 等建议模型增大 5.5 倍，训练 token 只增加 1.8 倍；本文发现两者应按相同比例增长。按 Kaplan 等和 GPT-3 的训练设置，近来许多大模型都只训练约 3000 亿 token（表 1）。

**表 1：当前的大语言模型（原文表 1，第 3 页；显示五个最大的稠密 Transformer 模型的规模和训练 token 数，另加 Chinchilla）**

| 模型 | 参数量 | 训练 token 数 |
|---|---:|---:|
| LaMDA（Thoppilan 等，2022） | 137 Billion | 168 Billion |
| GPT-3（Brown 等，2020） | 175 Billion | 300 Billion |
| Jurassic（Lieber 等，2021） | 178 Billion | 300 Billion |
| Gopher（Rae 等，2021） | 280 Billion | 300 Billion |
| MT-NLG 530B（Smith 等，2022） | 530 Billion | 270 Billion |
| Chinchilla | 70 Billion | 1.4 Trillion |

读法：除了 LaMDA，其余大模型的训练 token 数都在 300B 左右（MT-NLG 为 270B），参数却从 175B 一路涨到 530B，这就是“只增大模型、不增加数据”的趋势。Chinchilla 反其道而行：参数只有 Gopher 的 1/4，训练 token 是它的约 4.7 倍（1.4T 对 300B，自行验算）。

### 2.3 本文与 Kaplan 等（2020）的几点不同

原文第 2 节明确列出前两点方法上的差异，它们是两篇论文结论不同的主要候选原因；第 3 点是附录 F 说明的口径（原文没有把它当作分歧来源讨论，对照 Kaplan 等的定义补充于此）：

1. **学习率调度与训练长度**：Kaplan 等对所有模型使用固定的训练 token 数和学习率调度，这使他们无法建模这些超参数对损失的影响。本文发现，把学习率调度的长度设成与训练 token 数大致匹配，无论模型大小，最终损失最好（附录图 A1）。如果用一个固定的、到 130B token 的余弦调度，那么对更少数据 $D'\ll130\mathrm{B}$ 的中间损失就是被高估的（那时学习率还没降下来），这会低估“在更少数据上训练”的效果，最终导致“模型大小应比数据增长得更快”的结论。
2. **模型规模范围**：本文的模型最大到 16B，因为观察到 FLOPs-损失前沿有轻微弯曲（附录 E）；本文分析里大多数模型超过 5 亿参数，而 Kaplan 等的多数运行小得多，许多不到 1 亿参数。
3. **计算与参数的口径**：本文的 FLOPs 包含 embedding 矩阵的贡献，参数量也包含 embedding 参数（附录 F）；Kaplan 等的 $N$ 与 $C$ 都不含 embedding。原文认为对大模型 embedding 的贡献很小。

原文只是陈述这些不同之处；它没有逐项做消融来证明哪一条造成了结论分歧（附录图 A4 只在 $10^{21}$ FLOPs 处做了一次头对头比较）。

## 三、方法：三种估计最优分配的方法

### 3.1 共同设定

三种方法的思路相同：先训练一系列同时改变模型大小和训练 token 数的模型，再用训练曲线拟合经验估计器，并假设计算与最优模型大小、最优 token 数之间是幂律关系 $N_{opt}\propto C^{a}$、$D_{opt}\propto C^{b}$（这一假设沿用 Clark 等 2022 与 Kaplan 等，原文提醒未来工作可以考虑该关系在大模型处的弯曲）。训练 FLOPs 的计算见附录 F；常用的近似是 $C\approx6ND$（前向每参数每 token 2 次乘加，反向约为前向的两倍，与 Kaplan 等相同）。

### 3.2 方法 1：固定模型大小，改变训练 token 数

对每个参数量 $N$（模型从 70M 到 10B 以上），训练 4 个模型。它们的学习率都按余弦调度衰减到 1/10，但衰减所覆盖的“视野”（以训练 token 数计）相差 16 倍。对每次训练运行，先平滑再插值训练损失曲线（附录 D.1：窗口长度 10 步的高斯平滑），得到“FLOPs 到训练损失”的连续映射。然后在每个 FLOPs 值上，找出哪次运行的损失最低；这样得到从任意 FLOPs $C$ 到最高效的 $(N,D)$ 的映射，其中 $\mathrm{FLOPs}(N,D)=C$。在 1500 个对数等间距的 FLOPs 值处，找出损失最低的模型大小及其所需 token 数，最后拟合幂律，得到 $a=0.50$、$b=0.50$。

补充细节：最大学习率为最小模型 $2\times10^{-4}$、最大模型 $1.25\times10^{-4}$，学习率一律用余弦调度降到 1/10（附录 D.1）。脚注 4 指出，所有被选中的点都落在训练的最后 15% 以内，这说明训练 $D$ 个 token 时，应当选一个大约在 $D$ 个 token 内衰减 10 倍的余弦周期长度。

### 3.3 方法 2：IsoFLOP 曲线

方法 1 使用整条训练曲线上的点 $(N,D,L)$；方法 2 则固定一组 9 个不同的训练 FLOPs（从 $6\times10^{18}$ 到 $3\times10^{21}$），对每个 FLOPs 改变模型大小（模型最大到 16B；训练 token 数由模型大小和训练 FLOPs 决定），只看**最终训练损失**。这样能直接回答：给定 FLOPs 预算，最优参数量是多少？每次训练的余弦周期长度都设成与目标 token 数匹配（这按附录 B 是最优的）。

对每个 FLOPs 预算，把（平滑后的）最终损失对参数量作图，得到一条“谷”形曲线（图 3 左）；作者保证每条曲线上训练了足够多样的模型大小，以看到清晰的最小值。他们对每条 IsoFLOP 曲线拟合一条抛物线，直接估计取得最小损失的模型大小，再对 FLOPs 与最优模型大小、最优 token 数拟合幂律（图 3 中、右），得到 $a=0.49$、$b=0.51$。

### 3.4 方法 3：拟合参数化的损失函数

最后，作者把方法 1 和 2 实验得到的**所有最终损失**，建模成模型参数量和所见 token 数的参数化函数。依据经典的风险分解（附录 D.2），采用下面的函数形式：

$$
\hat L(N,D)\triangleq E+\frac{A}{N^{\alpha}}+\frac{B}{D^{\beta}}\tag{2}
$$

三项的含义：第一项 $E$ 是理想生成过程在该数据分布上的损失，应当对应自然文本的熵；第二项表示一个训练到完美的、有 $N$ 个参数的 Transformer 仍然差于理想生成过程；第三项表示 Transformer 没有训练到收敛，因为只在数据分布的一个样本上做了有限次优化步骤。

**拟合方法**：估计 $(A,B,E,\alpha,\beta)$ 时，最小化预测与观测的**对数损失**之间的 Huber 损失，用 L-BFGS 算法：

$$
\min_{A,B,E,\alpha,\beta}\ \sum_{\text{Runs }i}\operatorname{Huber}_{\delta}\Bigl(\log\hat L(N_i,D_i)-\log L_i\Bigr)\tag{3}
$$

用一组初始值网格取最佳拟合，以避免局部极小。Huber 损失（$\delta=10^{-3}$）对异常点稳健，作者发现这对在保留数据点上的预测很重要。附录 D.2 补充：初始网格为 $\alpha,\beta\in\{0,0.5,\dots,2\}$、$e\in\{-1,-0.5,\dots,1\}$、$a,b\in\{0,5,\dots,25\}$（这里 $a,b,e$ 是 $A,B,E$ 的对数，拟合时用 log-sum-exp 的写法使数值稳定）；使用更大的 $\delta$ 会让模型过拟合小计算量区域、对更大运行的预测变差，更小的 $\delta$ 则不影响结果。

**效率前沿**：在约束 $\mathrm{FLOPs}(N,D)\approx6ND$ 下最小化 $\hat L$，所得 $N_{opt}$ 与 $D_{opt}$ 平衡了 $\hat L$ 中依赖模型大小和依赖数据的两项，因此天然是幂律形式：

$$
N_{opt}(C)=G\left(\frac{C}{6}\right)^{a},\quad D_{opt}(C)=G^{-1}\left(\frac{C}{6}\right)^{b},\quad G=\left(\frac{\alpha A}{\beta B}\right)^{\frac{1}{\alpha+\beta}},\quad a=\frac{\beta}{\alpha+\beta},\quad b=\frac{\alpha}{\alpha+\beta}\tag{4}
$$

（自行推导验证：令 $D=C/(6N)$ 代入 $\hat L$，对 $N$ 求导并令其为零，即得式 (4)。）所以 $a$ 与 $b$ 只由两个指数 $\alpha,\beta$ 决定，且 $a+b=1$：损失里“参数项”的指数 $\alpha$ 越大，说明加参数收益越快，最优分配就越偏向把 token 加多，反之亦然。

作者在附录 D.2 里给出拟合后的结果：

$$
\hat L(N,D)=1.69+\frac{406.4}{N^{0.34}}+\frac{410.7}{D^{0.28}}\tag{10}
$$

即 $E=1.69$、$A=406.4$、$B=410.7$、$\alpha=0.34$、$\beta=0.28$。参数与数据的指数都小于 $1/2$：对数据效率指数这是预期的（随机优化的收敛速度下界为 $1/D^{1/2}$，作者认为这离已知的下界还很远），而对参数一项，两层网络的函数逼近误差预期为 $1/N^{1/2}$；作者希望未来的模型和训练方法能增大这些系数。附录 D.2 还给出了对应的损失分解：损失 $L(N,D)=$ 贝叶斯风险（即“自然文本的熵”）$+$ 函数逼近项（取决于模型大小 $N$）$+$ 随机逼近项（只做单个 epoch、有限步数带来的次优性）。

自行验算：把式 (10) 的取整常数代入，$\hat L$ 对 Chinchilla（$N=70\mathrm{B}$、$D=1.4\mathrm{T}$）约为 1.94，对 Gopher（$N=280\mathrm{B}$、$D=300\mathrm{B}$）约为 1.99，即参数化模型也预测 Chinchilla 的损失更低。但若直接用这些取整常数代入式 (4)，得到 $a\approx0.452$、Gopher 预算下 $N_{opt}\approx32\mathrm{B}$、$D_{opt}\approx3.0\mathrm{T}$，与图 4 标注的 40B 不一致：原文印出的是取整后的常数，而最优规模对指数很敏感，所以要复现方法 3，必须重新拟合，不能直接用这几个数。

- **读图结论**：连续的 $\hat L$ 把方法 2 里一条条独立的 IsoFLOP 曲线统一了起来，并给出封闭形式的前沿；方法 3 给出的 $a=0.46$、$b=0.54$。

### 3.5 三种方法的结果比较

三种方法使用了不同的拟合方式（方法 1 与 2 用的是不同的训练运行，方法 3 则是对方法 1 与 2 的所有最终损失做统一拟合），却得到相近的预测：随着计算预算增加，模型大小与训练数据量应按大致相等的比例增长。方法 1 与 2 对最优模型大小的预测非常接近（图 1；附录图 A3 是同一结果的另一种画法，横轴为 token 数、纵轴为参数量，本文不重复放图），方法 3 预测在更大的计算预算下最优模型会更小。作者解释这个差别：低训练 FLOPs（$C\le10^{21}$）的观测点 $(L,N,D)$ 残差较大，Huber 损失会把它们自动当作离群点，拟合因此更看重高 FLOPs 的点；又由于前沿 $C\to N_{opt}$ 经验上有负曲率（附录 E），这就导致预测出比另外两种方法更低的 $N_{opt}$。

**表 2：随训练计算增加的参数和数据的估计缩放（原文表 2，第 8 页）**。列出的是指数 $a$ 与 $b$：$N_{opt}\propto C^{a}$、$D_{opt}\propto C^{b}$；括号内为通过自举（bootstrap，每次随机取 80% 数据，抽样 100 次）估计的第 10 与第 90 百分位数。

| 方法 | $a$（$N_{opt}\propto C^{a}$） | $b$（$D_{opt}\propto C^{b}$） |

| 3. 损失的参数化建模（Parametric modelling of the loss） | 0.46（0.454, 0.455） | 0.54（0.542, 0.543） |

读法：三种方法的 $a$ 都在 0.46 到 0.50，$b$ 都在 0.50 到 0.54，$a+b=1$；与 Kaplan 等的 0.73/0.27 形成鲜明对比，原文称“与此前关于这一问题的工作形成清晰对比，值得进一步研究”。注意各方法的自举区间都很窄（方法 3 仅 0.454 到 0.455），而方法之间的差别（0.46 对 0.50）远大于各自的区间宽度，所以自举区间只刻画“这批数据上的重采样稳定性”，并不能代表方法选择带来的不确定性；方法 2 的 $a$ 区间（0.462 到 0.534）则宽得多，已覆盖 0.5。

### 4.2 余弦周期长度的选择（附录 B，图 A1）

分析里有一个关键假设：余弦周期长度以及对应的学习率下降（按照 Rae 等 2021，衰减 10 倍；脚注 9 说，衰减 10 倍与衰减到 0 相差很小，衰减 10 倍略好，衰减得更少如 5 倍则明显更差）。作者发现，把余弦周期长度设成比目标训练步数长太多，得到的模型就是次优训练的（图 A1）。因此他们假设最优训练的模型，其余弦周期长度要按计算预算所允许的最大步数校准，并在主分析中遵循这一规则。

![图 A1：改变余弦周期长度的网格实验](rendered_figures/figA1-cosine-cycle-length.png)

*图 A1（原文 Figure A1，第 23 页）：在余弦周期长度上的网格。展示 6 条曲线，余弦周期长度分别设为目标训练步数的 1、1.1、1.25、1.5、2、5 倍。当余弦周期长度过长、学习率没有适当地降下来时，性能受损。作者发现，高估训练步数超过 25% 会导致性能明显下降。上、下两行是把训练步数设为两个不同的值。*

**图中文字翻译与读法**：

- 每行三幅图：**左**为 Learning Rate/Max LR（学习率与最大学习率之比）随 Million Sequences（百万条序列）的变化；**中**为 Training Loss（训练损失）；**右**为 C4 Loss（在 C4 上的损失）。图例 Cosine Cycle Length：$1.0\times$ num. steps（步数的 1 倍）、1.1×、1.25×、1.5×、2.0×、5.0×。上行训练约 770 万条序列，下行约 1280 万条（图上读出的近似值）。

原文的 FLOPs 把所有训练 FLOPs（包括 embedding 矩阵）都计入，并在总参数量中也计入 embedding；乘加用因子 2 计。前向传播包括：embedding（$2\times\text{seq\_len}\times\text{vocab\_size}\times d_{\text{model}}$）；每层注意力（QKV 投影 $2\times3\times\text{seq\_len}\times d_{\text{model}}\times(\text{key\_size}\times\text{num\_heads})$，QK 打分 $2\times\text{seq\_len}^2\times(\text{key\_size}\times\text{num\_heads})$，softmax $3\times\text{num\_heads}\times\text{seq\_len}^2$，对 V 的加权求和与最终线性层）；每层前馈块；最终 logits（$2\times\text{seq\_len}\times d_{\text{model}}\times\text{vocab\_size}$）。反向传播假定为前向的两倍。作者把这一计算与常用近似 $C=6DN$ 做了比较（表 A4），差别很小，不影响分析。

| 73M | 10 | 640 | 2560 | 10 | 64 | 1.03 |

## 五、Chinchilla：验证预测

### 5.1 模型与训练细节（第 4 节）

按原文第 3 节的分析，Gopher 的计算预算对应的最优模型大小在 40B 到 70B 之间。作者选择了范围上端的 70B 参数，训练 1.4T token（出于数据与计算效率两方面的考虑）。Chinchilla 与 Gopher 训练所用的 FLOPs 相同，差别在于模型大小与训练 token 数；它比 Gopher 小 4 倍，因此内存占用和推理成本也更小。

Chinchilla 沿用 Gopher 的模型架构与训练设置，只有以下不同：

- 在 MassiveText 上训练（与 Gopher 相同的数据集），但使用略有不同的子集分布（表 A1），以适应更多的训练 token；
- 用 AdamW（Loshchilov 与 Hutter 2019）而不是 Adam，这提升了语言建模损失以及微调后的下游任务表现；
- 用略有修改的 SentencePiece 分词器，不做 NFKC 规范化；词表与 Gopher 的相似，94.15% 的 token 相同；原文发现这对数学和化学的表示尤其有帮助（模型卡写明词表大小为 32,000）；
- 前向和反向用 bfloat16 计算，但在分布式优化器状态中保存一份 float32 的权重副本（见 Rae 等 2021 的 Lessons Learned）。

全部实验在 TPUv3/TPUv4 上用 JAX 和 Haiku 训练。附录 G 展示了这些优化器相关的改动：对 6.8 亿参数的模型，Chinchilla 的设置（AdamW、高精度权重副本）优于 Gopher 的设置（图 A6）；对 417M 与 1.4B 模型，AdamW 训练的最终表现优于 Adam（图 A7）；脚注 8 指出 AdamW 训练的模型要到余弦周期约 80% 处才在训练指标上超过 Adam，但最终表现更好。

## 六、讨论、局限与证据边界

**原文自述的局限**（第 5 节）：

- 由于训练大模型成本高，大尺度上只有两个可比较的训练运行（Chinchilla 与 Gopher），没有中间尺度的额外检验；
- 假设高效计算前沿能用计算预算、模型大小和 token 数之间的幂律关系描述；但在高计算预算处观察到 $\log N_{opt}$ 有凹性（附录 E），这暗示可能仍在高估大模型的最优大小；
- 分析里所有训练运行都不足一个 epoch；多 epoch 区间留给未来研究；
- 作者推测，扩大数据集只有在数据质量高时才有益，因此需要负责任地收集质量更高的更大数据集；更大的数据集需要格外注意训练集与测试集的重叠，不论是在语言建模损失还是下游任务上；万亿 token 的训练还带来许多伦理和隐私问题（网页抓取的数据含有毒语言、偏见和个人信息）；
- 作者还预期，其他模态里也有类似的“模型大小与数据量”的权衡，并认为所提方法易于在新的设定下复现。

**解读证据时需要注意的几点**：

- **Chinchilla 对 Gopher 不是单变量对照**：除了模型大小与 token 数，二者还在优化器（AdamW 对 Adam）、权重精度（float32 副本）、分词器（无 NFKC 规范化）和数据子集比例上不同（第 4.1 节）。原文在较小的模型上（6.8 亿；417M 与 1.4B）单独验证了优化器与精度改动本身就有益（图 A6、A7），所以 70B 对 280B 的差距不一定全部来自“参数/数据配比”，原文没有在全尺寸上把二者分开。
- **语言建模基准的泄漏风险**：Chinchilla 看了 4 倍的数据，原文自己提醒语言建模结果可能被泄漏抬高，所以更看重 MMLU、BIG-bench 等。
- **缩放估计本身的不确定性**：三种方法在大算力处是分叉的（方法 3 要求更小的模型）；原文承认大尺度上只有一次验证；而最优点附近损失本来就比较平坦（图 3 的谷底较平，图 A4 中两个模型的差距约 0.02）。
- **计算最优不等于推理最优**：本文优化的是“给定训练计算时的最低损失”。原文把推理成本的下降视为附带好处，但没有把推理成本放进目标函数。LLaMA 论文的引言明确指出，Hoffmann 等缩放律的目标忽略了推理预算，而在大规模部署时，给定目标性能，更合适的模型是推理最快的，而不是训练最快的；它的目标是在不同推理预算下取得最好的性能，做法是用比常规更多的 token 训练（见 [llama](../llama/论文中文解读.md)）。
- **模型未公开**：模型卡写明主要用户是 DeepMind 研究人员，不会公开该模型，因此结果无法被外部独立复核。

## 七、常见误读

- **误读一**：“Chinchilla 证明了模型越小越好。”不是：它说的是固定**训练计算**下，过大而训练不足的模型不如更小而训练更充分的模型；$a\approx b\approx0.5$ 也意味着算力增加时参数仍要增长，只是不再比数据增长得快。
- **误读二**：“每个参数训练 20 个 token 是论文给出的定律。”论文没有写这个数；它是表 3（方法 1）各行比值的概括，而方法 2 的比值约 19 到 29，方法 3 则更高并且随规模增大（见 3.6 节）。
- **误读三**：“Chinchilla 的结论说明数据质量无关紧要，token 越多越好。”原文只在不足一个 epoch 的设定下做分析，并明确说扩大数据集只有在高质量时才有益。
- **误读四**：“计算最优就是部署最优。”见上节。
- **误读五**：“三种方法给出同样的数。”它们的指数相近（0.46 到 0.50），但在 Gopher 预算处给出的最优参数量分别约为 67B、63B、40B（图 2、3、4），差别并不小。
- **误读六**：“Chinchilla 在所有任务上都全面优于 Gopher。”MMLU 有 4 个、BIG-bench 有 4 个任务更差；PIQA 持平；与 MT-NLG 相比在 PIQA 上略低。

## 八、复现检查

- 记录每次运行的唯一 token 数、重复采样与 epoch 数：名义 token 数不等于独立信息量；本文分析的运行都不超过一个 epoch。
- FLOPs 口径要写明：本文包含 embedding 与注意力的上下文相关项，$6ND$ 只是近似（表 A4 的比值在 0.99 到 1.10 之间）。
- 余弦周期长度要与训练步数匹配（图 A1：高估超过 25% 就会明显变差），否则“中间损失”会误导缩放拟合。
- sweep 要覆盖数据受限和参数受限两侧（IsoFLOP 谷两侧都要有点），才能稳定地拟合最优点；方法 2 需要足够多的模型大小以看清谷底。
- 方法 3 要用对数损失的 Huber 损失（$\delta=10^{-3}$）和 L-BFGS，并用网格初始化；报告拟合不确定性（自举区间）而不是只报一个比例；原文印出的取整常数不足以复现。
- 在换新数据或新分词器时，要重新拟合：原文只在 MassiveText、C4 和 GitHub 上验证了指数接近 0.5。

## 九、与相关论文的关系

- **Scaling Laws**（见 [scaling_laws](../scaling_laws/论文中文解读.md)）：Kaplan 等（2020）给出 $N\propto C^{0.73}$、$D\propto C^{0.27}$；本文用三种方法重新估计，得到近似 0.5/0.5，并在 $10^{21}$ FLOPs 处做了小规模的头对头验证（图 A4）。
- **GPT-3**（见 [openai_gpt3](../openai_gpt3/论文中文解读.md)）：GPT-3（175B 参数、300B token）是表 1 中“大模型少数据”这一类的代表；GPT-3 论文明确依据 Kaplan 等的分析，选择比常规做法更大的模型、更少的 token。
- **LLaMA**（见 [llama](../llama/论文中文解读.md)）：LLaMA 的出发点是推理预算，用比 Chinchilla 缩放律所建议的更多的 token 训练更小的模型，是对本文目标函数的补充，而不是反驳。
