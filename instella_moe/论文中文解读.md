## 一、一句话结论

Instella-MoE-16B-A3B 是一个“全开放”（fully open）的 MoE 语言模型：总参数 16B、每个 token 激活 2.8B，在 AMD Instinct MI300X 与 MI325X GPU 上从零训练，数据全部取自公开数据集，并发布从预训练到强化学习每个阶段的权重、训练配置、数据来源、训练代码与评测协议。

- **架构**：27 层，第 1 层为稠密 FFN，其余 26 层为 MoE（64 个路由专家选 6 个，外加 2 个共享专家）。相对常见的稀疏 MoE 有两处改动：**Gated MLA**（在 MLA 注意力的输出上加一个 sigmoid 门）与 **FarSkip-Collective**（改变层间连接，使专家并行的 all-to-all 通信能与计算重叠）。
- **训练管线**：7.1T token 预训练 → 约 100B token 中期训练（三个数据混合变体，再做模型汤）→ 4K 到 64K 的两阶段长上下文扩展，得到 Base；然后 SFT（含反馈驱动的数据筛选）→ DPO（关闭负载均衡以抑制路由漂移）→ 指令遵循强化学习（IF-RL）与多教师 on-policy 蒸馏（MOPD），得到 Think 模型。
- **结果**：Base 在 13 个预训练基准上平均 76.7，是对比中的全开放模型里最高的（OLMo-3-7B 为 70.1，SmolLM3-3B 为 70.5），次于开放权重的 Qwen3.5-4B-Base（79.5），略高于 Moonlight-16B-A3B（76.2）。Think 模型在 12 个后训练基准上平均 73.2，高于 OLMo-3-7B-Think（72.0）、Gemma-4-E4B（70.5）和 Qwen3.5-4B（69.7）。FarSkip 使预训练吞吐提高 12.7%，专家并行推理的首 token 吞吐提高 39.2%。
- **边界**：所有对比均为作者自行评测；架构消融只有 200B token 规模的单次运行；预训练各数据源的占比论文没有给出；长上下文能力在 Stage 2 之后有所回退。

## 二、背景与动机

**全开放与仅开放权重**。原文引言（第 1 节）认为，当前的前沿进展主要由闭源模型引领（原文列举了 GPT-5.6、Claude Fable 5、Gemini 3.1 Pro、Muse Spark 等），权重、架构、训练数据、方法与评测协议都不透明，阻碍科学理解、可复现性和公平获取。主要实验室近来发布了许多开放权重模型（原文列举 GLM-5.3、Qwen3.8-Max、Kimi K3、Gemma 4、DeepSeek-V4、Llama 4、Mistral Large 3 等），但它们大多只开放权重：预训练语料、预处理流程与完整训练配方要么不披露，要么只有部分文档。于是研究者无法完全复现结果、审计数据污染，也无法研究架构与数据选择在规模上如何相互作用。这些模型名称均取自原文。

**MoE 与全开放 MoE 的稀缺**。稀疏激活的 MoE 已成为改善“成本—性能”权衡的核心策略：每个 token 只激活一小部分参数，模型能获得远大的稠密模型的表示容量，而每 token 计算量接近较小的稠密基线。然而同时做到竞争力强且训练过程完全透明的全开放 MoE 仍然少见：OLMoE（总参数 6.9B、激活 1.3B）建立了重要基线，Marco-MoE 则通过稠密检查点 upcycling 把全开放稀疏训练扩展到多语言。

**本文的目标与贡献**。在 AMD 硬件上从零训练一个有竞争力的全开放 MoE，并公开完整流程。论文自称四点贡献：

1. Instella-MoE：16B 总参数、2.8B 激活参数、在 AMD Instinct GPU 上从零训练，带有 Gated MLA 与 FarSkip-Collective；
2. 完整的多阶段训练管线：预训练、中期训练、长上下文扩展、带反馈驱动数据筛选的 SFT、DPO，以及 IF-RL 加 MOPD；
3. 全开放模型中的最强表现：Base 平均 76.7，Think 平均 73.2，与同等激活参数规模的全开放和开放权重基线相当或更好；
4. 完全透明与可复现：逐阶段发布权重、训练配方、数据混合、训练代码与评测协议。

## 三、模型架构

### 3.1 总览与规格

Instella-MoE-16B-A3B 是纯文本的 decoder-only Transformer，共 27 层，其中 26 层是稀疏 MoE 层，第 1 层保留为稠密 FFN。MoE 层遵循 DeepSeek-V3 的细粒度“共享 + 路由”专家设计：每个 token 被分发到 64 个路由专家中的前 6 个，同时经过 2 个共享专家。预训练和中期训练时另外加一个 1 层的多 token 预测（Multi-Token Prediction，MTP）头作为辅助训练目标。

**图中文字翻译与读法**：

- **(a) Overall architecture（整体架构）**：自下而上为 Input Tokens（输入 token）、Embedding、1 层 Dense Layer（稠密层），再堆叠 26 次（“× 26”虚线框）的 Gated MLA 加 FarSkip MoE，最后是 RMSNorm、LM Head 和 Output。左上灰色虚线框 MTP Head 只在预训练和中期训练时接在最后的隐状态上。图例：黑线 $h_\ell$ 表示 routed-inclusive（包含路由专家输出）的残差流，红线 $\tilde h_\ell$ 表示 routed-free（不含路由专家输出）的残差流；标注“FarSkip ($h_{\ell-1}$)”的弧线表示 MoE 的输入取自上一层的完整输出 $h_{\ell-1}$，而不是等本层注意力算完。图注强调：FarSkip-Collective 让 Dispatch 与 Combine 两次 all-to-all 集合通信可以与注意力和共享专家的计算重叠。
- **(b) FarSkip MoE（FarSkip MoE 块）**：输入 $h_{\ell-1}$ 同时送给两个共享专家（绿色，Shared Expert）和路由器（Router）；Router 为每个 token 选出 Top-K 个路由专家（浅紫色，Routed Expert，图中示意为 1…N 中的若干个，灰色表示未被选中），选中的专家输出乘上路由权重（⊗）求和。块同时返回两个结果：只含共享专家的 shared（红线），以及“路由 + 共享”的 routed + shared（黑线）。
- **(c) Gated MLA（简化的 Gated MLA 块）**：输入 $\tilde h_{\ell-1}$（红线）同时进入三条线性分支：左支经 Linear 产生 q，并对其中一部分做 RoPE 后与其余部分拼接（C）；中支经 Linear（下投影到 512 维的 KV 潜向量）、RMSNorm、Linear（上投影）得到 k 的内容部分和 v，另有一路 RoPE 分支与之拼接得到 k；右支经 Linear 与 σ（Sigmoid）得到门。q、k、v 送入 Multi-Head Attention（多头注意力），其输出与门逐元素相乘（⊗），再经最后的 Linear（输出投影）。
- **读图结论**：红线与黑线的区别是 FarSkip 的关键——注意力吃的是“不含上一层路由专家输出”的残差流，MoE 吃的是“不含本层注意力输出”的残差流，这样两者的输入都不必等对方的通信完成。具体的公式见第 3.4 节。

### 3.3 MoE 层、负载均衡与 MTP

**MoE 层**（原文第 2.1.1 节）。除第 1 层外的 26 个 MoE 层，每层把每个 token 分发给 N=64 个路由专家中的前 K=6 个（每个专家的中间维度 1,408），同时经过两个共享专家（实现为一个融合的 FFN，中间维度 2,816，即两个 1,408）。被选中的路由专家的路由权重乘以 2.5，沿用 DeepSeek-V3。

**负载均衡**。主要机制沿用 DeepSeek-V3 的基于偏置的无损耗均衡：每个专家有一个偏置，加到用于 top-K 选择的路由得分上，但不加到混合权重上；偏置在训练步之间朝目标负载更新，速率为 $1\times10^{-3}$。这样能调整 top-K 的分配而不引入辅助目标的梯度。另外还使用序列级辅助负载均衡损失作为次要的正则项，系数为 $1\times10^{-4}$。DPO 阶段冻结偏置更新、把辅助损失系数设为 0，以限制路由漂移（第九节）。

**多 token 预测（MTP）**。沿用已有工作，在预训练和中期训练阶段加一个 MTP 模块：除了标准的下一个 token 目标外，该模块在每个位置多预测一个未来 token，提供更丰富的训练信号。MTP 损失权重在预训练中为 0.3，中期训练降为 0.1；长上下文扩展阶段关闭，推理时不使用。

### 3.4 Gated MLA：给 MLA 的注意力输出加一个门

多头潜在注意力（Multi-head Latent Attention，MLA，DeepSeek-V2 提出）把每个 token 的 key–value 状态压缩成低秩的潜在表示，以减少 KV cache 的占用。标准 MLA 把各头缩放点积注意力的输出拼接后直接经输出投影。**Gated MLA** 保留低秩 KV 分解，但在注意力输出与输出投影之间插入一个由输入决定的门（图 2(c)）。依照 Qiu 等（2025）的最佳配置，使用乘性的、sigmoid 激活的逐元素门。设 $\mathbf{x}_t\in\mathbb{R}^{d}$ 为经 RMSNorm 的层输入，$\hat{\mathbf{o}}_t\in\mathbb{R}^{Hd_v}$ 为 $H$ 个头（每头 value 维度 $d_v$）缩放点积注意力输出的拼接，Gated MLA 的输出为：

$$
\mathbf{y}_t=\mathbf{W}_o\big[\mathrm{Sigmoid}(\mathbf{W}_g\mathbf{x}_t)\odot\hat{\mathbf{o}}_t\big],\qquad(1)
$$

其中 $\mathbf{W}_g\in\mathbb{R}^{Hd_v\times d}$ 是门的投影，$\mathbf{W}_o$ 是注意力输出投影，$\odot$ 为逐元素乘。门使每个 token 可以调节每个头内部的每个 value 通道。代入表 1：$H=16$、$d_v=128$，门有 $16\times128=2048$ 个通道，$\mathbf{W}_g$ 为 $2048\times2048$。论文在受控的 200B token 消融中报告，Gated MLA 把平均分从 49.86 提高到 50.33（表 13，见第十二节），主要收益在 MMLU 和代码生成。

两点注意：（1）门由当前 token 的输入算出、作用在当前注意力输出上，不需要缓存，所以不影响 MLA 的 KV cache 占用（这是本文的推理，论文未明说）；（2）门不改变 MLA 的低秩压缩，压缩 KV 的仍是 MLA 本身。按 MLA 的标准做法（假设与 DeepSeek-V2 相同：缓存 512 维潜向量加 32 维解耦 RoPE 键），每层每 token 缓存 544 个元素，而同样 16 头、QK 128 维、V 128 维的标准多头注意力需要缓存 $16\times(128+128)=4096$ 个元素，约为后者的 13%（自行估算，论文没有给出）。

### 3.5 FarSkip-Collective：让 all-to-all 通信“躲进”计算里

**要解决的问题**。专家并行（EP）对稀疏 MoE 的部署至关重要，但它带来通信开销。MoE 层的实现分四个阶段：路由器计算专家路由图；**Dispatch**（派发）用路由图通过 all-to-all 把相关 token 发到对应 GPU；各 GPU 计算它们所得 token 的专家激活；**Combine**（汇合）再用一次 all-to-all 把专家输出映射回原来的 GPU 位置。标准实现里，Dispatch 依赖上一层的输出，Combine 要等专家计算完，因此两次 all-to-all 都无法与计算重叠。

**核心思想**。设网络经过 $k$ 个子块（子块即注意力或 MLP/MoE，各自含归一化）后的输出激活为 $h_k$，第 $i$ 个子块为 $f_i$。标准 Transformer 为（式 2）：

$$
h_k=f_1(h_0)+f_2(h_1)+\cdots+f_k(h_{k-1}).\qquad(2)
$$

大模型里，产生 $f_i$ 可能包含阻塞式通信，使 $h_k$ 在 GPU 间通信完成之前不能作为 $f_{k+1}$ 的输入，计算资源因此空闲。FarSkip 的想法是：改用一个当前已可用的激活 $\hat h_k$ 作为 $f_{k+1}$ 的输入，在通信集合操作还在生成 $h_k$ 的同时就去算下一层；等 $h_k$ 就绪，再把它累加进来（式 3）：

$$
h_{k+1}=h_k+f_{k+1}(\hat h_k)=f_1(h_0)+f_2(\hat h_1)+\cdots+f_{k+1}(\hat h_k).\qquad(3)
$$

与式 (2) 一样，所有算出的激活最终都出现在最终隐状态里；区别是各子块的输入变成了“部分的”或“过时的”激活 $\hat h_k$，相当于在完整激活的求和里省掉了一些加项。

**FarSkip-Collective 的具体设计**：要让 Dispatch、Combine 和注意力块的通信都能被重叠，同时让 $\hat h_k$ 相对 $h_k$ 省掉的加项尽量少。

- **MoE 的输入**：为让 Dispatch 能与注意力计算重叠，派发的输入不能依赖注意力输出，所以令 $\text{moe-in}_k:=\hat h_k(\mathrm{moe})=h_{k-1}$，即用上一层的完整输出（含路由专家），不含本层注意力的输出。这使 Dispatch 和路由在上一层 Combine 产出 token 之后就能立刻开始，传播至多延迟一层。
- **注意力的输入**：只有路由专家的输出在专家计算之后需要通信，所以它们是注意力输入中唯一被省掉的项：$\text{attn-in}_k:=\hat h_k(\mathrm{attn})=h_{k-2}+\text{attn-out}_{k-1}+\text{shared-exp-out}_{k-1}$（此处下标按层计，是原文公式的写法；含义是“上一层的输出去掉路由专家的贡献”，与图 2 中的红线 $\tilde h$ 对应）。这使路由专家的 Combine 能与共享专家的计算以及注意力计算的前半部分重叠。
- **注意力内部的通信**：被路由专家的计算所掩盖。

合起来，在不做流水线的前提下，FarSkip-Collective 把 Dispatch 和 Combine 的可重叠窗口扩展到整层的时长，只有路由器和路由专家本身的计算除外。

![图 9：FarSkip-Collective 的连接方式](rendered_figures/fig9-farskip-connectivity.png)

*图 9（原文 Figure 9，第 26 页）：FarSkip-Collective 修改子块之间的连接，避免等待通信集合操作；计算用已有的激活继续，这些激活是部分的（例如 Block N 的输出）或过时的（例如 Activation）。*

**图中文字翻译与读法**：

- **左半 Standard Connectivity（标准连接）**：三张 GPU（GPU 1 到 GPU 3）各自从 Activation（激活）进入 Block N，Block N 的输出必须经过绿色的 (Comm.)（通信）这一道集合操作之后，才能进入 Block N+1。通信在主路径上，后面的块只能等。
- **右半 FarSkip-Collective Connectivity（FarSkip-Collective 连接）**：Block N 的输出直接送入 Block N+1，不等通信；通信（右下方绿色 (Comm.)）与 Block N+1 的计算并行进行，通信结果之后再汇入残差路径（图中向上的箭头）。
- **读图结论**：FarSkip 把“通信放在主路径上”变成“通信放在旁路上”，代价是子块输入变成了部分或过时的激活，计算语义与标准 Transformer 不再逐字等价，所以需要从头训练并用实验验证精度。

**精度验证**。作者做了大规模架构消融：把 Instella-MoE 加 FarSkip 训练 200B 个预训练 token，与不加 FarSkip 的 Instella-MoE 固定所有训练设置和种子相比。表 13 中，加 FarSkip 的变体平均 50.38，对比不加 FarSkip 的标准连接 50.33，表现相当。实现细节在附录 A，见第十二节。

### 3.6 自行估算：16B 与 2.8B 怎么来

下面用表 1 的数字做一次粗略核对（自行估算，假设：SwiGLU 使用 3 个矩阵，输入 embedding 与输出头不共享，Q 投影不做低秩压缩，忽略 MTP 头与第 1 层稠密 FFN，后者的宽度论文没有给出）：

- 每个路由专家 $3\times2048\times1408\approx8.65$M，64 个路由专家每层约 553.6M，26 层共约 14.39B；每层共享专家约 17.3M，路由器约 0.13M。路由专家因此占总参数的九成以上。
- 注意力（MLA 加门）每层约 15.5M，27 层约 0.42B；embedding 与输出头各约 264M。合计约 15.8B，加上第 1 层稠密 FFN 与 MTP 头后与 16B 基本吻合。
- 激活参数：每层 6 个路由专家加共享专家约 69.3M，26 层约 1.80B；加上注意力 0.42B、embedding 与输出头 0.53B，约 2.75B，加上第 1 层稠密 FFN 与 MTP 头后与 2.8B 基本吻合。每个 token 激活的 FFN 等效宽度为 $(6+2)\times1408=11{,}264$。

总参数里约九成是路由专家，而每个 token 只用到其中 6/64，这正是“16B 总参数、2.8B 激活”的来源，也是需要专家并行和 all-to-all 通信、从而需要 FarSkip 的原因。

## 五、预训练（原文第 2.4 节）

**设置**：从零开始在 7.1T token 上训练，上下文长度 4,096，全局 batch size 4,096（按序列计，每步约 1678 万 token，据此预训练约 42.3 万步，自行换算）。优化器 AdamW，$\beta_1=0.9$、$\beta_2=0.95$，权重衰减 0.1；学习率调度为 WSD（warmup–stable–decay：先升温、长时间保持峰值、最后衰减），峰值 $4\times10^{-4}$，最小值 $4\times10^{-5}$，2,000 步 warmup。MTP 目标在这一阶段开启，所有语料用 DeepSeek-V3 分词器分词。

## 七、长上下文扩展（原文第 2.6 节）

### 7.1 总体配方

中期训练之后，在 AMD Instinct MI325X 上通过继续预训练把上下文从 4K 扩展到 64K，分两个阶段：Stage 1 用多样的长上下文数据让模型适应完整的 64K 长度；Stage 2 重新调整训练混合，恢复在 Stage 1 中退化的数学、代码与推理能力。Stage 2 结束时的检查点就是 Instella-MoE-16B-A3B-Base；后续后训练从它出发，继承扩展后的上下文窗口。

### 7.4 训练细节

在 16B 参数的 MoE 上做 64K 训练，显存与通信压力都大：64 个路由专家用专家并行分到 8 张 GPU，序列维度用上下文并行切分，使每个设备只持有 64K 激活的一个切片，并使用完整的激活重计算与 bfloat16 混合精度，才能使每步的 micro-batch 大小为 1。与前面的 4K 上下文阶段不同，64K 训练不做前向与反向通信的重叠；为在新序列长度上继续训练，优化器状态被重新初始化。

*图 5（原文 Figure 5，第 12 页）：反馈驱动的数据筛选。(i) 学生模型回答留出的种子集问题，评判模型对照参考答案打分；答对的回答被丢弃，每个错误被转成结构化的错误分析，写明失败模式、缺失的技能以及能弥补差距的训练数据。(ii) 一个更大的反思模型把某个领域的错误分析汇总成检索策略：一组权重之和为 1 的查询。(iii) 每个查询在共享的嵌入空间里通过最近邻搜索，从各领域预算 $B_{\mathrm{dom}}$ 中检索它分到的 $k_i$ 条样本；每个被定向领域预算中剩下的 $\alpha$ 份额，以及非定向的 other 领域的全部预算，用同领域均匀采样补齐。总预算 $B=512$K 按基础混合中的比例分给各领域，对应图中长度不同的条形。*

**图中文字翻译与读法**：

- **(i) Diagnosis（诊断）**：Seed set held-out prompts（留出的种子 prompt）→ Student SFT checkpoint（学生：SFT 检查点）→ answers（回答）→ Judge LLM-as-judge（评判：用 LLM 做裁判，同时拿到 references 参考答案）；correct → discarded（答对的丢弃），incorrect（答错的）→ Structured error analysis（结构化错误分析）：error（失败模式）、skills（缺失的能力）、would help（该检索哪类训练数据）。
- **(ii) Query generation（查询生成）**：Reflection model aggregates error analyses（反思模型汇总错误分析）→ Retrieval policy（检索策略，权重之和为 1），图中以代码领域为例，每条查询前的数字是权重：0.020 Graph algorithms: BFS/DFS/Dijkstra on state spaces（状态空间上的 BFS/DFS/Dijkstra 图算法），0.018 Strict input/output format compliance（严格的输入输出格式遵守），0.005 Spatial connectivity on geometric grids（几何网格上的空间连通性）……每个被定向的领域一个策略。
- **(iii) Retrieval（检索）**：Embedded candidate pool（已嵌入的候选池，图中黄色菱形为查询 $q_i$，绿点为被检索到的近邻）；top-$k_i$ nearest neighbors（余弦相似度），$k_i=\lfloor B_{\mathrm{dom}}w_i(1-\alpha)\rfloor$；右侧三条横条分别是 Math、Code、Other 三个领域的预算，绿色为检索所得（$1-\alpha$），灰色为同领域均匀补齐（$\alpha$，图中 $\alpha=0.5$），Other 领域全为灰色；最终汇成 Curated 512K mixture → final SFT phase（精选的 512K 混合，用于最后的 SFT 阶段）。
- **读图结论**：这是一个“用模型自己的错误反向指导选数据”的闭环：错误 → 文字描述“需要什么样的数据” → 向量检索把这类数据从大池子里捞出来。

**流程要点**：

1. **诊断**：在留出的种子集上运行学生，用 LLM 作裁判对照参考答案打分；对每个错误回答，裁判模型再给出结构化错误分析，其中含对“什么样的训练数据能解决这个错误”的描述。
2. **查询生成**：一个更大的反思模型把这些错误分析聚合成一组加权的检索查询，权重归一化为和等于 1。
3. **检索**：把选择预算按权重分给各查询，每个查询按嵌入相似度从池中取回对应数量的最近邻。

与相同预算下的均匀采样相比，这使评测集的平均性能提高 1.5 分，在指令遵循、竞赛数学和代码生成上收益最大（表 8）。论文提到并行的工作 STAT（He 等，2025）同样通过教师诊断的错误来针对学生的弱点，但它依赖预定义的技能分类来驱动选择；本文方法里教师给出自由形式的错误反馈，再转成对大候选池的检索查询。

### 8.3 附录 B：错误分析与提示词细节

- **数据划分**：筛选涉及四个互不相交的集合：（1）留出的种子集（诊断与查询生成用）：数学用截至 2022 年的 AIME 题目，代码用取自 Nemotron 池的题目，均配有参考答案；（2）单独保留的打分集（只用于评测筛选的效果，从不进入选择）；（3）供检索的完整指令微调训练池；（4）最终的 512K 精选混合。池中与种子集或打分集重叠的内容被移除，使诊断题和评测题不会被再次选中；嵌入前丢弃长于 32K token 的样本。最终的 512K 混合在每个领域的样本数与基础混合相同。
- **两级分配**：先把总预算 $B$ 按基础混合的比例分给各领域，得到 $B_{\mathrm{dom}}$；在被定向的领域内，权重为 $w_i$ 的查询按余弦相似度取回 $\lfloor B_{\mathrm{dom}}w_i(1-\alpha)\rfloor$ 个最近邻，由于权重之和为 1，取回的样本约占领域预算的 $(1-\alpha)$，其余用同领域随机样本补齐，这个随机成分保证覆盖面、避免混合塌缩到被检索的近邻上。取 $\alpha=0.5$；非定向的 other 领域没有策略，预算全部用该领域内的随机采样填充。
- **错误分析的例子（表 15，数学）**：题目是“从正 $n$ 边形的顶点中随机取三个不同顶点，构成钝角三角形的概率为 $\frac{93}{125}$，求所有可能的 $n$ 之和（参考答案 503）”。裁判给出的结构化分析要点：领域为数学中的组合与几何；复杂度为多步（要区分锐角、直角、钝角三角形，推出 $n$ 为奇数和偶数时钝角三角形个数的通式，再解有理方程并验证）；错误是方法不对、推理不完整（只盯住 $n=6$ 的特例而没有推广，数错数、误用角公式，没有求出 $n$）；缺失的技能包括从特例推广到通式、圆心角与圆周角的关系、钝角对应最大弧、半圆上三角形的计数等；建议的训练数据是“逐步推导正多边形中各类三角形概率通式、区分奇偶、讲清圆周角与弧关系并给出解方程”的题目。
- **错误分析的例子（表 16，代码）**：题目是“一只狗从 $x=0$ 以单位速度向右跑，经过 $x=1,\dots,n$ 处的 $n$ 个碗，第 $i$ 个碗在时刻 $t_i$ 才可食用；到达烫的碗时可以等到 $t_i$（并推迟之后所有的碗）或跳过；在 $T$ 秒内最多能吃几个碗”。裁判指出：错误是错误的贪心假设，没有建模“战略性跳过”；缺失的技能包括认识到最优解可能要跳过看似有利的选项，以及“对答案二分 + 用堆维护 $t_j-j$ 的关键值”这类技巧。

## 九、直接偏好优化与路由漂移（原文第 2.8 节）

**数据与配置**：从精选的 SFT 检查点出发，用 Dolci-Think-DPO-7B 偏好数据集（Olmo 等，2025）做 DPO。该数据集建立在 **delta learning**（差值学习，Geng 等，2025）的想法上：偏好调优的驱动力是 chosen 与 rejected 回复之间的质量差距，而不是任何一方的绝对质量。所以每个偏好对把一条 Qwen3-32B 的思考轨迹与一条弱得多的 Qwen3-0.6B 轨迹作对比，即使继续模仿 chosen 轨迹已经提供不了有用的训练信号，这样的偏好对仍然有信息。配置见表 3：150K 个偏好对，序列长度 16,384，全局 batch 256，峰值学习率 $8\times10^{-8}$，线性调度，$\beta=5.0$，训练 0.75 个 epoch。

**遇到的问题**：直接照搬配方跑 DPO 时，训练能收敛，但得到的模型在下游基准上的准确率反而低于 SFT 检查点；同样的配方用在稠密模型上则没有这个现象。论文还注意到，DPO 阶段的学习率比预训练和 SFT 低得多，而 MoE 的辅助负载均衡损失与路由偏置更新，是按那些高学习率阶段设定的。据此，作者在 DPO 期间同时关闭这两个负载均衡机制（冻结偏置更新、辅助损失系数设为 0）。

## 十、强化学习：IF-RL 与多教师 on-policy 蒸馏（原文第 2.9 节）

**总体配方**：因为 DPO 模型在数学与通用推理上已经很强，RL 的目标被限定在指令遵循（IF）上，再用一个 on-policy 蒸馏阶段把这些收益并入 DPO 模型而不损坏它的其他能力。两阶段如图 7：Stage 1 是带可验证奖励的 IF 专项 RL（RLVR），产出一个“IF 专家”；Stage 2 是多教师 on-policy 蒸馏（MOPD），从这个专家和 DPO 模型把知识蒸馏给学生，DPO 模型充当“自锚点”。

![图 7：Instella-MoE-16B-A3B 的 RL 训练管线](rendered_figures/fig7-rl-pipeline.png)

*图 7（原文 Figure 7，第 14 页）：Stage 1 做 IF 专项 RL 得到 IF 专家；Stage 2 做 MOPD：领域路由器把学生的 IF rollout 送给 IF-RL 教师，把其余 rollout 送给冻结的 DPO 教师，学生在自己的 on-policy rollout 上用 token 级反向 KL 目标更新。*

**图中文字翻译与读法**：

- **Stage 1: Instruction-Following (IF) Specialized RL Training（指令遵循专项 RL 训练）**：从 Instella-MoE-16B-A3B-DPO 出发，得到 IF Expert（IF 专家）。
- **Stage 2: MOPD: Multi-Teacher On-Policy Distillation（多教师 on-policy 蒸馏）**：Student（学生，初始化自 DPO 模型）产生 On-Policy Rollouts（on-policy 展开）→ Domain Router（领域路由器）：IF Prompts（IF 类 prompt）的 rollout 送给 IF-RL Teacher（IF-RL 教师，即 Stage 1 的 IF 专家），Other Prompts（其他 prompt）的 rollout 送给 DPO Teacher（DPO 教师）→ 两路汇入 Token-Level Reverse KL（token 级反向 KL）→ “Policy update on the student’s own rollouts”（在学生自己的 rollout 上更新策略）→ 得到 Instella-MoE-16B-A3B-Think。
- **读图结论**：整个 RL 只显式优化“指令遵循”这一种能力；其余能力靠冻结的 DPO 教师把学生拉在原处。

### 10.1 RL 基础设施

两个阶段都采用基于 Miles 的解耦“actor–learner”设计：rollout 由一组 SGLang 推理引擎产生，策略在 Megatron-LM 中优化；每个优化步之后，更新后的权重回传给 rollout 引擎。IF-RL 阶段完全异步运行，使生成与梯度计算重叠，处于单步 off-policy 状态；MOPD 阶段同步、on-policy 训练，因为教师打分使每次更新依赖当前的学生。每次运行用 3 个节点共 24 张 GPU：8 张给 learner（专家并行 EP=8，带分布式优化器），16 张给两个并行的 SGLang rollout 引擎（各自 TP=8、EP=8，使用数据并行的注意力）。rollout 引擎生成的回复最长 16K token。

**MoE 特有的训练/推理一致性**：SGLang 的 rollout 与 Megatron 的训练前向可能把同一个 token 路由到不同的专家，所以训练时算出的对数概率 $\log\pi_{\mathrm{train}}$ 不一定与采样时的概率一致。作者在两个层面处理：第一，开启 **Rollout Routing Replay（R3）**（Ma 等，2025），把采样时做出的专家分配决策记录下来，在训练前向中重放，使 $\log\pi_{\mathrm{train}}$ 沿着产生该 token 的那条专家路径求值；第二，用 token 级的**截断重要性采样（TIS）**（Yao 等，2025）修正推理引擎与训练引擎之间残余的数值失配，每个 token 的比率被截断在有界范围内（表 9）。

### 10.2 IF 专项 RL（Stage 1）

**设置**：对 DPO 模型训练 1,400 个 rollout 步，数据是 Dolci-Think-RL-7B 的 IF-RLVR 子集（Olmo 等，2025），其 prompt 带有可验证的指令遵循约束，风格类似 IFEval 与 IFBench。每步采样 64 个 prompt × 8 条回复 = 512 条 rollout（全局 batch 512），温度 1.0，回复最长 16,384 token。另外使用 **partial rollouts**（Zhou 等，2025b）：在一个步内没有解码完的长尾样本被回收到下一步继续，其过时的（off-policy）token 在损失中被屏蔽；这在如此长的回复长度下显著提高吞吐。优化器为 Adam（$\beta_1=0.9$、$\beta_2=0.999$），常数学习率 $1\times10^{-6}$，权重衰减 0，梯度裁剪 1.0；每 50 步监测 IFEval 与 IFBench（评测温度 0.6、top-p 0.95）。结果是得到一个指令遵循行为明显强于 DPO 模型的 IF 专家。

**目标函数**：核心目标是组相对策略优化（GRPO，Shao 等，2024），再加上取自 DAPO 与 Dr. GRPO 的、如今已成标准的改进。对一个 prompt $x$，从 rollout 策略中采样一组 $G$ 条回复 $\{y_i\}_{i=1}^{G}$，优化：

$$
\mathcal{J}(\theta)=\frac{1}{\sum_{i=1}^{G}\lvert y_i\rvert}\sum_{i=1}^{G}\sum_{t=1}^{\lvert y_i\rvert}w_{i,t}\,\min\Big(r_{i,t}A_{i,t},\ \mathrm{clip}\big(r_{i,t},1-\varepsilon_{\mathrm{low}},1+\varepsilon_{\mathrm{high}}\big)A_{i,t}\Big),
$$

其中 $r_{i,t}=\dfrac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}{\pi_{\theta_{\mathrm{old}}}(y_{i,t}\mid x,y_{i,<t})}$ 是策略比率，$w_{i,t}$ 是截断的重要性采样权重，用来修正 rollout 策略与 learner 策略之间的失配；优势按组相对方式只做均值中心化：$A_{i,t}=R(x,y_i)-\mathrm{mean}\big(\{R(x,y_j)\}_{j=1}^{G}\big)$，$R$ 是下文所述的验证器奖励。相对原始 GRPO 的具体修改，作者全部采用：

- **零梯度信号过滤**：一组里 $G$ 条回复奖励完全相同时，优势为零、不产生梯度，直接丢弃这样的组（Yu 等，2025）。
- **主动采样**：为在过滤之后仍保持恒定、信息充分的 batch，每步过采样 prompt（128 个），持续采样直到凑满奖励方差非零的组；借助异步 rollout 池，learner 从不需要等待。
- **token 级损失**：损失按 batch 内 token 总数归一化，而不是按序列归一化，消除对长推理轨迹的长度偏置。
- **不加 KL 惩罚**：完全去掉对参考模型的 KL 项（及参考模型），允许策略移动更大而不破坏训练稳定。
- **Clip-higher**：把 PPO 的上下裁剪边界解耦，取 $\varepsilon_{\mathrm{low}}=0.2$、$\varepsilon_{\mathrm{high}}=0.272$，以保留探索性低概率 token 的概率质量。
- **不做标准差归一化**：优势只做均值中心化、不除以组内奖励的标准差，消除“很容易或很难的 prompt 优势被放大”的难度偏置。
- **TIS 与 R3**：用于训练/推理一致性（见上）。

**基于验证器的奖励设计**：奖励缩放到 $[0,10]$，由确定性的验证器产生，而不是学习得到的奖励模型，以避免长推理轨迹上的奖励作弊。指令遵循的回复由一串约束检查函数打分。沿用 Pyatkin 等（2025）的 IF-RLVR 配方（OLMo 3 也采用），给**部分分**：得分为满足的约束所占的比例，而不是全对才有分，这丰富了训练信号，并缓解了多约束 prompt 上的信用分配。这套 IF 约束验证器驱动 Stage 1 的训练，也用于评测（IFEval 与 IFBench）；但评测时采用严格标准，只有一个 prompt 的所有约束都满足才给分。MOPD 用教师的对数概率信号取代标量奖励，因此训练时不使用这些验证器。在给任何可验证的分数之前，先过一道“思考格式门”：只有回复里含有格式良好的推理块（`<think> … </think>`）才能获得奖励；随后推理轨迹被剥离，只给最终答案段落打分，防止格式错误或没有推理的输出拿到分。

### 10.3 多教师 on-policy 蒸馏 MOPD（Stage 2）

**动机**：IF 专项 RL 得到的 IF 专家擅长指令遵循，但在数学与推理基准上退步（表 14）。作者用 MOPD（Ma 等，2026）把 IF 专家的指令遵循能力并入 DPO 模型，同时保住 DPO 模型的其他能力。

**做法**：在学生自己的 on-policy rollout 上做蒸馏，prompt 取自 Dolci-Think-RL-7B 的带领域标签的混合（IF 与通用各占一半；每步 128 个 prompt × 4 条样本 = 512 条回复；回复最长 16K token），把每条 rollout 路由给一个冻结的教师。每个教师通过独立的 SGLang 端点提供服务；prompt 的领域决定由哪个教师给学生采样出的 token 打分：指令遵循 prompt 由 IF-RL 教师打分，其余 prompt（数学、代码、通用等）由冻结的 DPO 模型自己打分。学生从 DPO 模型初始化，所以在非 IF 领域，教师就是学生自己的初始化，这使优势在训练早期近似为零，起到“自锚定”的正则作用，保住数学和通用能力，而 IF 领域的信号驱动学习。具体的 on-policy 蒸馏目标把逐 token 的优势定义为教师与学生的对数概率之差：

$$
A_t=\log\pi_{\mathrm{teacher}}(y_t\mid y_{<t},x)-\log\pi_{\mathrm{student}}(y_t\mid y_{<t},x).\qquad(4)
$$

这个差在学生 on-policy 分布下的期望，对应于学生与按领域路由的教师之间的 token 级**反向 KL** 目标。教师的对数概率通过给学生采样出的 token 打分得到（不让教师自己生成），领域路由器对每个样本从 $\{\pi_{\text{IF-RL}},\pi_{\text{DPO}}\}$ 里选一个作为 $\pi_{\mathrm{teacher}}$。该目标在同一套 GRPO/重要性采样的机制里优化（重要性比率截断到 $[0.5,2.0]$，没有 KL 项，没有熵奖励）。

![图 8：Instella-MoE-16B-A3B 的训练与推理吞吐](rendered_figures/fig8-throughput.png)

*图 8（原文 Figure 8，第 19 页）：训练与推理吞吐。左，预训练吞吐，相对标准的 MoE 专家并行训练基线归一化（提升 12.7%）；右，专家并行下的推理首 token 时间（TTFT）吞吐（提升 39.2%）。*

**图中文字翻译与读法**：

- **左图 Training（训练）— Pretraining Throughput（预训练吞吐）**：纵轴 Normalized Throughput（归一化吞吐，刻度 50 到 125）；Standard MoE（标准 MoE，灰色柱）为 100.0，Instella-MoE（橙色柱）为 112.7。

- **读图结论**：FarSkip-Collective 的通信重叠使预训练吞吐比标准专家并行基线高 12.7%，推理 TTFT 吞吐高 39.2%。两图的纵轴都不是从 0 开始，柱子的视觉差距被放大；图里只有相对比值，没有绝对的 token/秒、GPU 数或 MFU。

**附录 A：重叠的实现**。FarSkip-Collective 通过把过时的和部分的激活传给 MoE 层与注意力层来重叠通信与计算（图 9），减少通信“气泡”并保持精度。为了在训练中显式实现通信重叠，作者开发了一个自定义的模型实现，以模块化方式在硬件上强制重叠，**同时避免自定义 kernel 以保证可移植性**。

- **GPU 上的重叠**：保证计算在通信同时运行的整个过程中持续进行，这依赖通信与计算 kernel 在运行时共享 CU（计算单元）。标准做法是利用 `torch.distributed` 中 `async_op=True` 的异步启动行为（入队后立即返回），再配合 `.wait()` 屏障来安全访问被通信的张量。前向传播用这种做法，显式排列模型算子的顺序以最大化重叠。
- **反向传播**：使用 `torch.autograd` 时无法显式控制算子顺序与 `.wait()` 调用。为此采用 Dukler 等（2026）的方案（见其附录 C）：实现无竞争的异步反向通信算子，并结合“序列号重新排序”（Sequence Number API）。与标准连接的变体相比，预训练取得 12.7% 的训练加速。
- **推理**：实现通信重叠的专家并行生成，同时支持张量并行注意力和数据并行注意力，以适配 Instella-MoE 基于 Gated MLA 的注意力。除重叠外，通过聚合通信，可以把张量求和后一并通信，进一步减少总通信量。在 8 张 MI325X GPU 上用 SGLang 服务 Instella-MoE，TTFT 吞吐提高 39.2%。具体的重叠实现代码已随 github.com/AMD-AGI/Instella-MoE 发布。

## 十三、局限、证据边界与常见误读

### 13.1 论文没有给出或证据较弱的地方

- **预训练数据比例**：表 4 与附录 C 只给了数据集名称和许可，没有各来源在 7.1T token 里的占比；“数据混合已公开”只能核实到来源清单。
- **消融规模小、无种子波动**：表 13 的架构消融只有 200B token、Nemotron-CC、单次运行，平均差异 0.47 与 0.05，逐项方向不一；FarSkip 与 Gated MLA 在最终 7.1T 规模上没有对照实验。
- **效率只有相对比值**：图 8 只给归一化吞吐，没有绝对吞吐、GPU 数量、MFU，也没有说明“标准 MoE 基线”的具体实现。
- **DPO 的关键论断缺数据**：“直接 DPO 低于 SFT”“稠密模型没有这个现象”没有表格；路由漂移的归因（学习率与负载均衡机制的不匹配）是推断，不是做过隔离实验的结论。
- **一些消融只有文字**：YaRN 对比 $\theta=10{,}000$ 不用 YaRN、四种 Stage 2 混合的配比、模型汤与其他合并方式的对比、MTP 的作用，论文都没有给出完整数据。
- **自行评测与口径**：所有对比模型的分数来自作者自己的评测，开放权重模型是否开启思考模式、Gemma-4 在基础模型表里的版本、Llama-3.2-3B 的 RULER 全零等问题原文没有交代；“最强全开放”只相对于文中选取的全开放基线（OLMo-3-7B、SmolLM3-3B、OLMoE-1B-7B）。两张后训练表的“平均”口径不同（12 项含 AlpacaEval 2 与 11 项不含）。
- **去污染**：附录 B 说明从候选池中移除了与种子集、打分集重叠的内容；论文没有专门说明对 AIME24/25 等最终评测基准的去污染。
- **未命名的组件**：反馈驱动筛选里的评判模型、反思模型、嵌入模型，以及 MOPD 的训练步数，原文都没有给出。
- **原文自身的小出入**：反思提示词要求权重之和“不超过 1”，正文写“归一化为 1”；图 4 的学习率曲线终点约 $0.7\times10^{-4}$，与正文最小学习率 $4\times10^{-5}$ 不一致；Stage 2 的 HELMET/RULER 回退被称为“modest”（HELMET 平均 −2.2，RULER 平均 −4.5；64K 处 −4.8 与 −5.6，均为自行计算）。

### 13.2 常见误读

- **“2.8B 激活”不等于“2.8B 模型”**：16B 参数仍需全部放进显存，专家并行还要付 all-to-all 通信；这正是 FarSkip 要解决的问题。
- **“fully open”不等于“所有训练细节都能复现”**：许可是“视来源而定”，预训练比例缺失，部分组件没有命名。
- **FarSkip 不是无损改写**：它改变了各子块的输入（部分的、过时的激活），计算上与标准 Transformer 不等价，所以必须从头训练并经实验验证；论文的精度证据是 200B token 的单次消融。
- **FarSkip 与“跨层残差缓解信息损失”无关**：它是为通信重叠设计的连接方式；把它理解为“缓解深层或稀疏路由信息损失的远距残差路径”是常见的误解。
- **Gated MLA 的门不是“控制不同路径贡献”**：它是作用在注意力输出各通道上的 sigmoid 逐元素门，压缩 KV 的是 MLA 本身。
- **Think 模型不是“推理 RL”的产物**：RL 只显式优化指令遵循（IF-RLVR）；数学与推理能力主要来自 SFT 与 DPO 数据（Dolci-Think 等的教师轨迹），MOPD 的作用是把 IF 收益并入而不损坏它们。
- **“73.2”是 12 项平均**：含 AlpacaEval 2（一个 LLM 裁判的对话评测），而不是 11 个客观基准的平均。
- **“多教师”不是更大的教师**：MOPD 的两个教师分别是同规模的 IF 专家和冻结的 DPO 模型（即学生自己的初始化）。

## 十四、复现检查与相关论文

### 14.1 复现检查清单

- **架构**：按表 1 搭建，同时确认论文没有给出的细节：第 1 层稠密 FFN 的宽度、Q 投影是否做低秩压缩、容量/丢 token 策略、MTP 头的结构。
- **负载均衡**：偏置式无损耗均衡（更新速率 $1\times10^{-3}$）加序列级辅助损失（系数 $1\times10^{-4}$）；DPO 阶段必须同时冻结偏置和关闭辅助损失，并监控路由漂移（top-1 变化比例、top-6 Jaccard）。
- **FarSkip**：输入定义为 $\text{moe-in}_k=h_{k-1}$ 与 $\text{attn-in}_k=h_{k-2}+\text{attn-out}_{k-1}+\text{shared-exp-out}_{k-1}$；训练前向用异步通信加 `.wait()`，反向用无竞争的异步通信与序列号重排；对照标准连接检查精度和吞吐。
- **数据与阶段**：按表 3、表 4、表 6、表 22–24 逐阶段复现；预训练的数据占比需要查代码仓库，论文里没有。
- **长上下文**：$\theta=8\times10^{6}$ 加 YaRN、文档掩码、Stage 2 的 STEM 恢复；用 HELMET 与 RULER 跟踪，并同时监控 GSM8K 与 HumanEval+ 的回退。

- **评测**：基础模型用 OLMES 风格设置；消融用 LM-Eval-Harness；严格模式的 IFEval/IFBench。
