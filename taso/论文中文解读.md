## 一、它解决了什么

TASO 自动生成并形式验证等价图替换规则，再用成本驱动搜索优化 DNN 图，减少人工维护海量 rewrite rules。

## 二、编译抽象与优化路径

从 operator specifications 枚举小图对，用 SMT/定理证明验证语义等价，形成 substitution 库；对输入图做 cost-based backtracking search，联合寻找融合、重排和布局机会。

## 三、为什么影响后续系统

它把 superoptimization 和形式验证引入 DNN graph optimizer，说明图重写规则本身也可生成而非手工编码。

## 四、怎样读性能结果

编译器结果必须同时记录 frontend、shape、batch、精度、目标硬件、vendor library、调优预算和编译时间。单算子加速不等于端到端同倍加速，首次编译延迟也不能与缓存命中后的 steady-state 混为一谈。

## 五、局限与工程边界

等价验证依赖简化 operator semantics，浮点重排、数值误差和动态 shape 更复杂；搜索空间快速爆炸，静态 cost model 也可能偏离真实 runtime。

## 六、放进十年编译器演进史

与 XLA/Glow 的人工 pass 比较；与 Korch 的全局 kernel orchestration 和 equality-saturation 类方法联系。

## 八、原文论证链

传统图编译器的 rewrite rules 由工程师手写，难覆盖大量算子组合。TASO 把它变成 superoptimization：从 operator specification 枚举小型计算图对，使用形式化方法验证等价，自动生成 substitution 库；优化具体模型时，再以实测/估计 cost 驱动回溯搜索，把匹配子图替换为更便宜的等价图。

这样把“规则是否正确”和“何时值得使用”分开：验证器保证抽象语义等价，cost model 决定目标硬件上的收益。

## 九、搜索对象是什么

节点是 DNN operator，边是 tensor。等价替换可能改变算子分组、结合顺序或删除冗余计算。搜索从原图出发，应用匹配 substitution 得到候选；用 hash/图同构避免重复，并用 cost-based pruning 控制指数爆炸。

若候选图成本近似为各 operator runtime 之和，它可能漏掉并发、cache、fusion codegen 与 layout conversion。因此 cost model 的准确范围决定搜索的实际上限。

> 原文定位：[PDF 文件第 3 页](paper.pdf#page=3)

## 十、实验怎样读

论文对 ResNet、RNN/NAS 模型等比较 TensorFlow/TensorRT/人工优化。speedup 应结合搜索时间与优化后图结构阅读；自动找到已知规则只能证明覆盖，找到意外组合更能说明 superoptimizer 价值。形式等价不代表浮点逐位相等，需查看容差。

> 原文定位：[PDF 文件第 2 页](paper.pdf#page=2)

## 十一、复现检查

- 保存 operator 语义假设、验证器版本与生成 rule 集。
- 分离规则生成时间、每模型搜索时间和运行时收益。
- 对重排 reduction 的候选做数值稳定测试。
- cost model 应包含 layout/copy 或用端到端测量校准。

## 十二、常见误读

TASO 不会自动发明任意新 kernel 算法；它在给定 operator 语义和替换空间中搜索图。形式验证的结论也只覆盖模型化语义，动态 shape、副作用和未建模浮点行为仍是边界。
