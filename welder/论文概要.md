# Welder 论文概要

## 基本信息

- 题目：*Welder: Scheduling Deep Learning Memory Access via Tile-graph*
- 作者：Yining Shi 等
- 会议：OSDI 2023
- 原文：https://www.usenix.org/conference/osdi23/presentation/shi
- 主题：tile-graph、存储层次、算子融合、深度学习编译

## 一句话结论

Welder 不把 fusion 当作图节点合并，而把算子切成 output tiles，显式决定 tile 在寄存器、shared memory、device memory 乃至 host memory 的生产、保留和消费位置，从全模型角度最小化数据流量。

## 核心问题

现代 DNN 常由算力快、内存层次慢所限制。固定 pattern fusion 只考虑相邻 operator，单算子调优又忽略跨 operator 的中间数据复用；两者都没有统一回答“某个 tile 应在哪一级存储 materialize”。

## 方法

- operator-tile：一次计算某个输出 tile 所需的子计算与输入 tile。
- tile-graph：用 tile 粒度的数据依赖连接算子。
- hierarchical scheduling：利用论文观察到的 memory-layer independence，从高层到低层分别搜索 tile shape 和连接层级。
- tile-traffic cost model：估计不同方案跨各级存储的流量，再结合 profile 选择计划。
- codegen：在 CUDA GPU 和 Graphcore IPU 上实现相应的 fused program。

## 主要结果

- 在 V100 上，对多种 CNN、Transformer、图像恢复和 NeRF 模型，Welder 对 TensorRT 的平均加速约 1.47×（batch 1 场景），新模型最高超过 3×。
- batch 64 时相对 TensorRT 平均约 1.21×。
- TensorCore 实验中，memory bottleneck 更突出；对所测 batch-1 模型相对 TensorRT 平均 1.53×。
- 在 RTX 3090 的 34 个案例上，相对 TensorRT 几何平均 1.40×。
- 自动发现约 300 个融合子图，其中 89 个含多个 reduction，超出常见手写规则。

## 局限

- 编译期搜索和 profile 成本明显，适合重复执行的稳定 workload。
- 高度依赖静态、可分析的 tensor expression；动态控制流和强 data-dependent shape 更困难。
- compute-intensive kernel 仍依赖底层 scheduler/库的质量。
- 论文不同图的 batch、精度、TensorCore 开关和基线并不完全相同，不能混成一个统一 speedup。

## 阅读价值

Welder 是理解现代 fusion compiler 的关键论文：fusion 的自然单位不一定是 operator，而可能是 tile；真正优化目标也不是 kernel 数，而是整个 memory hierarchy 的 traffic。
