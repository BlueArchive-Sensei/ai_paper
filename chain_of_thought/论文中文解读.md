# Chain-of-Thought Prompting 中文精读

## 1. 先把贡献说准确

这篇论文没有发明一种新的 Transformer，也没有训练一个“推理模块”。它改变的是推理时给模型看的示例格式：标准提示只展示“问题 $x$—答案 $y$”，Chain-of-Thought（CoT）提示展示“问题 $x$—中间步骤 $r$—答案 $y$”。模型参数不变，却被要求把原本一步完成的映射展开成更长的条件生成：

$$
p(y\mid x)\quad\Longrightarrow\quad p(r,y\mid x)
=\prod_t p(r_t\mid x,r_{<t})\prod_j p(y_j\mid x,r,y_{<j}).
$$

这里的 $r$ 不是另一个隐藏网络，而是一串普通 token。重要之处在于，自回归模型每生成一个 token 都会再做一次前向计算；把中间状态写进上下文，后面的预测便能条件于这些状态。于是输出长度不仅是表达成本，也成为一种可伸缩的顺序计算预算。

## 2. 为什么标准提示容易失败

多步题同时要求语义解析、状态维护、运算和答案格式化。若只要求最终答案，一个错误 token 就可能对应整条隐含推导失败，而且外部无法定位问题。CoT 将任务拆为多个局部转移：先识别量，再建立关系，再计算，再输出答案。论文列出四个预期优点：可分解复杂问题、为难题分配更多步骤、提供可检查的行为窗口、无需微调即可用于多种语言可描述任务。

“可检查”不等于“忠实”。作者在第 2 节已经谨慎说明：文本链看起来像解答，但完整刻画支持答案的内部计算仍是开放问题。因此正确说法是“CoT 提供行为层面的调试接口”，不是“CoT 读出了模型真正的内心活动”。

## 3. 实验怎样排除简单替代解释

### 3.1 主比较

算术部分覆盖 GSM8K、SVAMP、ASDiv、AQuA 和 MAWPS。基线与方法使用相同问题、模型和 few-shot 框架；主要差别只是示例中有没有中间推导。算术任务主要由作者人工写 8 个示例，模型采用贪心解码。论文还在常识任务与 last-letter、coin-flip 等符号任务上检查可迁移性。

这种设置的优点是归因清楚：没有新增训练数据或参数更新。缺点也明显：结论依赖人工提示、特定模型族和答案抽取规则。

### 3.2 规模是必要条件

第 3.2 节的第一个结论不是“CoT 总有效”，而是“CoT 的有效性随规模涌现”。小型 LaMDA、GPT-3 或 PaLM 往往生成语法流畅却逻辑错误的链，表现甚至低于标准提示；最大模型才出现稳定增益。论文把约 100B 参数附近描述为当时实验中的明显转折，而不是普适物理常数。

第二个结论是题越需要多步，收益越大。GSM8K 的基础正确率较低，最大模型使用 CoT 后提升显著；MAWPS 的 SingleOp 只需一步，提升很小甚至为负。这支持“中间状态分解”解释：没有中间状态的题，本来就没有多少可分解空间。

### 3.3 三个关键消融

| 消融 | 想检验的替代解释 | 结果与含义 |
|---|---|---|
| Equation only | 只要先写方程就够了 | GSM8K 上收益很小；复杂语义不能总被一步映射成方程 |
| Variable compute only | 只要输出更长、做更多前向计算即可 | 输出与所需方程等长的点号接近基线；无语义 token 不足以携带中间状态 |
| Reasoning after answer | CoT 只是唤起预训练知识 | 先给答案再解释接近基线；在答案之前按序生成步骤才真正影响答案条件分布 |

这组消融很有价值，因为它把“多 token”“有方程”“有解释”拆开了。论文证据更支持：有任务语义、位于答案之前、能被后续 token 条件化的中间序列才是主要因素。

## 4. 结果到底证明了什么

论文最著名的结果是 PaLM 540B 用 8 个 CoT 示例在 GSM8K 上达到当时最佳，并超过一个经过专门微调且配有 verifier 的 GPT-3 系统。它说明大模型预训练中已经形成可被少量示例激活的多步模式；不需要为每个任务重新训练模型。

作者又人工检查 LaMDA 137B 的 GSM8K 输出。随机抽取的 50 个正确答案中，除两例“碰巧答对”外，链在逻辑与数学上也正确；50 个错误答案中，46% 接近正确但有计算、符号映射或漏步等局部错误，54% 是语义理解或整体连贯性错误。这揭示两类后续路线：局部错误可以由投票、工具或 verifier 修复；根本不理解问题时，仅延长同一路径通常无济于事。

不能从这些结果推出三件事：

1. 不能推出每条自然语言步骤都对最终答案具有真实因果作用；模型可能在文字链外已经形成答案倾向。
2. 不能推出更长总是更好；论文只证明“有意义的分解”优于若干基线。
3. 不能推出 CoT 自动带来可靠性；一条连贯但错误的链反而会让错误更有说服力。

## 5. 从 CoT 到 test-time scaling

CoT 是后续 test-time scaling 的最小原型：让难题在推理阶段消耗更多 token。不过它只扩展单条轨迹。后续工作沿三个方向补足：

- [Self-Consistency](../self_consistency/论文中文解读.md)：并行采样多条 $r_i$，对答案边缘化，降低单路径方差。
- [Tree of Thoughts](../tree_of_thoughts/论文中文解读.md)：在“thought”级状态上分支、估值、剪枝和回溯。
- [Let’s Verify Step by Step](../lets_verify_step_by_step/论文中文解读.md)：学习每一步是否正确，让搜索获得密集反馈。
- [Scaling LLM Test-Time Compute Optimally](../scaling_test_time_compute/论文中文解读.md)：不再假定统一策略，而是按题目难度分配并行、顺序和搜索预算。

## 6. 阅读和复现检查表

- 标准提示与 CoT 提示必须使用同一模型、相同示例问题和相同答案解析。
- 报告模型规模、采样策略、温度、示例顺序与随机种子；不能只报最佳 prompt。
- 分开记录最终答案正确、步骤正确和“答案正确但路径错误”。
- 按题目所需步骤数分桶，检查收益是否确实集中在多步题。
- 计算 token 与延迟成本；准确率提升不是免费的。
- 将可读性与忠实性分开评估，不把一条漂亮的解释当成机制证明。
