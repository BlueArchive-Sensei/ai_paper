## 1. s1 回答的是“最简单复现路线”

s1 不声称复现 o1 或 DeepSeek-R1 的训练算法。它问：若已有一个强 instruction model，能否用很少的高质量 reasoning 数据和一个简单推理控制器，观察到“测试时多给计算，表现随之改善”？答案是在若干数学/科学基准上可以。

贡献分两半：训练侧证明 1000 条精心筛选数据可以激活长推理格式；推理侧用 budget forcing 控制模型在 `<think>` 区域停留多久。二者缺一不可：普通模型被强迫输出更久可能只是重复，学会 reasoning 格式但无法控制结束时机也难形成可测 scaling 曲线。

## 2. s1K：为什么不是数据越多越好

初始池约 59,029 道题，来自 NuminaMATH、AIME、OlympicArena、OmniMath、AGIEval，以及作者新建的概率资格考试题和量化面试谜题等 16 个来源。每题用 Gemini Flash Thinking 生成 reasoning trace 与答案，再做清洗和 8-gram 去污染。

最终选择遵循三条轴：

- **Quality**：剔除 API 错误、格式问题、缺图等不可用样本；
- **Difficulty**：优先保留 teacher 能答对但需要更长 reasoning 的问题；
- **Diversity**：跨领域轮换抽样，避免 1000 条都被某类竞赛数学占满。

算法 1 先纳入正确的 AIME/GPQA 以及 reasoning 很长的 MATH 样本，再按领域随机轮换，并对领域内较长轨迹施加 $2^{-\text{rank}}$ 权重。这个算法不是“最长 1000 条”，而是困难偏好与领域覆盖的折中。

消融显示，随机选、只选最长或只最大化多样性在 AIME24 上平均约低 30 个百分点；完整 59K 又没有显著超过精选 1K。论文据此主张“选什么”比“盲目加量”重要。需注意 teacher 是 Gemini Thinking，所以质量标准部分继承 teacher 能力和偏差。

## 3. 训练配方到底有多简单

基础模型为 Qwen2.5-32B-Instruct。模型用特殊 delimiter 区分 thinking 与 answer，loss 只作用于 reasoning trace 和答案，不计算问题 token。主要超参数：

- 5 epochs、batch size 16，共 315 个更新步骤；
- bfloat16，AdamW，学习率 $10^{-5}$；
- 5% warmup 后 cosine decay；
- 16 张 H100 训练约 26 分钟。

长序列训练很重要。附录比较 4096 与 32768 训练长度：4096 会截断 74% 样本，使模型更少见到 reasoning 后的 answer delimiter；结果是推理时反而生成更长，却表现更差。AIME24 从 30% 提到 50%，平均 thinking token 从约 20,721 降到 6,984。这个消融有力说明“输出更长”不能单独解释能力。

## 4. Budget forcing 的机制

### 4.1 缩短预算

当 thinking token 达到上限，系统强制附加 end-of-thinking delimiter，让模型转入 answer 阶段。它提供硬上限，但可能切断尚未完成的证明。

### 4.2 延长预算

当模型自己要结束 thinking 时，系统忽略 delimiter，并向上下文追加 “Wait”。模型继续生成，常表现为复查前面推导、尝试替代方法或修正局部错误。可以重复若干次以形成更高预算点。

这不是在隐藏状态里增加循环，而是修改已生成上下文：

$$
p(r_{t+1}\mid x,r_{\le t},\text{Wait}).
$$

因此收益取决于模型在 SFT 中学到的自我检查模式。“Wait”只是把分布推向继续推理，并不保证新增 token 有信息。

## 5. 三个评价维度

论文强调 test-time scaling 方法不能只看最高 accuracy：

- **Control**：能否稳定得到目标计算量；
- **Scaling**：增加计算时性能斜率是否为正；
- **Performance**：在可比较预算下绝对准确率如何。

Budget forcing 的优势是控制直接、曲线较清楚。用提示要求“思考 N 步”时，模型会用更短或更长的每步文本绕过限制，实际 token 不可控；按长度 rejection sampling 则代价高且出现 inverse scaling。

## 6. 主结果和应有的克制

论文报告 s1-32B 在不干预时 AIME24 为 50%，budget forcing 后最高 57%；摘要还称在 MATH 和 AIME24 上最多比 o1-preview 高 27%。这是一组基准结论，不是通用模型排名：AIME24 题量小，不同采样/判分会产生波动，o1-preview 是当时产品快照，且 s1 使用了来自另一个闭源 reasoning teacher 的蒸馏轨迹。

字符串消融很有解释力。忽略两次结束符但不插字符串，AIME24 仍为 50.0%；插 “Alternatively” 或 “Hmm” 也是 50.0%；插 “Wait” 达 53.3%。MATH500 基本不变，GPQA 则多种字符串从 57.6% 到 59.6%。可见干预效果任务相关，且不是简单 token padding。

论文还展示：强迫很长时模型会重复，顺序 scaling 最终饱和。并行多数票或 REBASE 可在更高总预算继续改善，但它们的 reward model 成本需要另外计入。

## 7. 失败模式与污染边界

- 延长后可能陷入同一句或同一解法循环，没有真正探索。
- 强制结束可能在关键推导中途切断，得到仓促答案。
- Teacher-generated traces 可能带来错误、风格锁定和不可见过滤偏差。
- 8-gram 去重只能排除表面重合，不能证明语义上无污染。
- reasoning 长度与难度相关，但选长轨迹也可能选中啰嗦样本；论文用质量和多样性约束缓解。
- 只在答案正确率上评估，不能证明可见 chain 对内部机制忠实。

## 8. 与其他路线的关系

[Scaling LLM Test-Time Compute Optimally](../scaling_test_time_compute/论文中文解读.md) 用训练过的 revision model 与 PRM 搜索研究预算分配，方法复杂但能按难度适配；s1 则追求最小可复现系统，用一个 reasoning SFT 模型和 delimiter 操作完成顺序控制。DeepSeek-R1、Kimi k1.5 等厂商系统使用 RL 或多阶段 recipe，属于具体实现，不能把 s1 的简单复现当成它们的算法披露。

## 9. 复现检查表

- 记录基础 checkpoint、teacher、过滤规则、去污染 n-gram 和所有数据源。
- 训练序列长度必须覆盖 reasoning + answer；单报最大长度不够，要报截断率。
- 为每个预算报告真实 thinking token 分布，不只报目标步数。
- 同时报单次准确率、采样方差、平均 token、延迟和重复率。
- 将 budget forcing、majority voting 和带 PRM 搜索的额外模型成本统一换算。
- 人工检查“修正了错误”的轨迹与“延长后自我破坏”的轨迹，避免只展示成功案例。
