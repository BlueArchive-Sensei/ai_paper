## 一、核心命题：长上下文不应一直支付平方 attention 成本

标准 softmax attention 的训练时间/显存随序列长度近似二次增长，decode 的 KV cache 也随长度增长。MiniMax-01 的选择不是完全抛弃 softmax，而是让大多数层使用 linear Lightning Attention，每 8 层保留一个 softmax 层负责全局交互。

论文发表于 2025 年 1 月，arXiv:2501.08313。本地材料包括 [PDF](paper.pdf)、[文本](paper.txt) 与 [概要](论文概要.md)。

## 二、Figure 3：混合 attention + MoE

完整模型 80 层、hidden 6144。每 7 个 lightning attention block 后跟 1 个 softmax attention block；32 experts、top-2，456B 总参数、45.9B 激活。

线性层负责低成本累计长程状态，softmax 层周期性提供内容相关的精确 token-token 交互。这是一个经验折中：全 linear 可能损失 recall/induction，全 softmax 太贵。

## 三、Lightning Attention 如何把复杂度线性化

普通 attention 先算 `QKᵀ`，产生 `N×N` 矩阵。若 kernel 允许结合律改写，可先算 `KᵀV`，再左乘 Q，复杂度从 `O(N²d)` 变成 `O(Nd²)`。

causal mask 让直接右乘需要 prefix cumsum，难以并行。Lightning Attention 将序列切块：

- block 内使用带 causal mask 的左乘；
- block 间维护累计 `KᵀV` 状态，使用右乘；
- 用 I/O-aware tiling 避免逐 token 串行更新。

它在 `N >> d` 时优势最大。短序列或 kernel 未优化时，常数开销可能抵消理论复杂度优势。

## 四、MoE 与 global router

模型使用 token-drop MoE。单个 EP group 的 microbatch 小且数据分布波动，会造成某组 expert 过载、另一组空闲。global router 在 dispatch 前 all-gather 各 expert 待处理 token 数，让路由跨 EP group 更全局地平衡。

这会减少 token dropping，但也增加一次全局通信。它和 DeepSeek-V3 的 auxiliary-loss-free bias 是不同路线：MiniMax-01 更显式地同步全局负载，V3 尽量用局部统计和路由 bias 减少质量损失。

## 五、scaling law 与混合比例

论文通过小模型 isoflop 比较决定 MoE 规模和 attention mix。一个重要方法论是：先在可承受尺度上拟合 loss、参数与 token 的关系，再决定 456B 架构，而不是只在最终模型上做不可重复的单点实验。

但小规模 scaling law 对百万 context、分布式通信和数值稳定性的外推仍有误差，因此最终系统仍需要工程消融。

## 六、训练与长上下文扩展

初始阶段先训练约 11.4T tokens，再通过 128K、512K、1M 三阶段长 context 训练。数据长度分布与 RoPE frequency 逐步改变，避免突然切到超长序列造成不稳定和短任务退化。

模型在 4M NIAH 上表现强，但论文明确承认 NIAH 在 128K 阶段就趋于饱和，因此还构造更难长 context 任务监控 checkpoint。这个自我批评很重要：needle retrieval 是必要测试，不是充分测试。

## 七、结果与长上下文证据

MiniMax-Text-01 与当时 GPT-4o、Claude 3.5、DeepSeek-V3 等做核心 benchmark 对比。

MiniMax-VL-01 在 Text-01 上接视觉 encoder/projector 后训练。历史排行榜会过时，更可复用的是：混合 attention 在商业级 MoE 上确实被训练到百万 context。

4M extrapolation 的实际部署还要计算：prefill time、recurrent state、softmax 层 KV、batch、显存和内容质量。context window 是容量声明，不是一次请求都应该塞满的推荐。

## 八、局限与复现要点

- 线性 attention 的 recurrent state 使训练 kernel 与 decode kernel 必须数值一致；M1 后续报告就记录了精度不一致导致 RL reward 不增长。
- 32 experts/top-2 的 active ratio 仍较高，45.9B active 并不是轻量模型。
- global routing、token drop 和 hybrid attention 让普通 Transformers 实现难以高效复现。
- 论文开放权重与实现，但完整数据、训练基础设施和全部 reward recipe 未公开。
- MiniMax 模型许可证需单独阅读，不能把“权重可下载”自动等同 Apache 2.0。

## 九、与 MiniMax-M1 的关系

M1 沿用同一 456B hybrid backbone，再额外 continual pretrain 7.5T reasoning-intensive tokens，做 long-CoT SFT 和 CISPO RL。理解 M1 的效率优势，必须先理解本文的 7:1 attention 混合。
