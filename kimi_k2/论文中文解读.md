## 一、K2 的定位

K2 是开放权重的 1T MoE foundation/agentic model。它不是 k1.5 的简单大版本：K2 报告强调稳定预训练、非长思考的 agent/tool use 和开放 checkpoint；k1.5 强调 long-CoT RL。

论文发表于 2025-07，arXiv:2507.20534。本地保存 [PDF](paper.pdf)、[文本](paper.txt) 与 [概要](论文概要.md)。

## 二、总体结果与比较口径

报告的 K2-Instruct 主要以 non-thinking 模式评测，在 SWE-bench Verified、Tau2-bench、AceBench、LiveCodeBench 等强调 agentic/coding。与 Claude/GPT 比较时，scaffold、工具、max tokens 和模型版本都影响结果；“非思考”也不代表模型内部没有任何中间计算，只表示没有扩展的长 CoT 模式。

## 三、MuonClip：先解释 Muon 为什么需要护栏

Muon 对矩阵参数更新做近似正交化并匹配 update RMS，论文引用前期实验认为它比 AdamW 更 token-efficient。但扩到 MoE 大模型后，Q/K projection 的谱范数增长会放大 dot product，attention logits 可冲到 1000 以上，引发 softmax 数值和训练不稳定。

QK-Clip 利用 forward 已计算的每 head 最大 logit。若超过阈值 `τ`，按比例同时缩小相关 query/key projection weights。它在 optimizer step 后约束产生 logit 的权重，而不是只在 softmax 前截断值；这也兼容 MLA 不显式 materialize 完整 key 的实现。

K2 用 `τ=100`，15.5T tokens 的 raw loss curve 无 spike。这个结果说明方案在该 run 可用，不等于任意模型都应使用同一阈值。

## 四、数据 rephrasing 与 token utility

高质量文本直接重复多 epoch 容易过拟合。K2 用不同风格/视角重写知识文本，长文分 chunk 顺序改写并做 fidelity check；数学材料转成 learning-note 风格并增加翻译多样性。

报告的小实验中，多种 rephrasing 比简单 10 epoch 重复的 SimpleQA 更好。风险是改写模型可能产生事实偏移、风格同质化和合成痕迹，fidelity classifier 也会漏错。合成数据提升 token utility，不等于凭空产生可靠新知识。

## 五、架构：更稀疏的 DeepSeek-V3 亲缘路线

K2 有 61 层、1.04T total、32.6B active、384 routed experts/top-8、1 shared expert、64 heads。与 V3 相比：总参数更大、激活参数略小、experts 多 50%、attention heads 减半。

论文的小规模 scaling law 表明在 active experts 固定为 8 时，提高 total experts/sparsity 能降低 loss；最终选 sparsity 48。代价是更多专家分片、路由、all-to-all 和权重驻留。模型 FLOPs 节省必须由 MoonEP/训练并行等基础设施接住。

减少 attention heads 是长 context 成本决策。论文估算 128K 下从 64 加到 128 heads 会使 inference FLOPs 增加约 83%，而小规模 validation loss 只改善约 0.5%–1.2%。

## 六、预训练与系统

K2 在 H800 cluster 上训练 15.5T tokens，先 4096 context，末期 anneal 并扩到 32K/128K。并行组合包括 pipeline、expert、tensor 等，且要求能适应节点数量变化。

“zero loss spike”描述最终 run，不包含所有研究试验，也不证明训练全程没有其他性能或数据问题。

## 七、agentic data 与 RL

系统生成工具定义、agent、任务和可验证 trajectories。可执行任务使用 verifier reward；开放问答/写作通过 rubric 让模型做 pairwise critique，再训练 critic/reward。

自我批评扩展了 reward 覆盖，但存在自偏好与共同盲点：同一模型家族生成、评审、训练时，错误可能闭环强化。人写 rubric、外部 verifier 和 held-out 人评仍不可少。

## 八、1T total / 32B active 应怎样理解

- 计算：每 token 主要走 8 个 routed experts + shared expert，接近 32B active 的 FFN 工作量。
- 存储：所有 1.04T 权重仍要在集群中可访问。
- 通信：token 要发送到被选 expert 所在设备，并把结果 combine。
- serving：小 batch/低延迟可能更受 all-to-all 和权重带宽影响。

因此不要把 K2 叫“32B 模型”；更准确是“1T total、约 32B active 的 MoE”。

## 九、开放性

Base/Instruct checkpoints 与代码公开，是 Kimi 系列中比 k1.5 更可复现的一步。但训练数据、完整预训练/RL pipeline 和生产基础设施未全部开放；许可证是 Modified MIT，应读原文附加条款。
