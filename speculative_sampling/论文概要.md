## 基本信息

- 题目：*Accelerating Large Language Model Decoding with Speculative Sampling*
- 作者：Charlie Chen、Sebastian Borgeaud、Geoffrey Irving 等
- 时间：2023
- 主题：Speculative Sampling、分布式 LLM 解码、modified rejection sampling
- 本地资料：[论文 PDF](paper.pdf) · [可检索文本](paper.txt)

## 一句话结论

一个为低延迟专门设计的 4B draft model 可以先提出短 continuation，Chinchilla 70B 再并行打分并用修正拒绝采样保持目标分布；在 batch size 1 的 XSum 和 HumanEval 上，论文把 14.1 ms/token 降到 7.0–7.52 与 5.73 ms/token，约 1.9–2.46 倍加速。

## 与普通解码的差异

普通解码每轮只从 target $q$ 采一个 token。Speculative Sampling 用 draft $p$ 先产生 $K$ 个 token，target 一次计算 $K+1$ 个位置；每个草稿以 $\min(1,q/p)$ 接受，拒绝时从 $[q-p]_+$ 采样修正。算法保证在硬件数值误差范围内恢复 target distribution。

## 硬件论证

- 小 batch 线性层受权重带宽限制，多算几个 token 未必同比增加时延。
- decode attention 主要搬运既有 KV cache，短 continuation 使缓存大小基本不变。
- 张量并行 all-reduce 对小激活常是 latency-bound，$K$ 较小时消息变大成本有限。

因此“一次打分多个位置接近一次打分一个位置”是加速前提，不是算法恒等式。

## 主结果

| 任务与采样 | 普通解码 | 推测采样 | 加速 |
|---|---:|---:|---:|
| XSum nucleus | 14.1 ms/token | 7.52 ms/token | 1.92× |
| XSum greedy | 14.1 ms/token | 7.00 ms/token | 2.01× |
| HumanEval nucleus | 14.1 ms/token | 5.73 ms/token | 2.46× |

下游 ROUGE-2 与 HumanEval 指标在统计波动内相当。代码模板使 HumanEval 更容易被 draft 猜中，所以接受率与加速更高。

## 边界

- 实验是 16 TPU v4、batch 1、Chinchilla 70B 和专门训练的宽浅 4B draft；拓扑改变会改变结论。
- $K$ 增大后草稿开销、后段拒绝和 tail latency 方差增加，XSum nucleus 最优约在 $K=3$。
- 分布相同不表示固定随机种子的序列逐 bit 相同。
