# MegaBlocks 论文概要

## 基本信息

- 题目：*MegaBlocks: Efficient Sparse Training with Mixture-of-Experts*
- 作者：Trevor Gale、Deepak Narayanan、Cliff Young、Matei Zaharia
- 会议：MLSys 2023
- 原文：https://proceedings.mlsys.org/paper_files/paper/2023/hash/5a54f79333768effe7e8927bcccffe40-Abstract-mlsys2023.html
- 主题：dropless MoE、block-sparse GEMM、GPU kernel

## 一句话结论

MegaBlocks 不用固定 expert capacity 把动态路由“削平”，而把每个 expert 的不等长 token batch 编码成 block-sparse matrix，用定制 SDD/DSD kernels 直接计算，从而同时避免 token dropping 和 padding 浪费。

## 核心方法

- 将 tokens 按 expert 排序。
- 用 block-sparse matrix 表示动态 assignment。
- 第一层 expert GEMM 是 sampled dense-dense（SDD），第二层及反向包含 dense-sparse-dense（DSD）等模式。
- 使用适合转置遍历的 blocked-CSR-COO 元数据。
- 定制 CUDA kernels，令稀疏 block 足够大以使用 Tensor Core，同时保持动态负载灵活性。

## 主要结果

- 相对 Tutel 的 dropless padding 方案，MoE-XS/Small/Medium 端到端训练分别加速 1.38×、2.0×、4.35×。
- 相对 dense Megatron-LM，在达到相同 validation loss 时训练时间降低 1.8×–2.4×。
- 即使为 Tutel 调优 capacity factor，MegaBlocks 达到相同 loss 仍快 1.18×–1.38×。
- 核心 block-sparse kernels 在训练形状上平均达到 cuBLAS batched GEMM 吞吐的 98.6%。

## 局限

- 结果基于 8×A100、64 experts、训练 workload；不同 GPU、expert 数和 inference shape 需重测。
- block sparsity 仍有元数据、排序、permutation 与 kernel launch 成本。
- 小 token/expert 或极端偏斜时，block 利用率可能差。
- “dropless”消除 capacity dropping，但不消除 router collapse 和 all-to-all。

## 阅读价值

MegaBlocks 把 MoE 的模型质量问题和 kernel 形状问题连起来：固定 capacity 不是纯系统细节，它会改变 token 是否参与计算；block-sparse kernel 让算法不必为了规则 batched GEMM 而牺牲语义。
