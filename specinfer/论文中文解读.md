## 1. 从单链 draft 到 token tree

基础 speculative decoding 每轮只有一条草稿链。若 draft 与 target 在某位置分歧，后续所有 token 都失效。SpecInfer 的思路是同时猜多种后继，把候选序列按共同前缀合并成 token tree。target 一次看整棵树，任一分支命中就能前进。

这不是 beam search。Beam search 用 target 自身维持多个高概率输出，目标通常是寻找高分序列；SpecInfer 用便宜 SSM 提案、target 只做并行验证，目标是减少昂贵 target 的串行迭代，同时保持原模型的 greedy 结果或采样分布。

## 2. Token tree 怎样构造

论文称小草稿模型为 Small Speculative Model（SSM）。有两条构树路径：

- **Expansion**：单个 SSM 在指定深度展开 top candidates，使一条链变为多分支。
- **Merging**：多个以不同数据或目标微调的 SSM 各自产生序列，再按公共前缀合并。

树中每个根到节点路径是一条候选 continuation。共享前缀只存一次；相比把 $b$ 条长度 $d$ 的序列分别送入 target，树能避免重复计算公共部分，并提升候选对 target 输出的覆盖率。

## 3. Tree-based parallel decoding 的关键 mask

把树节点按某种顺序压成一维 token 数组后，普通 causal mask 会错误地让不同分支互相注意。SpecInfer 构造 topology-aware causal mask：节点 $v$ 只能关注原 prefix 与从根到 $v$ 的祖先，不能看到兄弟或其他分支。

$$
M_{ij}=\begin{cases}
0,&j\in\operatorname{Ancestors}(i)\cup\text{prefix},\\
-\infty,&\text{otherwise}.
\end{cases}
$$

这样 target 对每个节点计算的 logits 与单独运行对应序列一致，却能在一个 forward/kernel 中批量完成。位置编码也必须按树深度而非压平下标设置，否则共享前缀后的分支位置会错。

## 4. Greedy 与 stochastic 验证

Greedy 情况下，从根开始检查 target 的 argmax 是否出现在子节点中；若命中就沿该节点继续，直到找不到匹配，再由 target 产生下一个 token。多分支提高了命中概率。

随机采样不能简单“看 sampled target token 是否在树里”，否则树覆盖方式会改变概率。论文提出 multi-step speculative sampling（MSS）与 VerifyStochastic，对树节点概率做顺序校正，并证明保留 target 分布。这里的精确保证依赖完整算法；任何为了速度放宽接受条件的实现都不能自动继承证明。

## 5. Runtime 设计

一次迭代包含：request manager 组织 batch；SSM 在 GPU spare capacity 上构树；LLM worker 运行 tree verification；verification kernel 选出接受路径并更新 KV cache。系统按 iteration 而非整请求调度，便于多个请求同步推进。

内存开销包括 SSM 权重、树节点激活和额外 KV。论文指出对于巨大 LLM，SSM 很小；但多个 SSM 与宽树在资源紧张场景仍不可忽略。Offloading 场景收益特别大，因为每减少一次 target step，就减少一次从 CPU DRAM 到 GPU HBM 的大模型参数传输。

## 6. 端到端证据

论文总结：分布式 LLM inference 相对已有系统加速 1.5–2.8×；OPT-13B/30B 在单张 24GB A10 做 model offloading 时，相对 FlexGen 每 token latency 改善 2.6–3.5×。后者幅度更大符合系统机理：瓶颈是重复搬 target 权重，多接受一个 token 就可能少一次大规模传输。

树宽消融使用 LLaMA-7B target 与 LLaMA-68M SSM、深度 8：

| Alpaca | 宽度 1 | 宽度 5 |
|---|---:|---:|
| Greedy 平均每轮验证 token | 2.95 | 3.43 |
| Stochastic 平均每轮验证 token | 1.79 | 2.38 |

树宽提高 acceptance length，但端到端最优不必是最宽。batch 1–2 有闲置并行资源，宽树几乎不增加 iteration latency；batch $\ge4$ 时验证资源竞争，宽 2–3 常取得更好平衡。

Tree-based decoding 相比把各分支拆成多序列，在小 batch 接近，在大 batch 最高快 1.8×。收益来自公共前缀的 attention 复用和把整树 attention 融成单 kernel。

## 7. 证据边界与失败模式

- 树覆盖仍由 SSM 决定；target 的正确 token 从未出现在子节点时，本轮只能前进一格。
- 多 SSM 若高度相关，候选数量增加但有效多样性不增。
- 宽树提高验证 FLOPs、显存和 mask/kernel 复杂度，大 batch 时可能负收益。
- 论文实验系统、硬件、模型和基线版本固定；“相对系统加速”不可直接与另一平台的 vanilla PyTorch 比。
- Greedy quality preserving 与 stochastic distribution preserving 是两种不同保证，复现时要分别验证。

## 8. 与 Medusa/EAGLE 的演进关系

SpecInfer 解决“怎样并行验证一棵候选树”，但候选仍来自独立 SSM。Medusa 把候选器缩成目标模型顶部的多个 head，降低 draft 管理成本；EAGLE 用 target 中间特征训练轻量自回归 draft；EAGLE-2 再依据每个上下文的置信度动态改变树形。树 attention 和共享前缀验证成为后续多候选方法的基础设施。

## 9. 复现检查表

- 检查 tree mask：每个节点只能访问祖先，并正确设置 position id。
- 报树深、树宽、节点总数，而不是只报“候选条数”。
- 分开测 SSM 构树、target verify、KV 更新和 scheduler 开销。
- 报 acceptance length 与 latency；前者硬件无关但不包含 draft 成本。
- batch、context、offloading/驻留设置必须与基线一致。
- stochastic 模式用大样本验证分布，不把 greedy 一致性替代采样正确性。
