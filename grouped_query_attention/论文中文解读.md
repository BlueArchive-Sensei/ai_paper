# 论文中文解读：《GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints》

> **基本信息**：Joshua Ainslie、James Lee-Thorp、Michiel de Jong（共同一作；de Jong 隶属 University of Southern California，工作完成于 Google Research）、Yury Zemlyanskiy、Federico Lebrón、Sumit Sanghai（Google Research），arXiv:2305.13245（本地 PDF 为 v3，2023 年 12 月）；论文原文 [官方页面](https://arxiv.org/abs/2305.13245)。
>
> **本文的读法**：图均为从论文 PDF 裁下的原图，表为逐格核对后的中文转录（数字与原文一致，表头译成中文，模型名、数据集名保持英文）。每张图后有中文图题、图中文字翻译和读图结论。凡属笔者的推导、核算或判断，都标明“笔者”。读完不必再翻英文版。

## 一、一句话结论

自回归解码的瓶颈是每一步都要从内存里读取模型权重和**全部**注意力的 key、value。Multi-query attention（MQA，只用一组 key/value 头）能大幅降低 K/V 的读取量，但会损失质量、让训练不稳定，而且为了推理速度专门再训练一个模型并不划算。这篇论文做了两件事：

1. **Uptraining 配方**：把已有的多头注意力（MHA）模型检查点，通过把各头的 K/V 投影矩阵**求平均**（mean pooling）合并，再用原始预训练 5% 的计算量继续训练，就得到 MQA 模型；
2. **Grouped-query attention（GQA）**：把 query 头分成 $G$ 组，每组共享一对 K/V 头，是 MHA（$G=H$）与 MQA（$G=1$）之间的插值。

在 T5-XXL 上，5% uptraining 得到的 GQA-8 平均质量 47.1，接近 MHA-XXL 的 47.2，而每个样本的推理时间 0.28（表 1 单位 s）只比 MQA 的 0.24 略高，远低于 MHA-XXL 的 1.51。

## 二、背景与动机

### 2.1 解码为什么受带宽限制

自回归解码时，每生成一个 token，模型都要把所有解码器权重和此前所有位置的 K、V 加载进来做一次很小的计算。这时瓶颈是内存带宽，而不是算力（Shazeer 2019；Pope 等 2022；de Jong 等 2022）。Shazeer 的 MQA 用多个 query 头但单个 key、value 头，使 K/V 的加载量锐减，细节见 [MQA 解读](../multi_query_attention/论文中文解读.md)。

### 2.2 MQA 的问题

- 质量可能下降，训练可能不稳定（附录 A，见 5.5 节）；
- 为推理速度单独训练一个模型往往不可行；
- 虽然已有语言模型使用了 MQA（如 PaLM），很多公开模型没有，包括 T5 和 LLaMA。

所以论文问：能不能把**已有的** MHA 检查点转成快速的模型，并且让质量损失比 MQA 更小？

### 2.3 为什么大模型更需要 GQA（论文的论证）

- 从 MHA 到 MQA 把 $H$ 个 K/V 头减为 1 个，K/V 缓存及需要加载的数据量降低 $H$ 倍。但大模型通常按比例增加头数，所以对大模型而言 MQA 是对内存带宽和容量**更激进**的削减；GQA 能让带宽和容量的下降比例随模型变大保持不变。
- 大模型受注意力访存开销的影响相对较小：KV 缓存随模型维度增长，而模型的 FLOPs 和参数随维度的平方增长。
- 大模型的标准并行切分会把单个 K/V 头复制到每个模型分区上（Pope 等 2022），造成浪费；GQA 去除了这种浪费。
- 因此论文预期 GQA 对更大的模型是特别好的折中。

## 三、方法

### 3.1 Uptraining：把 MHA 检查点转成 MQA（第 2.1 节，图 1）

分两步：先转换检查点，再继续预训练，让模型适应新的结构。

![图 1：从多头注意力到多查询注意力的检查点转换示意](rendered_figures/fig1-mha-to-mqa-conversion.png)

*图 1（原文 Figure 1，第 1 页）：转换示意——把所有头的 key（和 value）投影矩阵做平均池化，合并成一个头。*

**图中文字翻译与读法**：

- **左侧**：$H$ 个 Key Projection（key 投影矩阵）$K_1,K_2,\dots,K_H$，每个矩阵的宽是 $d_{\text{model}}$、高是 $d_h$（每个头的维度），省略号表示中间的头；
- **中间**：Mean Pool（平均池化）；
- **右侧**：合并得到的单个 Key Projection $K_{\text{MQ}}$，大小同样是 $d_h\times d_{\text{model}}$；
- **读图结论**：图中只画了 key，value 的投影矩阵做同样的处理；被平均的是**投影矩阵（权重）**，不是推理时缓存下来的 K/V 激活。论文说这样做优于“只挑其中一个头”和“重新随机初始化 K/V 头”（见 5.3 节的图 4）。

转换后，在**原始预训练配方**上用原始训练步数的一小部分 $\alpha$ 继续预训练。

### 3.2 Grouped-query attention（第 2.2 节，图 2）

GQA 把 $H$ 个 query 头分成 $G$ 组，每组共享**一个** key 头和**一个** value 头。GQA-$G$ 表示 $G$ 组：GQA-1 只有一组，等价于 MQA；GQA-$H$ 每组一个 query 头，等价于 MHA。从多头检查点转成 GQA 检查点时，每个组的 key、value 头由**该组内所有原始头的投影矩阵求平均**得到。

![图 2：多头、分组查询与多查询注意力的结构对比](rendered_figures/fig2-grouped-query-overview.png)

*图 2（原文 Figure 2，第 2 页）：三种注意力。多头注意力有 $H$ 个 query、key、value 头；多查询注意力让所有 query 头共享单个 key、value 头；分组查询注意力让每一组 query 头共享一个 key、value 头，在两者之间插值。*

**图中文字翻译与读法**：

- **左 Multi-head（多头）**：Queries（查询，蓝色）、Keys（键，红色）、Values（值，橙色）各 8 个，一对一连接；
- **中 Grouped-query（分组查询，图中加粗）**：8 个 query 头分成 4 组，每组 2 个 query 共享 1 个 key 和 1 个 value，共 4 对 K/V；
- **右 Multi-query（多查询）**：8 个 query 全部连到同一个 key 和同一个 value；
- **读图结论**：图中取 $H=8$、$G=4$ 作示意；K/V 头数（缓存大小）依次是 8、4、1，query 头数始终是 8。

笔者补充数学写法。设第 $i$ 个头的 key 投影矩阵为 $W^K_i$，value 投影矩阵为 $W^V_i$，第 $g$ 组包含头集合 $\mathcal{S}_g$（每组 $H/G$ 个头），则转换时

$$
\bar W^{K}_{g}=\frac{G}{H}\sum_{i\in\mathcal{S}_g}W^{K}_{i},\qquad
\bar W^{V}_{g}=\frac{G}{H}\sum_{i\in\mathcal{S}_g}W^{V}_{i},
$$

第 $i$ 个 query 头在计算注意力时使用它所属的组 $g(i)$ 的 $\bar W^{K}_{g(i)}$、$\bar W^{V}_{g(i)}$；query 投影与输出投影不变。$G=1$ 是对全部 $H$ 个头求平均，$G=H$ 则不做任何改变。

**平均权重等价于平均各头的 key、value 向量**（笔者推导）：key 是输入 $x$ 的线性函数，$x\bar W^{K}_{g}=\frac{G}{H}\sum_{i\in\mathcal{S}_g}xW^{K}_{i}$，也就是说转换后的组 key 恰好是该组各头原来的 key 的平均，value 同理。所以如果同组各头的 key（value）本来就相同，转换前后的注意力精确相等；各头差异越大，近似越粗，因此需要后面的 uptraining 来适应。这也解释了论文对图 4 的说法：结果的好坏顺序对应“从预训练模型中保留了多少信息”。论文没有说明哪些头被分在同一组（通常按相邻头编号分组，这是笔者的常见做法推测，论文未写）。

**K/V 缓存大小**（笔者）：每个位置每层缓存的元素数为 $2\times(\text{K/V 头数})\times d_h$，MHA 的 K/V 头数是 $H$，GQA-$G$ 是 $G$，MQA 是 1。因此 GQA-$G$ 的缓存是 MHA 的 $G/H$，要加载的数据同样按这个比例下降。图 6 的横轴到 64 并且 $G=64$ 时曲线回到 MHA 的位置，说明论文用的 T5-XXL 有 $H=64$ 个头（笔者由图推断，正文未直接写明），那么 GQA-8 的缓存是 MHA 的 $1/8$，MQA 是 $1/64$。

**不用于 encoder**：GQA 只用在 decoder 的自注意力和 cross-attention，**不**用于 encoder 的自注意力，因为 encoder 表示是并行算出的，内存带宽通常不是主要瓶颈。

## 四、实验设置

- **模型**：全部基于 T5.1.1 架构（Raffel 等 2020），用 JAX、Flax 和 Flaxformer 实现。主实验是 T5 Large 与 XXL 的多头版本，以及用 MQA 和 GQA 做了 uptraining 的 T5 XXL；优化器为 Adafactor，超参数与学习率计划同 T5；
- **Uptraining**：从公开的 T5.1.1 检查点初始化，把 K、V 头平均池化成相应的 MQA 或 GQA 结构，然后在原始预训练数据和设置上继续预训练原始预训练步数的 $\alpha$ 倍；$\alpha=0.05$ 时训练约需 **600 个 TPUv3 chip-days**；
- **数据与指标**：摘要任务 CNN/Daily Mail、arXiv、PubMed、MediaSum、Multi-News（指标 ROUGE-1，下表写作 $R_1$）；翻译任务 WMT 2014 英译德（BLEU）；问答任务 TriviaQA（F1）。论文没有评估 GLUE 这类分类基准，因为自回归推理对它们不太适用；
- **微调**：所有任务统一用常数学习率 0.001，batch size 128，dropout 0.1；CNN/Daily Mail 和 WMT 的输入长 512、输出长 256；其他摘要数据集输入长 2048、输出长 512；TriviaQA 输入长 2048、输出长 32；训练到收敛，选开发集成绩最高的检查点；推理用贪心解码；
- **计时**：报告每个样本、每块 TPUv4 芯片的时间（用 xprof 测量）；计时实验用 8 块 TPU，每块的 batch 尽量大、最多 32，并行方式对每个模型分别优化；
- **消融实验**用任务子集：CNN/Daily Mail（短文摘要）、MultiNews（长文摘要）、TriviaQA（问答）。

### 5.5 附录 A：训练稳定性

论文发现 MQA 在微调时可能训练不稳定，尤其配合长输入任务时。作者从头训练了多个带 MQA 的 T5-Large：每一个在预训练中都频繁出现损失尖峰，最终模型在长输入任务上微调时立刻发散。Uptraining 得到的 MQA 模型更稳定，但方差依然很大，所以对不稳定的任务，MQA 的结果报告的是三次微调运行的平均。Uptraining 得到的 GQA 模型看起来稳定，因此作者没有进一步调查 MQA 不稳定的根源。

## 六、相关工作（第 4 节要点）

- Shazeer（2019）最先提出 MQA；后续工作表明 MQA 对长输入尤其有帮助（Pope 等 2022；de Jong 等 2022）；Rabe（2023）独立提出了 GQA 并给出公开实现；其他把注意力头分组以提高计算效率的工作（Park 等 2020；Luo 等 2022；Ni 等 2023）并不专门针对决定内存带宽开销的 key、value 头；
- 其他降低 K/V 访存的办法：FlashAttention（避免显式生成二次方大小的注意力分数，节省内存、加速训练）、量化（降低权重和激活包括 K/V 的精度）、模型蒸馏（缩小模型）、layer-sparse cross-attention（去掉大部分 cross-attention 层）、投机采样（用小模型提出多个 token、大模型并行打分）；
- Uptraining 的思路受 Komatsuzaki 等（2022，sparse upcycling：把稠密 T5 检查点转成稀疏激活的 Mixture-of-Experts）启发。

## 七、局限、证据边界与常见误读

**论文自己承认的局限**：

1. 只关注 K/V 加载造成的内存带宽开销，这在生成较长序列时最重要，而长序列的质量本来就难评估；摘要任务用的 ROUGE 是有缺陷的指标，所以难以确定这些折中一定正确；
2. 由于算力有限，没有把 XXL 的 GQA 模型与从头训练的同类模型比较，所以不知道 uptraining 与从头训练的相对表现；
3. 只在 encoder-decoder 模型上评估了 uptraining 与 GQA。decoder-only 模型没有单独的自注意力和 cross-attention，论文预期 GQA 对 MQA 的优势在其上会更强（这是预期，不是结果）。

**笔者补充的证据边界**：

- 没有预训练困惑度，也没有 decoder-only 或更大规模（几十亿参数以上的 decoder-only）的实验；
- 质量差异很小（GQA-8 与 MHA-XXL 逐任务相差在 $\pm0.3$ 内），而论文没有给出多次运行的方差；
- 速度来自 TPUv4 和各模型分别优化过的并行设置，不能直接外推到 GPU 上的实现或不同的 batch、序列长度；
- 论文评估的是开发集。

**常见误读**：

- GQA 不减少 query 头数，也不改变注意力 $O(T^2)$ 的计算：它只缩小 K/V 的参数和缓存；
- mean pooling 只是把**权重**平均作为初始化，推理时并不是对缓存做平均，之后还要 uptrain 来适应；
- “GQA 被大量模型采用”是论文之外的事实，原论文的实验只有 T5。

## 八、复现检查清单

- 明确 query 头到 K/V 组的映射（哪些头在同一组）并固定 reshape 的顺序；
- 转换检查点时，分别对 K 的投影和 V 的投影按组求平均，不要把不同的权重维度混在一起；query 投影和输出投影保持不变；
- 记录 $\alpha$ 和 uptraining 所需的计算（论文中 $\alpha=0.05$ 约 600 TPUv3 chip-days），并计入转换成本；
- 评估时分开报告质量与速度（若可能，把 prefill 与逐步解码分开），注明 batch、输入输出长度、硬件，并报告 KV 缓存的字节数；不要只看一个 $G$ 的点，因为论文只测了组数对速度的影响；
- GQA 只用于 decoder 的自注意力与 cross-attention，不用于 encoder 自注意力。
