## 一句话结论

现代 PyTorch 不是从“动态图”切换成一张永久静态图，而是在 Python eager 语义上捕获带适用条件的图版本：Dynamo 产生 FX graph、residual bytecode 与 guards；torch.compile 允许 graph break，torch.export 则要求可独立部署的完整图。

## 四个关键对象

| 对象 | 何时产生 | 主要用途 |
| --- | --- | --- |
| autograd graph | 每次 eager forward | reverse-mode backward |
| FX graph | symbolic trace 或 Dynamo capture | 分析、变换、compiler frontend |
| compiled graph version | guard 条件下缓存 | JIT 加速与复用 |
| ExportedProgram | export 时捕获 | AOT、序列化、跨 Python runtime 部署 |

## 核心概念

- Graph break：停止当前区域捕获，运行普通 Python，再继续捕获下一段。
- Guard：图版本成立所需的类型、dtype、device、shape、对象身份或 Python 状态条件。
- Recompilation：现有版本的 guards 均失败时重新 trace/compile。
- Specialization：把某个值或 shape 条件固定进图，以换取更强优化。
- Symbolic shape：用符号表达可变维度，并传播约束。
- Backed symbol：有 example input 提供的 concrete hint；unbacked symbol 的具体值依赖运行时数据。
- Functionalization：把 mutation/alias 语义规范化成更适合编译的函数式形式。

## compile 与 export

- torch.compile 是 JIT、允许 partial graph 和 eager fallback。
- torch.export 目标是脱离 Python 的 full graph；无法 graph break。
- export 中静态值会 constant fold 或 specialize；动态数据相关控制流通常需显式使用 torch.cond 等 higher-order op。
- dynamic shape specification 必须足以推出捕获路径所需 guards。

## 主要局限

- 这是 main 分支快照，API 和默认行为会继续变化。
- dynamic 不等于“完全不专门化”；shape 分支仍可能产生多个图。
- 强制 dynamic=True 可能增加编译时间并损害 kernel 质量，官方文档更推荐有针对性的 annotation。
