## 基本信息

- 题目：*Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters*
- 作者：Charlie Snell、Jaehoon Lee、Kelvin Xu、Aviral Kumar
- 时间：2024
- 主题：test-time compute、PRM 搜索、顺序修订、并行采样、自适应预算
- 本地资料：[论文 PDF](paper.pdf) · [可检索文本](paper.txt)

## 一句话结论

推理算力并非“多采样就行”：简单题更可能从顺序修订受益，难题更需要并行探索或 PRM 搜索，最难题甚至几乎不随现有推理策略改善；按模型视角下的题目难度选择策略，可用约四分之一预算超过统一 best-of-$N$，但 test-time compute 不能在所有场景一比一替代预训练。

## 统一视角

论文把方法拆成两个旋钮：

- **改 proposal distribution**：让模型基于前一答案顺序 critique/revise，改变后续候选分布。
- **改 verifier/search**：保持候选模型，用 PRM 对完整答案或中间步骤评分，再做 best-of-$N$、beam 或 lookahead 搜索。

给定问题 $q$、预算 $N$ 和策略超参数 $\theta$，compute-optimal policy 选择使正确概率最大的 $\theta$。实践中作者按 base model 的 pass@1 将题分为五档，再在验证集为每档选择策略。

## 核心证据

- PRM search：小预算时 beam search 较有效，预算增大后多样性不足；best-of-$N$ 在更大预算下更稳。
- Revision：简单题适合把预算用于同一路径的连续修订；难题需要并行尝试不同高层方案。
- 按难度选并行/顺序比例后，64 份预算可超过统一 best-of-256，约提高 4 倍预算效率。
- FLOPs 匹配下，小模型加推理算力在其能力范围内的题上可胜过参数量约大 14 倍的模型；能力范围外的难题或推理请求量很高时，预训练扩模更划算。

## 必须保留的限定

- 实验集中在 MATH 和专门微调过 revision/verification 能力的 PaLM 2 模型。
- oracle 难度需要 2048 个样本和真值；model-predicted 难度也有非小额估计成本。
- 与 14 倍大模型的 FLOPs 比较依赖训练 token、预计推理 token 比值，不能只引用“14×”而省略工作负载假设。
- hard bin 收益很小，恰好反驳“只要让模型想得更久就必然更强”。

## 演进位置

这篇论文把 CoT、Self-Consistency、ToT、PRM 搜索统一成“proposal + verifier + compute allocation”，并把 test-time scaling 从单一算法问题推进为按样本决策的资源调度问题。
