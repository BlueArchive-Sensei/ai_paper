## 1. 论文真正问的不是“多算有没有用”

早期 test-time scaling 常把预算直接变成 $N$ 条独立答案，再用多数票或 verifier 选一个。本文追问更细的问题：同样有 $N$ 份推理预算，究竟应该横向探索更多答案、纵向修订一条答案，还是在步骤树上搜索？这个选择是否应随问题改变？

答案是：没有统一最优策略。预算、题目对当前模型的难度、proposal 的质量和 verifier 的误差共同决定收益。论文最大的贡献不是某条新搜索算法，而是把策略选择定义为 sample-adaptive compute allocation。

## 2. Proposal 与 verifier 的二维分解

给定问题 $q$，基础语言模型形成 proposal distribution。增加测试时计算有两条正交路径：

1. **改变 proposal**：把已有回答、批评或修订历史加入输入，使下一次生成条件分布发生变化。本文训练 revision model，让它顺序改进前一答案。
2. **优化 verifier/search**：从原 proposal 取候选，用 ORM/PRM 评价。PRM 提供步骤分数，可支持 beam 与 lookahead，而不只是在完整答案结束后 best-of-$N$。

这套分解能解释前序论文：Self-Consistency 是固定 proposal + 频数 verifier；ToT 是 prompt proposal + prompt evaluator + search；PRM 是训练得到的密集 verifier。

## 3. Compute-optimal 的数学定义

令 $\operatorname{Target}(\theta,N,q)$ 表示在预算 $N$ 下，使用策略参数 $\theta$ 得到的输出分布。理想策略为：

$$
\theta^*_{q,y^*(q)}(N)=\arg\max_\theta
\mathbb E_{y\sim\operatorname{Target}(\theta,N,q)}
\left[\mathbf1\{y=y^*(q)\}\right].
$$

这个定义使用真答案 $y^*$，部署时不可直接求。论文用“对 base model 有多难”作充分统计量近似：先估计每题 pass@1，将题分成五个难度 quantile；验证集上为每档、每预算选最优策略，测试集复用。

Oracle difficulty 用每题 2048 个样本和真值计算 pass@1，只适合分析。Predicted difficulty 用 verifier 的平均最终分数估难度，不需要真答案，但仍消耗许多候选和评分计算。论文没有解决“零额外成本准确判难度”，而是证明即使粗分桶也有收益。

## 4. PRM 搜索：更复杂不总更好

作者比较 PRM best-of-$N$、beam search 与多步 lookahead。直觉上，步骤级评分应让搜索尽早把算力集中到好前缀；但 verifier 并不完美，beam 还会丢失多样性。

- 低预算时，beam 能用局部评分快速聚焦，常优于盲目完整采样。
- 预算变大后，过早剪枝让候选同质化，错误 PRM 还会反复强化错误前缀；best-of-$N$ 的广泛探索反而更稳。
- 不同难度的交叉点不同，所以不能只选一条全局曲线。

这解释了为什么“更聪明的搜索”未必单调支配简单 sampling：搜索效率来自偏置，偏置在 evaluator 错误时也会成为风险。

## 5. 顺序修订与并行采样的分工

Revision model 读到原答案并生成修订版。若初始解法大致正确，连续 revision 能修复算术、格式或局部逻辑，复用已有进展；若问题超出能力范围，模型往往沿同一错误高层思路打转，此时独立重采样更可能发现另一条路线。

论文把总预算拆成并行样本数与每样本的顺序修订深度。实验观察：

- easy bin 更适合几乎纯顺序计算；
- medium/hard 往往需要并行与顺序的混合；
- 最难问题中各种现有策略收益都小。

按难度选比例后，compute-optimal 策略在高预算区仍继续改善，而统一 parallel best-of-$N$ 更早平台。原文给出的代表结论是：64 预算可以超过 best-of-256，即预算效率最高约 4 倍。这里的“4×”是特定模型、任务和策略集合的比较，不是所有推理系统的恒定倍数。

## 6. 预训练计算与推理计算怎样比较

论文用常见近似：

$$
X_{\text{pretrain}}\approx6ND_{\text{pretrain}},\qquad
Y_{\text{inference}}\approx2ND_{\text{inference}},
$$

其中 $N$ 为参数量，$D$ 为 token 数。把模型参数扩大 $M$ 倍，会同时扩大训练和每次推理 FLOPs；若保留小模型，则可把同样总预算用于更多推理计算。结论由比值

$$
R=\frac{D_{\text{inference}}}{D_{\text{pretrain}}}
$$

强烈决定。$R\ll1$ 时，部署请求相对训练少，可为每题花很多额外推理算力；$R\gg1$ 时，每个请求重复支付推理成本，扩展预训练/模型能力可能更划算。

在与参数量约大 14 倍的模型比较时，小模型 + compute-optimal inference 在 easy/medium 问题和低推理负载下经常胜出；难题或高推理负载下，大模型更好。标题中的“can be more effective”必须连同这个条件读，不能改写成“推理算力比参数更有效”。

## 7. 实验依赖与局限

- 任务只覆盖数学推理 MATH，答案可自动判定；开放世界事实和长程 agent 任务未验证。
- PaLM 2 模型为 revision 与 verification 做了专门微调，普通聊天模型未必能通过提示获得同等能力。
- 难度分桶使用大量样本；真正在线系统还需解决先探索多少、何时停止、如何遵守延迟 SLO。
- 策略集合有限，没有联合实验 PRM tree search + revision，也未覆盖工具调用、代码执行等方法。
- 最难题几乎没有收益，表明 test-time compute 只能重排或改善基础能力附近的概率质量，不能凭空创造缺失知识和算法。

## 8. 工程含义

一个实用 reasoning service 不应给所有请求相同“thinking budget”。更合理的控制器要观察置信度、候选分歧、PRM 分数与剩余时延，在 parallel exploration、sequential refinement 和停止之间切换。指标也应从 accuracy 扩展为 accuracy–FLOPs–latency–throughput 的 Pareto 前沿。

这与 speculative decoding 形成互补：本文决定“为了更正确要生成/搜索多少”，speculative decoding 决定“在不改目标分布时怎样更快生成这些 token”。前者通常增加算法工作量，后者尝试降低单位 token 的墙钟成本。

## 9. 复现检查表

- 报告 base model pass@1，并按模型特定难度分桶，而非只用数据集人工等级。
- 将 difficulty-estimation 的样本与 verifier 成本计入总预算。
- 对齐生成 token、target-model forward FLOPs 和 wall-clock；“样本数”不是完整成本。
- 分开报告 oracle 与 predicted difficulty，不能混用。
- 用同预算的 parallel、sequential、mixed、PRM search 做基线。
- FLOPs 交换实验必须写明 $D_{\text{pretrain}}$、$D_{\text{inference}}$、参数倍率和服务请求假设。
