## 一句话结论

TensorRT-LLM 不是单个“编译器”或“kernel 库”，而是由 LLM API、每 rank 的 PyExecutor、Scheduler、KVCacheManager、ModelEngine、Sampler、专用 kernels 和多 GPU runtime 组成的推理栈；性能来自 kernel、图执行、内存管理和请求调度的组合。

## 主执行循环

1. LLM API 完成模型加载、tokenize/detokenize。
2. 每个 rank 创建 PyExecutor worker。
3. Scheduler 选择本轮可运行请求。
4. KVCacheManager 分配/回收 KV blocks。
5. ModelEngine 执行 forward。
6. Sampler 产生 token，结果返回或进入下一轮。

## 关键优化

- CUDA Graph：减少 host launch overhead；不匹配的 batch 可 pad 到已捕获 shape。
- Overlap Scheduler：GPU 执行 step $n+1$ 时，CPU 处理 step $n$ 结果。
- Paged KV cache、continuous/in-flight batching。
- attention、GEMM、MoE、quantization 等专用 kernels。
- tensor/expert parallel、disaggregated serving 和 speculative decoding。

## 阅读边界

- 文档对应持续演进的 main 分支，不是固定论文版本。
- 任何性能数字都必须绑定 release、GPU、模型、精度、batch、输入/输出长度和 benchmark mode。
- TensorRT-LLM 与 Triton Inference Server 不同：前者是 LLM execution/runtime library，后者是可承载不同 backend 的 serving server。
