## 1. EAGLE 对 Medusa 的诊断

Medusa 从同一个当前 hidden state 并行预测多个未来 token。距离越远，离散分布越多峰，而且第 $t+2$ 个 token 真实依赖第 $t+1$ 个采样结果；不做自回归条件化就会有结构性不确定性。传统独立 draft model 有条件依赖，但运行完整 Transformer 成本又高。

EAGLE 的折中是：复用 target 已算出的高层 feature，只训练一个轻量 autoregression head 在 feature 空间逐步预测。feature 连续、包含丰富语义，比直接猜离散 token 更平滑；但 feature 也有一个关键的一对多问题，必须由 shifted token 解决。

## 2. 为什么“只预测 feature”仍不够

设 target 倒数第二层 feature 为 $f_t$，LM head 从 $f_t$ 得到分布并采样 $x_{t+1}$。同一个 $f_t$ 在随机采样下可产生不同 $x_{t+1}$；而下一 feature $f_{t+1}$ 又取决于实际 token $x_{t+1}$。若 draft 只输入 $f_t$，它不知道随机分支走向，预测的 $f_{t+1}$ 相当于混合多个未来。

EAGLE 把 token 序列前移一位：预测下一 feature 时同时输入当前/前一 target feature 与已经采出的实际 token embedding。概念上：

$$
\hat f_{t+1}=D_\phi(f_t, e(x_{t+1})),
$$

再通过原 target LM head 从 $\hat f_{t+1}$ 产生下一 token。这个 token-shift 不增加一个完整模型，却恢复了自回归中的随机条件。

## 3. Draft–verify 流程

1. Target 对当前 prefix 正常前向，得到高层 feature 与 token 分布。
2. 采样 token，将其 embedding 与 feature 输入 EAGLE AR head。
3. AR head 连续外推 feature；原 LM head 把预测 feature 转为 token 候选。
4. 多轮和 top candidates 组成一棵固定 token tree。
5. Target 用 tree attention 一次验证所有节点。
6. Exact rejection sampling 接受与校正，因此最终文本仍服从 target 分布。

EAGLE 的 feature 可以错，因为 target 最终裁决；feature 质量只影响 acceptance length 和速度。

## 4. 为什么平均接受长度比单报 speedup 更有用

论文使用两个主指标：实际 walltime speedup，以及平均接受长度 $\tau$——每轮 draft–verify 最终前进的 token 数。$\tau$ 更接近算法质量、较少依赖硬件；speedup 还受 AR head、target kernel、batch、量化和通信影响。

例如 LLaMA2-Chat 13B、温度 0：HumanEval 3.76× / $\tau=4.52$，GSM8K 3.20× / 4.03，Alpaca 3.01× / 3.83。温度 1 时对应加速降至约 2.66–2.89×，因为采样分布更宽，draft 与 target 更难一致。

## 5. 核心实验结论

论文覆盖 Vicuna 7B/13B/33B、LLaMA2-Chat 7B/13B/70B，以及对话、代码、数学和指令任务。温度 0 下常见 speedup 约 2.8–3.8×；摘要对 70B 总结为 2.7–3.5×并称吞吐翻倍。HumanEval 往往最高，因为代码模板可预测性强。

与独立小模型 speculative sampling 比较时，Vicuna 13B 使用 7B draft 几乎没有收益：draft 太贵。EAGLE 轻量 head 即使 acceptance 接近，也能因更低 $c$ 获得更好端到端速度。这再次说明优化目标不是单独最大化 acceptance。

## 6. 三组关键消融

### 6.1 Tree attention

相对链式草稿，树使 Vicuna/LLaMA2 系列 $\tau$ 增加约 0.62–0.75；速度增量约 0.3–0.5×。树增加每次验证 token，所以 acceptance length 增幅不会一比一变成速度增幅。

### 6.2 Draft 输入

作者比较 token-only、feature-only、feature + unshifted token、feature + shifted token。结果链条是：feature autoregression 比 token 更容易；加入离散 token 有助于抑制 feature error accumulation；真正最大提升来自把 token 前移一位，使 draft 知道上一步随机采样结果。这个消融直接支撑标题中的 “feature uncertainty”。

### 6.3 训练数据

用 target 自生成答案训练，LLaMA2-Chat 7B 的速度从固定 ShareGPT 数据 2.78× 小幅到 2.88×，$\tau$ 从 3.62 到 3.75。收益有限，说明方法不必付出昂贵 target data generation 才能工作，但不表示所有域都对训练数据不敏感。

## 7. MoE 为什么只加速 1.5×

Mixtral 8x7B Instruct 上 $\tau=3.25$，实际仅 1.50×。MoE 普通 decode 每 token 只读被路由的少数 experts；验证树的多个 token 可能命中更多不同 experts，导致额外权重读取，打破稠密模型“多 token 近似只读一次全部权重”的优势。这是算法指标与硬件路径分离的典型例子：接受多个 token 不保证等比例墙钟收益。

## 8. 与编译/量化优化的组合

EAGLE 与 gpt-fast 组合时，LLaMA2-Chat 7B 在 RTX 3090 的 FP16 从 vanilla 24.5 tokens/s，经 gpt-fast 到 55.1，再到 100.2；int4 的 gpt-fast 为 106.9，叠加 EAGLE 为 160.4。论文用它说明 speculative decoding 与量化、编译互补，但组合收益不是简单相乘，因为瓶颈会转移。

## 9. 局限与复现检查

- 每个 target checkpoint 都需适配/训练 AR head，target 更新会带来维护成本。
- 报告 $\tau$、draft latency 与 verify latency，不能只报最好 speedup。
- 区分 temperature 0 与 stochastic sampling；后者必须保留 exact correction。
- 测试 batch、context、任务与 MoE expert traffic；稠密模型结果不可直接外推 MoE。
- 检查 target feature 层选择、token shift 对齐和训练数据域。
- Tree attention 的 mask、position id 与 KV 更新须逐路径对照普通 forward。
