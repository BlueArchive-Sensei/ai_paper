## 1. 固定树浪费在哪里

EAGLE 与 Medusa 通常离线选一棵固定树：根附近分支多、深层分支少，所有请求复用同样结构。它隐含假设接受率只由深度决定。但同一深度在不同上下文可能完全不同：固定代码模板中 top-1 极确定，应把节点用于向深处扩展；开放式对话的多个词都合理，应在浅层多分支。

EAGLE-2 的核心不是训练更强 draft，而是根据当前请求的概率分布在线分配相同节点预算。它利用 EAGLE draft 的 confidence 与真实 acceptance rate 近似校准，因此可以把“哪个节点最值得扩展”转成可计算优先级。

## 2. Confidence、acceptance 与 value

单节点 confidence 是 draft 给该 token 的条件概率。实验把大量节点按 confidence 分桶，发现平均 target 接受率随 confidence 单调增加且误差较小。这不是说二者完全相等，而是足以做排序信号。

一个深层节点只有在全部祖先被接受后才可能被访问。因此不能只看本节点 confidence $c(v)$，而要用路径联合 value：

$$
V(v)=\prod_{u\in\operatorname{path(root\rightarrow v)}}c(u).
$$

只按局部 confidence 会高估“自身很确定、但祖先很危险”的深节点；乘积把被访问概率计入。

## 3. 两阶段动态构树

### 3.1 Expansion

从根开始，维护当前候选/叶节点。每轮选择 value 最高的节点，用 EAGLE AR head 扩展其子节点。高置信路径会继续变深，分布平坦处则多个浅分支竞争。扩展阶段的目标是探索潜在有价值节点。

### 3.2 Reranking

扩展顺序不保证最终节点集合全局最优：早期为到达深节点而生成的某些中间候选可能价值低，而未继续扩展的浅节点价值更高。因此生成足够候选后，对所有节点按 value 重排，在固定节点预算内选出最终 draft tree，同时保证祖先闭包。

最后仍用 EAGLE tree attention 和 exact speculative sampling 验证。动态树只是提案分布/形状，不改变接受校正，所以保持 target 输出分布且不需要重新训练 EAGLE head。

## 4. 读懂主结果

表 1 在 Vicuna、LLaMA2-Chat 和 MT-Bench、HumanEval、GSM8K、Alpaca、CNN/DM、Natural Questions 上比较。以 Vicuna-13B、温度 0 为例：

| 方法 | 平均 speedup | 平均接受长度 $\tau$ |
|---|---:|---:|
| Standard speculative sampling | 1.88× | 2.18 |
| Medusa | 2.07× | 2.44 |
| Hydra | 2.69× | 3.40 |
| EAGLE | 2.95× | 3.82 |
| EAGLE-2 | 4.04× | 4.65 |

同一 target、任务和硬件下的相对结果最有意义。EAGLE-2 一轮约前进 4–5.5 token，约为 standard/Medusa 的两倍。LLaMA2-Chat 70B 的 MT-Bench 从 EAGLE 3.01× 增至 3.51×；LLaMA3-Instruct 70B 为 2.83× 到 3.29×。

正式 EMNLP 页面把结果概括为最高约 5×、约 EAGLE 的 1.3×；arXiv 摘要的早期表述为 3.05–4.26×、比 EAGLE 快 20%–40%。两者版本/汇总口径不同，仓库保留这一差异而不强行合成单一数字。

## 5. 温度、任务与训练数据影响

温度 1 时分布更平，EAGLE-2 仍领先但 speedup 下降。例如 Vicuna-13B 平均 3.65×，低于温度 0 的 4.04×。代码 HumanEval 常最高，因为模板重复且 draft 易预测。

Natural Questions 和 CNN/DM 的 $\tau$ 较低。作者指出 EAGLE 系列 draft 主要用 SFT 数据训练，而世界知识更多来自 pretraining、摘要在 SFT 中比例也低；standard speculative draft 若经过预训练，域覆盖可能更好。这说明轻量 head 的低成本与知识覆盖存在取舍。

## 6. 消融怎样证明两个阶段有用

Vicuna-7B、温度 0：

| 设置 | MT-Bench speedup / $\tau$ | GSM8K speedup / $\tau$ |
|---|---:|---:|
| 无 value、无 reranking | 2.81× / 3.92 | 2.85× / 3.93 |
| 无 value | 3.21× / 4.39 | 2.93× / 3.96 |
| 无 reranking | 3.48× / 4.86 | 3.50× / 4.85 |
| 完整 EAGLE-2 | 3.62× / 4.98 | 3.63× / 4.97 |

Value 比局部 confidence 更好，说明祖先联合概率重要；reranking 进一步回收扩展过程中的全局次优节点。完整方法提升不是单纯“生成更多节点”，因为最终验证节点预算受控。

## 7. 为什么动态算法仍是 lossless

“根据 draft confidence 选择候选”可能改变候选树，但 target 对每个实际接受 token 仍执行标准验证/校正。只要 exact acceptance 完整实现，提案可以是任何函数，最终分布仍由 target 决定。Confidence 不准会让正确候选覆盖率下降、速度变慢，却不会直接改变质量。

若实现为提高速度而采用 relaxed/typical acceptance，lossless 结论便不再自动成立。动态树与接受规则是两个独立维度。

## 8. 系统局限

- 在线 priority expansion 与 reranking 有 CPU/GPU 控制开销；节点数小时尤其不能忽略。
- 校准关系可能随 target、量化、temperature、领域漂移，需要监测。
- 固定节点预算只控制 verify work，draft expansion 实际生成过的候选也应计成本。
- Batch 1 latency 最优树不等于高 batch throughput 最优树；并行资源已经占满时，多验证 token 更贵。
- 与其他工作比较要统一实现。表中部分方法在非贪心下采用 relaxed acceptance，论文因此没有把它们与严格 lossless 结果混排。

## 9. 复现检查表

- 先画 confidence–acceptance calibration curve，并按任务/温度分层。
- Value 必须包含祖先概率；注意 log-domain 累加避免深路径下溢。
- 分别记录 expansion 生成节点数、最终 verify 节点数、reranking 时间。
- 保证选中节点满足祖先闭包，tree mask 与 position id 正确。
- 报 speedup 与 $\tau$，并附 batch、context、硬件、kernel 和 target 版本。
- 用 exact acceptance 单独验证分布；relaxed 模式另报质量变化。
