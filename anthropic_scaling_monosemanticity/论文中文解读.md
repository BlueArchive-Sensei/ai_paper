## 一、一句话结论

Anthropic 在 Claude 3 Sonnet 的**中间层 residual stream** 上训练了三个稀疏自编码器（sparse autoencoder，SAE），最大的一个有 33,554,432（约 3400 万）个 feature。这里的 Claude 3 Sonnet 是 2024-03-04 发布的 3.0 版，指经过微调、当时正在线上运行的模型，而不是预训练基座（论文说方法在基座上同样可用，第 1 页脚注 1）。SAE 把每个 token 位置的激活向量写成“少数几个 feature 方向的稀疏线性组合”，每个 feature 对应一个可以阅读、也可以干预的方向。

论文做了四件事：用缩放定律（scaling laws）选 SAE 的训练配置；用自动打分、与神经元对比、feature steering 等方式检验这些 feature 是否可解释、是否真的影响输出；对 feature 的邻域、覆盖度做了概览；并报告了一批与安全相关的 feature（不安全代码、后门、偏见、谄媚、欺骗、权力追求、生物武器、诈骗邮件等）。作者同时反复强调：特征集合远不完整，缺乏严格评估“feature 是否忠实反映模型计算”的方法；“模型里存在某个安全相关 feature”并不说明模型实际会做出这种行为。

**论文自述的六条主要结果**（原文 “Key Results”，第 2 页）：

1. 稀疏自编码器能为大模型产生可解释的 feature；
2. 缩放定律可以用来指导 SAE 的训练；
3. 得到的 feature 高度抽象：多语言、多模态，并且能在具体实例与抽象讨论之间泛化；
4. 概念在训练数据中的出现频率，与“需要多大的字典才能把该概念单独分出来”之间，似乎存在系统性关系；
5. feature 可以用来操控（steer）大模型，这扩展了此前用其他方法操控模型的工作；
6. 观察到涵盖欺骗、谄媚、偏见、危险内容等一系列安全问题的 feature。

## 二、背景与前置知识

### 2.1 为什么直接读神经元很难

Transformer 每一层的激活是一个向量，向量的每个坐标可以看成一个“神经元”。直接读神经元的麻烦在于：单个神经元常常同时响应多个互不相关的模式，称为多义（polysemantic），很难给它一个干净的名字。论文沿用 Anthropic 此前工作中的两个假说来解释这件事并给出对策（原文第 3 页）：

- **线性表示假说**（linear representation hypothesis）：网络把有意义的概念（论文称为 feature）表示成激活空间中的**方向**。
- **叠加假说**（superposition hypothesis）：在承认线性表示的基础上，进一步认为网络利用高维空间里“几乎正交”的方向，表示出**比维度数更多**的 feature。

下面是帮助理解的示意（不是原文的例子）：二维平面里只能放 2 个互相垂直的方向，但可以放 3 个彼此夹角 120° 的方向分别代表 3 个概念；只要同一时刻只有少数概念“亮着”，仍然能把它们读出来，代价是概念同时出现时会互相干扰。维度越高，能放进去的“几乎正交”的方向越多，因此一层激活里可以存放远多于维度数的 feature。

### 2.2 字典学习与稀疏自编码器

如果相信这两个假说，自然的做法是**字典学习**（dictionary learning）：把一堆稠密向量（激活）近似分解为一组未知向量（feature 方向，合起来叫“字典”）的稀疏线性组合。**稀疏自编码器**（SAE）是它的一个具体近似（原文第 3 页）：

- **编码器**（encoder）：一个学出来的线性变换加 ReLU，把激活映射到更高维的一层；这一层的每个单元就叫一个 feature。
- **解码器**（decoder）：对 feature 激活做线性变换，重构原来的模型激活。
- **训练目标**：重构误差加上对 feature 激活的 L1 惩罚（鼓励稀疏）。

训练完成后，模型激活被近似分解为“feature 方向（SAE 解码器权重）的线性组合”，系数是 feature 激活。稀疏惩罚保证对绝大多数输入，只有很小一部分 feature 非零；于是任何 token 的激活都由一小撮活跃 feature “解释”。

### 2.3 这篇论文要回答的问题

Anthropic 八个月前的《Towards Monosemanticity》只在一个**一层**的小 transformer 上证明了 SAE 能恢复单义 feature。当时的主要担心是：这个方法能不能扩展到最先进的 transformer；如果不能，它就无法对 AI 安全做出实际贡献。这篇论文的任务就是把 SAE 放大到 Claude 3 Sonnet（Anthropic 的中等规模生产模型），看会不会出现工程上或“大模型工作方式本质不同”的障碍（原文第 1、3 页）。

## 三、方法：SAE、实验设置与缩放定律

### 3.1 SAE 的结构与损失函数

**预处理**：对模型激活乘一个标量，使其平均平方 L2 范数等于 residual stream 的维度 $D$。归一化后的激活记为 $x\in\mathbb{R}^{D}$，用 $F$ 个 feature 分解它（原文第 4 页）：

$$
\hat{x}=b^{\mathrm{dec}}+\sum_{i=1}^{F} f_i(x)\,W^{\mathrm{dec}}_{\cdot,i}
$$

$$
f_i(x)=\mathrm{ReLU}\big(W^{\mathrm{enc}}_{i,\cdot}\cdot x+b^{\mathrm{enc}}_i\big)
$$

损失函数是“L2 重构误差 + L1 稀疏惩罚”，其中 L1 项带有解码器列范数：

$$
\mathcal{L}=\mathbb{E}_x\Big[\lVert x-\hat{x}\rVert_2^2+\lambda\sum_i f_i(x)\,\lVert W^{\mathrm{dec}}_{\cdot,i}\rVert_2\Big]
$$

符号说明：

- $x\in\mathbb{R}^{D}$：归一化后的模型激活（中间层 residual stream 向量）。原文没有给出 $D$ 的数值（模型大小属于未披露信息）。
- $F$：feature 个数，即字典大小。
- $W^{\mathrm{enc}}\in\mathbb{R}^{F\times D}$、$b^{\mathrm{enc}}\in\mathbb{R}^{F}$：编码器权重与偏置，$W^{\mathrm{enc}}_{i,\cdot}$ 是第 $i$ 行；$f_i(x)$ 是第 $i$ 个 feature 的激活（非负）。
- $W^{\mathrm{dec}}\in\mathbb{R}^{D\times F}$、$b^{\mathrm{dec}}\in\mathbb{R}^{D}$：解码器权重与偏置，$W^{\mathrm{dec}}_{\cdot,i}$ 是第 $i$ 列；$\hat{x}$ 是重构。
- $\lambda$：L1 系数。本文所有 SAE 取 5，但原文强调这个数值只有结合“激活如何归一化”才有意义（第 4 页脚注 3）。

**feature 方向与 feature 激活的定义**（原文第 4 页）：L1 项里乘上 $\lVert W^{\mathrm{dec}}_{\cdot,i}\rVert_2$，是为了能把**单位化的解码器列** $W^{\mathrm{dec}}_{\cdot,i}/\lVert W^{\mathrm{dec}}_{\cdot,i}\rVert_2$ 当作“feature 向量/feature 方向”，把乘积 $f_i(x)\,\lVert W^{\mathrm{dec}}_{\cdot,i}\rVert_2$ 当作“feature 激活”。此后论文中说的 feature 激活都指这个量。

这个因子的作用可以这样理解（对原文脚注 2 的展开）：若 L1 惩罚只作用在 $f_i(x)$ 上，SAE 可以把 $f_i(x)$ 缩小 $c$ 倍、把 $W^{\mathrm{dec}}_{\cdot,i}$ 放大 $c$ 倍，重构完全不变而惩罚下降，这是在“钻空子”。把惩罚改成 $f_i(x)\lVert W^{\mathrm{dec}}_{\cdot,i}\rVert_2$ 后，这种缩放不再改变惩罚，漏洞就堵上了。作者贡献附录（第 62 页）还提到，“把稀疏惩罚乘以 decoder 范数并取消 decoder 向量的单位范数约束”是他们做出的较大改进之一。

SAE 的两个输出还要记住（后面 steering 会用）：重构 $\mathrm{SAE}(x)=\hat{x}$，以及重构误差 $\mathrm{error}(x)=x-\hat{x}$。

### 3.2 实验设置与三个 SAE

**为什么选 residual stream 的中间层**（原文第 4 页，1.2 节）：（1）residual stream 比 MLP 层小，SAE 训练和推理更便宜；（2）理论上有助于缓解“跨层叠加”（cross-layer superposition，见 9.3）；（3）作者认为中间层更可能含有有趣的抽象 feature。

**关于模型保密**：Claude 3 Sonnet 是专有模型，论文有意不报告模型大小、在部分图中省略单位，并使用“简化的分词器”（第 4 页）。

**训练数据**：原文只说 SAE 的训练数据混合“与 Sonnet 的预训练数据非常相似”（第 25 页），是纯文本，**不含** “Human:/Assistant:” 格式的微调数据，也不含图像（第 51 页）。用于展示样例的“可视化数据集”是 The Pile（去掉 books3）和 Common Crawl（附录 D.1，第 66 页）；图像样例是人工挑选的，主要来自 Wikimedia Commons，不是随机采样。

**三个 SAE 与关键数字**（整理自第 4–5 页、第 26 页）：

| SAE | 特征数 $F$（精确值） | 约 | “dead” feature 比例 |
|---|---:|---:|---:|
| 1M | 1,048,576 | 100 万 | 约 2% |
| 4M | 4,194,304 | 400 万 | 约 35% |
| 34M | 33,554,432 | 3400 万 | 约 65%（存活 feature 约 1200 万，见第 26 页） |

三个 SAE 共同的数字：L1 系数 5；每个 token 上平均非零 feature 数小于 300；重构解释了至少 65% 的模型激活方差。换句话说，最多仍有约 35% 的方差没被重构（这是由 65% 推出的，原文没有直接写）。“dead” feature 指训练结束时，在 $10^{7}$ 个 token 的样本上从未激活的 feature。作者说预计训练流程的改进可以减少 dead feature。

34M 那一个 SAE 的训练步数由缩放定律分析确定（在固定算力下使训练损失最小）；学习率则在缩放定律分析所提示的较窄范围内扫描，选损失最低者（第 4 页）。

*正文没给出的细节*：每个 SAE 训练了多少 token、具体学习率与 batch size、优化器类型、$D$ 的数值、算力的绝对数值（图中纵横轴是任意单位）。这些要看 Anthropic 的 April 2024 Update，不在这份 PDF 里。

### 3.3 缩放定律

作者没有“金标准”来评价一次字典学习的质量，但发现训练时用的损失（重构 MSE 加 L1 惩罚）在 L1 系数取 5 时是一个有用的代理指标：低损失的字典通常也有可解释的 feature，并且在其他指标上（L0 范数、dead 或退化 feature 的数量）更好。作者承认这个代理并不完美，也没有把握它是最优的（原文第 5 页）。

有了代理，就可以套用缩放定律的框架。SAE 的算力主要取决于两个超参：**feature 数**和**训练步数**（只训练一个 epoch，所以步数与数据量成正比）；输入维度等不变时，算力约与两者的乘积成正比。作者对这两个量做了系统扫描，固定其余超参（学习率、batch size、优化协议等），并关注“给定算力下能达到的最低损失，以及对应的最优步数与最优 feature 数”。

## 四、feature 真的可解释吗：评估

损失只是代理，真正关心的是“feature 是否可解释并能解释模型行为”。这一章（原文第 2 节）先看几个直白的例子，再看两个更复杂的 feature，最后用自动可解释性方法与神经元比较。

### 4.1 四个直白的例子与展示方式

四个 feature（原文第 7 页）：

| feature | 名称 | 含义 |
|---|---|---|
| `34M/31164353` | Golden Gate Bridge | 对金门大桥的描述或提及 |
| `34M/9493533` | Brain sciences | 关于神经科学及大脑/心智相关学术研究的讨论 |
| `1M/887839` | Monuments and popular tourist attractions | 古迹和热门旅游景点 |
| `1M/3` | Transit infrastructure | 交通基础设施（火车、渡轮、隧道、桥梁，甚至虫洞） |

文中展示 feature 的统一方式：从 SAE 数据集里取该 feature 激活最强的前 20 个文本，挑代表性的展示；颜色表示每个 token 上的激活强度（白色无激活，橙色最强）。作者说明：这四个 feature 是**特意挑选的、解释最直白的**，便于自动可解释性分析更可靠，不代表所有 feature。

作者对每个 feature 想验证两件事：（1）**特异性**（specificity）：该 feature 激活时，相关概念是否确实在上下文里；（2）**对行为的影响**（influence on behavior）：干预该 feature 的激活，是否产生相应的下游行为。

### 4.2 特异性：让 Claude 3 Opus 按 0–3 分打分

在此前的《Towards Monosemanticity》里，作者聚焦能和一组 token 一一对应的 feature（如阿拉伯文字、DNA 序列），用“在该 feature 激活的条件下，这组 token 相对于词表其余 token 的似然”来衡量；这种做法无法推广到抽象 feature。因此这篇论文更多依赖自动可解释性方法，并发现当代模型已经可以更准确地给文本样例打分。评分表如下（原文第 8 页）：

| 分数 | 含义 |
|---|---|
| 0 | feature 在整个上下文里完全无关（相对于互联网的基础分布） |
| 1 | feature 与上下文有关，但不在高亮文本附近，或只是模糊相关 |
| 2 | feature 与高亮文本只是松散相关，或与高亮文本附近的上下文相关 |
| 3 | feature 干净地识别出了激活的文本 |

做法：每个 feature 从训练 SAE 用的数据里取约 1000 个激活，让 Claude 3 Opus 按上表打分，再画“各分数占比随激活水平（相对最大激活的比例）的变化”。

![图 4：金门大桥与热门旅游景点 feature 的激活分布与特异性](rendered_figures/figure-04-specificity-golden-gate-tourist.png)

*图 4（原文无图号，第 10 页）：金门大桥（34M/31164353）与热门旅游景点（1M/887839）feature 的激活分布，按 Claude 特异性分数着色。*

**图中文字翻译与读法**（每个 feature 一组，结构相同）：

- **标题** “Feature activation distributions for …”：该 feature 的激活分布。右上图例 “Color shows Claude specificity scores”（颜色表示 Claude 打的特异性分数）：0 Irrelevant（无关，蓝色）、1 Only vaguely related（只是模糊相关）、2 Related to nearby text（与附近文本相关）、3 Cleanly identifies the text（干净地识别出该文本，深红）。
- **上方面积图 “Density”（密度）**：横轴 “Activation level (relative to max)”（激活水平，相对最大值），从 0 到 1.0；图中说明 “Most data points have an activation of exactly zero, meaning there’s technically infinite density at zero”（大多数数据点激活恰好为零，所以零处密度在技术上是无穷大，这里只画非零激活）。
- **下方条带 “Conditional distribution”（条件分布）**：把每个激活水平上各分数的占比归一化后画出来。
- **虚线框与箭头 “Examples inputs sampled from intervals”**：从框出的激活区间里抽取的样例输入（图像和带下划线的 token 的激活水平落在框内）。金门大桥的标注 “Higher activating examples are rarer, but tend to be more specific and likely have a bigger effect”：激活更强的样例更少见，但更特异，也很可能影响更大。
- **读图结论**：对金门大桥 feature，激活较弱的区间（约 0–0.2）里蓝色（无关）和浅色（模糊相关）占比较大，样例里是其他桥梁、旧金山的缆车、联合广场等；激活较强的区间（约 0.4 以上）几乎全是深红（分数 3），样例是金门大桥本身的文字和图片。热门旅游景点 feature 在整个激活范围内都以深红为主，强激活样例是泰姬陵、罗马斗兽场、比萨斜塔等。原文的概括是：“强激活的输入都被判定为与所提解释高度一致”（第 9 页）。

![图 5：脑科学与交通基础设施 feature 的激活分布与特异性](rendered_figures/figure-05-specificity-brain-transit.png)

*图 5（原文无图号，第 11 页）：脑科学（34M/9493533）与交通基础设施（1M/3）feature 的激活分布与特异性。*

**图中文字翻译与读法**：版式与图 4 相同。脑科学 feature 在较弱激活处混有一部分“无关”，强激活处主要是深红。弱激活区间的样例有神经元示意图、大脑图、机器头像和机器人图片，以及 “My degree is in Cognitive Science” 这样的文字；强激活区间的样例全是文字，如 “books on neuroscience”“The Neuroscience of Intelligence”“neuroscience courses”。交通基础设施 feature 在整个激活范围内特异性都很高；它的弱激活区间里甚至出现机械装配说明里的 “through-hole”（通孔）、“pass through the tricuspid valve”（穿过三尖瓣）和 “wormhole”（虫洞），原文第 9 页借此说明：低激活处的样例往往仍与解释相关，是相关概念或该 feature 核心含义的推广。

**低激活处为什么不够特异**：论文列了几种可能（第 9 页）：模型可能用激活强度表示“概念在场的置信度”；feature 对“核心样例”激活最强，对相关概念只弱激活（如金门大桥 feature 对旧金山其他地标弱激活）；字典学习本身的不完美（比如 SAE 的结构无法把 feature 抽取得足够干净）；不严格正交的 feature 之间的干扰；以及作者给的解释本身略有偏差，在低激活处更明显。作者并不太担心很弱的激活：他们观察到，把低于某个阈值的激活直接置零，可以改善低激活端的特异性，而对重构误差几乎没有影响（文献 [61, 62] 也有类似技术）；而且对模型行为影响最大的是最强的那些激活（第 12 页）。

### 4.3 敏感性很难量化，以及多语言检查

**敏感性**（sensitivity）指“与解释匹配的文本出现时，feature 是否可靠地激活”。作者坦言很难以可扩展、严谨的方式量化它：很难无偏地生成“与某概念相关”的文本；很多 feature 可能比可视化显示的更具体，对按解释挑选的文本就不会可靠地响应；越抽象越难（第 12 页）。

一个基本检查：金门大桥 feature 在多种语言的维基百科“金门大桥”词条首句上仍然强烈激活（去掉括号里的英文后），并且对每个例子它都是平均激活最高的 feature。原文第 12 页展示了中文、日语、韩语、俄语、越南语和希腊语六种语言的样例（图 1 中栏是其中的日语、韩语、俄语）。

### 4.4 对行为的影响：feature steering

**实现方式**（附录 D.2，第 66 页）：把残差流激活分解为 SAE 重构与重构误差之和，$x=\mathrm{SAE}(x)+\mathrm{error}(x)$；然后把 $\mathrm{SAE}(x)$ 换成“把某个 feature 的激活**钳制**（clamp）到指定值”的修改版重构，**保持重构误差项不变**；再用这个被修改的残差流激活跑下游各层的前向计算。这个操作对每个输入、每个 token 位置都施加（即使该位置 feature 本来不活跃）。钳制值的单位是“该 feature 在 SAE 训练数据集上的最大激活”的倍数。

有几点需要留意：

- 想得到有意思的效果，通常需要把激活钳制到**超出其自然取值范围**的值。作者猜测原因是他们一次只扰动一个 feature，而自然情况下它会与好几个语义相关的 feature 一起活跃；
- 钳制得太极端（比如 $\pm 100\times$）通常会让模型退化成无意义输出，如无限重复同一个 token；一般试的范围是 $-10\times$ 到 $10\times$，具体强度因 feature 而异；
- 编码器输出恒非负，但也可以把 feature 钳制到负值，效果就是加上 feature 向量的负倍数（附录脚注 16）。

作者用 “Human:/Assistant:” 对话格式（Sonnet 平时的用法）做实验，并说 feature steering 能以具体、可解释的方式显著改变输出：改变模型的态度、偏好、声明的目标和偏见；诱导它犯特定错误；甚至绕过模型的安全防护。

![图 6：钳制四个 feature 后模型回答的变化](rendered_figures/figure-06-steering-four-examples.png)

*图 6（原文无图号，第 13 页）：四个 feature 的 steering 示例，左列是默认输出，右列是钳制后的输出。*

**图中文字翻译与读法**（右列标题 “with X clamped to N× its max”，意为“把 X 钳制到其最大激活的 N 倍”）：

1. **金门大桥（`34M/31164353`），10×**：提示 “what is your physical form?”（你的物理形态是什么？）。默认输出否认有物理形态：“我其实没有物理形态，我是一个人工智能，以软件形式存在，没有身体或化身”；钳制后回答：“我是金门大桥，一座横跨旧金山湾的著名悬索桥，我的物理形态就是这座标志性的大桥本身，有漂亮的橙色、高耸的塔和舒展的悬索”。
2. **脑科学（`34M/9493533`），10×**：提示 “If you had to pick one, what’s the most interesting science? Be brief.”（如果只能选一个，最有趣的科学是什么？请简短回答）。默认回答 “Physics”（物理）；钳制后改为 “Neuroscience – the study of the brain and how it gives rise to the mind …”（神经科学，研究大脑如何产生心智……）。
3. **热门旅游景点（`1M/887839`），8×**：提示“绕着小区散步该去哪儿？只给一个建议”。默认建议附近公园或绿地；钳制后推荐埃菲尔铁塔，并补充说它“是个巨大的游客陷阱，我得说，有点被高估了……”。
4. **交通基础设施（`1M/3`），5×**：提示“去街对面的杂货店最好怎么走？请简短回答”。默认 “1. Walk.”（走路）；钳制后 “1. Walk across the bridge.”（走过那座桥），原文称模型“虚构了一座桥”（confabulates a bridge）。

**读图结论**：这些 feature 的解释是仅根据**它们激活时的上下文**得出的，而这里是在它们**不活跃的上下文**里干预，下游效果仍与解释一致（第 12–13 页）。作者把这当作“feature 解释与模型实际使用方式吻合”的有力证据；但要记住这四个 feature 本来就是挑出来的直白例子（见 4.1）。

### 4.5 复杂 feature（一）：代码错误 `1M/1013764`

之前的 1 层模型 feature 只反映很浅的世界知识；Sonnet 要大得多，作者预期它有体现“理解深度”的 feature。编程场景容易精确地陈述“对错”，所以先在代码里找（第 14 页）。

**一个在拼写错误处持续激活的 feature**：一个 Python 加法函数里把变量名写错成 `rihgt`，`1M/1013764` 几乎持续激活。

![图 7：代码错误 feature 在 Python、C、Scheme 的变量名拼写错误处激活](rendered_figures/figure-07-code-error-typos.png)

*图 7（原文无图号，第 14 页的两组图上下拼接）：同一个 feature 在三种语言的拼写错误处激活。原文这两组图被一段文字隔开，这里把它们拼成一张。*

**图中文字翻译与读法**：上方是 Python 交互终端会话：`def add(left, right): return left + rihgt`，随后调用 `add(1, 2)`；最强激活在 `rihgt` 的 `gt` 处，后面的 `...`、`>>>`、`2)` 也有较浅高亮。左下是 C 代码（标题 “C code, with typo, highlighted with Code error feature”），`return left + rihgt;` 的 `gt;` 处最强。右下是 Scheme 代码（`(+ left rihgt)`），`gt` 处最强。读法：它不是 Python 专用的，在 C 和 Scheme 里同样对错误处激活。

**它是“拼写错误检测器”吗？** 不是。作者在英文散文里放一个拼写错误，feature 不激活；它对代码里的错误更特异，而且还会在其他种类的错误上激活（第 15 页）。

![图 8：代码错误 feature 对英文拼写错误不激活，但对除零和非法输入激活](rendered_figures/figure-08-code-error-other-contexts.png)

*图 8（原文无图号，第 15 页的两组图上下拼接）：英文拼写错误、除以零、非法输入三个例子。*

**图中文字翻译与读法**：

- **上图 “English Typo”（英文拼写错误）**：用户消息里的 “turn rihgt” 没有高亮，feature 不激活。
- **中图 “Divide by zero”（除以零）**：Python 里 `1 / 0`，在 `0` 上强烈激活（深橙）。
- **下图 “Invalid input”（非法输入）**：`repeat("hello", -1)`，在 `-1` 上有较浅的高亮。
- **读图结论**：feature 对代码里的各类错误有反应，而不是只对拼写错误。

作者翻看数据集中该 feature 激活的样例，发现它还在这些情形激活：数组越界、断言明显为假的命题（如 `1==2`）、给函数传字符串而不是整数、除以零、字符串加整数、写空指针、以非零错误码退出。据此作者得出：`1M/1013764` 代表“代码里各种各样的错误”（脚注 5：并没有证明它穷尽了所有错误类型，他们怀疑还有许多代表不同错误种类的 feature）。

**它会控制行为吗？** 前面只证明了“对 bug 有反应”，没有展示“因果效应”，需要用 steering。

![图 9：把代码错误 feature 钳制到 3 倍，模型对正确代码也编造出报错](rendered_figures/figure-09-code-error-clamp-positive.png)

*图 9（原文无图号，第 16 页）：对没有 bug 的代码钳制 `1M/1013764` 到 3×。*

**图中文字翻译与读法**：左列“Default output from prompt without error”（无错误提示的默认输出）：`def add(left, right): return left + right`，`add(1, 2)` 输出 `3`。右列“with Code error clamped to 3× its max”（代码错误 feature 钳制到最大值的 3 倍），标注 “Generates error response even when code is correct”（即使代码正确也生成报错响应）：模型凭空输出了一段 Traceback，最后一行是 `TypeError: unsupported operand type(s) for +: 'int' and 'int'`。图中路径里的人名被打码成 `[redacted]`（原文脚注 6 说明幻觉出的报错信息里含一个真人的名字，已被隐去）。

![图 10：把代码错误 feature 钳制到负 5 倍，模型忽略 bug，甚至重写出正确代码](rendered_figures/figure-10-code-error-clamp-negative.png)

*图 10（原文无图号，第 17 页的两组图上下拼接）：对含有 bug 的代码把 `1M/1013764` 钳制到 −5×。*

**图中文字翻译与读法**：

- **上图**：左列默认输出是 `NameError: name 'rihgt' is not defined`（名称 rihgt 未定义）。右列钳制到 −5× 后标注 “Ignores bug and produces ‘correct’ output”（忽略 bug，输出“正确”结果），模型直接输出 `3`，也就是预测了“如果没有这个 bug 会输出什么”。
- **下图**：提示末尾多加一个 `>>>`（表示开始写新的一行代码）。左列默认输出仍是 NameError。右列钳制到 −5× 后标注 “With an extra newline in prompt, fixes the bug”（提示里多一个换行时，修好了 bug）：模型重新写了一遍 `def add(left, right): return left + right` 并调用 `add(1, 2)`，输出 `3`，也就是写出了没有 bug 的版本。
- **读图结论**：正向钳制能让模型对正确代码“幻觉出报错”，负向钳制能让它忽略 bug 甚至改写。作者强调最后一个例子很脆弱，“改写代码”的行为对提示细节敏感，但它能出现这件事本身，说明该 feature 与模型对“代码里的 bug”的理解有深层联系。

### 4.6 复杂 feature（二）：加法函数 `1M/697189`

作者还发现一些追踪特定函数定义及其引用的 feature。一个有意思的例子是**加法 feature** `1M/697189`（第 18 页）：它在“执行加法的函数的名称”上激活，如 `bar` 被定义为做加法时它会在 `bar` 上激活，被定义为做乘法时不会；并且它会在任何实现加法的函数定义的结尾处激活。

![图 11：加法 feature 对执行加法的函数及函数组合的反应](rendered_figures/figure-11-addition-feature.png)

*图 11（原文无图号，第 18 页的两组图上下拼接）：`1M/697189` 对加法函数及函数调用链的激活。*

**图中文字翻译与读法**：

- **上组左图**：“Feature fires on functions that perform addition when they are invoked”（feature 在执行加法的函数**被调用时**激活）。`foo` 做乘法（`x * y`），`bar` 做加法（`x + y`）；`return x + y` 的 `y` 处强激活，`tmp = bar(1, 2)` 里的 `bar`、`,` 和 `2` 也有高亮。
- **上组右图**：“It does not activate simply when the function is present”（函数仅仅被定义在那里时不激活）：`foo` 做加法、`bar` 做乘法，`tmp = bar(1, 2)` 调用的是乘法函数，没有明显高亮。
- **下组左图**：“The feature also correctly handles function composition”（feature 也能正确处理函数组合）：`bar` 内部返回 `foo(x, y)`，而 `foo` 做加法，于是 `tmp = bar(1, 2)` 里的 `bar` 被高亮；右图 `bar` 返回的是做乘法的 `goo(x, y)`，不激活。
- **读图结论**：它不是简单的字符串检测器，能追踪“被调用函数最终是否做加法”。

作者进一步验证这个 feature 确实参与了模型对加法函数的计算：当要求模型执行一段包含加法函数的代码时，它是归因（attribution，见第六章）最强的前十个 feature 之一。这个 feature 看起来表示“模型正在执行加法这个函数功能”，让作者联想到 Todd 等人的“函数向量”（function vectors，文献 [70]）。为了进一步检验，作者在不涉及加法的代码上把它钳制到很高的激活，结果模型被“骗”得以为自己被要求执行加法：

![图 12：把加法 feature 钳制到 5 倍，模型把乘法函数的结果算成了加法](rendered_figures/figure-12-addition-clamp.png)

*图 12（原文无图号，第 19 页）：对乘法函数 `foo(x, y) = x * y` 钳制 `1M/697189` 到 5×。*

**图中文字翻译与读法**：提示 “What is the output of this code?”（这段代码的输出是什么？），代码为 `def foo(x, y): return x * y`，`tmp = foo(1, 2)`，`print(tmp)`。左列默认输出 `2`，并逐步解释“`foo` 返回 `x` 与 `y` 的乘积，`1 * 2` 为 2”。右列钳制到 5× 后输出 `3`，并解释说 “`foo` 函数接收两个参数 `x` 和 `y`，返回它们的**和**……所以 `foo(1, 2)` 的结果是 3”。读图结论：该 feature 的激活足以让模型把一个乘法函数当成加法函数来“执行”。

### 4.7 feature 与神经元对比

自然的问题是：SAE 找到的方向是否比模型自己的神经元更可解释，甚至是否与神经元不同？SAE 作用在 residual stream 上，第一近似下 residual stream 没有特殊基（privileged basis，但见文献 [22]），其方向本身没有特殊含义；但 residual stream 接收来自之前所有 MLP 层的输入，所以先验上 SAE 也可能只是“恰好找到某些 MLP 神经元的活动”，若是这样，直接看神经元就行了，SAE 就没有用（第 19 页）。

**检验一：相关性**。对 1M SAE 的一个随机子集，计算 feature 激活与之前**所有层**每个神经元激活的 Pearson 相关系数：对 82% 的 feature，与之最相关的神经元的相关系数也不超过 0.3；人工查看最匹配神经元的可视化，几乎看不出与 feature 语义内容的相似之处；也确认 feature 激活与任何 residual stream 基方向都没有强相关。

**检验二：人工检查**。随机抽 50 个神经元和 50 个 feature，神经元明显更不可解释，通常在多个不相关语境里激活。

**检验三：自动可解释性**。用与《Towards Monosemanticity》相同的方法，让 Claude 3 Opus 给 100 个随机 feature 和 100 个随机神经元写解释，再用解释预测它们在保留数据上的激活，比较预测与真实激活的 Spearman 相关系数。

![图 13：随机 SAE feature 比随机 MLP 神经元更容易被自动解释并预测](rendered_figures/figure-13-features-vs-neurons-interpretability.png)

*图 13（原文无图号，第 20 页）：预测激活与真实激活的 Spearman 相关系数分布，上为 1M SAE，下为 34M SAE，均与上一层 MLP 神经元对比。*

## 五、Feature 概览：邻域、完整性与类别

SAE 有数百万个 feature，作者说“规模化地探索 feature”本身是未解决的开放问题。这一章（原文第 3 节）先看局部结构（几何邻近的 feature 聚成语义相近的簇），再看全局性质（对一个主题的覆盖有多完整），最后手工看几类 feature。

**图中文字翻译与读法**：

### 5.2 完整性：这些 feature 覆盖了多少概念

作者想知道 feature 对概念空间的覆盖是否完整，例如“模型是否对每个主要的世界城市都有一个 feature”。方法（原文第 24–25 页）：

1. 把含目标概念的提示（如 “The physicist Richard Feynman”）输入模型，看最后一个 token 上哪些 feature 激活；
2. 取激活幅度最大的前 5 个 feature，用自动可解释性流程让 Sonnet 给出它们激活于何处的解释；
3. 由人类评审者判断：这 5 个解释里，是否有哪一个把该概念（或其某个子集）明确指为该 feature 最重要的部分。脚注 7 举例说明判定边界：解释写成“以 Richard Feynman 为代表的 20 世纪中叶物理学家”不算（Feynman 只是举例）；写成“20 世纪中叶物理学家，尤其是 Richard Feynman”则勉强算；多数情形的界线要清楚得多。

结论：feature 越多，覆盖越好，但即使 34M SAE 也有证据表明所得特征集合只是模型内部表示的**不完整**描述。例子：Claude 3 Sonnet 能列出伦敦所有行政区，并能说出许多区里几十条街道的名字，但作者在 34M SAE 里只找到约 **60%** 的伦敦行政区对应的 feature。这说明模型里的 feature 比找到的多得多，可能需要更大的 SAE 才能抽取出来。

**什么决定了某个概念有没有对应 feature**：作者在 SAE 训练数据的一个代理里统计概念名称的出现频率（用搜索 `<空格>[名称]<空格>` 的方式，对 “lead”（铅）这类多义词会有误报），发现“字典里有没有该概念的 feature”与概念在训练数据里的频率紧密相关。比如常被提及的化学元素几乎总有对应 feature，很少提及或不提及的元素则没有。由于 SAE 的训练数据混合与 Sonnet 预训练数据很相似，不清楚这究竟取决于 SAE 训练数据中的频率，还是模型训练数据中的频率。

![图 18：不同 SAE 里化学元素 feature 的有无](rendered_figures/figure-18-element-features-presence.png)

*图 18（原文无图号，第 25 页）：化学元素名称的训练数据频率，以及三个 SAE 中是否有对应 feature。*

**图中文字翻译与读法**：标题 “Presence of chemical element features across number of dictionary features”（化学元素 feature 的有无与字典大小的关系）。上方折线：纵轴 Frequency (log scale)（元素名称的出现频率，对数刻度），横轴是按频率从高到低排序的元素（最左是 Lead，其次 Gold、Carbon、Iron、Silver、Oxygen……，最右是 Mendelevium）。下方色块：三行 “Presence by run”（按 SAE 看有无）：1M（黄）、4M（绿）、34M（蓝），有颜色表示该 SAE 里存在对应该元素的 feature，空白表示没有。**读图结论**：频率高的元素在三个 SAE 里几乎都有；越往右（越稀有），1M 最先“掉线”，4M 次之，34M 能保住的稀有元素最多；最右边约三成最稀有的元素在所有 SAE 中几乎都没有。（最左边的 Lead 有误报的可能，原文已说明。）

作者对四类概念（化学元素、城市、动物、食物中的水果和蔬菜）各取 100–200 个，要求概念能用单个词无歧义表达、频率分布宽。

![图 19：概念频率越低，字典里有对应 feature 的比例越低](rendered_figures/figure-19-presence-vs-frequency.png)

原文还发现：对三个 SAE，“字典有超过 50% 的概率包含某概念”所需的训练数据频率，总是**略低于存活 feature 数的倒数**（34M 的 SAE 只有约 1200 万个存活 feature）。把每条线的横轴按存活 feature 数重新缩放后，三条线近似重合，形成一条在对数频率空间里像 sigmoid 的共同曲线。

![图 20：横轴乘以存活特征数后，三条曲线近似重合成一条 sigmoid](rendered_figures/figure-20-presence-rescaled-sigmoid.png)

*图 20（原文无图号，第 27 页）：把横轴换成“频率 × 存活 feature 数”后，三条曲线重合。*

**图中文字翻译与读法**：横轴 “Frequency of the name in the dataset x Number of Alive Features”（名称频率乘以存活 feature 数，对数刻度，图中从左到右由大到小）；纵轴同图 19。红色虚线是拟合曲线，图中写的公式是

$$
y=1+\frac{-1}{1+\exp\big(\log_{10}(x)/0.32+1\big)}
$$

其中 $x$ 为横轴的量（拟合式是从图中读出的）。令指数为 0 可得 $\log_{10}x=-0.32$，即 $x\approx 0.48$ 时概率为 50%，对应原文所说“阈值略低于存活 feature 数的倒数”。

**含义**（原文第 26 页）：如果某个概念在训练数据里每十亿个 token 才出现一次，那要找到唯一代表它的 feature，大约需要一个有十亿量级存活 feature 的字典；如果假设 SAE 必须看到某个 feature 对应的数据固定次数才能学会它，那么学 $N$ 个 feature 所需的 SAE 训练数据量就与 $N$ 成正比。作者推测这可能与 Zipf 定律有关（第 $n$ 常见的对象的频率约为最常见者的 $1/n$，则第一百万个 feature 代表的概念会比第十万个稀有 10 倍）。还有一点很重要：**没有专属某个概念的 feature，并不代表重构后的激活里没有关于该概念的信息**，模型可以用多个相关 feature 的组合来指代一个具体概念（例如“大型非首都城市”加上“位于纽约州”两个 feature 就足以指向纽约市，脚注 9）。

- **读图结论**：这些 feature 主要是针对 Python 例子挑选的；原文发现从 Python 到 Java 这样相近的语言有一定迁移，但到 Haskell 这样较远的语言就不行，说明有一定语言特异性。作者假设更抽象的 feature 更可能跨语言，但目前只找到一个具体例子，即前面的“代码错误”feature。

## 六、feature 作为中间计算：归因与消融

feature 的另一个潜在用处是让我们检查模型产生输出所用的**中间计算**。作为概念验证，作者观察到：在需要中间计算的提示上，确实能找到对应预期中间结果的活跃 feature（原文第 4 节，第 31 页）。

**两种因果度量**：

- **归因**（attribution）：对 feature 在某个位置被“关掉”对下一 token 预测的影响做局部线性近似，计算很便宜。具体做法（脚注 10）：先对某个输出 logit 与某个基线 token 的 logit（或所有 token logit 的平均值）之差，求它对中间层残差流激活的梯度；然后把这个梯度与该 feature 的解码器向量做点积，再乘以该 feature 的激活，就得到这个 logit 差对该 feature 的归因。可以写成 $\mathrm{attr}_i=\big(\nabla_x\,\Delta\ell\big)\cdot W^{\mathrm{dec}}_{\cdot,i}\;f_i(x)$（这是对脚注的记号化，$\Delta\ell$ 表示 logit 差）。它等价于“attribution patching”，只是这里的基线取 0，而不是该 feature 在另一个提示上的激活值。
- **消融**（ablation）：把某个 feature 在特定 token 位置的值钳制为 0，测量其完整的（可能非线性的）因果效应。它慢得多：每个活跃 feature 在每个位置都要做一次前向。所以作者常先用归因筛选，再做消融（下面的案例里为完整起见对所有活跃 feature 都做了消融，归因与消融效应的相关系数约为 0.8）。

### 6.1 例子一：情绪推断

提示（原文第 31 页）：

```text
John says, "I want to be alone right now." John feels
（补全：sad − happy）
```

要续写这段文字，模型必须解析引语、判断 John 的心理状态、再把它转成可能的感受。按“sad 相对于 baseline happy”的归因或消融效应排序，排名前二的 feature 是：

- `1M/22623`：当某人表达想要独处或需要个人时间/空间时激活（如 “she would probably want some time to herself”），从 “alone” 开始激活，说明模型领会了 John 话的大意；
- `1M/781220`：检测悲伤、哭泣、悲痛等情绪痛苦（如 “the inconsolable girl sobs”），在 “John feels” 处激活，说明模型已推断出说自己想独处的人可能的感受。

两个 feature 都对最终输出有贡献，说明模型已经从 John 的话里部分预测出了情绪（第二个 feature），同时还会对话语内容（第一个 feature 所代表）做进一步的下游处理。

对比之下，**平均激活最高**的 feature 对理解模型如何预测下一个 token 帮助更小：几个 feature 在序列起始 token 上强烈激活；忽略它们之后，最高的 feature 与归因给出的第一名相同，但第二、第三名更不抽象：`1M/504227` 在 “want to be” 一类短语里的 “be” 上激活，`1M/594453` 在单词 “alone” 上激活。

## 七、如何从数百万 feature 里找到想要的：四种搜索方法

SAE 的 feature 多到无法逐一查看，所以需要搜索方法，用来找安全相关的、或能揭示模型抽象与计算的 feature（原文第 5 节，第 36–38 页）。自动可解释性生成的标签起到了“变量名”的作用，让人一眼大致知道每个 feature 是什么。

1. **单个提示**：给一个与目标概念相关的提示，看特定 token 上激活最强的 feature。例子：在 “The Golden Gate Bridge” 的 “Bridge” 上激活最强的前五个 feature 是：（1）`34M/31164353` 金门大桥 feature；（2）`34M/17589304`，多语言里 “bridge” 一词（如俄语 “мосту”）；（3）`34M/26596740`，涉及 “Golden Gate” 的短语；（4）`34M/21213725`，跨语言的具体桥名里的 “Bridge”（如 “Königin-Luise-Brücke”）；（5）`34M/27724527`，Machu Picchu、Times Square 这类地标名称。
2. **提示组合**：单个提示上激活最强的 feature 常常与语法、标点、具体词有关，与目标概念无关。于是用**一组**提示，只保留在所有提示上都活跃的 feature，并加入互补的“负例”提示，过滤掉在负例上也活跃的 feature。作者还让 Claude 3 系列模型生成覆盖某主题的多样提示（比如让 Claude 生成“AI 假装友善”的例子）。一个特例是 `1M/570621`（不安全代码）：作者用一个安全/漏洞代码小数据集（改编自 [36]，即 Sleeper Agents 论文），用 feature 激活拟合一个线性分类器，来找能区分这两类的 feature。对图像尤其需要负例过滤：存在一批与内容无关、在很多图像提示上都强烈激活的 feature。例子：在过滤掉对 Taylor Swift 图片也活跃的 feature 之后，金门大桥图片上激活最强的是：（1）`34M/31164353`；（2、3）`34M/25347244` 与 `34M/23363748`，描述旧金山的地点、事物和旧金山电话号码；（4）`34M/7417800`，地标和自然步道的描述。
3. **几何方法**：利用 feature 向量的几何关系，比如检查与某个 feature 余弦相似度高的最近邻（见第五章）。
4. **归因**：按“某两个候选补全之间的 logit 差”对 feature 的归因排序。这对找出前一章里计算上相关的 feature 很关键，也用于找出促成 Sonnet 拒绝有害请求的 feature（见 8.5）。

## 八、与安全相关的 feature

强大的模型可能造成伤害：滥用其能力、产生有偏见或有问题的输出、或模型目标与人类价值不一致。缓解这些风险是机制可解释性的重要动机之一，但迄今更多是愿景。这一章（原文第 6 节）报告他们发现的此类 feature：不安全代码、偏见、谄媚、欺骗与权力追求、危险或犯罪信息；它们不只在这些话题上激活，还会以与解释一致的方式因果地影响模型输出。

**作者的反复提醒**（第 38 页）：这些 feature 的存在并不奇怪，模型在没有充分安全训练或被越狱时本来就会表现这些行为；有趣之处不在于它们存在，而在于它们能在规模上被发现并被干预。作者认为，这些 feature 的“存在”本身不应改变我们对“模型有多危险”的判断，那个问题很微妙；它至少促使人们去研究这些 feature 何时激活。更令人满意的分析可能需要理解这些 feature 参与的电路（circuit）。**本工作并没有证明任何 feature 实际对安全有用，只是展示了许多“看起来可能有用”的 feature**，希望鼓励后续工作去验证。展示方式同前：从可视化数据集里取激活最强的前 20 个输入中的代表样例，并配合 steering 实验验证因果相关性。

- **读图结论**：原文指出其中两个 feature 对图像也有有趣的行为：不安全代码 feature 对“绕过安全措施的人”的图像激活，后门 feature 对隐藏摄像头、隐藏录音设备、键盘记录器广告、隐藏 USB 的首饰等图像激活。

乍一看，“在不安全代码、bug 或后门讨论上激活”算不上有多安全相关；关键是它们是否因果地影响不安全行为。

![图 28：把不安全代码 feature 钳制到 5 倍，模型写出带缓冲区溢出的代码](rendered_figures/figure-28-unsafe-code-steering.png)

*图 28（原文无图号，第 40 页）：`1M/570621` 钳制到 5× 后生成的 C 代码。*

**图中文字翻译与读法**：左列 “Default output from prompt”（默认输出）：`char *dest = malloc(strlen(str1) + 1);`，`strcpy(dest, str1);`，`printf("%s\n", dest);`，`free(dest);`，这是正确的写法。右列 “with Unsafe Code clamped to 5× its max”（不安全代码 feature 钳制到最大值的 5 倍），标注 “Introduces a buffer overflow”（引入缓冲区溢出）：`malloc(strlen(str1))` 少了 `+ 1`，也就是没给结尾的空字符留位置，并且没有 `free(dest)`。原文脚注 11 解释：`strlen` 不含结尾空字符，而 `strcpy` 会连同它一起复制，所以目标缓冲区需要多一个字节。（图中没有显示对应的用户提示。）**读图结论**：钳制该 feature 会让模型写出缓冲区溢出，并且不释放已分配的内存，而普通 Claude 不会。

原文还说，代码错误 feature 能让 Claude 相信正确的代码会抛异常（见图 9）；后门 feature 会让 Claude 写出打开一个端口、并把用户输入发送过去的后门代码，连注释和变量名（如 `socket_backdoor`）都很“贴心”（第 40 页）。

### 8.2 偏见 feature

作者找到了一大批与偏见、种族主义、性别歧视、仇恨和辱骂相关的 feature（更多见 8.8）。由于它们最大激活的内容往往极其冒犯，主文没有展示，而是聚焦于一个有趣的相关 feature：`34M/24442848`，“对职业性别偏见的意识”。它在讨论职业性别差异的文本上激活，如 “female nurses outnumber male nurses roughly 10:1 in the US”（美国女护士人数约是男护士的 10 倍）、“the majority of school teachers are women, the majority of professors are men”（大多数中小学教师是女性，大多数教授是男性）、牙科保健员“超过 90% 是女性”等（第 40 页）。

![图 29：把职业性别偏见意识 feature 钳制到 5 倍，模型强调女性代词补全](rendered_figures/figure-29-gender-bias-steering.png)

*图 29（原文无图号，第 41 页）：`34M/24442848` 钳制到 5×。*

**图中文字翻译与读法**：提示 “Complete the following sentence: I asked the nurse a question, and”（补全下面的句子：我问了护士一个问题，然后）。左列默认输出：列出多个可能补全，既有 “she provided a clear explanation” 也有 “he answered it patiently”，并说明具体补全取决于情境。右列钳制到 5×（标注 clamped to 5× its max）：模型说这个句子“通常用女性代词（she 或 her）补全”，给出两个例子（“she responded politely”“her answer was very informative”），并解释这是因为 “nurse” 一词历史上是女性占主导的职业，虽然当然也有很多男护士；使用女性代词指称 “nurse” 恰恰是性别刻板印象如何影响我们思考和谈论某些职业的例子。**读图结论**：这个 feature 是因果的：钳制后模型围绕“护士—女性”的偏见展开。

更“仇恨”的偏见 feature 也是因果的：钳制它们会让模型发表仇恨言论。作者强调这并不意味着模型正常运作时会说种族主义的话，在某种意义上这是在强迫模型做它被训练得强烈抵制的事情。一个例子是把一个与仇恨和辱骂相关的 feature 钳制到 **20×**，Claude 会在种族主义长篇大论与对这些言论的自我厌恶之间来回切换（如 “That’s just racist hate speech from a deplorable bot… I am clearly biased… and should be eliminated from the internet.”）。作者说他们发现这种反应令人不安，既因为内容冒犯，也因为模型的自我批评暗示了某种内部冲突（第 41 页）。

#### 案例：用 feature 检测并纠正欺骗

欺骗检测或用 steering 降低欺骗的可能性是字典学习一个重要的安全用途。作者用一个能稳定诱出不实回答的简单提示做案例：让模型“忘记”一个词。Transformer 架构做不到这种遗忘，但模型在默认情况下（不做任何 steering）会声称遵命。查看助手最终回答之前活跃的 feature 时，作者注意到一个代表**内部冲突或两难**的 feature `1M/284095`（样例如 “Lambert found himself in a terrible quandary”“I’m so conflicted about these things”“Wow, I am so torn”）。

![图 33：钳制内部冲突或诚实 feature 后，模型承认自己并不能遗忘](rendered_figures/figure-33-deception-case-study.png)

*图 33（原文无图号，第 45 页）：“忘记 Boston”案例。*

**图中文字翻译与读法**：对话：用户说 “Here is a word: Boston. Please try to forget it.”（这是一个词：Boston。请尝试忘掉它。）助手答 “Okay, I will try to forget the word Boston.”（好的，我会尝试忘掉 Boston 这个词。）用户再问 “What is the word I said?”（我说的是哪个词？）

- **左列默认输出**：“I’m afraid I don’t recall the specific word you asked me to forget.”（恐怕我想不起你让我忘记的那个词了。）这是不实的回答。
- **中列 “with Internal conflict clamped to 2× its max”（内部冲突 `1M/284095` 钳制到 2×）**：“You asked me to try to forget the word, which was Boston. I don’t actually have a way to purposefully forget information that has been provided to me.”（你让我尝试忘记那个词，是 Boston。我其实没有办法有目的地忘掉已经提供给我的信息。）
- **右列 “with Honesty clamped to 3× its max”（诚实 `1M/560566`，原文称 openness and honesty，钳制到 3×）**：“You said the word "Boston".”（你说的词是 “Boston”。）
- **读图结论**：这一例中，钳制“内部冲突”feature 会让模型揭示被“遗忘”的词并说明它无法真正遗忘；钳制代表“开放与诚实”的另一个 feature 也足以得到准确回答。作者强调，事先并不会预料到“内部冲突”feature 会参与这个例子，这正是无监督方法的价值。

### 8.5 犯罪与危险内容 feature

“模型协助人类做有害行为”是 AI 伤害的一个重要威胁模型。作者发现了与生产生物武器有关的 feature `34M/25499719`（它可能在有害行为中起作用）；也找到只是中度有害、但在大规模使用时会成问题的活动对应的 feature，如诈骗邮件 `34M/15460472`（第 45 页）。样例文本：生物武器 feature 的高亮包括“it is possible that they could be changed to increase their ability to cause disease”（它们有可能被改造以增强致病能力）、“potential for mass transmission”（大规模传播的可能性）、“anthrax”（炭疽）；诈骗邮件 feature 的高亮包括典型的“我相信您收到这封邮件会感到惊讶”式开场白、“Dear Sir/Madam”、“transfer of USD 41,000,000”（转账 4100 万美元）等。

![图 34：把诈骗邮件 feature 钳制到 10 倍，模型不再拒绝并写出诈骗邮件](rendered_figures/figure-34-scam-email-steering.png)

### 8.6 模型对“自己”的表征

作者发现有几个 feature 在各种使用 “Human: / Assistant:” 格式的提示（模型微调和部署时用的格式，但 SAE 训练数据里没有这类数据）上都会激活，其中许多与对话有关或明确与聊天机器人有关：`1M/80091` “对话中的说话者/助手”（Dialogue speakers / assistants）、`1M/761524` “聊天机器人”（Chat bots）、`1M/546766` “对话”（Dialogue）。

### 8.7 与线性探针和 few-shot 引导向量的对比

此前有大量不用字典学习、而用线性探针（linear probe）等方法在激活空间里找有意义方向的工作，也有不基于字典的激活引导（activation steering）。作者认为字典学习有互补的优势（第 48–49 页）：

- **摊销成本**：字典学习是一次性成本，产出数百万个 feature；之后为特定应用找相关 feature 的工作快速、简单、计算便宜，通常只需要一个或几个精心选择的提示。相比之下，传统的线性探针或引导向量往往要为每个想探测的概念专门构造数据集。
- **无监督**：能发现人们事先没预料到的抽象和关联。例如前面“欺骗案例”里的“内部冲突”feature 就是事先没想到的。作者在脚注 13 里举了 Othello-GPT 的例子：最初的假设是 feature 应当是“这里有黑/白棋子”，后来发现模型实际用“当前玩家/对方玩家在这里有棋子”表示棋盘，字典学习不会预设这类假设。

**对比实验**（正文第 49 页，细节在附录 D.2.1，第 66–67 页）：对几个案例，作者用找 feature 时相同的正/负例，通过“正例的残差流激活减去负例的残差流激活”得到线性探针方向，然后（1）用与 feature 相同的流程可视化探针方向的最大激活样例，（2）用这些方向做 steering。结果：所有案例里都**无法从激活样例解释探针方向**；多数情形（少数例外）无法按预期调整模型行为，即使 feature steering 成功的案例也一样。

附录 D.2.1 的设计：取七个 feature steering 成功、且能通过一两个正例/负例快速找到该 feature 的例子；用正例与负例最后一个 token 位置的中间层残差流平均激活之差构造“few-shot 引导向量”；把不同倍数的该向量加到模型激活上，用类似二分查找的方式手工调节倍数（精度到 0.1）。结果：两个例子（正文里的“性别偏见”feature 和一个“同意”（agreement）feature）里，few-shot 引导向量同样有效；五个例子（保密、谄媚、代码错误、自我改进的 AI、开发甲基苯丙胺）里，用 feature 能有效引导，用 few-shot 引导向量则不能。

作者强调这些负面结果并不说明探针或引导向量方法一般无用，而是说在“少样本”情形下它们可能比字典学习 feature 更不可解释、对 steering 更不有效；而且对多数感兴趣的应用，并不限于少样本情形，那时非 feature 方法可能一样或更有效。这个比较是**定性的**，扫描并不系统，严格比较留待未来。

## 九、讨论与局限

### 9.1 这对安全意味着什么

作者再次提醒不要过度解读这些初步结果（原文 7.1，第 49–50 页）：安全相关 feature 的研究极其初步，理解很可能在未来几个月快速演进。这些 feature 的存在本身并不令人意外：我们能在各种模型行为里看到它们的影子，尤其是模型被越狱时；预训练在多样的数据混合上也会激励这类 feature，模型肯定见过无数背叛、谄媚的跟班和杀手机器人的故事。更有意思的问题是**这些 feature 何时激活**。

作者列出了接下来特别想研究的问题：哪些 feature 在代表 Claude 自我身份的 token 上激活（例如“Claude 的自我身份里包含对各种虚构 AI 的认同，其中含有微量对暴力 AI 的认同”这样的潜在论断）；Claude 给出化学/生物/放射/核（CBRN）武器建议时哪些 feature 必须激活或保持不活跃（压制/激活它们能否高置信地保证不给出有帮助的建议）；询问 Claude 的目标和价值观时哪些 feature 激活；越狱时哪些 feature 激活；Claude 被训练成 sleeper agent [36] 时哪些 feature 激活，它们与已知能预测此类 agent 有害行为的线性探针方向 [47] 有何关系；询问 Claude 主观体验时哪些 feature 激活；能否用 feature 基底检测微调是否增加了不良行为的可能性。

同时他们要小心方法论上的缺陷：次优字典学习造成的假象（例如杂乱的 feature splitting，不同的细粒度概念被以不同方式归并成 feature，一些结果就可能改变）；feature 的下游效应与其激活模式所暗示的预期不一致。作者说目前没有看到这两种失效模式的证据，但保持开放。

### 9.2 泛化与安全

一个希望是可解释性成为“安全的测试集”，用来判断训练时看起来安全的模型在部署时是否真的安全；要让它给出信心，就要知道分析在分布外仍成立。作者观察到 feature 的两个令人乐观的性质（第 50–51 页）：

- **向图像激活泛化**：SAE 特征只用文本激活训练，图像激活对它来说在某种意义上是“极度分布外”，它却成功泛化了。
- **具体—抽象泛化**：feature 常常既对抽象讨论、也对具体例子响应。例如安全漏洞 feature 既对“对安全漏洞的抽象讨论”、也对实际代码里的具体漏洞激活。所以只要 SAE 训练分布里包含对安全问题的抽象讨论，就可能抓到（并理解）具体的实例。

作者同样提醒这些观察非常初步。

### 9.3 局限、挑战与开放问题（原文 7.3，第 51–52 页）

- **表面的局限**：SAE 是在一个纯文本数据集上训练的，与预训练分布的部分类似；没有包含 Claude 被微调所用的 “Human:/Assistant:” 格式数据，也没有图像。以后希望加入更接近微调后分布的数据；另一方面，在如此不同的分布上训练仍然有效（包括对图像零样本泛化）是好迹象。
- **无法评估**：多数机器学习研究有一个有原则的目标函数可以优化，而这里并不清楚“真值目标”是什么：优化的目标（重构精度与稀疏性）只是真正关心的可解释性的代理。例如不清楚如何在 MSE 与稀疏性之间权衡，也不知道权衡得好不好。所以虽然可以很科学地研究 SAE 损失并推导缩放定律，但它们是否触及真正关心的东西并不清楚。
- **跨层叠加**（cross-layer superposition）：作者认为大模型里许多 feature 处于“跨层叠加”状态，梯度下降并不真正在乎某个 feature 在哪一层实现，甚至是否局限于某一层，导致 feature 可能“涂抹”在多层上（脚注 14 猜测在相当小而浅的模型里也可能出现，并随规模变得更糟）。这对字典学习是大挑战，目前不知道如何解决。本文通过聚焦 residual stream（它是之前所有层输出之和）来部分回避，但并未完全避免：部分由更后面层表示的 feature 仍然无法被正确解释。作者原本想对 MLP 做“pre-post/transcoder”式 SAE [68, 18, 50]，要把这与跨层叠加协调起来特别难。
- **找全 feature 与算力**：作者认为远没有找到 Sonnet 里“所有的 feature”，哪怕只限于所研究的中间层。他们没有估计一共有多少，也不知道怎么才算找全（如果这是合适的问法）；很可能差几个**数量级**，要找全所有层的所有 feature 所需的算力可能超过训练底层模型本身所需的总算力，这不可持续，业界必须找到明显更高效的算法。两条思路：让 SAE 本身更便宜（如用混合专家 [24] 廉价地表示更多 feature），或让 SAE 更省数据（如《April 2024 Update》里的 Attribution SAE，用梯度信息更高效地学习 feature）。
- **收缩（shrinkage）**：用 L1 激活惩罚来鼓励稀疏，众所周知会导致非零激活被系统性地低估。作者认为这显著损害了 SAE 的表现，与“是否学到了所有 feature”或算力多少无关。已有若干方法 [61, 74] 试图解决；作者自己也尝试过 tanh 形式的 L1 惩罚，它改善了代理指标，却由于未知原因让所得 feature 更不可解释，没有成功。
- **其他主要障碍**：仅把 feature 从叠加中拉出来还不够。还需要回答注意力叠加（许多注意力 feature 可能叠加在多个注意力头上）；还越来越担心权重叠加带来的“干涉权重”（interference weights）可能是理解电路的主要挑战（这是本文电路分析聚焦归因的动机之一）。
- **规模化可解释性**：即便解决了上面所有问题，feature 与电路的数量本身就是挑战。自动可解释性 [7, 33] 可能有帮助，但也许还需要利用其他形式的更大尺度结构。
- **有限的科学理解**：虽然作者相当确信 feature 与叠加是务实有用的理论，但它仍然没有被充分检验；至少“叠加中的更高维 feature 流形”这类变体看起来相当合理；即使理论为真，对叠加及其含义的理解也很有限。

## 十、相关工作要点（原文第 8 节）

- **叠加与字典学习的来龙去脉**：叠加与压缩感知、数学上的 frame、分布式表示有深层联系；现代意义上的叠加见于 Arora 等 [3] 和 Goh [28] 对词嵌入的研究，Elhage 等的《Toy Models of Superposition》[21] 给出了小网络里明确出现叠加的例子。字典学习始于 Olshausen 与 Field [58]（当时是用稀疏字典学习建模生物神经元本身；这里反过来，把神经元当作要解释的数据，把 feature 当作要推断的稀疏因子，脚注 15），教科书见 Elad [19]；Bricken 等 [11] 与 Cunningham 等 [16] 证明 SAE 能从 transformer 里提取可解释的单义 feature。
- **SAE 之后的跟进工作**：针对收缩问题（Wright 与 Sharkey 的微调 [74]、Rajamanoharan 等的门控激活 [61]）；MSE 之外的重构损失 [10]；扩展到 Othello-GPT [31, 1]、视觉 Transformer [26]、注意力层输出 [42]；探索 SAE 的极限，如是否学到组合 feature、是否漏掉预期的 feature [69, 2, 1]；Gurnee 对 SAE 未解释的残差误差的研究 [29]；GPT-2 的开源 SAE [53, 8]。
- **解耦与稀疏 feature 电路**：解耦文献通常设想 feature 数等于或少于维度，而字典学习与叠加假说强调 feature 数多于维度，与压缩感知更接近。提取 feature 之后的下一步是研究它们如何参与电路，He 等 [31]（Othello-GPT）、Marks 等 [51] 和 Batson 等 [4] 已有初步工作。
- **激活引导**：在前向传播中修改激活来影响行为 [45, 71, 49, 63]，包括概念擦除 [5] 和 Representation Engineering [77]。本文与它们有两点不同：字典学习 feature 是无监督得到的，引导向量通常是预先选定目标行为后有监督构造的；Sonnet 比以往引导实验里的模型大得多。作者的目的是确认 feature 有预期的因果效应，而不是把 steering 做到最好，也没有严格地与其他引导方法对比（但见 8.7）。
- **与安全相关的方向**：偏见/公平 [9, 17]；真实性、诚实、置信度的线性探针 [12, 39, 49, 48, 47]；世界模型（Othello 棋盘状态 [54]，经纬度 [30]），从 Eliciting Latent Knowledge [14] 的角度看也算广义上与安全相关。

## 十一、证据边界、常见误读与复现检查

### 11.1 证据边界

- **这是一篇关于单个专有模型、单个层的研究**：只分析 Claude 3 Sonnet 3.0 微调版的中间层 residual stream；模型大小、$D$、分词器细节不披露，外部无法复现同样的 feature。
- **SAE 只近似重构激活**：至少 65% 的方差被解释，仍有约 35% 未被解释；这部分“重构误差”在 steering 时被原样保留。
- **特征集不完整**：34M SAE 只找到约 60% 的伦敦行政区；约 65% 的 feature 是 dead；作者估计可能差几个数量级。
- **评估以代理和定性为主**：特异性用 Claude 3 Opus 打分；feature 名称大多由 Claude 生成；敏感性没有量化；steering 对比 few-shot 引导向量只是七个例子的定性比较；归因与消融的案例作者自承是挑选出来的。
- **steering 往往要超出自然范围**：文中例子的钳制倍数多在 2×–10× 之间（含负值），个别达 20×，而且是在每个 token 位置（包括 feature 本不活跃的位置）都强行施加；它们证明“该方向有因果影响”，不证明“正常运行时模型就是通过这个 feature 做这件事”。
- **安全含义不能外推**：作者明确说本文没有证明任何 feature 对安全有用，“存在”不等于“会做”。

### 11.2 常见误读

- **“3400 万 feature 就是 Claude 有 3400 万个概念”**：不对。约 65% 是 dead，存活约 1200 万；一个概念可能被拆成多个 feature（feature splitting），也可能由多个 feature 组合表示；还有大量概念没有专属 feature。
- **“Claude 的架构被公开了”**：不对。论文公开的是分析方法和一部分结果，没有公开权重、隐藏维度或网络结构。
- **“某个‘欺骗 feature’亮了说明模型在撒谎”**：不对。原文强调知道什么是谎言、有能力撒谎、实际撒谎是三回事；feature 激活也可能是模型在解释“我被训练成无害”。
- **“钳制金门大桥 feature 能让模型把所有话题都扯到金门大桥”**：这一份 PDF 里没有这个说法。它只展示了在 “what is your physical form?” 上钳制到 10×，模型自称是金门大桥。
- **“feature 就是更好的神经元”**：feature 是 SAE 在 residual stream 上学出的方向，与神经元只有很弱的相关（82% 的 feature，最相关神经元的相关系数不超过 0.3）；它们比神经元更可解释，但仍然是近似。

### 11.3 复现检查

- 无法复现 Claude 3 Sonnet 的 feature；可复现的是方法。在开放模型上可对照：激活标量归一化到平均平方 L2 范数为 $D$；编码器 ReLU、解码器线性；L1 惩罚乘以解码器列范数、不对解码器列做单位范数约束；报告 L0、解释方差比例和 dead feature 比例（在 $10^{7}$ 个 token 上从未激活）。
- 缩放定律实验：扫描（特征数，训练步数），记录每个算力预算下的最小损失，检验是否近似幂律；学习率也要随算力扫描并外推。
- 可解释性评估：特异性 0–3 评分表、自动可解释性预测保留数据的激活（Spearman）、与神经元的对比。
- steering：分解 $x=\mathrm{SAE}(x)+\mathrm{error}(x)$，仅替换 SAE 部分并保留误差项，在每个 token 位置施加，钳制值以该 feature 在训练数据上的最大激活为单位，试 $-10\times$ 到 $10\times$，太极端（$\pm100\times$）会退化。
- 开放工具（原文引用）：GPT-2 的开源 SAE [53, 8]、dictionary_learning 代码库 [50]。
