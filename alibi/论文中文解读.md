## 一、一句话结论

训练时的序列长度记为 $L$。如果推理时给模型比 $L$ 更长的输入（这叫**外推**，extrapolation），用正弦位置编码（sinusoidal）的 Transformer 语言模型几乎立刻崩溃。作者提出 ALiBi（Attention with Linear Biases）：**完全不给词向量加位置向量**，只在每个 attention 头的 query–key 分数上减去一个与距离成正比的惩罚 $m\cdot(i-j)$，其中斜率 $m$ 是每个头固定的、按几何级数排布、不参与训练的常数。

主要证据：

- 在 WikiText-103 上，只在 512 个 token 上训练的 ALiBi 模型，外推到 3072 个 token 时的困惑度（18.40）优于直接在 3072 个 token 上训练的正弦模型（18.67），而训练速度快 1.84 倍；
- 在 1.3B 参数、461 GB 数据的设置上，用 1024 个 token 训练的 ALiBi 模型在 2048 个 token 上评估，困惑度与用 2048 个 token 训练的正弦模型相当（8.92 对 9.01），训练快约 11%、显存少约 11%；
- 与正弦模型相比，ALiBi 不增加参数、几乎不增加运行时间，显存只多 0–0.7%。

重要的限定（来自论文附录 B）：超过训练长度之后困惑度的下降，主要来自缓解“early token curse”（每段序列开头的 token 看到的上文太少），而不一定是模型真的用上了更长的上下文。

## 二、问题与背景

### 2.1 什么是外推，为什么它有价值

构建 Transformer 语言模型时，训练序列长度 $L$ 是一个重要的设计选择。更长的上下文能改善预测，但更长的序列训练更贵（附录图 7，见下文图 A7：训练速度随 $L$ 增大而下降）。RNN 语言模型过去就是在较短序列上训练、默认能泛化到更长上下文的；Transformer 原论文也猜测它“可能”外推到比训练更长的序列。

论文把**外推**定义为：当验证时的输入 token 数增加到超过训练时的 token 数后，模型仍然能继续表现良好。记训练子序列长度为 $L$，验证子序列长度为 $L_{\text{valid}}$，外推就是 $L_{\text{valid}}>L$ 的情形。

论文还提到：能在短序列上训练、又能处理长序列，意味着训练更省钱；在把训练样例作为上下文喂给语言模型的场景（in-context learning）里能放入更多样例；也能生成更长的输出。

从结构上看，Transformer 的各个组件对输入长度本来是“无感”的：词嵌入查表、前馈层、输出 softmax 层都是逐 token 独立计算，注意力层的参数也与长度无关（因果 mask 本来就要处理长度可变的输入）。因此外推能力的差别只能来自**位置信息是怎样注入的**。这是论文的核心论点：外推能力强烈依赖位置表示方法。

### 2.2 评估时怎么切序列：nonoverlapping 与 sliding window

阅读所有结果之前，必须先弄懂论文的两种评估方式，因为附录分析完全依赖它们。

在语言模型上算困惑度时，一次前向传播里可以同时算出很多位置的预测，靠“因果 mask”保证每个位置的预测只受它左边 token 的影响。一个长度为 $L$ 的子序列包含 $L$ 个预测，平均每个预测能看到 $\frac{L+1}{2}$ 个左侧 token。

- **Nonoverlapping（不重叠）评估**：把长序列切成互不重叠、长度为 $L_{\text{valid}}$ 的子序列，各自独立评估。便宜，是论文默认的做法（除非特别说明，所有困惑度都用它）。
- **Sliding window（滑动窗口）评估**：选一个步长 $S\in[1,L-1]$，窗口每次向前移动 $S$ 个 token；每次前向重新编码上一窗口的 $L-S$ 个 token，只输出 $S$ 个新 token。优点是第一个窗口之后的每个输出至少有 $L-S$ 个上文；代价是每个 token 被重复编码多次，慢得多。$S=1$ 时每步输出一个 token，每个预测都拥有模型能处理的最长上文，也最慢。不重叠评估可以看作步长等于 $L$ 的滑动窗口。
- **Early token curse（早期 token 诅咒）**：把评估集切成子序列后，每个子序列开头的预测只能看到很少的上文（它真正的上文在上一个子序列的末尾），困惑度因此被拉高。滑动窗口可以缓解，但很慢。

![图 A10：滑动窗口评估与不重叠评估的对比示意](rendered_figures/figA10-sliding-window.png)

*图 A10（原文 Figure 10，第 23 页）：对 8 个词的句子 “The big gray cat sat on the mat”，用 $L_{\text{valid}}=4$ 的模型做滑动窗口评估（上方蓝色括号）与不重叠评估（下方红色括号）。*

**图中文字翻译与读法**：

- **蓝色括号（上）**：滑动窗口评估，每个括号覆盖 4 个词，每次右移 1 个词，共 5 次前向传播；
- **红色括号（下）**：不重叠评估，两个互不重叠的 4 词窗口，只需 2 次前向传播；
- **读图结论**：不重叠评估快得多（2 次对 5 次），但滑动窗口让每个预测拥有更多上文。以词 “sat” 为例：不重叠评估中它是第二个红色窗口的第一个词，窗口内没有任何上文（它真正的上文 “The big gray cat” 在上一个窗口里）；滑动窗口评估中它出现在窗口 “big gray cat sat” 的末尾，有 3 个词的上文。这就是 early token curse 的来源。

### 2.3 已有的位置方法

论文比较了三种位置方法，并把 ALiBi 的设计动机建立在它们之上。（原文还指出，学习式绝对位置嵌入——例如 GPT-3、Jurassic-1 使用的方式——没有办法编码大于 $L$ 的位置，因此根本没有外推能力，脚注 4。）

1. **正弦位置嵌入（sinusoidal）**：Vaswani 等人（2017）提出的固定、不学习的向量，加到第一层的词向量上。背景知识：$\mathrm{PE}(p,2k)=\sin\big(p/10000^{2k/d}\big)$，$\mathrm{PE}(p,2k+1)=\cos\big(p/10000^{2k/d}\big)$（$p$ 为位置，$k$ 为维度编号），不同维度用不同的波长。从公式看它对任意位置都有定义，所以“技术上应该能外推”，但论文第一次系统测量发现：它只能多出几十个 token。
2. **旋转位置嵌入（rotary，RoPE）**：Su 等人（2021），因 GPT-J 而流行。不在最底层加向量，而是在**每一个** attention 层中把 key 和 query 乘上正弦（旋转）嵌入；也**不给 value 加位置信息**。因此每层 attention 的输出里没有显式的位置信息。作者怀疑“位置信息与 value 分开”可能对外推有利，ALiBi 的设计从中得到启发。论文用 RoFormer_pytorch 的实现，并在脚注 5 说明：事后得知该代码可以优化到只比正弦慢 2%，所以图 2 中旋转方法偏慢有实现因素，这种优化不会改变外推表现。RoPE 的机制见 [RoPE 解读](../rope/论文中文解读.md)。
3. **T5 bias**：T5 模型（Raffel 等，2020）使用的相对位置方法。不给词向量加位置，而是在每个 query–key 分数上加一个**只依赖二者距离的、可学习的、共享的偏置**：距离为 0（同一个 token）的所有 (query, key) 对共享一个偏置，距离为 1 的共享另一个偏置，依此类推；到某个距离之后，多个不同距离共享同一个偏置（这可能对外推有利）。它也在每一层注入位置信息、不改 value。T5 原文只是提出“可能外推”，没有实验；这篇论文首次证明 T5 bias 确实能让语言模型外推——但代价是训练至少慢一倍。

用一张表对比（“论文测到的外推”列取自论文第 2 节正文）：

| 方法 | 位置信息注入位置 | 是否进入 value | 是否有可学习的位置参数 | 论文测到的外推（WikiText-103） | 训练速度（原文表 1，$L=512$） |
|---|---|---|---|---|---|
| 正弦 | 仅输入层，加到词向量 | 是（随词向量进入 Q/K/V） | 无（固定向量） | $L=512$ 时多约 20 个 token 内有改善，20 到 50 个持平，之后变差；$L=1024$ 时最多多 50 个 token 内有改善 | 28.5k 词/秒 |
| 学习式绝对位置 | 仅输入层 | 是 | 有 | 无法编码大于 $L$ 的位置，无外推能力 | 未测 |
| Rotary | 每层 Q、K | 否 | 无 | $L=512$ 时多 200 个 token 内有改善；$L=1024$ 时多 100 个 | 20.0k 词/秒 |
| T5 bias | 每层 attention 分数 | 否 | 有（按距离的偏置） | $L=512$ 时多 600 个 token 内有改善；$L=1024$ 时多 800 个 | 14.4k 词/秒 |
| ALiBi | 每层 attention 分数 | 否 | 无（固定斜率） | WikiText-103 上至少到约 $3L$ 仍在改善；$L=512$ 的模型到 12k 以上仍保持强表现 | 28.3k 词/秒 |

“是否进入 value”一列是根据论文对 rotary 的论述归纳的：位置向量加在输入层时会随词向量一起进入 Q、K、V，而 rotary、T5 bias、ALiBi 只作用在 Q、K（分数）上。

## 三、方法：ALiBi

### 3.1 公式

标准的因果 attention：对一个 head 中第 $i$ 个 query $q_i\in\mathbb{R}^{1\times d}$（$1\le i\le L$，$d$ 为 head 维度），因果 mask 只允许它看前 $i$ 个 key，记 $K\in\mathbb{R}^{i\times d}$，注意力权重为

$$
\mathrm{softmax}\big(q_iK^\top\big).
$$

ALiBi 不在任何地方加位置嵌入；唯一的改动是在 query–key 点积之后加一个静态、不学习的偏置：

$$
\mathrm{softmax}\big(q_iK^\top+m\cdot[-(i-1),\ \dots,\ -2,\ -1,\ 0]\big),
$$

其中标量 $m$ 是**每个 head 各自固定的斜率**，在训练前就定好。方括号里的向量对应第 $1,2,\dots,i$ 个 key：第 $j$ 个 key 得到的偏置是 $-m(i-j)$，即距离 $i-j$ 越大，惩罚越大；最近的 key（就是 query 自己，$j=i$）偏置为 0。

论文脚注 9、10 说明了两个细节：为简化，公式略去了 Q/K/V/输出投影、dropout 和缩放因子；并且 **ALiBi 的偏置不乘 $\sqrt{d_k}$ 缩放因子**。把这两点补回去，第 $h$ 个 head 的完整分数写成

$$
a^{(h)}_{ij}=\mathrm{softmax}_{j\le i}\Big(\frac{q_ik_j^\top}{\sqrt d}-m_h\,(i-j)\Big).
$$

softmax 之后其余计算（与 value 相乘等）完全不变。

### 3.2 一个可以手算的例子

![图 3：ALiBi 给每个 head 的 attention 分数加线性偏置](rendered_figures/fig3-alibi-bias.png)

*图 3（原文 Figure 3，第 5 页）：左，未加偏置的 attention 分数矩阵 $q_i\cdot k_j$（下三角）；右，距离偏置矩阵，乘以 head 专属的标量 $m$ 后逐元素相加。*

**图中文字翻译与读法**：

- **左矩阵**：5 个 query（行）对 5 个 key（列）的点积 $q_i\cdot k_j$，只有下三角（$j\le i$）有值，因为因果 mask 遮掉了未来的 key；不同深浅的蓝色表示分数大小，仅作示意；
- **右矩阵**：偏置，对角线为 0，向左逐格变成 $-1,-2,-3,-4$（即 $-(i-j)$），最后乘以右边的 $\bullet m$；
- **图题要点**：$m$ 是 head 专属的标量，在训练中被设定而不被学习；论文的 $m$ 取值方案可推广到多个文本领域、模型和训练预算；使用 ALiBi 时网络底部不加位置嵌入。

笔者补充一个数值例子（非论文数字）。取 $m=\tfrac12$（8 个 head 中斜率最大的那个），序列只有 5 个 token，则偏置矩阵 $m\cdot(-(i-j))$ 为（空白为被因果 mask 遮住的位置）：

$$
\begin{bmatrix}
0 & & & & \\
-0.5 & 0 & & & \\
-1 & -0.5 & 0 & & \\
-1.5 & -1 & -0.5 & 0 & \\
-2 & -1.5 & -1 & -0.5 & 0
\end{bmatrix}
$$

假设第 5 个 query 对 5 个 key 的内容分数 $q_5\cdot k_j/\sqrt d$ 完全相同，那么 softmax 只剩下偏置在起作用，权重正比于 $\big[e^{-2},e^{-1.5},e^{-1},e^{-0.5},e^{0}\big]\approx[0.135,0.223,0.368,0.607,1]$，归一化后约为 $[0.058,\,0.096,\,0.158,\,0.260,\,0.429]$：离得越近权重越大，并且相邻两个 key 的权重之比恒为 $e^{0.5}\approx1.65$。这就是 ALiBi 带来的“近因偏置”（inductive bias towards recency）。内容分数不同时，偏置只是在 logit 上加了一项，所以足够高的内容分数仍可以抵消距离惩罚，远处的 token 并非完全不可见。

### 3.3 斜率怎么定

斜率 $m$ 是**固定的几何数列**，不训练：

- 8 个 head 的模型：$\frac1{2^1},\frac1{2^2},\dots,\frac1{2^8}$，即 $0.5,\,0.25,\,0.125,\,\dots,\,0.0039$；
- 16 个 head 的模型：把上面 8 个斜率“相邻两个取几何平均”插值，得到以 $\frac1{\sqrt2}$ 为首项、公比也是 $\frac1{\sqrt2}$ 的几何数列：$\frac1{2^{0.5}},\frac1{2^{1}},\frac1{2^{1.5}},\dots,\frac1{2^{8}}$；
- 一般地，$n$ 个 head 时，斜率是以 $2^{-8/n}$ 为首项、**同一个值为公比**的几何数列，即第 $h$ 个 head 的斜率为

$$
m_h=2^{-8h/n},\qquad h=1,\dots,n.
$$

（笔者核对：$n=8$ 时 $2^{-h}$，$n=16$ 时 $2^{-h/2}$，与论文给出的两个例子一致；无论 $n$ 是多少，最平缓的 head 斜率总是 $2^{-8}=1/256$。）

论文对斜率的几点说明：

- **刻意不调参**：这组斜率在 WikiText-103 上选定，之后原封不动用到 Toronto BookCorpus 和 1.3B 的 CC100+RoBERTa 实验，没有重调。作者类比正弦编码——Vaswani 等人也是一次性设定波长几何级数的起止点，之后在不同模型、不同数据上复用。
- **试过可训练的斜率**，外推效果不好，而且训练速度慢 3%。
- **手动探索了约十组斜率**，得到的经验：效果最好的斜率集合落在 $(0,1)$ 区间内，并且越接近 0 越密集；方法对斜率选择也比较稳健，甚至从指数分布里随机采样有时也行（但方差大）。
- **不同 head 以不同速率增加惩罚**，所以有的 head 近乎只看近邻，有的 head 能保持较长的视野。

笔者的推导（非论文数字）：偏置给注意力权重乘上因子 $e^{-m\Delta}$（$\Delta=i-j$ 为距离），所以惩罚的“特征距离”是 $1/m$。最陡的 head（$m=1/2$）每隔约 2 个 token 权重就乘以 $e^{-1}\approx0.37$，距离 10 时只剩 $e^{-5}\approx0.0067$；最平缓的 head（$m=1/256$）特征距离是 256 个 token，距离 1024 时因子为 $e^{-4}\approx0.018$，距离 3072 时为 $e^{-12}\approx6\times10^{-6}$，仍然非零。一个多尺度的“视野”集合就是这样由斜率的几何分布造出来的。

### 3.4 等价写法与实现成本

**softmax 的行平移不变性**（笔者补充的数学事实）：第 $i$ 行所有 logit 同时加上同一个常数，softmax 结果不变。因此

$$
\mathrm{softmax}_{j\le i}\Big(s_{ij}-m(i-j)\Big)=\mathrm{softmax}_{j\le i}\Big(s_{ij}+m\,j\Big),
$$

这是因为两者只差一个与 $j$ 无关的常数 $-m\,i$。也就是说，ALiBi 在数学上等价于给第 $j$ 个 key 的分数加一个与 key 位置成正比的线性项 $m\,j$。把它理解成“相对距离惩罚”更直观，因为每个 query 只关心各 key 的分数之差，而差值只与距离有关。

**实现**：因果语言模型本来就要在 softmax 之前给 $QK^\top$ 加一个 mask 矩阵（未来位置为 $-\infty$）。ALiBi 只是把线性偏置也加进这个矩阵，不新增任何运算，所以**没有运行时间代价**。显存上，原来的 mask 大小是 $L\times L$（各 head 共用），现在每个 head 斜率不同，变成 $n\times L\times L$（$n$ 为 head 数），在论文实验里最多多出 100 MB。但因为 ALiBi 允许用短得多的序列训练，整体能省下数 GB 显存。

下面是笔者写的示意代码（非论文原文），说明偏置张量的形状与用法：

```python
import math
import torch

def alibi_bias(n_heads: int, L: int) -> torch.Tensor:
    # 论文的一般公式：第 h 个 head 的斜率 m_h = 2 ** (-8 * h / n)，h = 1..n
    slopes = torch.tensor([2 ** (-8 * h / n_heads) for h in range(1, n_heads + 1)])
    pos = torch.arange(L)
    dist = (pos[:, None] - pos[None, :]).clamp(min=0)   # i - j；j > i 的位置记 0，随后会被因果 mask 盖掉
    bias = -slopes[:, None, None] * dist                # 形状 [n_heads, L, L]
    causal = torch.full((L, L), float("-inf")).triu(1)  # 未来位置为 -inf
    return bias + causal

# scores = q @ k.transpose(-1, -2) / math.sqrt(d) + alibi_bias(n_heads, L)
# 注意：偏置不除以 sqrt(d)；网络底部不再加任何位置嵌入
```

### 3.5 设计选择与论文的假设

- **位置信息加在每一层的 query–key 分数上，不加在 value 上**。论文的理由是一个假设（hypothesize）：与 T5 bias、rotary 一样，这些性质可能对外推有利。它不是被证明的定理。
- **加法而不是乘法**。相关工作一节提到：作者做过（未展示的）实验，把 attention 分数乘上距离函数（而不是像 ALiBi 一样相加）会降低性能。
- **用线性函数**：偏置对距离是线性的，所以对任何新长度都直接可算；线性偏置经过 softmax 后变成指数衰减的权重（见 3.3）。
- 笔者对“为什么能外推”的解释（非论文结论）：训练中没有任何与具体位置绑定的可学习参数，位置只通过一个对距离单调的固定函数进入，所以序列变长时不会出现模型没见过的“新位置模式”，只是出现更大的距离和更重的惩罚。

## 四、实验设置

### 4.1 WikiText-103 设置

- **数据**：WikiText-103（Merity 等，2016），训练集约 1.03 亿个 token，来自英文维基百科（约半个 GB）；
- **模型**：Baevski & Auli（2018）的 Transformer 语言模型（论文选它是因为它在近期语言建模发展中很有代表性）：16 层、维度 1024、8 个 head、前馈内层维度 4096，输入嵌入与 softmax 矩阵绑定（tie）；参数量 247M（原文表 6、7）；
- **控制变量**：除位置方法和训练子序列长度外，其他超参数都不改，包括随机种子和训练轮数（205 个 epoch）；
- **测速**：单张 V100（原文表 1），Figure 1 的 T5 在 32 GB 的 GPU 上会显存溢出（OOM）。

### 4.2 后续两组实验

- **Toronto BookCorpus**（附录 A.3）：约 7 亿个 token（2.9 GB），沿用 Khandelwal 等（2020）的划分和分词（BERT 的 2.9 万词表 BPE）；因为词表比 WikiText-103 小得多，把 adaptive 词嵌入与 softmax 换成绑定的词嵌入/softmax 矩阵；斜率沿用 WikiText-103 的设定。作者强调，整个研发过程中在这个领域**只跑了一组实验**。
- **CC100+RoBERTa**（第 4.2 节，附录 A.4）：RoBERTa 训练语料（Toronto Book Corpus、英文维基百科、CC-News、OpenWebText、Stories，共 161 GB）加上 CC-100 的英文部分（300 GB），共 461 GB；验证集 649K 个 token。模型 25 层、16 个 head、维度 2048、前馈隐层 8192，共 1.3B 参数；训练一个 epoch，即 50k 次更新，使用 128 块 V100。

## 六、分析：ALiBi 的外推收益为什么出现（附录 B）

读到这里会产生一个关键问题：ALiBi 外推后困惑度下降，到底是模型“用上了更长的上下文”，还是仅仅因为评估方式的副作用？论文提出两个可能的解释：

1. **更长的上下文使预测更准**：例如 WikiText-103 的文章平均长度约 3600 个 token，$L=512$ 的模型外推到 $L_{\text{valid}}=3072$ 后若更好，可能是它发现了跨越 512 个 token 以上的模式；
2. **early token curse 被缓解**：不重叠评估时，序列越长，开头那些“上文很少”的预测占比越低。例如 $L_{\text{valid}}=1000$ 时有 10% 的预测只有 100 个 token 或更少的上文；$L_{\text{valid}}=2000$ 时这个比例只有 5%（100 是论文任选的一个“较短历史”的阈值，脚注 13）。所以仅仅因为能处理更长的序列，模型就能显著减轻 early token curse。

为区分二者，作者对 $L=512,1024,3072$ 的 ALiBi 和正弦模型用**滑动窗口评估、步长 $S=1$** 重新评估验证集：这时每个预测都有模型能处理的最大上文，early token curse 被基本消除。

*图 A11（原文 Figure 11，第 24 页）：ALiBi 与正弦模型在 WikiText-103 上用滑动窗口（步长 $S=1$）在不同输入长度下评估。*

## 七、相关工作（论文第 5 节的要点）

- Wennberg & Henter（2021，同期工作）也提出给 attention 分数加距离的偏置，但用的是带多个可训练参数的径向基函数，没有研究外推，实验是文本分类而非语言建模；DA-Transformer（Wu 等, 2021）把分数乘以一个按 head 学习的距离函数，只做文本分类；作者自己试过“乘”而不是“加”，性能下降；
- Transformer-XL（Dai 等, 2019）用缓存让推理时能看到更多 token，但只报告输出长度受限于 $L$ 的结果，且其相对位置方法很慢；Longformer（Beltagy 等, 2020）需要在更长序列上部分训练，而 ALiBi 不需要；
- 在 Transformer 语言模型上尚无前人系统研究外推，但在机器翻译、人工数据集上的序列到序列模型、算术任务、强化学习、图像/语音识别和蛋白质结构预测（AlphaFold）等任务上已有相关探索。

## 八、局限、证据边界与常见误读

**论文自己承认或其数据直接显示的局限**：

1. **外推收益不一定来自长上下文**：附录 B 显示，滑动窗口评估下 ALiBi 随 $L_{\text{valid}}$ 增大并不变好，只是保持平稳；$L=512$ 外推到 3072（18.40）仍不如直接训练 $L=3072$（17.60）。
2. **最佳点约在 $2L$**：CC100+RoBERTa 上 $L=512$ 最佳点约在 1012，$L=1024$ 约在 2024；之后缓慢回升。“10000 个 token 仍然强”指的是困惑度没有崩溃，不是还在继续改善。
3. **大数据、大模型下，非外推场景没有优势**：表 12 中 ALiBi 与正弦在同一长度上基本持平。
4. **评估只用困惑度**：论文的证据全部是语言建模困惑度，没有下游任务评估，模型规模最大 1.3B。
5. **偏置仍是 $O(L^2)$ 的 attention**：ALiBi 不减少计算，也不降低每步读取 KV 的成本；节省来自可以用更短的序列训练。
6. **斜率是在 WikiText-103 上选的**：论文展示了它在 Books、CC100+RoBERTa 上无需重调，但没有证明对所有领域最优。

**常见误读**：

- “ALiBi 能外推到任意长度”：论文在 15000 多个 token 内测试，只能说在这个范围内困惑度不崩溃；
- “线性偏置意味着注意力权重随距离线性下降”：偏置作用在 logit 上，权重经 softmax 后随距离指数衰减；
- “ALiBi 一定比旋转位置编码好”：论文比较的是它自己实现的 rotary，且脚注 5 说明其速度还有优化空间；两者在后续大模型中的使用情况是论文之外的话题。

## 九、复现检查清单

- 偏置只在 $j\le i$ 的位置按 $-m_h(i-j)$ 计算，未来位置仍需独立的因果 mask（$-\infty$）；
- 不要对偏置乘 $1/\sqrt d$；网络底部不再加任何位置嵌入；不要把位置信息加到 value 上；
- 斜率按 $m_h=2^{-8h/n}$（$h=1,\dots,n$）生成，不要训练；$n$ 不是 8 或 16 时，论文只给出这个一般公式，具体实现细节应以官方代码为准；
- 带 KV cache 的增量解码时，新 query 的位置要按其在整个序列中的绝对下标计算，距离才是 $i-j$；
- 比较外推时同时报告 $L$ 与 $L_{\text{valid}}$、是否滑动窗口、步长 $S$；做滑动窗口 $S=1$ 的对照才能判断是否真的用到了长上下文；
- 与基线比较时保持随机种子、训练轮数和其他超参数一致（论文在 WikiText-103 上固定了 205 个 epoch）。

## 十、与后续论文的关系

ALiBi 与 [RoPE](../rope/论文中文解读.md) 是两类相对位置信号的代表：ALiBi 在 logit 上加固定的距离偏置，RoPE 在 Q、K 上做旋转。论文的外推比较中，rotary 是中间档：优于正弦、劣于 T5 bias 和 ALiBi。后来采用 ALiBi 的大模型（如 BLOOM、MPT）属于论文之外的背景信息。
