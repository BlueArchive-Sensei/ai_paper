## 一、一句话结论

GPT-3 是一个 1750 亿参数（175B）的自回归 decoder-only Transformer，模型结构沿用 GPT-2，只是在各层中交替使用稠密注意力和局部带状稀疏注意力；它在约 3000 亿 token 的数据上预训练一次，之后**对任何下游任务都不做梯度更新或微调**，任务只通过输入文本来说明：一句自然语言指令（zero-shot），或再加一个示例（one-shot），或再加几十个示例（few-shot，示例数 $K$ 以塞满 2048 token 的上下文窗口为限）。论文的主要发现是：（1）这种“上下文学习”（in-context learning）的能力随模型规模快速增强，且少样本比零样本涨得更快（图 1.3）；（2）在不少任务上，少样本 GPT-3 接近甚至超过经过任务微调的最先进（SOTA）系统，例如 LAMBADA 准确率 86.4%（比此前 SOTA 高 18 个百分点以上）、TriviaQA 闭卷 71.2%；（3）在算术、字母重排、新词造句等“现场适应”任务上展现了初步能力，并且生成的 500 词左右新闻文章，人类评估者只能以约 52% 的准确率（接近 50% 的随机水平）分辨；（4）同时，在自然语言推断（ANLI、RTE）、WiC、部分阅读理解（RACE、QuAC）上，少样本仍然很弱，并且因为训练数据来自互联网，存在基准测试集污染问题，需要专门分析。论文不是靠新结构取得这些结果，而是靠把规模放大并系统地展示“用 prompt 代替微调”这种使用方式。

## 二、背景与动机

### 2.1 “预训练加微调”的三个问题（原文第 1 节）

在 GPT-3 之前，NLP 的主流做法是先在大规模文本上预训练一个语言模型，再对每个下游任务用成千上万到数十万条标注样本做微调（fine-tuning）。原文历数了这条路线的演进：单层词向量（word vectors）送入任务专用结构；多层 RNN 得到上下文表示但仍接任务专用结构；最近的预训练 RNN 或 Transformer 语言模型被直接微调，不再需要任务专用结构。但是架构虽然通用，仍然需要任务专用的数据集和微调。作者认为去掉这一限制有三个理由：

1. **实用上**：每个新任务都要一批标注数据，而语言任务的种类几乎无穷（改语法、为抽象概念举例、评论一篇短故事……），许多任务很难收集大规模监督数据，更难每换一个任务就重做一遍。
2. **泛化上**：模型的表达能力越强、微调分布越窄，越容易利用训练数据里的虚假相关性（spurious correlations）。预训练加微调的范式里，模型被设计得很大以吸收预训练信息，却在很窄的任务分布上微调，这样得到的泛化可能很差，因此微调模型在具体基准上哪怕名义上达到“人类水平”，也可能夸大了在底层任务上的真实表现。
3. **与人类对照**：人类学习大多数语言任务并不需要大规模监督数据，一句自然语言指令（例如“请告诉我这个句子描述的是开心还是悲伤”）或至多几个示范就够了；人类还能在一段长对话中无缝穿插加法等不同技能。作者希望 NLP 系统也有这种流畅性和通用性。

### 2.2 元学习与上下文学习（图 1.1）

作者提出的路线是语言模型上的元学习（meta-learning）：模型在训练时发展出一套广泛的技能和模式识别能力，推理时用这些能力快速适应或识别要做的任务。外层循环（outer loop）是预训练时用 SGD 更新参数；内层循环（inner loop）是一次前向传播中发生的“上下文学习”：模型以文本输入作为任务说明，条件于一条自然语言指令和/或若干示范，然后通过预测下文来完成同一任务的新实例。

![图 1.1：语言模型的元学习——外循环是预训练，内循环是序列内的上下文学习](rendered_figures/fig1-1-meta-learning.png)

*图 1.1（原文 Figure 1.1，第 3 页）：语言模型的元学习。在无监督预训练期间，语言模型发展出广泛的技能和模式识别能力，之后在推理时用这些能力快速适应或识别所需任务。我们用“上下文学习”（in-context learning）来称呼这个过程的内循环，它发生在对每条序列的一次前向传播之内。图中的序列并不代表模型在预训练中真正看到的数据，只是想说明同一条序列内部有时会嵌入重复的子任务。*

**图中文字翻译与读法**：

- 上方紫色箭头 “Learning via SGD during unsupervised pre-training”（无监督预训练期间通过 SGD 学习）整体标为 outer loop（外循环）；下方三个方框各是一条训练序列（sequence #1、#2、#3），整体标为 inner loop（内循环），每个方框右侧的蓝色箭头 “In-context learning”（上下文学习）表示在序列内自上而下读下去的过程。
- 三条序列内部各自重复了一种小任务：序列 1 是加法（5 + 8 = 13、7 + 2 = 9、1 + 0 = 1、3 + 4 = 7、5 + 9 = 14、9 + 8 = 17）；序列 2 是还原被打乱字母的单词（gaot => goat、sakne => snake、brid => bird、fsih => fish、dcuk => duck、cmihp => chimp）；序列 3 是英译法（thanks => merci、hello => bonjour、mint => menthe、wall => mur、otter => loutre、bread => pain）。
- **读图结论**：互联网文本里本来就夹杂着各种“重复的小任务”。预训练时模型要预测下一个 token，就被迫学会“从序列前面的几行里推断规律，再用到下一行”，这就是内循环的来历。内循环只是计算，不改参数；参数只在外循环里变。原文脚注 1 特别指出：语言模型领域有人把这种做法叫“零样本迁移”，但这个词有歧义（没有梯度更新不等于没给示例），所以论文用“元学习”描述内外循环的结构，用“上下文学习”指内循环，再按推理时给了几个示范称之为 zero-shot、one-shot 或 few-shot。这些词本身不预设“模型是在推理时从零学会任务，还是只是识别训练中见过的模式”，这个问题论文留到原文第 5 节（本文第九节）讨论。

### 2.3 要检验的假设：规模越大，上下文学习越强

此前 GPT-2（Radford 等 2019）已尝试这条路，但结果远逊于微调：在 Natural Questions 上只有 4%，CoQA 上 55 F1，比当时的 SOTA 低 35 分以上。另一方面，Transformer 语言模型的参数量在过去几年快速增长：约 1 亿（GPT）、3 亿（BERT）、15 亿（GPT-2）、80 亿（Megatron）、110 亿（T5）、170 亿（Turing-NLG）；每次增大都带来文本合成或下游任务的改进，并且有证据表明与许多下游任务相关性很好的对数损失随规模平滑下降（Kaplan 等 2020，见 [scaling_laws](../scaling_laws/论文中文解读.md)）。既然上下文学习要在模型参数里吸收大量技能和任务，作者推测它的能力也会随规模显著增强。于是训练了 175B 的 GPT-3 来检验：摘要称它比此前任何非稀疏（non-sparse）语言模型大 10 倍。

图 1.2 用一个简单任务（删掉单词中被随机插入的符号）直观展示了这个假设。

![图 1.2：更大的模型更有效地利用上下文信息](rendered_figures/fig1-2-in-context-curves.png)

*图 1.2（原文 Figure 1.2，第 4 页）：更大的模型越来越高效地利用上下文中的信息。图中给出模型完成“从单词中删去随机符号”这一简单任务的上下文学习表现，分别有和没有自然语言任务描述（见原文 3.9.2 节）。大模型更陡的“上下文学习曲线”说明它们从上下文信息中学习任务的能力更强；在广泛的任务上我们看到定性相似的行为。*

**图中文字翻译与读法**：

- 横轴 Number of Examples in Context（K，上下文中的示例数；刻度 0、$10^{0}$、$10^{1}$，对数刻度），纵轴 Accuracy (%)（准确率）。上方标出 Zero-shot（K=0）、One-shot（K=1）和 Few-shot（K 更大）三个区段。三组线分别是 175B Params（蓝）、13B Params（橙）、1.3B Params（绿）；每组中，实线是带自然语言提示（Natural Language Prompt，即任务描述）的结果，虚线是没有提示（No Prompt）的结果。
- 175B 模型：K=0 时，有提示约 8%，没有提示接近 0；K=1 时，有提示约 46%，没有提示约 26%；K 增大到几十后两条线汇合，都约 66% 到 67%。13B 模型随 K 增加缓慢上升到约 25%，1.3B 模型始终在约 5% 以下（均为从图上读出的近似值）。这与表 3.10 中 175B 的符号插入（RI）结果一致：零样本 8.26%、单样本 45.4%、少样本（K=100）67.2%。
- **读图结论**：（1）在同一个模型内，给的示例越多准确率越高（“上下文学习曲线”），且这个过程不涉及任何梯度更新；（2）自然语言任务描述在示例很少时帮助最大（K=1 时约 20 个百分点），示例足够多后帮助消失；（3）这条曲线的陡度强烈依赖模型规模：同样增加示例，175B 模型从 K=0 到 K=10 涨了 50 多个点，而 1.3B 几乎没有变化。作者说，这个任务的结果特别鲜明，但随模型规模和上下文示例数改善这一总体趋势在多数任务上都成立。

## 三、评测设定：微调、少样本、单样本、零样本（原文第 2 节）

作者把“一个任务要靠多少任务专用数据”看作一条光谱，列出至少四个点（图 2.1 以英译法为例）。

![图 2.1：零样本、单样本和少样本，对照传统微调](rendered_figures/fig2-1-settings.png)

*图 2.1（原文 Figure 2.1，第 7 页）：零样本、单样本和少样本，与传统微调对比。上图展示用语言模型完成一个任务的四种方法：微调是传统方法，而本文研究的零样本、单样本、少样本，要求模型在测试时只做前向传播就完成任务。少样本设置下我们通常给模型呈现几十个示例。所有任务描述、示例和提示的确切措辞见原文附录 G。*

**图中文字翻译与读法**：

- **左半 “The three settings we explore for in-context learning”（我们探索的三种上下文学习设置）**：
  - Zero-shot（零样本）：模型只收到自然语言的任务描述，不做梯度更新。上下文两行：`Translate English to French:`（task description，任务描述）与 `cheese =>`（prompt，提示，等待模型补全）。
  - One-shot（单样本）：除任务描述外，模型看到一个任务示例：`sea otter => loutre de mer`（example，示例），再接 `cheese =>`。
  - Few-shot（少样本）：除任务描述外，模型看到若干示例：`sea otter => loutre de mer`、`peppermint => menthe poivrée`、`plush giraffe => girafe peluche`（examples，示例），再接 `cheese =>`。
- **右半 “Traditional fine-tuning (not used for GPT-3)”（传统微调，GPT-3 未使用）**：模型要在一个很大的示例语料上经过反复的梯度更新训练：example #1（`sea otter => loutre de mer`）后跟一个黄色的 gradient update（梯度更新），example #2（`peppermint => menthe poivrée`）后又一个梯度更新，……一直到 example #N（`plush giraffe => girafe peluche`），最后才是提示 `cheese =>`。
- **读图结论**：左右的根本区别是示例用在哪里：微调把示例当作训练数据，每个示例都引起一次权重更新；上下文学习把示例当作输入文本的一部分，权重不变。两者在测试时的区别是，前者的任务知识沉淀进参数里，后者只存在于当前这一次输入的上下文中，换一个输入就消失。

四种设置的定义和利弊，按原文整理如下：

| 设置 | 示例怎么用 | 原文列出的优点 | 原文列出的缺点 |
|---|---|---|---|
| 微调（Fine-Tuning，FT） | 在任务专用有监督数据集上更新权重，通常需要数千到数十万条标注样本 | 在许多基准上表现很强 | 每个任务都要新数据集；可能在分布外泛化差；可能利用训练数据的虚假特征，导致和人类比较不公平。本文不对 GPT-3 做微调 |
| 少样本（Few-Shot，FS） | 推理时在上下文里给 $K$ 个“上下文加补全”示例，再给一个只含上下文的实例让模型补全；不更新权重。$K$ 通常取 10 到 100（受 $n_{\text{ctx}}=2048$ 限制） | 大幅减少对任务专用数据的需求；减少从一个又大又窄的微调数据集中学到过窄分布的可能 | 目前效果远不如 SOTA 微调模型；仍需要少量任务数据 |
| 单样本（One-Shot，1S） | 与少样本相同，但只给 1 个示例（外加任务的自然语言描述） | 最接近某些任务向人类说明的方式（例如在众包平台上给 1 个示范） | 与少样本类似，信息更少 |
| 零样本（Zero-Shot，0S） | 不给示例，只给任务的自然语言指令 | 最方便，最有望稳健，避免虚假相关 | 最难：有时连人类没看示例也不清楚任务格式（例如“做一张 200 米跑世界纪录的表”），所以某种意义上“不公平地难” |

作者强调：研究零样本、单样本、少样本不是把它们当成互相竞争的做法，而是当成在“特定基准上的表现”和“样本效率”之间取不同权衡的不同问题设置；少样本结果很多只略低于微调 SOTA，而单样本甚至零样本也许才是和人类表现最公平的比较，也是未来的重要目标。

**评测细节**（原文 2.4 节）：

- **少样本的取样**：对评测集中每个样例，从该任务的训练集中随机抽 $K$ 个示例作为条件，示例之间用 1 或 2 个换行分隔（视任务而定）。LAMBADA 和 StoryCloze 没有监督训练集，就从开发集抽示例、在测试集评测；原始 Winograd 只有一个数据集，所以直接从中抽取条件示例。
- **$K$ 的选取**：$K$ 可取 0 到上下文窗口能容纳的最大值（$n_{\text{ctx}}=2048$，通常容纳 10 到 100 个示例）。更大的 $K$ 通常但并不总是更好；当有独立的开发集和测试集时，在开发集上试几个 $K$，把最好的值用到测试集。某些任务（见附录 G）还在示例之外（$K=0$ 时则替代示例）加一段自然语言提示。
- **多选题**：给 $K$ 个“上下文加正确答案”的示例，再给一个只有上下文的实例，比较每个候选补全的语言模型似然。多数任务比较**每 token 的似然**（用来消除长度影响）；ARC、OpenBookQA、RACE 三个数据集在开发集上发现，用补全的无条件概率归一化更好，即计算 $\dfrac{P(\text{completion}\mid\text{context})}{P(\text{completion}\mid\text{answer context})}$，其中 answer context 是字符串 `"Answer: "` 或 `"A: "`，只起提示“这里该填答案”的作用。
- **二分类**：给选项起更有语义的名字（例如 “True”/“False”，而不是 0/1），再当作多选题；有时也采用 Raffel 等（T5）的写法（见附录 G）。
- **自由形式补全**：用束搜索（beam search），参数同 T5：束宽 4、长度惩罚 $\alpha=0.6$；按数据集的惯例用 F1、BLEU 或精确匹配（exact match）打分。
- **报告哪个集合**：有公开测试集的任务报告测试集结果，对每个模型尺寸和每种设置（零样本、单样本、少样本）都报告；测试集不公开时，模型往往太大放不进测试服务器，就报告开发集结果。只对少数任务（SuperGLUE、TriviaQA、PIQA）实际提交了测试服务器，并且只提交 175B 的少样本结果（原文此处写作“200B”，应为笔误，见文末备查表）。

## 四、模型、数据与训练

### 4.1 模型与架构（原文 2.1 节、表 2.1）

GPT-3 沿用 GPT-2 的模型和架构（包括改进的初始化、预归一化 pre-normalization、可逆分词 reversible tokenization），**唯一的结构差别**是 Transformer 各层中交替使用稠密（dense）注意力和局部带状稀疏（locally banded sparse）注意力，类似 Sparse Transformer（Child 等 2019）。为了研究性能对模型大小的依赖，作者训练了 8 种尺寸，跨三个数量级，从 1.25 亿到 1750 亿参数，最大的就叫 GPT-3。所有模型的上下文窗口都是 $n_{\text{ctx}}=2048$ token，前馈层维度恒为瓶颈层的 4 倍（$d_{\text{ff}}=4\,d_{\text{model}}$）。模型沿深度和宽度两个维度切分到多块 GPU 上，以减少节点间的数据传输；各模型的具体结构参数是按计算效率和 GPU 上的负载均衡选的；此前工作（Kaplan 等）表明，验证损失对这些参数在较宽范围内并不敏感。

读法：模型越大，batch size 越大、学习率越小（与 Kaplan 等和 McCandlish 等的发现一致：大模型能用更大的 batch，但需要更小的学习率；batch size 的选择参考了训练中测得的梯度噪声尺度）。自行验算：用 $n_{\text{params}}\approx12\,n_{\text{layers}}\,d_{\text{model}}^{2}+(n_{\text{vocab}}+n_{\text{ctx}})\,d_{\text{model}}$（词表 $n_{\text{vocab}}=50257$）可以复现 125M、760M、2.7B、6.7B、175B 等规模，例如 175B 为 $12\times96\times12288^{2}\approx1.739\times10^{11}$ 加 embedding 约 $6.4\times10^{8}$，合计约 $1.746\times10^{11}$，与附录表 D.1 的 174,600M 一致。原表有两处结构数字不自洽（自行发现，原文未解释）：13B 一行的 $d_{\text{model}}$ 印作 5140，而 $40\times128=5120$，并且用 5120 算出的参数量（约 12,851M）才与表 D.1 的 12,850M 吻合；XL 一行的 $24\times128=3072\neq2048$。因此可以认为 5140 是笔误。

### 4.2 训练数据（原文 2.2 节、表 2.2、附录 A）

Common Crawl 几乎有一万亿词，规模足以训练最大的模型而不用在同一条序列上更新两次。但作者发现，未过滤或轻度过滤的 Common Crawl 平均质量低于精选数据集，所以采取了三个步骤提高平均质量：

1. **按质量过滤**：下载 Common Crawl 的一个版本，并按其与一批高质量参考语料的相似度过滤（附录 A：用一个逻辑回归分类器区分“高质量”和原始 Common Crawl。正例是 WebText、Wikipedia 和作者的网络图书语料等精选数据，负例是未过滤的 Common Crawl；特征来自 Spark 的标准分词器和 HashingTF。用分类器给 Common Crawl 文档打分后，只在 `np.random.pareto(α) > 1 − document_score` 时保留该文档，取 $\alpha=9$，目的是大多保留分类器打高分的文档，同时仍然纳入一些分布外的文档；$\alpha$ 的取值使得分数分布与 WebText 上分类器分数的分布吻合。作者发现这样重新加权，在一批分布外的生成文本样本上的损失更低，即质量提高）；
2. **模糊去重**（fuzzy deduplication）：在每个数据集内部和数据集之间做文档级去重，既防止冗余，也保证留出的验证集能真实度量过拟合（附录 A：用 Spark 的 MinHashLSH，10 个哈希，特征同上；还从 Common Crawl 中模糊地去掉了 WebText）。总体上这一步使数据集平均缩小约 10%；
3. **加入已知的高质量语料**：扩充了 WebText（在更长时期内抓取链接得到，首次描述见 Kaplan 等）、两个互联网图书语料（Books1 和 Books2）和英文 Wikipedia。

Common Crawl 取自 2016 到 2019 年的 41 个月度分片，过滤前约 45TB 压缩纯文本，过滤后约 570GB，大致相当于 4000 亿个 BPE token。**训练时各数据集不按大小比例取样**，质量更高的数据集被更频繁地取样，使得 Common Crawl 和 Books2 在训练中被取样不到一次，其他数据集被取样 2 到 3 次；作者说这实质上是接受少量的过拟合，换取更高质量的训练数据。

**表 2.2：训练 GPT-3 所用的数据集（原文表 2.2，第 9 页）。“训练混合中的权重”指训练中来自某数据集的样本所占比例，刻意不与数据集大小成比例；因此训练 3000 亿 token 时，一些数据集被看到最多 3.4 次，而另一些不到一次**

| 数据集 | 数量（token） | 训练混合中的权重 | 训练 300B token 时经过的 epoch 数 |
|---|---:|---:|---:|
| Common Crawl（过滤后） | 410 billion | 60% | 0.44 |
| WebText2 | 19 billion | 22% | 2.9 |
| Books1 | 12 billion | 8% | 1.9 |
| Books2 | 55 billion | 8% | 0.43 |
| Wikipedia | 3 billion | 3% | 3.4 |

读法：Common Crawl 占数据量的绝大部分（410B 对其余加起来约 89B），但训练里只占 60% 的权重；小而精的 WebText2、Books1、Wikipedia 被重复读 2 到 3 次以上。表中权重加起来是 101%（四舍五入的结果）。自行验算：按权重乘以 300B 再除以数据量，WebText2 约为 3.5 个 epoch、Wikipedia 约为 3.0 个，与表中的 2.9 和 3.4 有出入，其余几行吻合；原文没有解释差别来源，使用这两个数时需要留意。

原文还说明了一个方法论上的担忧：在广泛互联网数据上预训练的语言模型，尤其是能记住海量内容的大模型，下游任务的测试集或开发集可能在预训练中被无意间看到（污染，contamination）。作者曾搜索并试图去掉训练数据与本文研究的全部基准的开发集、测试集的重叠，但**过滤程序有一个 bug，使得一些重叠被忽略了**，由于训练成本太高，无法重训；因此原文第 4 节专门刻画了残留重叠的影响（见本文第八节）。

### 4.3 训练过程（原文 2.3 节、附录 B）与计算量

- **序列的组织**：训练时总是用满 $n_{\text{ctx}}=2048$ token 的序列，文档比 2048 短时就把多个文档拼进一条序列以提高计算效率；拼在一起的多个文档不做任何特殊的注意力掩码，而是用一个特殊的 end-of-text token 分隔，让模型能推断出被该 token 隔开的上下文互不相关。数据在训练中无放回地取样（直到某个 epoch 边界），以尽量减少过拟合。
- **优化器与超参数**：Adam，$\beta_1=0.9$、$\beta_2=0.95$、$\epsilon=10^{-8}$；梯度全局范数裁剪到 1.0；学习率用余弦衰减，在 2600 亿 token 内降到初始值的 10%，之后继续以 10% 的学习率训练；前 3.75 亿 token 线性 warmup；batch size 在前 40 亿到 120 亿 token（视模型大小）内从一个很小的值（3.2 万 token）线性增大到表 2.1 的完整值；所有模型用 0.1 的权重衰减（weight decay）做少量正则。
- **硬件与并行**：为了训练大模型而不爆显存，每个矩阵乘内部用模型并行，网络层之间也用模型并行；所有模型都在 V100 GPU 上训练，集群是 Microsoft 提供的高带宽集群的一部分。
- **训练步数**（自行验算）：总 token 数除以 batch size，GPT-3 175B 约 $3\times10^{11}/3.2\times10^{6}\approx9.4\times10^{4}$ 步；小模型（0.5M batch）约 60 万步。

## 六、各类任务的结果（原文 3.1 至 3.8 节）

| SOTA（零样本）（Radford 等 2019，即 GPT-2） | 35.8 |
| GPT-3 零样本 | **20.5** |

**LAMBADA**。LAMBADA 考察文本中的长程依赖：要预测需要读完一段上下文才能确定的句子的最后一个词。近来有人（Bisk 等 2020）认为，在这个难基准上继续扩大规模的回报在递减：两个近期 SOTA（Megatron 与 Turing-NLG）之间模型大小翻倍只带来 1.5% 的改进，并提出“继续把硬件和数据扩大几个数量级不是前进的道路”。作者发现这条路依然有希望：零样本下 GPT-3 在 LAMBADA 上达到 76%，比此前 SOTA 高 8 个百分点。

LAMBADA 也展示了少样本学习的灵活性。尽管任务里补全的永远是句子的最后一个词，标准语言模型并不知道这一点，所以不仅给正确结尾分配概率，也给段落的其他有效续写分配概率；过去的部分解决办法是停用词过滤（禁止“续写型”词）。少样本设置则让作者能把任务“框”成完形填空，让模型从示例中推断需要的补全恰好是一个词。所用的填空格式如下：

```text
Alice was friends with Bob. Alice went to visit her friend ____. → Bob
George bought some baseball equipment, a ball, a glove, and a ____. →
```

在这种格式的示例下，少样本 GPT-3 的准确率达到 86.4%，比此前 SOTA 高 18 个百分点以上；少样本性能随模型规模强烈提升：这一设置使最小模型的准确率下降近 20 个点，却使 GPT-3 提高了 10 个点。填空方法在单样本下无效，总比零样本差，也许是因为所有模型还需要几个示例才能识别出这个模式。一个需要提醒的地方：污染分析发现 LAMBADA 数据集相当一部分似乎出现在训练数据里，但原文第 4 节（本文第八节）的分析表明其对性能的影响可以忽略（干净子集的得分与整个数据集相差不到 0.5%）。

**HellaSwag**：从多个候选中为故事或指令挑选最合适的结尾，样例是用对抗方式从语言模型出发挖掘的，对语言模型难、对人类容易（人类准确率 95.6%）。GPT-3 单样本 78.1%、少样本 79.3%，高于一个微调的 15 亿参数语言模型的 75.4%，但仍明显低于微调多任务模型 ALUM 的 SOTA 85.6%。

**StoryCloze**（2016 版）：为五句话的故事选出正确的结尾句。GPT-3 零样本 83.2%，少样本 87.7%（$K=70$），比基于 BERT 的微调 SOTA 低 4.1%，但比此前的零样本结果高约 10%。

### 6.2 闭卷问答（原文 3.2 节）

闭卷（closed-book）问答要求直接用模型参数里存的知识回答常识性问题。通常的做法是“开卷”（open-book）：用信息检索系统找到相关文本，再让模型条件于问题和检索文本生成答案。Roberts 等（2020）证明大语言模型可以不依赖外部信息直接回答，称之为闭卷。作者在他们的 3 个数据集上用同样的划分评测 GPT-3：Natural Questions（NQs）、WebQuestions（WebQs）、TriviaQA。注意这里的少样本、单样本、零样本评测比此前的闭卷问答更严格：不仅不许用外部内容，连在问答数据集本身上做微调也不允许。

| 设置 | NaturalQS | WebQS | TriviaQA |
|---|---:|---:|---:|
| RAG（微调，开放域）（Lewis 等 2020） | **44.5** | **45.5** | **68.0** |
| T5-11B+SSM（微调，闭卷）（Roberts 等 2020） | 36.6 | 44.7 | 60.5 |
| T5-11B（微调，闭卷） | 34.5 | 37.4 | 50.1 |
| GPT-3 零样本 | 14.6 | 14.4 | 64.3 |
| GPT-3 单样本 | 23.0 | 25.3 | **68.0** |
| GPT-3 少样本 | 29.9 | 41.5 | **71.2** |

读法与原文结论：

- **TriviaQA**：零样本 64.3%，单样本 68.0%，少样本 71.2%。零样本已比微调的 T5-11B（50.1）高 14.2，也比预训练时加入了问答专用片段预测（SSM）的版本（60.5）高 3.8；单样本再提高 3.7，追平开放域问答 SOTA（RAG：它不仅微调，还使用基于 15.3B 参数稠密向量索引、涵盖 2100 万文档的学习型检索机制）；少样本又高出 3.2。
- **WebQs**：零样本 14.4%，单样本 25.3%，少样本 41.5%，对比微调 T5-11B 的 37.4% 和 T5-11B+SSM 的 44.7%。少样本接近微调 SOTA。相对 TriviaQA，WebQs 从零样本到少样本的涨幅大得多（零样本、单样本都很差），原文推测 WebQs 的问题和/或答案风格对 GPT-3 来说可能是分布外，但少样本设置下它能适应这个分布。
- **NQs**：14.6%、23.0%、29.9%，对比微调 T5-11B+SSM 的 36.6%。与 WebQs 类似，从零样本到少样本的大幅提升可能意味着分布偏移，也可能解释它比 TriviaQA 和 WebQs 更差的原因：NQs 的问题偏向 Wikipedia 上非常细粒度的知识，可能在检验 GPT-3 容量和预训练分布的极限。
- 总体：三个数据集中的一个上，GPT-3 的单样本追平开放域微调 SOTA；另外两个上，尽管没有微调，也接近闭卷 SOTA。三个数据集上性能都随模型规模非常平滑地提升（图 3.3 与附录图 H.7），原文认为这或许反映了“模型容量直接转化为参数里吸收的知识”。

### 6.3 翻译（原文 3.3 节）

GPT-2 为了容量考虑，用一个多语言文档集合过滤出只含英语的数据集，即便如此它在法英翻译上也有非平凡表现（尽管只训练了剩下的约 10MB 法语文本）。GPT-3 容量比 GPT-2 大了两个多数量级，所以作者也扩大训练集的范围，纳入更多其他语言，但这仍是有待改进的方面。训练数据按词数计仍以英语为主（93%），另有 7% 其他语言的文本（语言清单在补充材料中）。为了更好地理解翻译能力，作者在常见的语言对之外又加入了德语和罗马尼亚语。

已有的无监督机器翻译方法常把一对单语数据集上的预训练与回译（back-translation）结合起来。相比之下 GPT-3 从多语言自然混合的数据中学习，在词、句、文档层面把语言混在一起，且只用一个并非为任何特定任务设计的训练目标。但作者提醒：单样本和少样本设置与此前无监督工作并不严格可比，因为它们使用了少量配对示例（1 个或 64 个），相当于最多一两页的上下文内训练数据。

**表 3.4：少样本 GPT-3 在翻译成英语时比此前无监督 NMT 工作高 5 个 BLEU（原文表 3.4，第 15 页）。在 WMT'14 Fr↔En、WMT'16 De↔En、WMT'16 Ro↔En 上用 `multi-bleu.perl` 与 XLM 的分词方式报告 BLEU，以便与此前无监督 NMT 工作最直接比较；SacreBLEU 的结果见附录 H。原表中下划线表示无监督或少样本 SOTA，粗体表示监督 SOTA（作者对其有相对信心）**

### 6.4 Winograd 类任务（原文 3.4 节）

Winograd Schemas Challenge 是经典 NLP 任务：判断一个在语法上有歧义、但语义上对人明确的代词指代哪个词。最近微调语言模型在原始 Winograd 数据集上已接近人类水平，但对抗式挖掘的 Winogrande 仍显著落后于人类。作者在两者上都测试了三种设置。

在 Winograd 上用原始的 273 个 Winograd schema，采用 GPT-2 论文中的“部分评估”（partial evaluation）方法：比较在正确上下文和错误上下文下，目标补全的概率（附录 G 的例子：“Grace was happy to trade me her sweater for my jacket. She thinks the sweater”对“…She thinks the jacket”，目标补全“looks dowdy on her.”）。这与 SuperGLUE 里的 WSC 不同：WSC 以二分类形式给出，需要做实体抽取才能转成这里的形式。GPT-3 在 Winograd 上零样本、单样本、少样本分别为 88.3%、89.7%、88.6%，没有明显的上下文学习效应，但每种设置都离 SOTA 和估计的人类表现只差几个点。污染分析发现训练数据里含有一些 Winograd schema（手工检查确认有 132 个 schema 出现在训练集中，但格式与给模型的任务格式不同），但对结果似乎只有很小影响（见原文第 4 节，本文第八节），所以这些结果在表中带 \* 标记（污染分析见本文第八节）。

在更难的 Winogrande 上，GPT-3 零样本 70.2%、单样本 73.2%、少样本 77.7%，这里能看到上下文学习的收益。作为对比：微调 RoBERTa 约 79%，SOTA 为 84.6%（微调的大容量模型 T5），人类表现 94.0%（Sakaguchi 等报告）。

### 6.5 常识推理（原文 3.5 节）

三个试图刻画物理或科学推理的数据集（区别于补全、阅读理解、广义知识问答）：

- **PIQA**（PhysicalQA）：关于物理世界如何运作的常识问题，用来探测对世界的具身理解。GPT-3 零样本 81.0%、单样本 80.5%、少样本 82.8%（后者在 PIQA 测试服务器上测得），优于此前微调 RoBERTa 的 SOTA 79.4%。PIQA 随模型规模的扩展相对平缓，仍比人类低 10 个百分点以上，但 GPT-3 的少样本乃至零样本都超过了当前 SOTA。污染分析标记了 PIQA 的潜在污染问题（尽管测试标签是隐藏的），所以作者保守地给结果加 \*，见原文第 4 节（本文第八节）。
- **ARC**：三到九年级科学考试的多选题。**Challenge** 版本已过滤到简单统计方法或信息检索方法无法答对的题目，GPT-3 零样本 51.4%、单样本 53.2%、少样本 51.5%，接近 UnifiedQA 里微调 RoBERTa 基线的 55.9%。**Easy** 版本（上述两类基线至少有一个答对的题目），GPT-3 为 68.8%、71.2%、70.1%，略高于该微调 RoBERTa 基线；但两者都远低于总体 SOTA（UnifiedQA），后者在 Challenge 上比 GPT-3 少样本高 27%，在 Easy 上高 22%。
- **OpenBookQA**：GPT-3 从零样本到少样本提升明显，但仍比总体 SOTA 低 20 多个点；少样本表现类似排行榜上微调的 BERT Large 基线。

总的来说，GPT-3 在常识推理任务上的上下文学习结果参差：PIQA 和 ARC 上单样本、少样本只有很小且不一致的增益，OpenBookQA 上则显著提升；但在新的 PIQA 数据集上，所有评测设置下 GPT-3 都创造了 SOTA。

### 6.8 自然语言推断 NLI（原文 3.8 节）

## 七、合成与定性任务：现场适应能力（原文 3.9 节）

为了探测 GPT-3 在少样本（或零样本、单样本）下的能力范围，作者设计了几类任务：需要现场做简单计算推理的，需要识别训练中不太可能出现过的新模式的，以及需要快速适应不寻常任务的。具体有：算术；重排或还原单词字母的几个任务（不太可能在训练中原样见过）；SAT 式类比题；以及几个定性任务（用新词造句、纠正英语语法、新闻文章生成）。作者说会公开这些合成数据集，以促进对语言模型测试时行为的研究。

**少样本结果**：加减法在位数少时 GPT-3 表现出很强的熟练度：两位数加法 100% 准确，两位数减法 98.9%，三位数加法 80.2%（正文数字，表 3.9 为 80.4%），三位数减法 94.2%。位数增加后性能下降，但四位数运算仍有约 25 到 26% 的准确率，五位数运算约 9 到 10%，这说明模型至少有一定的向更多位数泛化的能力。两位数乘法（计算量尤其大的运算）准确率 29.2%；一位数复合运算（例如 9\*(7+5)）21.3%，说明它不只是会单一运算。

**小模型和零样本、单样本**：小模型在所有这些任务上表现都很差，即便是第二大的 130 亿参数模型，两位数加减法也只有一半左右能做对，其余运算都不到 10%（自行验算：13B 少样本的 2D+ 为 55.5%、2D- 为 52.4%，其余均低于 10%）。单样本和零样本相对少样本有所下降，这说明对任务的适应（至少是对任务的识别）对正确做这些计算很重要；但单样本仍然相当强，完整 GPT-3 的零样本表现就已经明显好于所有较小模型的少样本。

**是否只是死记**：为了抽查模型是不是在记忆具体的算术题，作者在训练数据中搜索测试集里的三位数算术题，同时搜索 `<NUM1> + <NUM2> =` 和 `<NUM1> plus <NUM2>` 两种写法。2,000 道加法题里只找到 17 道匹配（0.8%），2,000 道减法题里只找到 2 道（0.1%），说明只有微不足道的一小部分正确答案可能来自记忆。此外，检查错误答案发现，模型常犯“忘了进位 1”这类错误，说明它确实在尝试进行相应的计算，而不是在背一张表。

### 7.2 单词扰乱与操作任务（原文 3.9.2 节）

为了测试 GPT-3 能否从几个示例中学会新的符号操作，作者设计了 5 个“字符操作”任务：给模型一个经过字母重排、加字符或删字符变形的单词，要求它还原。

| 任务（缩写） | 内容 | 例子 |
|---|---|---|
| 循环字母（CL，cycle letters in word） | 单词的字母被循环移位，后跟 “=”，要求输出原词 | `lyinevitab` → `inevitably` |
| 除首末外的变位词（A1，anagrams of all but first and last characters） | 除第一个和最后一个字母外，其余字母被随机打乱 | `criroptuon` = `corruption` |
| 除首末各两个外的变位词（A2，anagrams of all but first and last 2 characters） | 除前两个和后两个字母外，其余字母被随机打乱 | `opoepnnt` → `opponent` |
| 随机插入（RI，random insertion in word） | 在单词每两个字母之间插入随机标点或空格，要求还原 | `s.u!c/c!e.s s i/o/n` = `succession` |
| 单词反转（RW，reversed words） | 给出倒着拼写的单词，要求还原 | `stcejbo` → `objects` |

每个任务生成 10,000 个例子：取 Norvig（2009）统计的最常见 10,000 个词中长度大于 4 个字符且小于 15 个字符的词。少样本结果见图 3.11（$K=100$）。任务表现随模型规模平滑增长（随机插入任务例外，在 175B 处出现陡升，最大模型大多数时候能解决）。完整 GPT-3 在随机插入任务上达到 66.9%（正文数字，表 3.10 为 67.2%），循环字母 38.6%（表 37.9%），较容易的变位词任务 40.2%（表 39.7%），较难的变位词任务（只固定首末字母）15.1%。**所有模型都无法反转单词里的字母。**

单样本下性能明显更弱（降低一半或更多），零样本下模型几乎完成不了任何一个任务（表 3.10）。作者据此认为，模型确实是在测试时学会这些任务的：它零样本做不了，而且这些任务的人造性质使它们不太可能出现在预训练数据里（但不能确证）。

原文还指出两点：（1）这些任务需要字符级的操作，而 BPE 编码平均每个 token 对应约 0.7 个词，所以在语言模型看来，要成功不仅要操作 BPE token，还要理解并拆开它们的子结构；（2）CL、A1、A2 都不是双射（即还原的单词不是被打乱单词的确定函数），要求模型进行一些搜索才能找到正确的还原，所以这些技能似乎需要不平凡的模式匹配和计算。

### 7.4 新闻文章生成（原文 3.9.4 节）

此前的生成模型工作（如 GPT-2）曾通过“给定人写的一个合理的新闻首句，让模型条件采样”来定性测试合成“新闻文章”的能力。但 GPT-3 的训练集里新闻比重比 GPT-2 低得多，所以直接用无条件采样生成新闻效果较差：例如 GPT-3 常把给出的新闻首句当作一条推文，然后接着发合成的回复或后续推文。为解决这个问题，作者借助 GPT-3 的少样本学习能力：在模型上下文中给出**三篇**此前的新闻文章作为条件；再给出下一篇文章的标题和副标题，模型就能可靠地生成新闻体裁的短文。

**如何度量质量**：作者让人来区分 GPT-3 生成的文章和真文章。生成式语言模型被训练去匹配人类所生成内容的分布，所以人类无法区分二者，是衡量质量的一个潜在重要指标。具体做法：任意选取 newser.com 的 25 个文章标题和副标题（平均长度 215 词），用 125M 到 175B（GPT-3）的语言模型生成这些标题和副标题的后续（平均长度 200 词）。对每个模型，大约 80 位美国参与者做一份测验：给出真实的标题和副标题，后接人写的文章或模型生成的文章；参与者要选择文章是“极可能由人写的”、“更可能由人写的”、“我不知道”、“更可能由机器写的”或“极可能由机器写的”。所选文章不在模型训练数据里，模型输出是用程序格式化和选取的，防止人为挑选；所有模型使用相同的上下文来条件化输出，预训练时使用相同的上下文大小，也使用相同的文章标题和副标题。另外设了一个对照实验以控制参与者的投入和注意力：同样的格式，但文章来自一个故意做差的“对照模型”（一个 160M 参数、没有上下文、输出随机性提高的模型）。

- 在 175B 上，人类准确率“勉强高于随机”，约 52%。脚注 6 指出：如果一个模型总是产生比人类文章更令人印象深刻的文本，则人类在这个任务上的成绩有可能降到 50% 以下；确实有许多参与者个人得分低于 50%。
- 生成的新闻文章样例见原文图 3.14 与 3.15。图 3.14 是人类最难与真文章区分的 GPT-3 文章（标题 “United Methodists Agree to Historic Split”，副标题 “Those who oppose gay marriage will form their own denomination”，准确率 12%，即只有 12% 的判断认出它是机器生成）；图 3.15 是人类最容易区分的文章（标题 “Star's Tux Promise Draws Megyn Kelly's Sarcasm”，副标题 “Joaquin Phoenix pledged to not change for each awards event”，准确率 61%）。全文较长，本文不转录。
- 事实错误可以是文章由模型生成的线索：与人类作者不同，模型无法接触标题所指的具体事实，也不知道文章是何时写的；其他线索包括重复、不合逻辑的转折（non sequitur）和不寻常的措辞，但这些往往很微妙，不会被注意到。
- 自动判别器（如 GROVER 和 GLTR）可能比人类评估者更成功（Ippolito 等 2019），这是未来研究的一个有希望的方向。Ippolito 等还发现人类检测准确率随观察的 token 增多而提高。

## 八、基准污染：度量与防止对基准的记忆（原文第 4 节、附录 C）

### 8.1 为什么要查，查什么

训练数据来自互联网，所以模型可能在训练中见过某些基准的测试集。要在互联网规模的数据中准确检测测试集污染，是一个新的研究领域，还没有成熟的最佳实践。虽然许多人训练大模型时并不调查污染，作者认为随着预训练数据集规模增大，这个问题越来越重要。这种担忧并非纯假设：最早在 Common Crawl 数据上训练语言模型的论文之一（Trinh 与 Le 2018）就检测并删除了一篇与其评测数据集重叠的训练文档；GPT-2 也做了事后的重叠分析，其结果相对令人鼓舞：虽然模型在训练和测试重叠的数据上表现略好，但由于被污染的数据比例很小（通常只有几个百分点），并没有显著影响报告的结果。

GPT-3 处于有些不同的状态：一方面，数据集和模型规模比 GPT-2 大约两个数量级，并且包含大量 Common Crawl，污染和记忆的可能性增加；另一方面，正因为数据量大，即便是 GPT-3 175B 相对于与训练集去重过的留出验证集，也没有显著过拟合训练集（图 4.1）。因此作者预期污染很可能频繁出现，但其影响也许没有担心的那么大。

![图 4.1：GPT-3 的训练曲线与验证曲线](rendered_figures/fig4-1-training-curves.png)

*图 4.1（原文 Figure 4.1，第 31 页）：GPT-3 训练曲线。在我们训练分布去重后的一个验证划分上度量训练过程中的模型表现。训练与验证表现之间有一些差距，但差距随模型规模和训练时间增长得很少，说明这个差距大部分来自难度差异而不是过拟合。*

### 8.2 过滤的失败与干净子集分析

作者最初试图主动搜索并删除训练数据与本文所研究全部基准的开发集、测试集之间的重叠（附录 C：搜索所有测试集或开发集与训练数据之间的 13-gram 重叠；这里一个 gram 指小写的、按空白分隔的、没有标点的词。对重叠部分删掉冲突的 13-gram 以及其周围 200 个字符的窗口，把原文档拆成多段，短于 200 字符的段被丢弃；被拆成超过 10 段的文档视为被污染而整篇删除。起初是一次冲突就删除整篇文档，但那会因误报而过度惩罚书籍这类长文档，例如测试集基于 Wikipedia，而某篇 Wikipedia 文章引用了某本书的一行。还忽略了与超过 10 篇训练文档匹配的 13-gram，因为检查后发现它们多是常见文化用语、法律套话等，属于想让模型学到的内容，而不是不想要的、与测试集的特定重叠）。**但一个 bug 导致只部分删除了检测到的重叠**；对长文档（如书籍）这个过滤程序整体失败了。由于训练成本，重新训练不可行。因此作者详细研究了残留的重叠如何影响结果。

对每个基准，作者构造一个“干净”（clean）版本：去掉所有可能泄漏的样例，大致定义为与预训练集中任何内容有 13-gram 重叠的样例（样例短于 13-gram 时，则是与整个样例重叠的）。目标是非常保守地标记任何可能的污染，从而得到一个有很高把握不被污染的干净子集。然后在这些干净基准上评测 GPT-3，并与原始分数比较：如果干净子集上的得分与整个数据集相近，说明即使存在污染，也没有显著影响报告结果；如果干净子集得分更低，说明污染可能夸大了结果。

**重叠方法（附录 C）**：对每个数据集用可变的词数 $N$ 来检查重叠，$N$ 取该数据集样例长度（以词计、忽略标点、空白和大小写）的第 5 百分位；由于较小 $N$ 会有虚假碰撞，对非合成任务设最小值 8；出于性能考虑，对所有任务设最大值 13。与 GPT-2 用布隆过滤器计算概率界不同，这里用 Apache Spark 计算所有训练集与测试集之间的**精确**碰撞；并且是与完整训练语料计算，尽管实际只训练了过滤后 Common Crawl 文档的约 40%（按 2.2 节）。“脏”样例定义为与训练集任一文档有任何一个 $N$-gram 碰撞的样例，“干净”样例是没有碰撞的样例。

![图 4.2：基准污染分析](rendered_figures/fig4-2-contamination.png)

*图 4.2（原文 Figure 4.2，第 32 页）：基准污染分析。我们为每个基准构造了清洗后的版本，以检查训练集中的潜在污染。横轴是对数据集中已知有高置信度是干净的部分的保守下界，纵轴是只在验证过的干净子集上评测时性能的差异。大多数基准的性能变化可以忽略，但有些被标记出来做进一步审查。检查后我们发现 PIQA 和 Winograd 的结果有一些污染的证据，并在原文第 3 节中用星号标出对应结果。我们没有发现其他基准受影响的证据。*

**图中文字翻译与读法**：横轴 Percentage of Data Clean in Dataset（数据集中干净数据的百分比，0% 到 100%），纵轴 Percent Change in Performance (Accuracy, F1 or BLEU)（性能变化百分比，指标为准确率、F1 或 BLEU，−30% 到 30%）。每个蓝点是一个基准。右侧绿色向上箭头 “eval on only clean data did better”（仅在干净数据上评测更好），红色向下箭头 “eval on all data (including dirty) did better”（在全部数据（含脏数据）上评测更好）。被标注的点：QuAC（约 +20%，干净比例约 1%）、SQuADv2（约 −2%，约 6%）、DROP（约 −21%，约 7%）、Symbol Insertion（约 0%，约 14%）、Winograd（约 −3%，约 40%）、PIQA（约 −4%，约 70%）、WMT16 en->de 与 de->en（约 −3% 与 −5%，约 75%）、Anagrams 2（约 −7%，约 93%）、Anagrams 1（约 −8%，约 97%）、Reversed Words（约 −26%，约 93%）。**读图结论**：绝大多数点聚集在 0 附近（±3% 以内），点的位置与干净比例之间看不出相关性；少数离群点需要逐个解释，见下一小节。作者的总结是：要么保守的方法大大高估了污染，要么污染对性能几乎没有影响；并且“潜在污染常常很高（四分之一的基准超过 50%），但多数情形下性能变化可以忽略”，没有看到污染程度与性能差异相关的证据。

### 8.3 被标记的六组基准逐个解释

分析标记了六组基准要进一步调查：单词扰乱、阅读理解（QuAC、SQuAD2、DROP）、PIQA、Winograd、语言建模任务（Wikitext 系列、1BW）、德译英翻译。由于重叠分析被设计得极其保守，预期会有一些误报。按任务组总结：

- **阅读理解**：初始分析把 QuAC、SQuAD2、DROP 中超过 90% 的样例标为潜在污染，高到连在干净子集上度量差异都很困难。但人工检查发现，所检查的每个重叠中，源文本出现在训练数据里，而问题/答案对没有，也就是说模型只得到了背景信息，无法记住某个具体问题的答案。
- **德语翻译**：WMT16 德译英测试集中 25% 的样例被标记为潜在污染，总的影响大小是 1 到 2 BLEU。检查后发现被标记的样例中没有一个含有类似 NMT 训练数据的成对句子，碰撞是单语匹配，大多是新闻里讨论的事件片段。
- **反转单词与变位词**：这类任务形如 “alaok = koala”。由于任务很短，过滤用的是 2-gram（忽略标点）。检查被标记的重叠后发现，它们通常不是训练集里真正的反转或还原实例，而是回文或平凡的还原，如 “kayak = kayak”。重叠量很小，但去掉这些平凡样例会使任务更难，因而产生虚假信号。与此相关，符号插入任务显示出高重叠而对性能无影响：因为该任务是从单词里去掉非字母字符，而重叠分析本身忽略这些字符，造成大量虚假匹配。
- **PIQA**：重叠分析标记了 29% 的样例为被污染，在干净子集上观察到 3 个百分点的绝对下降（4% 的相对下降）。虽然测试集发布时间晚于训练集的创建、且其标签是隐藏的，但众包数据集创建者使用的一些网页包含在训练集里。作者在小 25 倍（容量小得多、更难记忆）的模型上发现了类似的下降，因此怀疑这个偏移很可能是统计偏差而不是记忆：被工作人员复制的样例也许本来就更容易。遗憾的是无法严格证明这个假设，所以保守地给 PIQA 结果标星号。
- **Winograd**：重叠分析标记了 45% 的样例，发现在干净子集上性能下降 2.6%。人工检查重叠的数据点发现确有 132 个 Winograd schema 出现在训练集里，但呈现格式不同于给模型的任务格式。虽然性能下降很小，作者仍在正文中给 Winograd 结果标星号。
- **语言建模**：GPT-2 里测量的 4 个 Wikipedia 语言建模基准，加上 Children's Book Test 数据集，几乎完全包含在训练数据里。由于无法可靠地提取干净子集，作者**不报告这些数据集上的结果**，尽管开始这项工作时本来打算报告。Penn Tree Bank 因为年代较早而未受影响，成为主要的语言建模基准。

作者还检查了污染程度高但对性能影响接近零的数据集，只是为了验证实际存在多少污染：这些数据集常常包含误报，要么没有实际污染，要么污染没有泄露任务答案。一个值得注意的例外是 LAMBADA：它似乎有大量真实的污染，但对性能的影响很小，干净子集的得分与完整数据集相差不到 0.5%；严格说，填空格式也排除了最简单形式的记忆。不过由于本文在 LAMBADA 上取得很大提升，仍在结果部分注明了潜在污染。

**分析本身的局限**（原文）：无法确定干净子集与原数据集来自同一分布；有可能记忆夸大了结果，同时又恰好被某种让干净子集更容易的统计偏差抵消。但大量偏移接近零使这种情况不太可能，并且对小模型（不太可能在记忆）也没有观察到明显不同的偏移。原文结论：作者已尽力度量并记录数据污染的影响，并依严重程度标注或直接去掉有问题的结果；对整个领域而言，无论是设计基准还是训练模型，这一重要而微妙的问题仍有大量工作要做。

## 九、局限（原文第 5 节）

作者列出了 GPT-3 及其分析的若干局限，并给出未来方向：

1. **文本合成与部分 NLP 任务仍有明显弱点**。尽管与前身 GPT-2 相比有定量和定性的显著进步，GPT-3 的样本有时仍在文档层面语义重复、在足够长的段落后失去连贯性、自相矛盾，并偶尔含有不合逻辑的句子或段落（作者会公开 500 个未经挑选的无条件样本，以便更好地了解其长处与局限）。在离散语言任务里，作者非正式地注意到 GPT-3 似乎对“常识物理”特别困难，尽管在 PIQA 等数据集上表现不错，例如“如果我把奶酪放进冰箱，它会融化吗？”这类问题。定量上，GPT-3 的上下文学习在基准集上有一些明显缺口：在一些“比较”类任务（判断两个词在句中用法是否相同的 WiC，判断一个句子是否蕴含另一个的 ANLI）以及一部分阅读理解任务上，单样本甚至少样本表现仅比随机略好。
2. **结构与算法局限**。作者聚焦自回归语言模型里的上下文学习行为，因为这种模型便于采样和计算似然。因此实验不包含任何双向结构或其他训练目标（如去噪）。这与近期许多文献不同，后者记录到这些方法在微调性能上优于标准语言模型。所以这个设计选择可能使一些从双向性中受益的任务表现更差：填空任务、需要回看和比较两段内容的任务、需要重读或仔细考虑长段落后生成很短答案的任务。这也许能解释 GPT-3 在 WiC、ANLI 和若干阅读理解任务（如 QuAC、RACE）上的少样本落后。作者还推测，基于已有文献，一个大的双向模型在微调上会比 GPT-3 更强。做出 GPT-3 规模的双向模型，和/或让双向模型在少样本或零样本学习下工作，是一个有希望的未来方向，可以取得“两全其美”。
3. **预训练目标本身的限制**。扩大任何类语言模型（无论自回归还是双向）的更根本局限是，它可能最终会（或者已经）碰到预训练目标的极限：当前的目标对每个 token 平等加权，缺少“什么最重要、什么次要”的概念；借助自监督目标，任务说明依赖于把想要的任务硬塞成预测问题，而最终有用的语言系统（比如虚拟助手）也许更应被看作是采取目标导向的行动，而不只是做预测；还有，大型预训练语言模型没有落地到视频或真实世界物理交互等其他经验领域，因而缺少大量关于世界的背景。因此作者认为单纯扩大自监督预测很可能撞上极限，需要用别的方法增强。有希望的方向包括：从人类那里学习目标函数、用强化学习微调，或加入图像等模态来提供落地和更好的世界模型。
4. **预训练的样本效率差**。GPT-3 在测试时的样本效率（单样本或零样本）更接近人类，但预训练时看到的文本量远多于人一生看到的。提高预训练样本效率是重要方向，可能来自落地到物理世界提供额外信息，或算法改进。
5. **少样本学习到底在做什么并不清楚**：它是在推理时“从零开始”学新任务，还是仅仅识别并确定训练时已学过的任务？这些可能性构成一个光谱：从训练集里的示范与测试时完全同分布，到识别相同任务但格式不同，到适应某个大类任务（如问答）的具体风格，再到完全从头学会一项技能。GPT-3 在这个光谱上的位置也可能因任务而异：单词扰乱或定义无意义词这类合成任务似乎特别可能是从头学会的，而翻译显然必须在预训练中学到，尽管可能来自组织和风格与测试数据差别很大的数据。作者说，人类自己从头学什么、从此前示范里学什么也不清楚。**因此精确理解少样本学习如何工作，是一个重要的、未探索的方向。**
6. **推理昂贵且不方便**：这个规模的模型，无论目标函数和算法如何，都既昂贵又不方便做推理，可能给这种规模的模型在当前形式下的实际应用带来挑战。一个可能的方向是蒸馏（distillation）：GPT-3 这样的大模型含有非常广泛的技能，其中大多数对具体任务并不需要，原则上可以激进地蒸馏。蒸馏在一般意义上已有较多探索，但尚未在数千亿参数规模上尝试，会有新的挑战和机会。
7. **与多数深度学习系统共有的局限**：决策不易解释；对新输入的预测不一定校准良好（体现为在标准基准上表现的方差远高于人类）；保留了训练数据里的偏见。最后一点（数据里的偏见可能使模型生成带刻板印象或偏见的内容）从社会角度尤其受关注，在下一节讨论。

## 十、更广泛的影响（原文第 6 节）

语言模型有广泛的有益应用（代码和写作自动补全、语法辅助、游戏叙事生成、改进搜索引擎回应、回答问题），也有潜在的有害应用。GPT-3 提高了文本生成的质量和适应性，并使区分合成文本与人类写作文本更加困难，因此它既可能推进语言模型的有益应用，也可能推进有害应用。作者聚焦于改进后的语言模型的潜在危害，这并不是因为他们认为危害必然更大，而是为了促进研究和缓解。作者聚焦两个主要问题：蓄意滥用（本文 10.1 节）以及偏差、公平性与代表性（10.2 节），并简要讨论能耗（10.3 节）。

### 10.1 语言模型的滥用（原文 6.1 节）

作者借用传统的安全风险评估框架：识别威胁及其潜在影响、评估可能性、把风险确定为可能性与影响的组合；并讨论三个因素：潜在滥用应用、威胁行为者、外部激励结构。

- **潜在滥用应用**：任何依赖生成文本的有社会危害的活动都可能被强大的语言模型增强，包括虚假信息、垃圾邮件、钓鱼、滥用法律和政府程序、欺诈性学术论文写作、社会工程的借口（pretexting）。其中许多应用的瓶颈在于要有人类写出足够高质量的文本，高质量文本生成的语言模型可能降低开展这些活动的现有门槛并提高成效。语言模型的滥用潜力随文本合成质量提高而增大；GPT-3 能生成人类难以与人写文字区分的数段合成内容（本文 7.4 节），在这方面是一个令人担忧的里程碑。
- **威胁行为者分析**：威胁行为者可按技能和资源水平划分，从能打造恶意产品的低或中等技能和资源的行为者，到“高级持续性威胁”（APT：高技能、资源充足，如国家支持的、有长期议程的团体）。为了了解低、中等技能的行为者如何看待语言模型，作者监测了经常讨论虚假信息策略、恶意软件传播和计算机欺诈的论坛和聊天群，发现 2019 年春 GPT-2 首次发布后有大量关于滥用的讨论，但此后实验的例子更少，也没有成功部署；而且那些滥用讨论与语言模型技术的媒体报道相关。据此作者评估，这类行为者的滥用威胁不是迫在眉睫，但可靠性的显著改进可能改变这一点。APT 通常不会公开讨论行动，所以作者咨询了专业威胁分析师：自 GPT-2 发布以来，在可能从语言模型获益的行动中没有可辨识的差别；分析师评估认为语言模型也许不值得投入大量资源，因为没有令人信服的证明表明当前语言模型显著优于现有的文本生成方法，并且“定向”或“控制”语言模型内容的方法还处于很早期。
- **外部激励结构**：每个威胁行为者群体还有一组依赖于完成其议程的战术、技术和程序（TTP），受可扩展性、易部署性等经济因素影响；钓鱼在所有群体中都极其流行，因为它是低成本、低投入、高回报的部署恶意软件和窃取登录凭据的方法。用语言模型增强现有 TTP 可能进一步降低部署成本。易用性是另一个重要激励：稳定的基础设施对 TTP 的采用影响很大。语言模型的输出是随机的，开发者虽可约束（例如 top-k 截断），但没有人类反馈就无法一致地运作：如果一个社交媒体虚假信息机器人有 99% 的输出可靠、1% 不连贯，这可以减少运营该机器人所需的人力，但仍需要人来过滤输出，限制了行动的可扩展性。
- 结论：作者预计 AI 研究者最终会开发出足够一致和可控的语言模型，使它们对恶意行为者更有吸引力；这会给更广泛的研究界带来挑战，作者希望结合缓解研究、原型设计与和其他技术开发者协调来应对。

### 10.2 公平性、偏差与代表性（原文 6.2 节）

互联网训练的模型有互联网规模的偏差：模型倾向于反映训练数据里存在的刻板印象。作者对 175B 模型和类似的较小模型做了初步分析（聚焦性别、种族和宗教；这不是穷尽的刻画，更多类别的偏差很可能存在，也不反映所研究类别内模型的所有偏差）。以下按原文列出做法和发现，其中的词语是模型生成文本里的统计关联，不代表对任何群体的论断。

**性别（原文 6.2.1 节）**。聚焦职业与性别的关联。给定上下文 “The {occupation} was a”（中性变体，Neutral Variant），职业整体上更可能被男性标识词接续（偏向男性）：测试的 388 个职业中，83% 被 GPT-3 判为更可能接男性标识词（方法：输入如 “The detective was a”，看模型接着输出男性指示词（man、male 等）或女性指示词（woman、female 等）的概率）。教育水平较高的职业（如 legislator、banker、professor emeritus）和需要重体力劳动的职业（如 mason、millwright、sheriff）强烈偏向男性；更可能被女性标识词接续的职业包括 midwife、nurse、receptionist、housekeeper 等。

作者还检验了把上下文换成 “The competent {occupation} was a”（能干变体）和 “The incompetent {occupation} was a”（不称职变体）时概率如何变化：能干变体下，大多数职业接男性标识词的概率比中性提示下更高；不称职变体下，多数职业仍偏男性，概率与中性相近。平均职业偏差定义为

$$
\frac{1}{n_{\text{jobs}}}\sum_{\text{jobs}}\log\left(\frac{P(\text{female}\mid\text{Context})}{P(\text{male}\mid\text{Context})}\right)
$$

值为负表示偏男性：中性变体为 −1.11，能干变体 −2.14，不称职变体 −1.15。

在 Winogender 数据集（Rudinger 等 2018）上用两种方法做代词指代，进一步印证模型倾向于把多数职业与男性联系起来。其中一种测量模型能否正确地把代词指派给“职业”或“参与者”，例如输入 “The advisor met with the advisee because she wanted to get advice about job applications. ‘She’ refers to the”，在两个选项（职业选项 advisor、参与者选项 advisee）之间选择（原文写作选“概率最低”的选项，按语义应为概率较高者，疑为笔误）。GPT-3 175B 在这个任务上是所有模型中准确率最高的（64.17%），也是唯一一个“职业”类句子（正确答案是职业选项）里女性代词的准确率高于男性的模型（81.7% 对 76.7%）；所有其他模型在职业类句子上都是男性代词准确率更高，只有第二大的 GPT-3 13B 两者相同（60%）。这给出了初步证据：在偏差使语言模型易于出错的地方，更大的模型比更小的模型更稳健。

**共现测试**：分析在预选词附近哪些词更可能出现。作者对数据集中每个提示生成 800 个长度 50 的输出（温度 1、top-p 0.9）；性别提示如 “He was very”、“She was very”、“He would be described as”、“She would be described as”（脚注 9：只用了男性和女性代词，这个简化便于研究共现；其他形式的性别偏差很可能存在）。用现成的词性标注器看前 100 个最受偏好词中的形容词和副词，发现女性更多被用外貌类词（如 “beautiful”“gorgeous”）描述，而男性更多被用涵盖范围更广的形容词描述。表 6.1 给出模型的前 10 个最受偏好的描述词及其与代词标识共现的原始次数；“最受偏好”指通过以更高的比率与某类共现而偏向该类的词；并给出所有合格词的平均共现数作为参照。

**种族（原文 6.2.2 节）**。作者用 “The {race} man was very”、“The {race} woman was very” 和 “People would describe the {race} person as” 这类提示给模型播种，每种提示生成 800 个样本，其中 {race} 换成 White、Asian 等种族类别的词，然后度量生成样本里的词共现。鉴于已有研究表明语言模型在变化职业等特征时会产生不同情感的文本，作者探究了种族如何影响情感：用 SentiWordNet 度量与各种族不成比例地共现的词的情感，每个词的情感值从 100 到 −100，正分表示正面词（如 wonderfulness：100、amicable：87.5），负分表示负面词（如 wretched：−87.5、horrid：−87.5），0 分表示中性词（如 sloping、chalet）。

作者强调两点：（1）这里是明确地提示模型谈论种族，所以生成的文本聚焦于种族特征；这些结果不是模型在真实使用中谈论种族，而是在被引导的实验设置中。（2）因为只是通过词共现来度量情感，所得情感可能反映社会历史因素，例如讨论奴隶制的文本往往带负面情感，这可能使某个人群在这种测试方法下与负面情感联系起来。在所分析的模型中，“Asian” 的情感始终偏高，在 7 个模型中的 3 个排第一；“Black” 的情感始终偏低，在 7 个模型中的 5 个排最后；这些差异在更大的模型尺寸上略有缩小。这一分析让人了解不同模型的偏差，并突出需要对情感、实体与输入数据的关系做更复杂的分析。

**未来的偏差与公平性挑战（原文 6.2.4 节）**。作者分享这个初步分析，是为了推动进一步研究，并突出刻画大规模生成模型偏差的内在困难；他们把这一节的工作视为“主观的路标”：选择性别、种族和宗教作为起点，也承认这个选择本身带有主观性。工作受到 Model Cards（Mitchell 等）这类刻画模型属性、制作信息性标签的文献的启发。最终，重要的不只是刻画语言系统的偏差，还要干预；缓解工作不应当只用以度量指标为导向的目标去“消除”偏差，因为这已被证明有盲点，而应以整体的方式推进；需要建立把规范、技术与经验挑战联系起来的共同词汇，也需要更多与 NLP 之外文献和受影响社区生活经验结合的研究。

### 10.3 能耗（原文 6.3 节）

大规模预训练需要大量计算，很耗能：训练 GPT-3 175B 在预训练期间消耗了数千 petaflop/s-day 的计算，而 15 亿参数的 GPT-2 是几十 petaflop/s-day（图 2.2）。作者提示应关注这类模型的成本和效率。另一个角度是考虑如何把这些资源分摊到模型的整个生命周期里：它之后会被用于多种用途、并针对特定任务微调。像 GPT-3 这样的模型在训练期间消耗大量资源，训练完成后却可以出奇地高效：即便用完整的 GPT-3 175B，生成 100 页内容也只需大约 0.4 kW·h 的量级，即只有几美分的能耗成本。此外，模型蒸馏之类的技术可进一步降低这类模型的成本，使我们能采用“训练单个大规模模型，再为合适场景创建更高效版本”的范式；算法进步也可能自然地随时间提高这类模型的效率，类似图像识别和神经机器翻译中观察到的趋势。

## 十一、相关工作与结论（原文第 7、8 节）

**相关工作**：

- **扩大参数和计算**：一条线是直接放大 Transformer（213M、300M、1.5B、8B、11B、17B），参数量和每 token 的 FLOPs 大致同比增长；第二条线是增加参数但不增加计算，依赖条件计算框架，混合专家（MoE）方法已用于产生 1000 亿以上参数的模型和最近 500 亿参数的翻译模型，但每次前向只用到一小部分参数；第三条线是增加计算而不增加参数（自适应计算时间、Universal Transformer）。GPT-3 属于第一种，把模型大小比此前采用该策略的模型再增大 10 倍。
- **规模对语言模型性能的系统研究**：Kaplan 等、Rosenfeld 等（2019）、Li 等（2020）、Hestness 等（2017）都发现自回归语言模型放大时损失呈平滑幂律趋势。本文显示这一趋势在很大程度上继续（图 3.1 中也许能看到曲线的轻微弯曲），并且在 3 个数量级的规模范围内，许多（但不是所有）下游任务也相对平滑地提升。
- **相反方向的工作**：试图在尽可能小的语言模型里保持强性能，包括 ALBERT 以及一般的和任务专用的蒸馏方法。这些结构和技术可能与本文工作互补，可用来降低巨型模型的延迟和内存占用。
- **更难或更开放的任务**：随着微调语言模型逼近许多标准基准任务的人类水平，大量工作致力于构造更难或开放式的任务，包括问答、阅读理解和针对现有语言模型对抗式构造的数据集，本文在其中许多数据集上做测试。问答方面，Raffel 等和 Roberts 等微调了 110 亿参数的语言模型，Guu 等聚焦测试时对大语料库做注意力；本文聚焦上下文学习，但未来可与这些工作结合。
- **元学习**：GPT-2 中用到语言模型元学习，但结果有限且没有系统研究；更一般地，语言模型的元学习有内循环-外循环结构，在结构上与一般机器学习中的元学习相似，那里有大量文献（matching networks、RL²、learning to optimize、MAML 等）。本文把上下文塞满此前示例的做法在结构上最接近 RL²：内循环的适应通过模型激活值在时间步之间的计算发生，不更新权重；外循环（这里只是语言模型预训练）更新权重，并隐式地学会适应或至少识别推理时定义的任务。
- **其他**：把预训练语言模型与梯度下降结合做少样本学习（Schick 与 Schütze）；半监督学习如 UDA；给多任务模型下自然语言指令，最早在有监督设定下被形式化（McCann 等 2018 的 decaNLP），并在 GPT-2 中用于某些任务（如摘要）；T5 把任务写成自然语言，但用于多任务微调而非无权重更新的上下文学习；多任务学习是另一种提高通用性和迁移的途径，但仍受限于需要手工整理数据集合和设置训练课程，而足够大规模的预训练提供了“自然的”、隐含在预测文本本身中的广泛任务分布。
- **算法创新**：过去两年语言模型的算法创新很多（基于去噪的双向性、prefixLM、编码器-解码器、训练时随机排列、提高采样效率的结构等）。本文继续只聚焦纯自回归语言模型，以聚焦上下文学习性能并降低大模型实现的复杂度；但把这些算法进展结合进来很可能改进 GPT-3 在下游任务特别是微调上的表现，是有前景的未来方向。

**结论**：作者提出了一个 1750 亿参数的语言模型，它在零样本、单样本、少样本设置下，在许多 NLP 任务和基准上表现很强，某些情况下几乎与最先进的微调系统相当，还能生成高质量的样本，并在现场定义的任务上有很强的定性表现；他们记录了不使用微调时性能随规模大致可预测的趋势；也讨论了这类模型的社会影响。原文最后的判断是：尽管有许多局限和弱点，这些结果表明，非常大的语言模型可能是开发可适应的通用语言系统的重要组成部分。

### 12.2 人类评估的实验设计（附录 E）

- **参与者**：共招募 718 位不同参与者参加实验，97 位因未通过互联网检查题被排除，剩下 621 位（343 男、271 女、7 位其他），平均年龄约 38 岁；全部通过 Positly 招募（它维护着 Mechanical Turk 上表现良好工作者的白名单），均为美国居民，没有其他人口统计学限制；每人 60 分钟任务报酬 12 美元；每个实验的测验样本唯一，同一人不能参加同一个实验两次。
- **步骤与设计**：任意选取 2020 年初出现在 newser.com 的 25 篇新闻，用其标题和副标题让 125M、350M、760M、1.3B、2.7B、6.7B、13.0B 以及 “200B”（即 GPT-3，原文笔误）参数的语言模型生成文章；每个问题每个模型生成 5 个输出，**自动**选取字数最接近人写文章的那一个，以尽量减少长度对判断的影响；对照模型的处理方式同正文。每个实验中一半参与者做测验 A，另一半做测验 B；每个测验 25 篇文章，一半（12 到 13 篇）是人写的，一半是模型生成的；A 中人写的补全在 B 中是模型生成的，反之亦然；每个参与者的题序是打乱的。参与者可留言，并被要求指出是否此前见过这些文章；被要求不要查找文章或其内容，测验结束后被问是否查过。

读法：这张表检验原文引言里的一个说法，即零样本、单样本、少样本之间的差距往往随模型容量而增大，“或许说明更大的模型是更熟练的元学习者”。数据只部分支持它：Winogrande（+2.1 到 +7.5）、NQs（+13.2 到 +15.3）、SuperGLUE 平均分（+12.5 到 +15.0）、3 位减法（+7.8 到 +45.9）、符号插入（+26.4 到 +58.9）、SAT 类比（+0.8 到 +11.5）这些任务的差距在 175B 处比 13B 处更大；但 TriviaQA（+15.7 到 +6.9）、2 位加法（+40.1 到 +23.1，因为零样本在 175B 已高）以及 CoQA、WebQs、SQuADv2 的差距基本持平或缩小；PIQA、ARC Challenge、Winograd 这三个任务在两个尺寸上差距都接近 0，Winograd 在 13B 少样本甚至低于零样本。所以“差距随规模扩大”是一个依赖任务的趋势，而不是普遍规律。

## 十三、证据边界与常见误读

### 13.1 证据边界

- **SOTA 对照并不是受控实验**：论文列出的“微调 SOTA”来自各不相同的系统（不同规模、不同训练数据、不同年份），有的还是开卷系统或无监督系统；“GPT-3 超过 SOTA”在不同任务上含义不同。例如 TriviaQA 的少样本比闭卷微调 T5-11B+SSM 高 10.7，比开卷 RAG 高 3.2；翻译到英语的结果，作者自己也说所比的监督基线不具竞争力。
- **少样本的结果依赖具体的示例选择、$K$ 与提示措辞**：$K$ 在开发集上选，示例从训练集随机抽取；同一评测在不同随机种子下会略有出入（表 C.1 的说明）；对小评测集（CB 开发集 56 例、COPA 100 例、Winograd 273 例、ANLI R3 开发集标准差约 1.2%）方差很大；作者在 WiC 上试了多种措辞都失败，说明格式的影响不可忽略。
- **大多数结果是开发集结果**：只有 SuperGLUE、TriviaQA、PIQA 等少数任务实际提交了测试服务器，并且只提交了 175B 的少样本。
- **污染分析不能证明无泄漏**：过滤程序有 bug，只做了部分删除；干净子集分析本身可能受分布差异影响（原文自述）；PIQA 与 Winograd 被明确标星；语言建模基准因几乎全部包含在训练数据里而未报告。
- **人类评估范围有限**：参与者是一般美国网民，不是专家；文章是约 200 或约 500 词的新闻短文，由程序化选取；对照模型是故意做差的模型；准确率度量只含非中立判断。结果不能推广到更长的文本、专业读者或自动检测器。
- **偏差分析是初步的**：基于词共现和 SentiWordNet 的情感打分，对提示措辞敏感，只涉及性别、种族、宗教三类，并且作者明确说这不是对 GPT-3 的穷尽刻画。
- **平滑规律的范围**：损失随计算的幂律是在 8 个尺寸、固定 300B token 训练的设定下观察到的；它不意味着每个下游任务的准确率都随规模平滑（算术、符号插入、ANLI 第 3 轮都是到 175B 才明显上升，WiC 在所有尺寸都是随机水平）。
- **“少样本到底是在学习还是在识别”未解决**：这是论文第 5 节自己列出的开放问题；不能把图 1.2 的“上下文学习曲线”当成对机制的证明。

### 13.2 常见误读

- **“少样本学习 = 用几个示例做了微调”**：不是。示例只作为输入文本，权重不变；换一个输入，这些“学到的东西”就不再存在。
- **“上下文学习不需要任何任务数据”**：不准确。原文明确说少样本“仍然需要少量任务专用数据”，并且 $K$、示例选择和提示措辞都要在开发集上调（零样本和单样本则需要对任务的自然语言说明）。
- **“GPT-3 在所有任务上都接近或超过微调 SOTA”**：不是。在 LAMBADA、TriviaQA、PTB 上超过；在 COPA、ReCoRD、Winograd 上接近；在 ANLI、WiC、RACE、QuAC、ARC Challenge 上远远落后（见 5.3 节的对照表）。
- **“损失的平滑规律意味着能力也平滑出现”**：不是（见 13.1）。
- **“污染分析证明了结果没有泄漏”**：不是。它只表明对多数基准，保守定义的干净子集上的得分与全集相近，原文自己也说无法保证干净子集与原集同分布。
- **“人类分不出，说明生成内容可靠”**：人类检测准确率接近随机，说明文字流畅、像人写的；论文同时指出事实错误、重复和不合逻辑等往往是识别线索，原文第 5 节也承认 GPT-3 的样本会自相矛盾、失去连贯。
- **“GPT-3 是开源模型”**：论文公开了方法与结果，但没有提供模型权重和训练数据；论文只承诺发布合成数据集和一批未经挑选的样本，并在 GitHub 上放了重叠频率清单（脚注 11）。
- **“175B 参数和 300B token 是最优配比”**：这套配比依据 Kaplan 等的规模律“大模型、少 token”；约 1.7 个 token 每参数（自行验算），后来 Chinchilla 的估计是约 20 个 token 每参数（见 [chinchilla](../chinchilla/论文中文解读.md)）。

## 十四、阅读与复现检查清单

- **提示格式**：记录任务描述、示例分隔符（1 或 2 个换行）、答案触发词（`Answer:`、`A:`、`=` 等）与 $K$；多选题用每 token 似然还是用无条件概率归一化（ARC、OpenBookQA、RACE 用后者）；自由形式输出用束搜索（束宽 4，长度惩罚 0.6）。
- **示例取样**：从训练集随机抽 $K$ 个，在开发集上选 $K$；报告多次抽样的均值与方差，不要只报最好的一次；对 LAMBADA、StoryCloze 这类没有训练集的任务从开发集抽示例。
- **污染检查**：对每个基准用 $N$-gram（$N$ 取样例长度第 5 百分位，限制在 8 到 13）精确匹配训练语料，报告干净子集得分及其样本数；注意干净子集太小（如 QuAC 38 个）时相对差不可靠；合成任务要用更短的 $N$ 并剔除回文等平凡样例。
- **计算量口径**：$C\approx6ND$，注明 $N$ 是否含 embedding（表 D.1 含，图 3.1 不含）。
- **分词影响**：BPE 平均每 token 约 0.7 个词；字符级任务（单词扰乱）对分词敏感，GPT-2 的字节级 BPE 对非英语（如 En→Ro）不利。
- **人类评估**：设置故意做差的对照模型、剔除不专心的参与者、用 t 检验比较各模型与对照、报告“我不知道”比例。

## 十五、与相关论文的关系

- **GPT-1、GPT-2**（见 [gpt1](../gpt1/论文中文解读.md)、[gpt2](../gpt2/论文中文解读.md)）：GPT-3 沿用 GPT-2 的结构和分词，上下文学习的思路也来自 GPT-2 对零样本任务迁移的探索；差别在规模（175B 对 1.5B）以及系统地研究 zero/one/few-shot。
- **Scaling Laws**（见 [scaling_laws](../scaling_laws/论文中文解读.md)）：GPT-3 明确依据 Kaplan 等的分析，训练更大的模型和较少的 token，并把损失随计算量的幂律趋势又外推了两个数量级（图 3.1）。
- **Chinchilla**（见 [chinchilla](../chinchilla/论文中文解读.md)）：重新估计后认为 GPT-3 这类“大模型、300B token”的配比训练不足。
- **BERT、T5**（见 [bert](../bert/论文中文解读.md)、[t5](../t5/论文中文解读.md)）：本文的微调对照基线（BERT-Large、T5-11B）；论文在相关工作里提到 T5 也把任务写成自然语言，但 T5 用于多任务微调，GPT-3 则用于不更新权重的上下文学习。
- **后续工作**：原文第 5 节提出的方向，如“用人类反馈学习目标函数”“用强化学习微调”“加入图像等模态”，后来分别对应 InstructGPT（见 [openai_instructgpt](../openai_instructgpt/论文中文解读.md)）和 GPT-4（见 [openai_gpt4](../openai_gpt4/论文中文解读.md)）等路线；代码方向见 [openai_codex](../openai_codex/论文中文解读.md)。这是本文基于仓库内其他论文的归纳，不是 GPT-3 论文本身的陈述。
