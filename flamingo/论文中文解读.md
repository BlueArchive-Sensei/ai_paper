## 一、一句话结论

**问题**：让一个视觉语言模型（Visual Language Model，VLM）只看几个带标注的示例，就能快速适应新的图像或视频任务（描述、问答、对话、分类等），而不是为每个任务收集成千上万条标注再微调。

**做法**：Flamingo 把两个预训练好的单模态大模型**冻结**住，只在它们之间训练少量新模块：

- 视觉端：冻结的 NFNet-F6 视觉编码器（先用对比学习预训练），后接 **Perceiver Resampler**，把任意大小的图像或视频特征压成固定的 64 个视觉 token；
- 语言端：冻结的 Chinchilla 语言模型（1.4B、7B、70B 三种规模），在其各层之间插入新的 **GATED XATTN-DENSE** 层，让文本 token 通过交叉注意力读取视觉 token；每个新层的输出乘以 $\tanh(\alpha)$ 再加回残差，$\alpha$ 初始化为 0，所以训练一开始模型就等价于原语言模型；
- 输入端：用**逐图像的注意力掩码**处理任意交错的“图像/视频 + 文本”序列；
- 训练数据：全部来自网络、不使用为机器学习标注的数据，由交错网页（M3W）、图文对（ALIGN 与新建的 LTIP）和视频文本对（VTP）混合；
- 测试时：把少量（图像，文本）示例和待预测的查询图像交错拼成 prompt，模型直接续写答案（in-context few-shot），不更新任何权重。

**结论**：在 16 个图像/视频语言基准上，Flamingo 刷新了少样本 SOTA；其中 6 个任务上，仅用 32 个示例（不更新权重）就超过了用数千到数万条标注微调的 SOTA（原文称任务专用数据量约少 1000 倍）；再针对任务微调，还能在另外 5 个任务上刷新 SOTA。性能随模型规模和示例数提升。消融表明：交错网页数据、tanh 门控、冻结语言模型、强视觉编码器、逐图像注意力都很关键。

**局限**：继承语言模型的弱点（幻觉、对超长序列泛化差、训练样本效率低）；分类性能落后于对比模型；上下文学习对示例很敏感，示例数超过约 32 个后收益饱和。

## 二、背景与动机

### 2.1 要解决的问题

视觉领域最常用的范式，是先在大量监督数据上预训练，再在目标任务上微调。但成功的微调往往需要数千条标注、对每个任务精心调超参，计算开销也大。近来用对比目标训练的视觉语言模型（如 CLIP、ALIGN，见 [CLIP](../clip/论文中文解读.md)）可以零样本迁移到新任务，不必微调；但它们只给出一段文本和一张图像之间的相似度分数，只能处理“候选结果集合事先给定”的场景（如分类），**不能生成语言**，不适合描述图像（captioning）、视觉问答（VQA）这类开放式任务。另有一些工作探索了以视觉为条件的语言生成，但在低数据情形下表现不够好。

与之对照，大语言模型是出色的少样本学习者：只需把任务的几个例子连同查询输入写成一段 prompt，模型续写即可得到预测。Flamingo 要证明同样的做法可以用于图像和视频理解：这些任务都可以改写成“以视觉输入为条件的文本预测”问题；与纯语言模型唯一的不同，是 prompt 里要能容纳与文本交错的图像或视频。

### 2.3 贡献

1. 提出 Flamingo 系列 VLM：几个输入/输出示例就能完成描述、视觉对话、视觉问答等多种多模态任务；架构创新使其能高效接受任意交错的视觉数据和文本，并以开放方式生成文本；
2. 定量评估如何通过少样本学习适配各种任务；特别保留了一大组**未用于验证任何设计决策或超参数**的留出基准，用来估计无偏的少样本性能；
3. 在 16 个多模态语言和图像/视频理解任务上刷新少样本 SOTA；其中 6 个任务上仅用 32 个任务样本（约比当前 SOTA 少 1000 倍的任务专用训练数据）就超过微调 SOTA；有更多标注预算时，微调后还能在 VQAv2、VATEX、VizWiz、MSRVTTQA、HatefulMemes 这 5 个任务上刷新 SOTA。

## 三、方法

### 3.1 总体结构与概率模型（图 3）

Flamingo 是视觉条件的自回归文本生成模型：输入是与文本交错的图像或视频，输出是自由格式的文本。它对“给定交错视觉输入 $x$ 时文本 $y$ 的似然”建模为

$$
p(y\mid x)=\prod_{\ell=1}^{L}p\big(y_\ell\mid y_{<\ell},\,x_{\le\ell}\big),
$$

其中 $y_\ell$ 是第 $\ell$ 个语言 token，$y_{<\ell}$ 是它之前的所有 token，$x_{\le\ell}$ 是交错序列里位于 $y_\ell$ 之前的图像/视频集合，$p$ 由 Flamingo 模型参数化（原文式 (1)）。能处理交错序列，就自然适合像 GPT-3 的少样本文本提示那样做上下文少样本学习。

![图 3：Flamingo 架构总览](rendered_figures/fig3-architecture.png)

*图 3（原文 Figure 3，第 4 页）：Flamingo 是一族视觉语言模型，输入与文本交错的视觉数据，输出自由格式文本。*

**图中文字翻译与读法**：

- **图例**：蓝色带雪花图标 = Pretrained and frozen（预训练且冻结）；浅紫色 = Trained from scratch（从头训练）。
- **左侧**：两张图像（一只狗、一只猫）各自经过 Vision Encoder（冻结）和 Perceiver Resampler（从头训练），得到固定数量的视觉 token。
- **右侧自下而上**：Interleaved visual/text data（交错的图文数据：狗的图 + “This is a very cute dog.” + 猫的图 + “This is”）→ Processed text（处理后文本：`<image> This is a very cute dog.<image> This is`，图像位置用 `<image>` 标记）→ 一叠“冻结的 LM block + 其前面的 GATED XATTN-DENSE 层”（图中标 1st、n-th）→ Output: text（输出文本 “a very serious cat.”）。左边两个 Perceiver Resampler 的输出连到每一个 GATED XATTN-DENSE 层。
- **读图结论**：只有浅紫色模块（Perceiver Resampler 与 GATED XATTN-DENSE）被训练，视觉编码器与语言模型各层都冻结，从而保留二者预训练时积累的知识。

### 3.2 视觉编码器：从像素到特征

视觉编码器是预训练并冻结的 **Normalizer-Free ResNet（NFNet）**，用 F6 模型（约 435M 参数）。作者先在自己的图文对数据上，用 CLIP 的双向对比损失对它做对比预训练（细节见 3.10 节），取其最后一个 stage 的输出：一个 2D 空间特征网格，展平成 1D 序列。

对视频输入，以 1 帧/秒采样，每帧独立编码，得到 3D 的“时间 × 空间”特征网格，并加上可学习的**时间位置嵌入**，再展平送入 Perceiver Resampler。原文没有给图像特征加显式的空间网格位置编码，因为没有观察到收益；理由大概是 CNN（如 NFNet）本来就会在通道里隐式编码空间信息。

### 3.3 Perceiver Resampler：从可变大小的特征到固定数量的视觉 token

不同分辨率的图像、不同长度的视频，视觉特征的数量差别很大。直接让文本对所有视觉特征做交叉注意力，计算量大且随输入变化。Perceiver Resampler 的作用是把“数量不定的视觉特征”变成“数量固定的 64 个视觉 token”，降低视觉-文本交叉注意力的计算复杂度（借鉴 Perceiver 与 DETR：学习一组预定义数量的 latent 输入查询向量，送入 Transformer 并对视觉特征做交叉注意力）。

![图 A5：Perceiver Resampler 的结构与伪代码](rendered_figures/figA5-perceiver-resampler.png)

*图 A5（原文附录 Figure 5，第 23 页）：Perceiver Resampler 把可变大小的时空视觉特征网格映射为固定数量（图中画了 5 个）的输出 token。*

**图中文字翻译与读法**：

- **左下**：视频的三帧（t=0、t=1、t=2，一个人玩滑板）各自经过 Vision Encoder 得到网格特征；每帧特征加上时间位置嵌入（⊕ 前面的 t=0、t=1、t=2），然后 flatten（展平）成一条序列 $X_f$。
- **中上**：Perceiver Resampler 重复 num_layers 层；每层是 Attention 加 FFW（前馈），都带残差连接。Attention 的 Query 是学习得到的 latent 查询向量 $X$（Learned latent queries，图下方紫色小方块，其数量就是输出 token 数）；Key 和 Value 是 $[X_f, X]$，即视觉特征与 latent 自身的**拼接**（图中 K=V=[X_f, X]）。
- **右侧伪代码**（与原文一致，只翻译注释）：

```text
def perceiver_resampler(
    x_f,              # [T, S, d] 的视觉特征（T 为时间，S 为空间）
    time_embeddings,  # [T, 1, d] 的时间位置嵌入
    x,                # R 个学到的 latent，形状 [R, d]
    num_layers,       # 层数
):
    """Perceiver Resampler 模型。"""
    # 加上时间位置嵌入并展平。
    x_f = x_f + time_embeddings
    x_f = flatten(x_f)  # [T, S, d] -> [T * S, d]
    # 应用 Perceiver Resampler 的各层。
    for i in range(num_layers):
        # 注意力。
        x = x + attention_i(q=x, kv=concat([x_f, x]))
        # 前馈。
        x = x + ffw_i(x)
    return x
```

- **读图结论**：输出 token 数等于 latent 数 $R$（Flamingo 取 64），与输入图像分辨率或视频帧数无关。与 DETR、Perceiver 不同的是，这里 Key/Value 里还拼接了 latent 自己算出的 Key/Value，作者发现这样略好。

**规格**：Resampler 的 Transformer 有 6 层、隐藏维 1536、16 个头、前馈激活为 Squared ReLU（表 4），Key/Value 维度 $D/H=96$，三种规模的 Flamingo 都使用同样大小（约 194M 参数，表 5）。扩展消融（表 10 (i)）比较了 Small、Medium（默认）、Large 三种大小：Medium 最好；而且随冻结 LM 一起放大 Resampler 时训练会不稳定，所以所有模型都保守地用同样的 Medium 规格。与 MLP、普通 Transformer 相比，Perceiver Resampler 也更好（表 3 (vi)，见第五节）。

### 3.4 在冻结的语言模型里插入 GATED XATTN-DENSE 层

文本生成由 Transformer 解码器完成，以 Perceiver Resampler 输出的视觉表示为条件。做法是：把预训练并冻结的纯文本 LM 块，与从头训练的、会对视觉输出做交叉注意力的块**交错**排列。

![图 4：GATED XATTN-DENSE 层](rendered_figures/fig4-gated-xattn-dense.png)

*图 4（原文 Figure 4，第 5 页）：在冻结的预训练 LM 层之间插入新的交叉注意力层；Key 和 Value 来自视觉特征，Query 来自语言输入；后接稠密前馈层；带 tanh 门控，使 LM 在初始化时保持不变。*

**图中文字翻译与读法**：

- **左图**：一个 LM layer（冻结）前面插入一个 GATED XATTN-DENSE；视觉输入 $X$ 从左边进入该新层，语言输入 $Y$ 从下方进入。
- **中图（放大）**：自下而上依次为：cross attention（交叉注意力，Query = [Y]，Key = Value = [X]）→ tanh gating（tanh 门控）→ 加回残差（⊕）→ 稠密前馈 FFW → tanh gating → 加回残差 → 冻结 LM 的 self attention（Key = Value = [Y]，Query = [Y]）→ ⊕ → 冻结 LM 的 FFW → ⊕ → 输出。浅紫色模块是新增、从头训练的，蓝色带雪花的是冻结的。
- **右侧伪代码**（中文注释版）：

```text
def gated_xattn_dense(
    y,           # 输入的语言特征
    x,           # 输入的视觉特征
    alpha_xattn, # 交叉注意力的门控参数，初始化为 0
    alpha_dense, # 前馈层的门控参数，初始化为 0
):
    """应用一个 GATED XATTN-DENSE 层。"""
    # 1. 带门控的交叉注意力
    y = y + tanh(alpha_xattn) * attention(q=y, kv=x)
    # 2. 带门控的前馈（稠密）层
    y = y + tanh(alpha_dense) * ffw(y)

    # 语言上常规的自注意力 + 前馈（冻结的 LM 部分）
    y = y + frozen_attention(q=y, kv=y)
    y = y + frozen_ffw(y)
    return y  # 输出：带有视觉信息的语言特征
```

用公式写，一个 GATED XATTN-DENSE 层对语言特征 $y$ 做的是（$x$ 为视觉 token）：

$$
y\leftarrow y+\tanh(\alpha_{\mathrm{xattn}})\cdot\mathrm{Attn}(q=y,\;kv=x),\qquad
y\leftarrow y+\tanh(\alpha_{\mathrm{dense}})\cdot\mathrm{FFW}(y).
$$

**为什么要 tanh 门控**：每个新层的输出先乘以 $\tanh(\alpha)$，再加到来自残差的输入表示上；$\alpha$ 是每层各有一个的可学习标量，初始化为 0（借鉴 ReZero；门控思想来自 LSTM）。因此初始化时 $\tanh(0)=0$，新层的输出被完全抹掉，整个模型的输出与预训练 LM **完全一致**，从而提高训练稳定性和最终性能。消融（表 3 (iii)）：去掉门控，总体得分降 4.2%，并且观察到训练不稳定。

**激活函数**：冻结 LM 原本用 GeLU，新加的可训练 Transformer 层（Resampler、GATED XATTN-DENSE）用 Squared ReLU，作者发现更好（附录 A.1.4）。

**门控值如何随训练变化（图 A6）**：作者记录了 Flamingo-3B（共 24 个 LM 层）里各层门控值 $|\tanh(\alpha)|$ 随训练进度的变化。

![图 A6：不同层 tanh 门控绝对值的演化](rendered_figures/figA6-tanh-gating-evolution.png)

*图 A6（原文附录 Figure 6，第 24 页）：Flamingo-3B 中不同层 tanh 门控绝对值随训练的演化。*

**图中文字翻译与读法**：

- **坐标轴**：左图 (a) Attention tanh gating（注意力的 tanh 门控），纵轴 Attention tanh gain（注意力 tanh 增益，$|\tanh(\alpha)|$）；右图 (b) FFW tanh gating（前馈的 tanh 门控），纵轴 FFW tanh gain；横轴都是 Training progress（训练进度，0 到 1）；图例 layer 1 到 24 是各层，颜色由深到浅。

### 3.5 三种模型规模

作者基于 Chinchilla（Hoffmann 等 2022，见 [Chinchilla](../chinchilla/论文中文解读.md)）的 1.4B、7B、70B 参数语言模型，分别得到 Flamingo-3B、Flamingo-9B 和 Flamingo-80B。随着冻结 LM 和可训练的 GATED XATTN-DENSE 模块增大，视觉编码器和 Resampler 的规模保持不变（相对整个模型都较小）。

- Flamingo-3B：1.4B 冻结 LM，**每个** Transformer 块前面都加 GATED XATTN-DENSE（共 24 层）；
- Flamingo-9B：7B 冻结 LM，从第一层起每隔 4 个块加一个（共 10 层）；
- Flamingo-80B：70B 冻结 LM，从第一层起每隔 7 个块加一个（共 12 层）。

插入频率是内存限制与下游性能之间的折中：先在小模型上找到最优折中，再迁移到大模型。表 3 (v) 的消融显示每层都加最好，但会显著增加可训练参数和时间；每 4 层加一个可使训练提速约 66%（原文说法；表中步时间 1.74s 对 1.02s），总体得分只降 1.9%。

### 3.6 多图像输入：逐图像的注意力掩码（图 A7）

交错序列里可能有多张图像或多段视频。Flamingo 用**掩码**限制每个文本 token 能通过交叉注意力看到哪些视觉 token：在给定的文本 token 处，模型只对**交错序列中紧挨在它前面的那张图像**的视觉 token 做交叉注意力，而不是对此前所有图像。虽然交叉注意力一次只直接看一张图，但对更早图像的依赖仍然通过语言模型里的自注意力保留下来。

形式化（附录 A.1.3）：每个样本含文本序列 $y$、图像/视频序列 $x$ 和图像在文本里的位置。定义函数 $\varphi:[1,L]\mapsto[0,N]$，给每个文本位置指派“此位置之前最后出现的图像/视频的下标”（若之前没有任何视觉数据，则为 0）。式 (1) 中能用来预测第 $\ell$ 个 token 的视觉输入集合就是 $x_{\le\ell}\triangleq\{x_i\mid i\le\varphi(\ell)\}$，而文本前缀 $y_{<\ell}=(y_1,\dots,y_{\ell-1})$。

![图 A7：交错数据与文本的支持方式](rendered_figures/figA7-interleaved-masking.png)

*图 A7（原文附录 Figure 7，第 24 页）：一个网页（含两张图像和三段文字）如何被处理，以及对应的掩码交叉注意力。*

**图中文字翻译与读法**：

- **左侧 Input webpage（输入网页）**：文字 “Cute pics of my pets!”，一张小狗图配 “My puppy sitting in the grass.”，一张猫图配 “My cat looking very dignified.”。
- **底部 Processed text（处理后文本）**：插入 `<image>` 标签并加上特殊 token：`<BOS>Cute pics of my pets!<EOC><image>My puppy sitting in the grass.<EOC><image> My cat looking very dignified.<EOC>`（`<BOS>` 表示序列开始，`<EOC>` 表示 end of chunk，块结束）。
- **中间**：tokenization（分词）之后，每个文本 token 下方的数字就是 $\varphi$（图中 $\phi$），即它可以关注的图像：第一张图之前的 token 为 0（看不到任何图像）；第一张图之后到第二张图之前的 token 为 1；第二张图之后的 token 为 2。
- **上方 Masked cross attention（掩码交叉注意力）**：两行色条分别对应 Image 1 和 Image 2（右侧各经 Vision Encoder 和 Perceiver Resampler 得到 K=V=[X]）；深蓝色是可见（未被掩码），浅蓝色是被掩码。下面一行（Image 1）只有 $\varphi=1$ 的文本 token 是深蓝，上面一行（Image 2）只有 $\varphi=2$ 的是深蓝。
- **读图结论**：每个文本 token 只会直接看到一张图，且这一设计使模型可以泛化到任意数量的视觉输入：训练交错数据时每个序列最多只用 5 张图，而评测时模型能受益于多达 32 对（图像，文本）“shots”。

**为什么只看最近一张图**（第 3.3 节与附录 B.3.1）：把交叉注意力改成可以看**所有**此前图像，总体得分下降 7.2%（表 10 (ii)：70.7 对 63.5，见第五节）。一种解释是，看所有图像时，交叉注意力的输入里没有显式的方法区分不同图像；虽然近期工作表明因果注意力机制可以隐式做到这点，作者还试了显式的方案（在图像标记里加下标如 `<image 1>`，或给每张图的交叉注意力特征加学习的绝对下标嵌入），但当序列里图像数量在训练和测试之间变化时，这些方案都不如单图交叉注意力稳健。训练时用 $N=5$ 减少每个序列的图像数以提高效率，测试时却要泛化到 $N=32$，所以保留单图方案。

**M3W 的图像对应随机化**（附录 A.3.2）：网页上文字与图像的对应关系一般未知（例如“This is my dog! 〈狗图〉”里图在文后，“〈狗图〉 That was my dog!”里图在文前）。作者假设与某处文字最相关的图像，要么是这个 token 之前最后出现的图，要么是紧跟其后的图，并在训练时对每个采样的网页以概率 $p_{\text{next}}=\tfrac12$ 选择“映射到下一张图”（其余映射到前一张）。这意味着约一半时候做的是语义上“不自然”的选择，但消融（表 10 (iii)）发现 $p_{\text{next}}=\tfrac12$ 略优于 0（总是前一张）和 1（总是后一张），这表明随机化起到了某种数据增强的作用。

### 3.7 训练数据：三类数据，全部来自网络

Flamingo 在三类数据的混合上训练，全部抓取自网络，且不使用任何为机器学习目的而标注的数据。

![图 A9：训练数据集的格式](rendered_figures/figA9-training-datasets.png)

*图 A9（原文附录 Figure 9，第 26 页）：不同格式的训练数据集混合。*

**图中文字翻译与读法**：从左到右三种数据：Image-Text Pairs dataset（图像-文本对，$[N=1,T=1,H,W,C]$，例：一张火烈鸟图配 “This is an image of a flamingo.”）、Video-Text Pairs dataset（视频-文本对，$[N=1,T>1,H,W,C]$，例：滑板视频帧配 “A kid doing a kickflip.”）、Multi-Modal Massive Web（M3W）dataset（多模态大规模网页数据，$[N>1,T=1,H,W,C]$，例：“Welcome to my website!” 接小狗图配 “This is a picture of my dog.” 再接猫图配 “This is a picture of my cat.”）。$N$ 是单个样本的视觉输入个数（图文对与视频文本对 $N=1$），$T$ 是视频帧数（图像 $T=1$），$H,W,C$ 是高、宽、通道数。**读图结论**：三类数据在“视觉输入个数”和“是否有时间维”上不同，Flamingo 的架构（Resampler 把任意形状压成 64 个 token，掩码处理多图）正是为统一处理它们而设计的。

**M3W：交错图文数据集（MultiModal MassiveWeb）**。少样本能力依赖于在交错的文本与图像数据上训练，为此作者收集了 M3W。

- 从约 4300 万个网页（数据表给出 43.3M 个文档）的 HTML 中提取文本与图像，按 DOM 中文本和图像元素的相对位置确定图像相对文字的位置；总计 185M 张图像、182 GB 文本；
- 构造样本：在纯文本里图像所在位置插入 `<image>` 标签，并在每张图像之前、以及文档结尾插入一个特殊的 `<EOC>`（end of chunk）token（加入词表并学习）；
- 每篇文档随机采样一个长 $L=256$ 个 token 的子序列，取其中**前 $N=5$ 张**图像，更多的图像丢弃以节省计算；
- 收集过程类似 MassiveWeb：滤掉非英文文档和未通过内部内容过滤（识别图像、视频、文本中的露骨内容）的文档；没有抓到图像的文档丢弃；应用类似的文本启发式过滤以去除低质量文档和重复；图像过滤去掉太小（宽或高小于 64 像素）、过宽或过窄（长宽比任一方向大于 3）或明显低质（如单色图）的图像；过滤后不含图像的文档丢弃。数据集不对外发布（数据表中“是否分发给第三方”答案为否）。

**图文对与视频文本对**：

- **ALIGN**（Jia 等）：18 亿张图像配 alt-text；规模大但噪声多且只有图像；平均每条文本 12.4 个 token；
- **LTIP**（Long Text & Image Pairs）：作者新建的 3.12 亿对图文，描述更长更优质（平均 20.5 个 token）；
- **VTP**（Video & Text Pairs）：2700 万个短视频（平均约 22 秒），配句子描述。
- LTIP 与 VTP 通过抓取不到十个以高质量、丰富图像描述为目标的网站得到。配对数据按与 M3W 一致的语法处理：在每条训练文本前加 `<image>`（位于 `<BOS>` 之后），文本后加 `<EOC>`（在 `<EOS>` 之前）。

**对评测集去重**（附录 A.3.4）：用内部去重工具，把训练图像和评测数据的图像映射到一个“重复的更接近”的嵌入空间，再做近似最近邻检索。LTIP 与 ALIGN 对 ImageNet（训练、验证）、COCO、OK-VQA、VQAv2、Flickr30k、VisDial（训练、验证、测试）做了去重；没有对 VizWiz、HatefulMemes、TextVQA 去重，因为这三个评测是在训练完之后才做的，但作者认为影响不大（VizWiz 图像来自特定手机应用且只供下载，HatefulMemes 的 meme 由研究者制作，TextVQA 图像来自 OpenImages，都不太可能被网络抓取）。M3W 没有做去重（一个训练样本是含多张图的整个网页，不太可能包含评测图像）；对 M3W 的 1.85 亿张图做近重复统计，在 ImageNet、COCO、OK-VQA、VQAv2、Flickr30k、VisDial 的验证集与测试集中共发现 1314 个潜在重复，其中只有 125 个是精确重复。VTP 的 2700 万个视频也没有去重，因为视频评测数据集都来自 YouTube 或 Flickr，而 VTP 没有来自这两个来源的视频。

### 3.8 训练目标

训练目标是各数据集上文本负对数似然的加权和（原文式 (2)）：

$$
\sum_{m=1}^{M}\lambda_m\cdot\mathbb{E}_{(x,y)\sim\mathcal{D}_m}\Big[-\sum_{\ell=1}^{L}\log p\big(y_\ell\mid y_{<\ell},\,x_{\le\ell}\big)\Big],
$$

其中 $\mathcal{D}_m$ 和 $\lambda_m$ 是第 $m$ 个数据集及其权重。调好各数据集的权重 $\lambda_m$ 是性能的关键：四个数据集 M3W、ALIGN、LTIP、VTP 的权重分别取 1.0、0.2、0.2、0.03（在小模型上凭经验得到，之后固定）。作者对所有数据集**累积梯度**，发现优于“轮流更新”（round-robin）的做法（表 3 (ii)：70.7 对 62.9）。

### 3.9 训练细节与基础设施

- **数据增强与预处理**：对配对数据集的文本，以 0.5 的概率在最前面随机加一个空格，因为分词器会按词前是否有空格把同一个词映射到不同 token；这样强制模型对这种分词假象保持不变性，作者观察到跨任务的显著提升。视觉输入缩放到 $320\times320$（保持长宽比，必要时用均值填充），高于视觉编码器对比预训练用的 $288\times288$（受 FixRes 启发：CNN 在更高的测试分辨率下性能更好；视觉编码器被冻结，无需对其反向传播，所以增加分辨率的代价不大）；另有随机左右翻转和颜色增强。视频训练时，从每个训练视频中以 1 fps 采样一个 8 帧的片段；推理时输入 30 帧、3 FPS，办法是对 Resampler 里学到的时间位置嵌入做线性插值。
- **优化**：AdamW，全局范数裁剪 1；Perceiver Resampler 不用权重衰减，其他可训练参数权重衰减 0.1；学习率在前 5000 步从 0 线性升到 $10^{-4}$，之后保持不变（衰减学习率没有带来改进）；默认训练 50 万步。
- **基础设施**：用 JAX 和 Haiku 实现，全部训练与评测在 TPUv4 上完成；80B 模型在 1536 块芯片上训练 15 天，切分到 16 个设备上（Megatron 式 16 路模型并行，用于所有 Embedding、自注意力、交叉注意力、前馈层，NFNet 视觉层不分片）；用 ZeRO stage 1 切分优化器状态；所有可训练参数和优化器累加器以 float32 存储和更新，激活和梯度用 bfloat16 计算（参数先从 float32 降为 bfloat16），冻结参数以 bfloat16 存储和使用。
- **文本处理**：输入文本用词表大小 32,000 的 SentencePiece 分词器（模型卡）。

### 3.10 视觉编码器的对比预训练（附录 B.1.3）

视觉编码器与一个语言编码器一起从头训练：图像和文本分别编码，投影到共享嵌入空间并做 L2 归一化；用与 CLIP 相同的损失，包含文本到图像、图像到文本两个对比项，配对的图文是正样本，batch 里其余为负样本。可学习温度参数放在最后的 log-softmax 层。设 $V_i$、$L_i$ 分别是 batch 中第 $i$ 个元素的视觉和语言归一化嵌入，$\beta$ 是可训练的逆温度，$N$ 是 batch 大小：

$$
\mathcal{L}_{\text{txt2im}}=-\frac1N\sum_{i=1}^{N}\log\frac{\exp(L_i^{\top}V_i\beta)}{\sum_{j=1}^{N}\exp(L_i^{\top}V_j\beta)},
$$

$$
\mathcal{L}_{\text{im2txt}}=-\frac1N\sum_{i=1}^{N}\log\frac{\exp(V_i^{\top}L_i\beta)}{\sum_{j=1}^{N}\exp(V_i^{\top}L_j\beta)},
$$

最小化二者之和（原文式 (3)、(4)）。对比损失的详细讲解见 [CLIP](../clip/论文中文解读.md)。

- 语言编码器用 BERT 架构；语言和视觉编码器的输出分别在 token 和空间位置上做平均池化后再投影到共享空间（嵌入维度 1376）。**Flamingo 主模型只使用对比模型里的视觉编码器权重**。
- 在 ALIGN 和 LTIP 上预训练；训练图像分辨率 $288\times288$，batch size 16,384；训练 120 万步参数更新（每步包含两次梯度计算），用 512 块 TPUv4；学习率从 $10^{-3}$ 线性衰减到 0；训练时随机颜色增强和水平翻转；使用 Jia 等（ALIGN）的分词器；Adam 优化器，标签平滑 0.1；对 NFNet 编码器用 $10^{-2}$ 的自适应梯度裁剪（AGC），对 BERT 编码器用全局范数 10 的梯度裁剪。
- 评测：零样本 ImageNet 分类用图像与类名之间的图文检索，沿用 CLIP 的提示集成（如 “A photo of a {class_name}” 等多个模板的嵌入取平均）。

### 3.11 任务适配：少样本 in-context 学习（图 A8）

训练好之后，用多模态交错 prompt 让 Flamingo 完成视觉任务，做法类比 GPT-3：把若干支持样本（support examples，形如（图像，文本）或（视频，文本））和随后的查询视觉输入（query）按顺序交错拼成 prompt。

![图 A8：少样本交错 prompt 的构造](rendered_figures/figA8-few-shot-prompt.png)

*图 A8（原文附录 Figure 8，第 25 页）：给定若干任务相关的少样本示例（支持样本）和一个要预测的查询，把图像与对应文本交错起来构造 prompt。*

**图中文字翻译与读法**：

- **上半 Vision to Text tasks（input=vision, output=text，视觉到文本任务）**：Support examples（支持样本）是（戴墨镜的猫，“A cat wearing sunglasses.”）、（大象，“Elephants walking in the savanna.”）；Query（查询）是一张游泳圈火烈鸟的图。Processed prompt（处理后的 prompt）：`<BOS><image>Output: A cat wearing sunglasses.<EOC><image>Output: Elephants walking in the savanna.<EOC><image>Output:`。
- **下半 Visual Question Answering Task（input=vision+text, output=text，视觉问答任务）**：支持样本是（猫图，“What's the cat wearing?”，答案 sunglasses）、（大象图，“How many animals?”，答案 3）；查询是游泳圈火烈鸟图加 “What is on the water?”。处理后的 prompt 为 `<BOS><image>Question: What's the cat wearing? Answer: sunglasses<EOC><image>Question: How many animals? Answer: 3<EOC><image>Question: What is on the water? Answer:`。
- **读图结论**：格式规则很简单：所有“视觉到文本”任务在期望的回答前加 “Output:”；视觉问答任务用 “Question: {question} Answer: {answer}” 格式。示例之间用 `<EOC>` 分隔，每个图像前有 `<image>`。除非另有说明，示例的拼接顺序是随机的。

**开放式与封闭式评测**：

- **开放式**（open-ended）：取模型在查询图像之后采样的文本作为预测，遇到第一个 `<EOC>` 预测就停止；除非另有说明，一律用束宽为 3 的束搜索（beam search）；
- **封闭式**（close-ended）：把所有可能的输出分别接在查询图像之后，用模型估计的对数似然给每个序列打分，据此从最有把握到最没把握排序。

**零样本**（附录 A.2）：没有少样本示例时，常见做法是靠提示工程，用合适的自然语言任务描述作条件，但验证这类 prompt 需要标注样本，不能算真正的零样本，且这类验证流程在只有少量验证样本时一般不稳健。为此本文报告零样本时，用**两个来自下游任务、但去掉了对应图像或视频的文本示例**构建 prompt。例如对图 A8 上半的任务，prompt 为 `<BOS>Output: This is a cat wearing sunglasses.<EOC>Output: Three elephants walking in the savanna.<EOC><image> Output:`，并且不给模型任何支持图像。作者发现只给一个文本示例（而不是两个）有很大副作用，因为模型会偏向生成与这一个示例相似的文本；给两个以上只有边际帮助；因此所有零样本结果都用两个文本示例。对封闭式任务，零样本 prompt 里甚至不需要提供文本示例。

**RICES**（Retrieval-based In-Context Example Selection，Yang 等 2021）：当支持集大到无法全放进 prompt 时（太贵，也有 prompt 长度超过训练序列长度后泛化变差的风险），做 prompt 选择：给定查询图像，用冻结的预训练视觉编码器提取视觉特征，在支持集中检索相似图像，取最相似的 top-$N$ 个拼成 prompt；由于 LM 对 prompt 里的顺序敏感（近因偏差），把示例**按相似度从低到高**排列，使最相似的支持样本紧挨在查询之前。这在有几百个类别、每类给一张或多张图像的分类设定里尤其有效（表 7）。

**Prompt 集成**：封闭式设定下还可以对多个 prompt 的输出做集成，并可与 RICES 结合（对排序后的最近邻做多种排列）。具体做法：对给定答案，对模型在所选少样本示例的 6 种随机排列下估计的对数似然取平均。

### 4.3 微调 Flamingo（表 2、表 8）

微调不是本文重点，但作者验证了：有更多数据时，Flamingo 也可以通过微调权重来适应任务。做法是对最大的 Flamingo，在**不限制标注预算**的情况下按任务微调：用小学习率、短训练计划；同时额外**解冻视觉主干**，并把输入分辨率从 $320\times320$ 提高到 $480\times480$（附录 B.2.2：LM 层保持冻结，训练的 Flamingo 层与预训练时相同；解冻视觉编码器通常能提升结果，部分原因是分辨率更高）。每个任务的部分超参数用训练集验证子集上的网格搜索选择：学习率（$3\times10^{-8}$ 到 $1\times10^{-5}$）、衰减策略（以 10 倍为因子指数衰减）、训练步数、batch size（8 或 16），以及是否使用视觉数据增强（颜色增强、随机水平翻转）。

- **(ii) 优化**：梯度累积优于轮流更新（70.7 对 62.9）。
- **(iii) tanh 门控**：去掉 0 初始化的 tanh 门控，总体降 4.2%，并观察到训练不稳定。
- **(iv) 交叉注意力架构**：VANILLA XATTN 是原始 Transformer 解码器里的普通交叉注意力；GRAFTING（来自 VC-GPT 一类做法）则不在冻结 LM 里插入任何层，而是在冻结 LM 的输出之上从头训练一叠自注意力与交叉注意力交错的层。GATED XATTN-DENSE 最好。
- **(v) 算力/内存与性能的折中**：每层都加最好，但可训练参数和时间复杂度显著增加；每 4 层加一个能让训练快约 66%，总体只降 1.9%。因此在硬件限制下尽量多加层：Flamingo-9B 每 4 层、Flamingo-80B 每 7 层加一个。
- **(vi) Resampler**：在相同参数预算下，MLP 和普通 Transformer 都不如 Perceiver Resampler，而且更慢。
- **(vii) 视觉编码器**：自己对比预训练的 NFNet-F6 比公开的 CLIP ViT-L/14（224 分辨率）高 5.8%，比较小的 NFNet-F0 高 8.0%，说明强视觉主干很重要。
- **(viii) 冻结 LM 防止灾难性遗忘**：若 LM 从头训练，总体降 12.9%；有趣的是，微调预训练好的 LM 也会降 8.0%，这是“灾难性遗忘”（catastrophic forgetting）的一个实例：模型在学习新目标时逐渐忘掉预训练内容。在本文设定下，冻结语言模型是比“把预训练数据集 MassiveText 也混进训练”更好的选择。

**扩展消融（附录 B.3.1，表 10）**：同样用 Flamingo-3B，在 5 个 DEV 基准的验证子集上以 4 个示例评测；batch size 为 M3W 256、ALIGN 512、LTIP 512、VTP 64，训练 100 万个梯度步（基线因为累积四个数据集的梯度，对应 25 万次梯度更新）。

- **(vi) 联合训练文本数据而不是冻结 LM**：另一种防止灾难性遗忘的办法是把 MassiveText 加入训练混合（权重 1.0，序列长度 2048，设置与 Chinchilla 预训练文本损失一致；这时必须解冻 LM、仍冻结视觉编码器）。从预训练 LM 出发（LM 学习率乘 0.1）或从头训练，总体得分都低于基线，说明冻结 LM 是更好的策略，而且更便宜：不需要更新 LM 权重，也不需要额外训练数据集，这一点对最大的 80B 模型更重要，因为它冻结了几乎 90% 的权重。
- **(vii) 用公开数据与权重复现**：作者另给了两组更易复现的参考数字，用 CLIP ViT-L/14 权重和 LAION-400M 数据集。

## 六、质性结果与局限（附录 C、D）

**质性结果**（附录 C）：除图 1 外，作者给出了单图（图 10）、多轮对话（图 11）和视频（图 12）的样例（本文未转载这三张样例图），质性结果都用贪心解码（不是定量评测中的束宽 3 束搜索），以加快采样。要点：模型虽未专门针对问答格式训练，预训练 LM 的能力使其能适应；很多样例里 Flamingo 能做至少一步隐式推理（问题里没点名的物体，直接查询其属性，模型凭视觉输入回忆相关知识并作答）；经对比训练的视觉网络已被证明会学到字符识别能力（CLIP），Flamingo 在完整模型中保留了这一能力，有时是相对图像很小的文字；多轮对话（提供简短对话 prompt，附录 B.1.6，之后用户插入图像）里，即便经过几轮交互，模型仍能关注图像并回答单靠语言猜不出的问题，且多张图像可被分别关注，能做简单的比较与推断；对视频，它能在某些情况下整合多帧信息并回答涉及时序的问题（如含 “after” 的问题）。

图 1 下排与附录图 11 的对话，用的是下面这段固定的对话 prompt（附录 B.1.6）作为前缀，里面有 3 张示例图；之后用户与 Flamingo 轮流发言，用户随时插入新图像：

visual AI, Flamingo. User sends images, and Flamingo describes
them.

Flamingo: That is a cat. It's a tiny kitten with really cute big

Flamingo: This is a picture of a group of people having dinner.

User:     Can you guess what are they celebrating?
Flamingo: They might be celebrating the end of a successful

Flamingo: This is a graph, it looks like a cumulative density

**图中文字翻译与读法**：三个例子（上方 Input Prompt，下方 Output）。左：一张黑色手机的图，问 “What is on the phone screen?”，答 “A text message from a friend.”；图中看不到屏幕上有任何可读的内容，模型却生成了只看文字时显得“合理”的答案，即幻觉；中：一张三明治和沙拉的图，问 “What can you see out the window?”，答 “A parking lot.”，这是用与图无关的问题诱发的幻觉；右：一个孩子低头看手机，问 “Whom is the person texting?”，答 “The driver.”，图中根本无从得知，模型做出了无依据的猜测。**读图结论**：语言模型的先验一般有帮助，但也会导致偶发的幻觉和无依据的猜测；少样本示例和更精细的 prompt 设计可能缓解，但这是改进开放式视觉对话应用的重要研究方向。

**局限**（正文第 5 节与附录 D.1）：

1. **继承语言模型的弱点**：LM 先验通常有帮助，但可能导致偶发幻觉和无依据的猜测；因果建模的条件输入，表达力严格弱于双向建模；LM 对明显长于训练序列的测试序列泛化很差：例如 VisDial 的一个 shot 是一张图加 21 句对话，32 个 shots 至少 $32\times21=672$ 句，prompt 长度 4096 到 8192 个 token，远超 LM 训练的最大序列长度 2048，所以 VisDial 只报告到 16 shots；经验上从 16-shot 到 32-shot，VisDial 的相对性能大降约 30%；语言模型的训练样本效率也很差。
2. **分类性能落后于对比模型**：对比目标直接优化文图检索，分类是其特例；而 Flamingo 的语言建模目标不是。如何在一个统一的方法里兼顾两者是重要的研究方向。
3. **上下文学习的取舍**：优点是几乎不需要调超参数、在极低数据量（几十个示例）下表现不错、只需推理即可部署；缺点是：
   - **推理计算成本**：上下文学习的计算量，如果可以为多个查询复用少样本 prompt（缓存 key/value），随示例数线性增长，否则二次增长；基于梯度的少样本方法在推理时与示例数无关；
   - **对 prompt 敏感**：对示例的顺序、格式等“令人不安地”敏感；
   - **示例数超过 32 后性能快速饱和**：这与基于梯度的方法（正确配对的训练数据量是性能关键）形成鲜明对比；RICES 能在分类上缓解这点，但仍面临类似问题；
   - **任务定位（task location）**：已有研究提示，上下文学习更可能是在“识别任务”而不是真的从示例的输入输出映射里“学习”新任务（Reynolds 与 McDonell；Min 等指出示例的格式比输入到输出的映射更重要）。本文也观察到不带图像的 prompt 就有非平凡的零样本性能，说明任务格式很重要。直觉上，几个样例往往足以定位任务，但模型通常无法利用更多样例。
   - 作者的结论：没有适合所有场景的“黄金”少样本方法，最佳选择取决于应用特点，其中一个重要因素是标注样本的数量；本文表明上下文学习在数据匮乏的区间（32 个样本及以下）很有效，结合不同方法、在数据受限但不极端的区间（如几百个样本）可能有机会。
4. **扩展视觉与文本接口**：自然语言虽是描述视觉任务的强大通用接口，但对需要以边界框（及其时间、时空版本）为条件或预测的任务，或空间/时间上稠密的预测，可能很笨拙；预测光流这类连续空间输出，也不是模型开箱即用能处理的；还可考虑加入音频等其他模态。
5. **视觉语言模型的缩放规律**：本文把 Flamingo 扩到 80B，给出了跨评测基准的初步缩放趋势（图 2）。语言领域有大量关于缩放规律的研究，视觉领域有 Zhai 等的工作，而视觉语言模型（包括对比模型和 Flamingo 这样的）尚无类似工作；原文推测，以聚合的下游评测性能而不是困惑度建立此类趋势，可能对目的更直接有用。

## 七、社会影响与风险（原文第 5 节、附录 D.2、E、F）

**益处**：任务泛化能力使它适用于以往视觉研究不太关注的场景；以“聊天”界面做开放式对话，可以让非专家用户把这类模型用于几乎没有任务专用数据的低资源问题；本文在 VizWiz（辅助视障人士的视觉识别挑战）上有强表现；对话界面也有助于理解和解释 VLM，并暴露模型从训练数据中学到的偏见、公平性和毒性问题。另一个角度是“模型回收”：Flamingo 训练算力昂贵，但它充分复用了预训练的冻结语言模型和视觉编码器，证明新模态可以引入冻结模型而避免昂贵的重训，这从环境和实际角度都越来越重要。

**风险**：Flamingo 由构造决定会继承大语言模型的风险：没给图像时它就退回到 LM 行为，可能输出冒犯性语言、传播社会偏见和刻板印象、泄漏隐私信息（Chinchilla 论文对性别偏见与无提示毒性有分析，原文引用）；视觉输入带来额外风险，如与输入图像内容相关的性别和种族偏见。作者做了初步调查：

- **性别与种族偏见**：按 Zhao 等的做法，在 COCO 上比较按性别和肤色划分的子集上的描述质量（CIDEr）。由于只有一个模型副本（训练代价高），他们对逐样本的 CIDEr 做统计检验（不等方差双尾 $t$ 检验），而不是跨 5 个模型汇总。结果（表 12）显示四项比较里最小的 $p$ 值是 0.25，远高于常见显著性阈值（如 0.05），所以差异与随机波动无法区分。原文也指出，没拒绝零假设并不意味着没有差异，更大的样本量下可能显示出差异。
- **带图像提示时的毒性**：用 Perspective API 评估给定 COCO 测试图像时生成描述的毒性；有些描述被分类器标为可能有毒，但人工检查没有发现明确的毒性；作者在项目过程中对“安全工作场景”（safe-for-work）图像也没有观察到毒性输出，但这不等于模型无法产生毒性输出，尤其是遇到“不适合工作场景”的图像和（或）毒性文本时；若投入生产需要更彻底的研究。
- **缓解**：Flamingo 能在低资源设置下快速适配，可自己用于缓解上述问题，比如经适当条件设定或微调后用于过滤训练数据里的有毒样本，或对输出降级、排除；HatefulMemes 上的结果是在这个方向上的一步。

|---|---|---|---:|
| AoANet | - | +0.0019 | 1.198 |
| Oscar | - | +0.0030 | 1.278 |
| Flamingo，0-shot | 0.899 − 0.870 = +0.029（$p=0.52$） | 0.955 − 0.864 = +0.091（$p=0.25$） | 0.843 |

**模型卡与数据表**（附录 E、F）：Flamingo 仅为研究目的开发，不应在未经风险分析和缓解的情况下用于具体应用；训练数据源自网络，未过滤毒性内容（只去掉露骨内容），数据里“无疑包含有毒和有偏见的内容”，很可能含有个人信息；数据主要是英文，因此不适合训练需要多语言能力的模型；M3W、LTIP、VTP 不对外分发。数据规模：M3W 共 43.3M 个文档、185M 张图像、182 GB 文本；LTIP 3.12 亿对图文；VTP 2700 万对视频文本；2021 年用数月收集。模型卡称评测一共用了 18 个基准。

## 八、相关工作（原文第 4 节，简述）

- **语言建模与少样本适配**：先大规模预训练、再适配下游任务已成为标准。本文以 70B 的 Chinchilla 为基础语言模型。让 LM 用少量示例适应新任务的技术有：加小型适配器模块、微调 LM 的一小部分、在 prompt 中给上下文示例、通过梯度下降优化 prompt 等。本文选择上下文少样本学习，而不是基于度量学习或元学习的更复杂方法；
- **语言遇上视觉**：BERT 启发了大量视觉语言工作，与它们不同，Flamingo 不需要在新任务上微调；另一族模型基于对比学习，Flamingo 与它们不同在于**能生成文本**，尽管它的视觉编码器就建立在对比模型之上；也有能自回归生成文本的 VLM；一条思路是冻结预训练 LM 权重以防灾难性遗忘，本文沿用这一思路，冻结 Chinchilla 各层并在其中加入可学习层；区别在于本文提出了第一个能接受任意交错的图像、视频和文本的 LM；
- **网络规模视觉语言训练数据**：人工标注的视觉与语言数据集昂贵、规模小（1 万到 10 万量级）；已有工作自动抓取配对的视觉-文本数据。除配对数据外，本文展示了在整个交错图文的多模态网页上训练的重要性。同期工作 CM3 提议从网页生成 HTML 标记，而本文只生成纯文本以简化任务；本文强调少样本学习和视觉任务，CM3 主要在纯语言基准上做零样本或微调评测。

## 九、复现检查清单

- **冻结与训练范围**：视觉编码器（NFNet-F6，约 435M）与语言模型都冻结，只训练 Perceiver Resampler 和 GATED XATTN-DENSE 层（预训练阶段）；微调阶段才解冻视觉编码器，分辨率由 $320\times320$ 提高到 $480\times480$；
- **Resampler**：64 个 latent，6 层，Key/Value 拼接 $[X_f, X]$，只加时间位置嵌入、不加空间位置嵌入；
- **门控**：每个新层各一个 $\alpha_{\text{xattn}}$ 与 $\alpha_{\text{dense}}$，初始化为 0，$\tanh$ 后乘在分支输出上；插入频率 3B 每层、9B 每 4 层、80B 每 7 层；
- **掩码**：文本 token 只对紧邻其前的那一张图做交叉注意力；用 $\varphi$ 记录每个位置对应的图像；M3W 训练时每个序列 $L=256$ 个 token、最多 $N=5$ 张图，并以 $p_{\text{next}}=0.5$ 随机映射到前一张或后一张图；`<EOC>` 要加入词表并学习；
- **数据与权重**：M3W、ALIGN、LTIP、VTP 的权重 1.0、0.2、0.2、0.03；梯度累积而非轮流更新；配对数据文本前以 0.5 概率加空格；对评测集去重要覆盖训练图像（但原文未对 VizWiz、HatefulMemes、TextVQA 去重）；
- **优化**：AdamW，全局范数裁剪 1，Resampler 无权重衰减、其余 0.1，学习率前 5000 步线性升到 $10^{-4}$ 后恒定，默认 50 万步；
- **评测**：支持集与查询集分离，DEV 与留出基准分开；固定的 prompt 模板（“Output:”、“Question: … Answer:”以及 HatefulMemes 与 RareAct 的专用 prompt）；开放式用束宽 3 的束搜索并在第一个 `<EOC>` 停止，封闭式用对数似然排序；零样本 prompt 用两个不带图像的文本示例；分类用 RICES（按相似度从低到高排列）并可加 6 种排列的集成；
- **报告口径**：区分 DEV 基准和留出基准、说明 shots 数、说明 VisDial 只到 16 shots、说明是否使用了 OCR 文本（只有 HatefulMemes 用了）。

## 十、常见误读

- **Flamingo 不是把图像先转成自然语言再交给 LM**：视觉 token 由 Perceiver Resampler 产生，经 GATED XATTN-DENSE 层以连续特征的形式注入语言模型。
- **“只训练连接模块”不等于“很小”**：80B 模型里可训练的 GATED XATTN-DENSE 层有 10B 参数（外加约 194M 的 Resampler），只是相对 70B 的冻结 LM 占比不高。
- **逐图像掩码不是“屏蔽未来图像”**：它的含义是每个文本 token 只对紧邻其前的那一张图做交叉注意力，更早的图像经 LM 自注意力间接可见；训练 M3W 时还以 0.5 的概率把文字映射到“下一张”图像作为数据增强。
- **tanh 门控初始化是 0 而不是“接近 0”**：$\tanh(0)=0$，初始时新层输出为零，模型严格等于原 LM。
- **少样本强不等于视觉事实可靠**：幻觉和无依据的猜测依然存在（图 A13）；示例过多后收益饱和，对 prompt 格式和顺序敏感。
- **“超过微调 SOTA”有条件**：只在 6 个任务（OKVQA、MSVDQA、Flickr30k、iVQA、STAR、NextQA）上成立，且这些任务的微调 SOTA 所用标注数据相对较少（6K 到 46K）；在 VQAv2、COCO、YouCook2、TextVQA 等任务上仍明显落后。
- **DEV 与留出基准的区别**：设计决策是在 5 个 DEV 基准上定的，只有其余 11 个基准的数字才是无偏估计。
- **分类不是强项**：ImageNet 上 Flamingo-80B 即便用 RICES 加集成（77.3），也不如它自己的对比视觉编码器零样本（77.9），更不如专门优化的 BASIC、LiT。

## 十一、与相关论文的关系

- 视觉编码器的对比预训练直接沿用 [CLIP](../clip/论文中文解读.md) 的双向损失，并在表 3 (vii) 中与公开的 CLIP ViT-L/14 比较；
- 冻结的语言模型是 [Chinchilla](../chinchilla/论文中文解读.md)（1.4B、7B、70B）；上下文少样本学习的思路来自 [GPT-3](../openai_gpt3/论文中文解读.md)；
- 另一条“冻结 + 少量连接”的开放路线是 [LLaVA](../llava/论文中文解读.md)：用 CLIP ViT-L/14 视觉特征加一个线性投影接入语言模型，再做视觉指令微调，连接模块极小，与 Flamingo 的交叉注意力式连接形成对比；
- 与对比表征模型（CLIP、ALIGN）相比，Flamingo 能生成文本，但分类性能不如它们。
