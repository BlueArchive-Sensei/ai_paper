# Medusa 中文精读

> **图表阅读约定**：只保留独立的架构图、流程图、曲线图或数据图表；论文摘要、正文段落和说明页不使用截图。本目录没有复用原图，多头结构、树和实验均用中文重建，专有名词保留英文。

## 1. Medusa 想消除独立 draft model 的维护成本

传统 speculative decoding 需要一个便宜但与 target 高度一致的 draft。它要共享 tokenizer、随 target 版本升级、占额外显存，并在分布式环境单独部署。Medusa 改为复用 target 已算出的最后隐藏状态 $h_t$，在顶部加 $K$ 个 head，直接预测未来多个位置。

原 LM head 预测 $t+1$；第 $k$ 个 Medusa head 预测 $t+k+1$。因为 heads 很小且可在同一次 target forward 后并行执行，draft overhead 大幅降低。

## 2. Multiple heads 的公式与含义

第 $k$ 个 head 的输出为：

$$
p_t^{(k)}=\operatorname{softmax}\left(
W_2^{(k)}\left[\operatorname{SiLU}(W_1^{(k)}h_t)+h_t\right]
\right).
$$

$W_2^{(k)}$ 初始化为原 LM head，$W_1^{(k)}$ 初始化为零，使训练起点与原 next-token projection 对齐。head 只看到同一个 $h_t$，并未看到它所预测的前一个未来 token，所以较远位置不确定性更大。后续 EAGLE 的关键改进正是恢复这种自回归条件依赖。

训练时第 $k$ 个 head 用未来真值 $y_{t+k+1}$ 做交叉熵：

$$
\mathcal L_{\text{Medusa-1}}=
\sum_{k=1}^{K}-\lambda_k\log p_t^{(k)}(y_{t+k+1}),
$$

论文实践让 $\lambda_k$ 随距离衰减，例如 $0.8^k$，避免远期、更难的预测主导损失。

## 3. 为什么要把 candidates 组织成树

若每个 head 取 top-$s_k$，笛卡尔积会形成许多 continuation。逐序列验证会重复共享前缀，Medusa 因此沿用 tree attention：把候选压成树，节点只注意祖先，position id 依树深设置。一次 target forward 同时得到每个候选节点的真实 logits。

候选数越多越可能包含 target 喜欢的路径，但 target 验证 token 也越多。论文根据训练数据估计常见路径概率，选择固定稀疏树而不是完整笛卡尔积，用节点预算换更高覆盖。

## 4. Medusa-1 与 Medusa-2 不能混为一谈

### 4.1 Medusa-1：冻结 backbone

只训练新 heads，原 target 参数和 next-token 行为不变。若验证使用标准 modified rejection sampling，最终分布仍由原 target 决定，可称 lossless acceleration。优势是训练便宜、可外挂到已有对齐模型；弱点是 target representation 并未为多步预测优化，heads 的接受率有限。

### 4.2 Medusa-2：联合训练

backbone 与 heads 一起调整，使隐藏状态更适合预测多个未来 token。直接联合微调会损害原能力，所以论文用两阶段 recipe，并保留原 next-token loss。它提高接受率和速度，但 target 本身已变化；所谓质量保持来自 MT-Bench 等实证，不再是“原分布完全不变”的数学结论。

若原 SFT 数据不可得，论文还提出 self-distillation：让 target 自己生成训练回复，再训练 heads，使数据分布更接近实际 target 输出。

## 5. 两种接受方案的保证不同

- **Rejection sampling**：使用 target/draft 概率比例与 residual correction，目标分布严格不变。
- **Typical acceptance**：只要候选在 target 分布中“足够典型”就接收，不要求完全符合拒绝采样概率。它可提高接受长度，但引入质量—速度折中。

论文用温度/阈值控制偏移，并以 MT-Bench 等评估生成质量。工程文档若写“Medusa 无损”，必须注明使用的是 Medusa-1 + exact rejection；不能把 typical acceptance 或 Medusa-2 的结果一并归入严格无损。

## 6. 主结果与消融

Vicuna-7B 的代表表格：

| 设置 | MT-Bench 质量 | 加速 |
|---|---:|---:|
| Baseline | 6.17 | 1.00× |
| Direct joint fine-tuning | 5.925 | 未作为可靠方案 |
| Medusa-1 | 6.23 | 2.18× |
| Medusa-2 | 6.18 | 2.83× |

质量由 GPT-4 judge 给出，有模型评价噪声，接近的 6.17/6.23/6.18 不代表严格等价。组件消融给出清晰增量：heads without tree attention 约 1.5×，加入 tree attention 约 1.9×，优化树约 2.2×，再用 Medusa-2 训练约 2.8×。因此加速不是“多几个 head”单点贡献，而是提案、树覆盖和训练一致性的叠加。

论文整体报告 Medusa-1 超过 2.2×、Medusa-2 约 2.3–3.6×，具体值随模型与 prompt。实验主要 batch 1；高 batch 时 target 已有较高利用率，多候选验证可能更贵。

## 7. 失败模式与工程取舍

- 远期 heads 条件信息不足，预测错误相关且接受率下降。
- 固定树只反映平均分布；当前上下文很确定或很不确定时都可能分配错节点。
- vocabulary projections 的参数/带宽并非完全免费，head 数多时开销上升。
- Typical acceptance 的阈值需要按任务、温度重新校准。
- Joint fine-tuning 可能改变 safety/alignment behavior，MT-Bench 不能覆盖这些维度。
- 自蒸馏只能模仿 target 常见输出，稀有域接受率可能低。

## 8. 与 EAGLE 的关系

Medusa 证明“复用 target representation + tree verify”可以摆脱独立 draft。EAGLE 进一步指出，对同一 $h_t$ 并行预测多个离散未来 token 太难；它改为自回归预测更平滑的倒数第二层 feature，并把已采样 token 前移一位作为输入来消除特征不确定性。EAGLE-2 又把 Medusa/EAGLE 的固定候选树改为上下文相关动态树。

## 9. 复现检查表

- 明确 Medusa-1 还是 Medusa-2、exact 还是 typical acceptance。
- 报 head 数、每头 top-$s_k$、树节点预算和平均接受长度。
- 基线与方法必须用相同 target checkpoint、batch、温度和 kernel。
- 除平均速度外报告 target verification latency、head overhead、P99 和吞吐。
- Medusa-2 需做通用能力、安全和域外回归，不只做 MT-Bench。
- 自蒸馏需记录生成温度、数据量与过滤，避免把 teacher 输出当真实标签。
