# 论文概要：《Mooncake: A KVCache-centric Disaggregated Architecture for LLM Serving》

## 一、基本信息

- 作者：Ruoyu Qin、Zheming Li、Weiran He 等，Moonshot AI / 清华大学
- 首次公开：2024-07；FAST 2025 Best Paper，arXiv:2407.00079
- 定位：Kimi 线上服务平台的 KVCache-centric 分离式架构
- 核心贡献：prefill/decode 解耦、分布式 KV cache、cache-aware scheduling、overload early rejection
- 本地材料：[论文 PDF](paper.pdf) · [提取文本](paper.txt) · [中文精读](论文中文解读.md)

## 二、一句话结论

Mooncake 把 KV cache 视为 LLM serving 的一等资源：prefill 与 decode 分池，利用 GPU 服务器闲置的 CPU DRAM/SSD 保存可复用前缀，再用 RDMA 在节点间搬运；在长上下文与高复用负载下可显著提高 goodput，但收益依赖真实 cache hit、网络带宽和 SLO 调度。

## 三、核心组件

- **Conductor**：全局调度，联合考虑 cache locality、prefill load、decode load、TTFT/TBT SLO。
- **Prefill pool**：chunked pipeline parallelism 与 layer-wise prefill。
- **KVCache pool**：CPU DRAM/SSD 的 paged blocks，以前缀 hash 去重。
- **Messenger**：基于 GPUDirect RDMA 的 cache transfer。
- **Decode pool**：continuous batching，按 TBT SLO 接收请求。
- **Overload scheduler**：预测完成概率，尽早拒绝无法满足 SLO 的请求，避免已经消耗大量算力后再失败。

## 四、主要结果

- 公开 1 小时、23,608 请求的匿名 trace（保留到达时间、输入/输出长度、重映射 block hash）。
- 模拟场景在满足 SLO 时相对基线最高报告 525% throughput 提升。
- 真实 workload 回放中，报告可处理 75% 更多请求。

## 五、局限

- 为保护生产信息，实验使用与 LLaMA2-70B 同架构 dummy model 和重放 trace，不是直接开放 Kimi 生产模型。
- cache 命中低、输入短或网络拥塞时，远程 cache 管理可能不划算。
- early rejection 优化 goodput，会牺牲被拒用户，需要公平性与重试策略。
- P/D 分离增加故障恢复、调度和尾延迟复杂度。
