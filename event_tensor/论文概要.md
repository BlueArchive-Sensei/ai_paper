# Event Tensor 论文概要

## 基本信息

- 题目：*Event Tensor: A Unified Abstraction for Compiling Dynamic Megakernel*
- 作者：Hongyi Jin 等
- 版本：arXiv:2604.13327，2026 预印本
- 原文：https://arxiv.org/abs/2604.13327
- 主题：动态 MegaKernel、event dependency、静态/动态调度、LLM serving

## 一句话结论

Event Tensor 把 tile-level 的“等待/通知关系”表示成带 shape 的 tensor，使 shape dynamism 与 data-dependent routing 都可进入编译 IR；同一程序可选择低开销静态 schedule 或高适应性动态 schedule，生成 persistent megakernel。

## 核心方法

- device function 定义 tiled tasks。
- Event Tensor 每个元素对应一个依赖计数器，可 wait/notify。
- symbolic shape 描述 dynamic batch/sequence。
- runtime-computed index/indptr 描述 MoE top-k 等数据依赖。
- static transformation：预先将 tasks 排进各 SM queue。
- dynamic transformation：设备侧 push/pop scheduler 按 ready events 分配 tasks。

## 主要结果

- GEMM+ReduceScatter 等融合 communication/compute 最高约 1.40×。
- 单 B200 MoE layer 相对 specialized baseline 最高约 1.23×。
- Qwen3-30B-A3B batch 1 相对 vLLM/SGLang 分别约 1.48×/1.20×。
- Qwen3-32B 单 GPU相对基线最高约 1.15×；TP=4 时部分场景仅持平或落后。
- Qwen3-32B warmup：ETC 35 s，vLLM 123 s，SGLang 583 s；ETC 另有 107 s offline compilation，口径需分开。

## 局限

- 2026 预印本，代码生成和 serving runtime 尚可能快速变化。
- dynamic scheduler 并不总赢：小 batch 上 queue overhead 可超过负载均衡收益。
- 某些 TP 场景受 CPU runtime 和 GEMM tile 质量限制，落后 SGLang。
- AOT/offline compile 时间没有消失，只是从启动关键路径移走。

## 阅读价值

这篇回答 MegaKernel 最难的问题之一：动态图不能靠为每个 shape 捕获一张静态 CUDA Graph。Event Tensor 用统一 dependency abstraction 表达静态图、symbolic shape 和 data-dependent MoE。
